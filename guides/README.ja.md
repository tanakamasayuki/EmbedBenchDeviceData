# デバイスガイド

`guides/chips/<chip>.md` は **人が読むためのデバイス解説**である。1 ファイルだけ開けば
「これは何で、どう繋がっていて、どう叩けて、何に気をつければいいか」が分かることを目指す。

## 位置づけ

**このディレクトリはリポジトリの主目的から外れる。** 正本は `chips/` `knowledge/` `runs/` の
機械可読なデータである。ガイドはそれを人向けに読み下したもので、`tools/validate.py` はリンク切れだけを検査する。

I2CDeviceDB（commit 38f1d82）から移した。そこでの `profiles/` と `observations/` への参照は、
その commit への固定のリンクにしてある。`knowledge/` と `runs/` ができたチップから、参照をそちらへ書き換える。

それでも置いている理由は 2 つ。

1. **一次資料が無いデバイスがある。** M5Stack の Unit の多くは I2C の相手が
   固定機能 IC ではなくファームウェアが載ったマイコンで、レジスタ表を公開した
   datasheet が存在しない。ライブラリのソースから起こしたレジスタマップは
   `knowledge/` に入るが、**それ単体では「何のデバイスか」が分からない**。
   ガイドがその欠けている datasheet の役目を果たす。
2. **datasheet があっても読むのは重い。** 100 ページの PDF のどこに何が書いてあるかを
   先に示しておけば、必要な章に直行できる。

## 書式

[`guides/chips/m5stack-mcu-u186.md`](chips/m5stack-mcu-u186.md) を手本として写す。節の順番は固定する（横断で読むときに
同じ場所に同じ情報があることが価値なので）。

| 節 | 中身 |
|---|---|
| 冒頭の引用ブロック | 一行要約と、一次資料の有無・確度 |
| これは何か | 用途・構成・何ができて何ができないか。専門外の人が読んで製品像が掴める記述 |
| 早見表 | アドレス、電源、インタフェース、中身の IC、代表的な仕様 |
| レジスタ / コマンド | `knowledge/`（移すまでは I2CDeviceDB の profile）の内容を人向けに読み下したもの。単位とバイト順を必ず書く |
| 典型的な使い方 | 初期化から読み出しまでの手順。コードではなく手順として |
| 利用上の注意 | 落とし穴。ここが一番の価値 |
| どこに何が書いてあるか | 一次資料の索引。datasheet があれば章立て、無ければソースのどのファイル |
| 出典と確度 | 何を根拠に書いたか、どこが未確認か |

## 確度の書き方

**確認していないことを確認したように書かない。** ガイドは読みやすさのために
根拠を落としがちなので、冒頭の引用ブロックで必ず断る。

- `datasheet` 由来 → 「メーカーの datasheet に基づく」
- `inferred` 由来（ライブラリのソースから起こした） → 「**未確認**。ライブラリ実装から
  起こした推定で、実測で確かめられていない」
- 実測で確認済み → 「run `<run-id>` で確認済み」（I2CDeviceDB の pilot は observation の id のまま）

## 更新

ガイドは手で書く。`knowledge/` を直したらガイドも直す。索引は保存せず、`tools/build.py` が `build/guides.ja.md` に作る。
