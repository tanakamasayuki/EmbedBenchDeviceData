# RCWL-9620 — 超音波距離センサ IC

> 40kHz の超音波で距離を測るワンチップ。I2C（`0x57`）では `0x01` を書いて 100ms 待ち、
> 3 バイト読むと距離が返る。**生値の単位は µm**（1000 で割って mm）。
>
> **確度**: メーカー（无锡日晨物联科技）の中国語 datasheet V1.0 が M5Stack のサーバに
> ホストされており、**I2C のアドレス・コマンド・単位・待ち時間はそこに明記されている**
> （p.7「三：IIC 模式」）。ただしメーカー自身の公開サイトにコピーが無く、文書中に改訂日も
> 無い（V1.0 はファイル名から取った）。実測は無い。
> `profiles/rcwl-9620.yaml` の evidence は `inferred` のままだが、**I2C の枠組みについては
> datasheet に裏付けがある**（下の「出典と確度」を参照）。

## これは何か

外付けの開放型プローブ（16mm / 12mm / 10mm）向けに設計された測距チップ。1 チップで超音波の
送信・受信・復調・処理・計算・出力を行う。M5Stack Unit Ultrasonic-I2C（U098-B1）に載っている。

**出力モードが 4 つある**: GPIO（HC-SR04 互換）、UART（9600 N 1）、IIC、1-WIRE。
どのモードになるかは **ピン 7 / ピン 9 に付ける 10kΩ 抵抗の有無**で決まる。基板上で
固定されるので、**ソフトからは変えられない**。Unit Ultrasonic-I2C は IIC モードに配線されている。

| モード | PIN7（40K+_IIC） | PIN9（40K-_UART） |
|---|---|---|
| GPIO | NC | NC |
| IIC | 10kΩ | NC |
| UART | NC | 10kΩ |
| 1-WIRE | 10kΩ | 10kΩ |

チップの特徴として datasheet が挙げているのは、掃引駆動（扫频模式）でプローブのばらつきに
強いこと、プローブの温度特性に対する補償を駆動側で行っていること、√ の比較フィッティング曲線で
不規則な形の対象への追従を上げていること、盲区消除技術でプローブの一致性要求を下げていること。
外付け部品は最小限で済み、水晶も要らない（内蔵高精度発振器）。**最遠測距は外付け抵抗 R9 で
変わる**（メーカーのプローブで R9 が `753`（= 75kΩ）なら 3〜4m、`104`（= 100kΩ）なら 5〜6m
と書かれている）。

### できないこと・持っていないもの

- **I2C 上のコマンドは `0x01`（測距開始）1 個だけ。** 設定を変える手段が I2C に無い。
  出力モードも最遠測距も、外付け部品でしか変えられない。
- **バージョン情報は I2C で読めない。** UART モードには `0xF1`（会社・バージョン情報）が
  あるが、IIC モードの表には載っていない。
- **アドレスは `0x57` 固定。** 変更手段の記載が無い。
- **温度センサは無い。** datasheet が言う温度補償は**プローブの温度特性に対する駆動側の
  補償**であって、音速の温度補正ではない。GPIO / 1-WIRE モードの説明では
  「精確な距離が必要なら温度の影響を考慮して温度補償をすること」と明記されている。
  IIC モードの 3 バイト値に音速の温度補正がどこまで入っているかは**書かれていない**。
- **エラーの返し方が書かれていない。** 測距失敗時に何が返るかは不明。
- **盲区（2cm 以内）では「随机值」（ランダムな値）が返る**と性能表にある。0 でもエラー値でも
  ないので、**値だけを見て「近すぎる」と判定することはできない。**
- **データレディ信号も割り込みも無い。** 100ms 待つことでしか完了を知れない。

### 電気的・物理的な現実

- 電源 2.8〜5.5V、動作電流 3mA typ / 3.5mA max（5V）。IO は 5.5V 耐圧。動作温度 -40〜90℃。
- **トリガを書くと実際に 40kHz の超音波バーストが出る。** 近くの他の超音波センサと干渉する。
  同カタログの QMP6988 は datasheet で「超音波を含む高周波振動下で使うな」と明記している。
- 測定周期 50ms（カスタム可）。datasheet は測距の最大時間として 100ms を挙げている。
- 検出角 ±15°（typ）〜±20°（max）。指向性は 9600 の振動子より狭い。
- 探測精度 同一温度で ±2%、分解能 1mm（理論値）。
- **最大探測距離はプローブと R9 次第。** IC の性能表は「平らな壁で typ 600 / max 700cm」だが、
  `chips/rcwl-9620.yaml` は Unit としての公称を「約 2〜450cm（±2%）」としている。
  **IC 単体の数字とユニットの数字は一致しない。**
- 音速の温度式は datasheet に載っている: `c = 331.45 + 0.61·t [m/s]`（0℃ で 330.45m/s、
  20℃ で 342.62m/s、40℃ で 354.85m/s）。0〜40℃ で約 7% 変わる。

### RCWL-9600 との違い

**共通点**: 40kHz、I2C アドレス `0x57`、コマンド `0x01` で測距開始、応答 3 バイト MSB first、
割り込み無し、トリガで超音波が出る、**I2C だけでは互いを区別できない**。

| | RCWL-9600 | RCWL-9620 |
|---|---|---|
| IC の datasheet | **無い**（振動子の納入仕様書しか無い） | **ある**（M5Stack ホストの V1.0、中国語） |
| プローブ | 一体型（TC40-10T/R の 2 素子） | 分体開放式（10 / 12 / 16mm。Unit は 16mm） |
| ユニット公称の範囲 | 約 30〜150cm | 約 2〜450cm |
| 盲区 | 不明 | 2cm typ / 3cm max（内部はランダム値） |
| 指向性 | 80°±15°（振動子の -6dB 全角） | ±15〜±20°（IC の性能表） |
| 温度補償 | 不明 | プローブ温度特性の補償あり（音速補正は別問題） |
| 出力モード | I2C（他は不明） | GPIO / UART / IIC / 1-WIRE を外付け抵抗で選択 |
| トリガ後の待ち時間 | **不明** | **100ms**（datasheet 明記）。測定周期 50ms |
| 単位 | 不明（9620 と同じと推定） | **µm**（3 バイト値 ÷ 1000 = mm、datasheet 明記） |
| 電源 | 不明 | 2.8〜5.5V、3mA |
| 搭載製品 | Unit Ultrasonic (U098)、**EOL** | Unit Ultrasonic-I2C (U098-B1) |

## レジスタ / コマンド

レジスタは無い。datasheet の IIC モードの表はこれだけである。

| 方向 | 内容 | 意味 |
|---|---|---|
| 書き込み（`0xAE` = `0x57`+W） | `0x01` | 測距開始。超音波バーストが出る |
| 読み出し（`0xAF` = `0x57`+R） | 3 バイト | `BYTE_H`, `BYTE_M`, `BYTE_L`。距離[mm] = (H<<16 + M<<8 + L) / 1000 |

**転送の形**: 書き込みは `S` → `0x57`+W → `0x01` → `P`。読み出しは `S` → `0x57`+R →
3 バイト → NACK → `P`。レジスタポインタを書く手順は無い。

**生値は µm 単位の整数**である。1000 で割ると mm になる。datasheet の UART モードの説明にも
同じ式が書かれており、両モードで同じスケールであることが分かる。

## 典型的な使い方

1. `0x57` に ACK が返ることを確認する。
2. `0x01` を 1 バイト書く。**この時点で超音波が出る。**
3. **100ms 以上待つ。** datasheet が「模块最大测距时间」として明示している値。
4. 3 バイト読む。
5. `(H<<16 | M<<8 | L) / 1000` で mm を得る。
6. 次の測距までは間隔を空ける。測定周期は 50ms だが、実質は手順 3 の 100ms が律速になる。

## 利用上の注意

- **RCWL-9600 とバス上で区別できない。** アドレス・コマンド・応答長がすべて同じ。
  製品のラベルで見分けるしかない。**待ち時間と単位を 9600 と共用してよいかは、
  9600 側の資料が無いので確認できない。**
- **100ms の待ちは必須。** datasheet は「向模块写入 0X01，模块开始测距；等待 100mS
  (模块最大测距时间) 以上。直接读出 3 个距离数据」と書いている。短縮したときに何が返るかは
  書かれていない。
- **生値は µm。** 3 バイトをそのまま mm や cm と解釈すると 3 桁ずれる。450cm は `4500000`
  という値になり、24bit（最大 16777215）には収まる。
- **盲区 2cm 以内はランダム値。** エラー値でも 0 でもないので、値を見て「近すぎる」と
  判定できない。ホスト側で「あり得ない距離」のフィルタを掛けるにしても、ランダム値が
  たまたま妥当な範囲に入ることを避けられない。
- **最遠測距は外付け抵抗 R9 で決まる。** IC の性能表（平らな壁で 600〜700cm）と、
  M5Stack のユニット公称（約 2〜450cm）が食い違うのはこのため。手元のユニットの実力は
  実測するしかない。
- **出力モードは基板上で固定されている。** ピン 7 の 10kΩ が IIC を選んでいる。
  I2C デバイスとして繋いだものを UART に切り替えることはできない。
- **音速の温度依存はホスト側の問題として残る可能性がある。** datasheet の温度補償は
  プローブの温度特性に対するもので、GPIO / 1-WIRE モードの説明では「精確な距離が必要なら
  温度補償をせよ」と明記されている。IIC モードで内部補正がどこまで入っているかは
  書かれていない。0〜40℃ で音速は約 7% 変わる。
- **トリガには物理的な副作用がある。** 40kHz のバーストが出る。他の超音波センサと干渉するし、
  同カタログの QMP6988 は「超音波を含む高周波振動下で使うな」と datasheet で明示している。
- **アドレス `0x57` は MAX30100 と衝突する。** 本カタログでは `max30100`（Unit Heart）が
  `0x57` 固定。アドレス変更手段が無いので、衝突したら mux を挟むしかない。
- **datasheet は中国語のみで、改訂日が無い。** V1.0 はファイル名から取った版番号で、
  本文には版も日付も書かれていない。メーカー公式サイトにコピーが無く、M5Stack がホストする
  コピーだけが頼り（`chips/rcwl-9620.yaml` の notes）。文書末尾の資料配布先が Baidu Pan の
  短縮リンクである点も、資料の安定性の目安になる。
- **測れない対象がある。** 吸音材、斜めの面、細い物。返らなかったときの値は不明。
- **I2C の速度上限が datasheet に書かれていない。** 100kHz / 400kHz とも未実測。

## 出典と確度

- I2C のアドレス・コマンド・応答形式・単位・待ち時間、および電気/性能仕様:
  **RCWL-9620 datasheet V1.0**（中国語、无锡日晨物联科技有限公司）。M5Stack がホストする
  コピー。**文書中に改訂日も版番号も無く、V1.0 はファイル名から取った**
  （`chips/rcwl-9620.yaml` の `note: revision taken from the document filename;
  the body states none`）。メーカー公式サイトに生きたコピーが無い。
- **`profiles/rcwl-9620.yaml` の `evidence.source` は `inferred` のままだが、これは実態より
  控えめである。** `transport` の note は「framing follows the vendor driver and the
  M5Stack-hosted datasheet copy」と書いており、実際に datasheet p.7 がコマンド `0x01`、
  応答 3 バイト、MSB first、µm 単位、100ms 待ちをすべて明記している。プロファイルの
  evidence を `datasheet` へ引き上げられる可能性がある（YAML の変更は本ガイドの範囲外）。
- ユニット公称の範囲「約 2〜450cm（±2%）」は `chips/rcwl-9620.yaml` の notes 由来で、
  M5Stack の製品情報に基づく。**IC の性能表（平らな壁で 600〜700cm）とは一致しない。**
  プローブと R9 の設定によるという説明は推定である。
- **未確認**: 実機のキャプチャがまだ無い。presence、実際のトリガ〜結果の時間、距離バイトの
  中身と単位、盲区での返り値、最大測距、温度依存、400kHz での動作、繰り返し測距の最短周期は
  いずれも未実測（`scenarios/rcwl-9620/p0.yaml` の `outputs` と `deferred` がそのまま残っている）。
- **未確認**: IIC モードの 3 バイト値に音速の温度補正が入っているかどうか。datasheet は
  GPIO / 1-WIRE モードについてのみ「温度補償をせよ」と書いており、IIC モードでは言及が無い。
