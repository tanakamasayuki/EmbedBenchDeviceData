# Unit DDS (U105) — AD9833 波形発生ユニット

> 正弦波・三角波・矩形波などを 0Hz〜1MHz で出す信号発生器。AD9833 を STM32 が SPI で
> 叩いており、ホストからは I2C のレジスタとして見える。**I2C のレジスタマップは
> AD9833 自身の SPI レジスタとは別物**で、名前だけが AD9833 の概念を借りている。
>
> **確度**: M5Stack が製品ページに I2C Protocol の**画像**（V1 FW、2024-05-16 付）を
> 掲載しており、レジスタとビット配置はそれに基づく。転送長・バイト順・スケール係数・
> 順序の制約は `M5Unit-DDS` v0.1.1 のソースから起こした**推定**で、実測では未確認。

> ⚠️ **書き込むと実際に信号が出る。** 周波数・波形・制御レジスタへの書き込みは、
> その場で出力を変える。本リポジトリの probe は read-only
> （`scenarios/m5stack-mcu-u105/p0.yaml` の `safety: read-only`）で、
> 書き込みの挙動は一切確かめていない。

## これは何か

AD9833（DDS 波形発生 IC）を STM32F031 が SPI で制御し、そのフロントエンドとして
I2C を喋るユニット。ホストが叩くのは **STM32 のファームウェアが定義したレジスタ**であって、
AD9833 のデータシートに載っているレジスタではない。AD9833 のデータシートを読んでも
このユニットの叩き方は分からない（波形の理屈を理解する役には立つ）。

出力は SMA と 2.54mm ケーブルで取り出す。71.4 × 24.0 × 8.0mm、11.2g。

できること:

- 波形の選択: 正弦波 / 三角波 / 矩形波 / のこぎり波 / DC。
- 周波数の設定: 0Hz〜1MHz。基準クロック（MCLK）は 10MHz、分解能は 28bit。
- 位相の設定: 分解能 11bit（ベンダー表は 12bit 相当の場所を確保している。後述）。
- **周波数と位相をそれぞれ 2 バンク持ち、どちらを出力に使うか切り替えられる。**
  あらかじめ 2 つの周波数を仕込んでおいて、制御レジスタ 1 バイトで切り替える、
  という使い方ができる。
- MCLK / DAC を個別にスリープさせる。DAC をリセットして中点電位に固定する。
- ユニットの識別（`0x10` が ASCII で `ad9833` を返す）。

できないこと・持っていないもの:

- **出力振幅は変えられない。** 0〜0.6V 固定。AD9833 自体に振幅設定が無い。
- **周波数と位相は読み戻せない。** `0x30` / `0x34` は書き込み専用で、
  今どの値が入っているかを問い合わせる手段が無い。ライブラリはホスト側の変数で覚えている。
- **掃引（スイープ）機能は無い。** 連続的に周波数を変えたければホストが書き直し続ける。
- **トリガ入力・外部同期・出力 ON/OFF の専用端子は無い。** 出力を止めたければ
  制御レジスタでスリープさせる。
- **のこぎり波と DC は周波数・位相の設定を無視する。** のこぎり波は 13.6kHz 固定。
- **割り込み線は無い。**
- **I2C アドレスを変更するレジスタが無い。** `0x31` 固定。同一バスに 2 台は載らない。
- **ファームウェアバージョンを読むレジスタが無い。** 通信確認と身元確認は `0x10` の
  `ad9833` 文字列で行う。

## レジスタ

| アドレス | 長さ | R/W | 意味 |
|---|---|---|---|
| `0x10` | 6 | R | ASCII 6 文字。`ad9833` が返る。身元確認用 |
| `0x20` | 1 | R/W | 波形モード。bit2–0 が波形、**書き込み時は bit7 を 1 にする** |
| `0x21` | 1 | R/W | 制御。バンク選択・スリープ・リセット、**書き込み時は bit7 を 1 にする** |
| `0x30` | 4 または 6 | W | 28bit 周波数チューニングワード。**MSB first** |
| `0x34` | 2 | W | 位相ワード。**MSB first** |

`0x20`（波形モード）:

| bit | 意味 |
|---|---|
| 7 | 書き込みマーカ。**書くときは必ず 1**。読むと 0 |
| 6–3 | 予約 |
| 2–0 | 波形。`0` 予約 / `1` 正弦波 / `2` 三角波 / `3` 矩形波 / `4` のこぎり波 / `5` DC |

`0x21`（制御）:

| bit | 意味 |
|---|---|
| 7 | 書き込みマーカ。**書くときは必ず 1**。読むと 0 |
| 6 | FSELECT。`0` = 周波数バンク 0 を使用、`1` = バンク 1 |
| 5 | PSELECT。`0` = 位相バンク 0 を使用、`1` = バンク 1 |
| 4 | `1` で MCLK をスリープ（出力は最後の値を保持） |
| 3 | `1` で DAC をスリープ（出力停止） |
| 2 | `1` で DAC をリセット（出力を中点電位に固定） |
| 1–0 | 予約 |

`0x30`（周波数、4 バイト・MSB first）:

| バイト | 内容 |
|---|---|
| 0 | bit7 = 書き込みマーカ（必ず 1）、bit6 = 書き込み先バンク（0 = バンク0、1 = バンク1）、bit5–4 = 予約、bit3–0 = FTW の bit27–24 |
| 1 | FTW の bit23–16 |
| 2 | FTW の bit15–8 |
| 3 | FTW の bit7–0 |

つまり先頭バイトは、バンク 0 なら `0x80 | (FTW>>24 & 0x0F)`、バンク 1 なら `0xC0 | ...`。

`0x34`（位相、2 バイト・MSB first）:

| バイト | 内容 |
|---|---|
| 0 | bit7 = 書き込みマーカ（必ず 1）、bit6 = 書き込み先バンク、bit5–4 = 予約、bit3–0 = 位相ワードの上位 |
| 1 | 位相ワードの bit7–0 |

**`0x30` は 6 バイトのペイロードも受け付ける。** 周波数 4 バイトの直後に位相 2 バイトを
続けると、1 トランザクションで両方が書ける。ライブラリの `writeFrequencyAndPhase()` と
`begin()` はこちらを使う。

**単位とスケール**:

- 周波数レジスタに入るのは Hz ではなく**チューニングワード**である。
  `FTW = 周波数[Hz] × 2^28 / 10MHz` を 28bit にマスクした値。10kHz なら FTW は 268435。
- 位相レジスタに入るのは度ではなく**位相ワード**である。
  `位相ワード = 角度[度] × 2048 / 360` を 11bit にマスクした値。
- **ライブラリはこの換算を行うが、レジスタを直接叩く場合は自分で換算する必要がある。**

**転送の形**: 書き込みは「レジスタバイト + ペイロード」を 1 トランザクション。
読み出しはレジスタバイトを書いて STOP を打ち、改めて読み出しトランザクションを起こす。

## 典型的な使い方

1. `0x10` から 6 バイト読み、`ad9833` であることを確認する。違えば別のデバイスである。
2. 周波数と位相を書く。`0x30` に 6 バイト（周波数 4 + 位相 2）を書くのが手っ取り早い。
   このとき先頭バイトの bit6 で、どちらのバンクに入れるかを決める。
3. `0x20` に波形を書く（bit7 を立てるのを忘れない）。
4. `0x21` に制御バイトを書く。ここで初めて**どのバンクを出力に使うかが決まる**。
   同時に MCLK / DAC のスリープとリセットを解除する。
5. 周波数を切り替えたいときは、あらかじめもう一方のバンクに値を仕込んでおき、
   `0x21` の bit6 だけを反転させる。

## 利用上の注意

- **書き込みは実際に信号を出す。** 波形・周波数・制御のいずれを書いても出力が変わる。
  本リポジトリはこの理由で probe を read-only にしている。
- **書き込むバイトは bit7 を 1 にしないと無視される。** これは `0x20` / `0x21` の
  1 バイト書き込みでも、`0x30` / `0x34` の先頭バイトでも同じ。**そして読み出しでは
  bit7 が落ちて返る。** つまり `0x21` を読んで 1 ビットだけ変えて書き戻す
  read-modify-write では、**書き戻す前に `0x80` を足し直さないと何も起きない**。
  ライブラリはこれを `write_register8()` というヘルパで隠している。
- **周波数と位相だけがビッグエンディアン。** このユニットで多バイトの数値はこの 2 つだけで、
  どちらも上位から出す。M5Stack の他のユニット（ほとんどがリトルエンディアン）から
  移ってくると間違えやすい。
- **値を書いても出力は切り替わらない。** `0x30` / `0x34` への書き込みは
  「指定したバンクに値を格納する」だけである。**実際にどのバンクが出力されるかは
  `0x21` の bit6（周波数）と bit5（位相）が決める。** 周波数を書いたのに音程が変わらない、
  という症状はたいていこれ。ライブラリの `writeOutput()` が
  「周波数と位相 → 波形 → 制御」の順で書くのはこのため。
- **波形を変えたら制御レジスタを書き直す。** firmware は波形の変更を、制御レジスタが
  書かれたときに初めて反映する。**制御レジスタの値自体が変わらなくても書き直しが要る。**
- **のこぎり波と DC を通ると周波数が消える。** これらのモードを選ぶと firmware が
  内部の周波数を 0 にする。そこから正弦波などに戻すときは、**両方のバンクの周波数を
  書き直さなければならない**。ライブラリの `writeMode()` はこの再書き込みを自動で行う。
- **リセットビットを落とした直後は出力が安定しない。** AD9833 は RESET を 0 に戻してから
  7〜8 MCLK サイクル（10MHz なら約 0.8 マイクロ秒）で出力が有効になる。
  ライブラリは余裕を見て 2 マイクロ秒待っている。
- **電源投入直後は MCLK スリープが有効らしい。** ベンダーの Protocol 画像の注記に
  「mclk は既定で 1 に設定されており、最後の出力振幅を保持する」とある。
  そのまま読めば、起動直後は出力が止まっていて、`0x21` の bit4 を落とすまで信号が出ない。
  ライブラリの `begin()` が `writeOutput()` の後に `wakeup()` を呼ぶのはこれと整合するが、
  **この解釈は実測で確かめられていない**。
- **位相の有効ビット数が資料とライブラリで食い違う。** ベンダーの Protocol 画像は
  位相レジスタを 12bit（bit11–0）と書いているが、ライブラリは 11bit（`0x7FF`）で
  マスクし、ソースのコメントに「STM32 のレジスタは 12bit を受け付けるが、AD9833 の
  出力に効くのは 11bit（2048 ステップ）だけ」「2026-04-02 に実機で確認」と記録している。
  この「実機で確認」はライブラリ作者による記録であって、**本リポジトリの実測ではない**。
- **のこぎり波の周波数の記載が資料間で食い違う。** 製品ページは 13.6kHz 固定と書き、
  `M5Unit-DDS` の M5UnitUnified 側ヘッダのコメントも「13600 固定」と書いているが、
  同じライブラリの旧ドライバ `src/Unit_DDS.h` のコメントは「1.3kHz 固定」と書いている。
  **未確認。** 製品ページの 13.6kHz を採るのが妥当。
- **`0x10`（識別文字列）はベンダーの Protocol 画像に載っていない。** 画像に描かれているのは
  `0x20` 行と `0x30` 行だけである。`0x10` の存在は `M5Unit-DDS` の 2 つのドライバ
  （旧 `Unit_DDS.cpp` と新 `unit/unit_DDS.cpp`）が両方とも読んでいることが根拠で、
  どちらも `ad9833` 以外ならデバイスを拒否する。
- **旧ドライバ（`src/Unit_DDS.cpp`）には演算子の優先順位に起因する不具合がある。**
  新しい M5UnitUnified 側のドライバ（`src/unit/unit_DDS.cpp`）を使えば回避できる。
  - `setFreq()` / `setFreqAndPhase()`: 先頭バイトを
    `(((freq >> 24) & 0xff) | (reg == 1) ? 0xC0 : 0x80)` と書いている。`|` は `?:` より
    優先されるので、**FTW の上位 4bit は捨てられ**、条件式が非ゼロなら `0xC0` になる。
    結果として、**FTW が `0x1000000` 以上になる周波数（約 625kHz 以上）では上位ビットが
    失われ、しかもバンク 0 を指定したつもりでもバンク 1 に書かれる。**
  - `selectFreqReg()` / `selectPhaseReg()`: 同じ理由で、書かれるバイトが常に `0x40`
    （または `0x20`）になる。**必須の bit7 マーカが落ち、他の制御ビットも全部 0 になる。**
    バンクを切り替えるつもりで呼ぶと、期待した動作にならない。括弧が正しく付いている
    `OUT()` を使うか、新ドライバに移ること。
  - `readDDSRegs()` は引数 `size` に関わらず常に 6 バイトを読み込む。
  - 旧ドライバの `begin()` は ESP32-C6 以外では既定で **`Wire1`** を使う。
  - `quickOUT()` は `0x21` に `0x80` を書くので、バンク選択・スリープ・リセットを
    すべてクリアする。常にバンク 0 からの出力になる。
- **1MHz を超える指定はドライバによって扱いが違う。** M5UnitUnified 側は 0〜1MHz の
  範囲外を拒否するが、旧ドライバは範囲検査をしない。

## 出典と確度

- レジスタ `0x20` / `0x21` / `0x30` / `0x34` のアドレスとビット配置、波形コード、
  FSELECT / PSELECT / スリープ / リセットの意味、bit7 が書き込みマーカであること、
  位相レジスタが 12bit 幅であること: **ベンダーの Protocol 画像に基づく**。
- 周波数範囲 0〜1MHz、MCLK 10MHz、出力振幅 0〜0.6V、のこぎり波 13.6kHz 固定:
  **製品ページに基づく**。
- 転送長・バイト順・6 バイト書き込み・スケール係数・順序の制約（値を書いてから
  制御レジスタでバンクを選ぶ、波形変更後に制御レジスタを書き直す、のこぎり波 / DC を
  通ると周波数が消える）・リセット後の待ち時間: `M5Unit-DDS` v0.1.1 のソースから起こした**推定**。
  一部はソース中のコメントが「firmware の実装から」と明記している。
- レジスタ `0x10`（`ad9833` 文字列）: **ライブラリのソースのみが根拠**。
  ベンダーの Protocol 画像には載っていない。
- **未確認**: 実機のキャプチャがまだ無い。電源投入直後に MCLK スリープが有効かどうか、
  位相が 11bit と 12bit のどちらで効くか、のこぎり波が 13.6kHz と 1.3kHz のどちらか、
  400kHz で安定するかは確かめられていない。
- **未調査**: **書き込み側の挙動は一切検証していない。**
  `scenarios/m5stack-mcu-u105/p0.yaml` は `safety: read-only` で、
  `write-frequency` / `write-phase` / `write-behaviour` が `deferred` に置かれている。
