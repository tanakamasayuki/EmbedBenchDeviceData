# MCP4725 — 12bit 単チャンネル D/A コンバータ（EEPROM 内蔵）

> I2C で書いた 12bit の値を、そのままアナログ電圧としてピンに出す DAC。書いた値を
> 不揮発 EEPROM に残せるので、電源を入れ直しても同じ電圧から始まる。
>
> **確度**: Microchip の datasheet（DS20002039E, rev E, 2022）に基づく。**実測では未確認**で、
> 本カタログの probe は read-only のため書き込み系の挙動は一切触れていない。

## これは何か

I2C の書き込みが**そのままユーザーの回路の電圧になる**デバイスである。センサのように
「読むだけ」で済むデバイスとは性格が違う。書いた瞬間に VOUT ピンの電圧が変わり、その先に
繋がっているもの（アンプの基準、モータドライバの指令値、可変電源のフィードバック）が動く。

構成は、抵抗ストリング型の 12bit DAC + 出力バッファ（レールツーレールのオペアンプ）+
14bit の EEPROM。EEPROM には 12bit の出力コードと 2bit のパワーダウン設定が入り、
電源投入時（POR）に自動で DAC レジスタへロードされる。

できること:

- 0 〜 VDD の範囲を 4096 段で出力する。1LSB は VDD/4096（5.0V で 1.22mV、3.0V で 0.73mV）。
- 今の出力コードを電源投入時の既定値として EEPROM に焼く。
- 出力を切って、既知の抵抗（1kΩ / 100kΩ / 500kΩ）で GND に落とすパワーダウンモードに入る。
- 自分が書いた DAC 値と EEPROM の中身、EEPROM 書き込み中かどうか（RDY/BSY）、POR 状態を読み返す。

できないこと・持っていないもの:

- **チャンネルは 1 本だけ。**
- **基準電圧を選べない。** VREF は VDD そのもので、内部リファレンスは無い。VDD のノイズや
  ドリフトはそのまま出力誤差になる（5.3 Voltage Reference）。
- **A/D 変換はしない。** 外部電圧を測る機能は無い。
- **アドレスの上位ビットをソフトで変えられない。** A2/A1 は工場で焼かれる（発注時オプション）、
  A0 だけがピン。同一バスに置けるのは A0 違いの 2 個までで、それ以上は別品番を調達する話になる。
- **割り込み線・データレディ線が無い。** EEPROM 書き込みの完了は読み出して RDY/BSY を見る以外にない。
- **大電流は流せない。** データシートの特性は RL = 5kΩ、CL = 100pF 前提。負荷を直接駆動する石ではない。

電気的な現実:

- 電源 2.7 〜 5.5V 単一。VDD がそのまま出力レンジの上限になる。
- SDA / SCL は open-drain、**プルアップは外付け**。
- I2C は standard / fast / high-speed（3.4Mbit/s）に対応。
- セトリングは 6µs typ（1/4 → 3/4 スケール変化で 1/2LSB 以内）。パワーダウンからの復帰は 10µs 未満。
- **EEPROM 書き込みは 25ms typ / 50ms max かかり、その間 DAC への書き込みも含めて全コマンドが無視される。**
- EEPROM の書き換え耐久は 1M サイクル min、保持は 200 年 typ（+25°C）。

M5Stack Unit DAC (U012) はこれを 0x60 で使い、出力レンジは 0〜3.3V とされている。
VOUT の上限は VDD なので、これはユニット上の VDD が 3.3V であることを意味する。

## レジスタ / コマンド

**このデバイスにレジスタアドレスは無い。** アドレスバイトの次に来るバイトの上位 3bit
（C2, C1, C0）でコマンドの種類が決まり、それによって続くバイト数とビットの並びが変わる。

| 形式 | C2 C1 C0 | アドレスバイト以降の長さ | EEPROM |
|---|---|---|---|
| Fast Mode Write | `0 0 X` | 2 バイト | 変えない |
| Write DAC Register | `0 1 0` | 3 バイト | 変えない |
| Write DAC Register and EEPROM | `0 1 1` | 3 バイト | **書く（永続）** |

`1 0 0` 〜 `1 1 1` は reserved で、デバイスは無視する。

**永続するのは 3 番目の形式だけ**である。前の 2 つは DAC レジスタしか触らないので、
電源を切れば EEPROM の値に戻る。

ビットの並び:

```
Fast Mode Write（2 バイト）
  byte1: 0  0  PD1 PD0 D11 D10 D9 D8
  byte2: D7 D6 D5  D4  D3  D2  D1 D0

Write DAC Register / Write DAC Register and EEPROM（3 バイト）
  byte1: 0  C1 C0 X  X  PD1 PD0 X
  byte2: D11 D10 D9 D8 D7 D6 D5 D4
  byte3: D3  D2  D1 D0 X  X  X  X      ← 下位 4bit は don't care
```

読み出しはアドレスバイト + R だけを送る。レジスタ指定は無く、**必ず 5 バイトが決まった順で返る**:

| バイト | 中身 |
|---|---|
| 1 | 状態: `RDY/BSY, POR, X, X, X, PD1, PD0, X`。RDY/BSY = 0 は EEPROM 書き込み中 |
| 2 | DAC レジスタ D11..D4 |
| 3 | DAC レジスタ D3..D0 + don't care 4bit |
| 4 | EEPROM `X, PD1, PD0, X, D11..D8` |
| 5 | EEPROM D7..D0 |

6 バイト目以降を要求すると、2〜6 バイト目の内容が繰り返される。

General call（アドレス `0x00`）を 2 つ受け付ける:

| 2 バイト目 | 動作 |
|---|---|
| `0x06` | リセット。POR と同じで、EEPROM の内容を DAC レジスタにロードし直す |
| `0x09` | ウェイクアップ。DAC レジスタの PD ビットを 00 に戻す（EEPROM の PD は変わらない） |

## 典型的な使い方

1. 出力したい電圧から コード = 4096 × Vout / VDD を求める（VDD は実測値を使う。カタログ値ではない）。
2. **出力を変えたいだけ**なら Fast Mode Write（2 バイト）か Write DAC Register（3 バイト）を送る。
   この 2 つは MCP4725 では機能が同じで、短いぶん Fast Mode が速い。
3. **電源投入時の既定値を変えたいときだけ** Write DAC Register and EEPROM を送る。送ったあとは
   25〜50ms 待つか、読み出して RDY/BSY が 1 に戻るのを確認する。
4. 電源投入直後で VDD の立ち上がりが遅い設計なら、安定後に general call reset（`0x00`, `0x06`）を
   1 回送って EEPROM の値をロードし直す。
5. 出力を止めたいときは PD1/PD0 に 01/10/11 を入れて書く。VOUT は Hi-Z ではなく抵抗で GND に落ちる。

## 利用上の注意

- **書き込みは実世界の副作用である。** 「とりあえず書いて反応を見る」が許されないデバイス。
  未知のコードを書く前に、VOUT の先に何が繋がっているかを確認する。probe が書き込み系を
  deferred にしているのはこのためである（[`scenarios/mcp4725/p0.yaml`](https://github.com/tanakamasayuki/I2CDeviceDB/blob/38f1d82/scenarios/mcp4725/p0.yaml)）。
- **EEPROM には寿命がある。** 耐久は 1M サイクル min。1kHz で波形を出すつもりで
  `0x60` 形式（C2C1C0 = 011）を使い続けると、20 分足らずで規定回数に達する。
  **追従させたい値は EEPROM 形式で書かない。** 電源投入時の既定値を決めるときだけ使う。
- **EEPROM 書き込み中は全部無視される。** RDY/BSY が 0 の間（最大 50ms）、DAC レジスタへの
  書き込みもリピートバイトも受け付けない。ACK は返るのに値が変わらない、という形で現れる。
- **A0 ピンのレベルはトランザクション開始前に確定させる。** デバイスは受け取った A0 アドレスビットと
  A0 ピンの論理レベルを比較してから ACK を返す。転送中に A0 が動くと ACK が返らない。
- **VDD がそのまま誤差になる。** 5V ± 5% の電源なら、出力も ± 5% ずれる。精度が要るなら
  VDD を実測して換算に使うか、VDD を安定化する。DAC の INL/DNL より電源のほうが効く。
- **VDD の立ち上がりが 1V/ms より遅いと、EEPROM の内容が DAC にロードされないことがある。**
  この場合、電源投入直後の VOUT は EEPROM に焼いた値にならない。データシートは
  電源安定後の general call reset を「強く推奨」している（5.4.2）。
- **general call は他人が撃つ。** 同じバスの別デバイス向けに general call reset（`0x00 0x06`）や
  wake-up（`0x00 0x09`）が流れると、MCP4725 も無条件に反応して出力が EEPROM 値に戻る。
  複数ベンダーのデバイスが同居するバスでは、意図しない出力ジャンプの原因になる。
- **high-speed マスターコード（`0000 1XXX` = 0x08〜0x0F）に反応する。** ACK は返さないが HS モードに
  入り、次の STOP で抜ける。0x08〜0x0F を舐めるバススキャンでも同じことが起きる（実害は
  ほぼ無いが、スキャン結果でこのアドレスが「無応答」に見えるのは正常）。
- **パワーダウンは出力の切り離しではない。** VOUT は 1kΩ / 100kΩ / 500kΩ のいずれかで GND に
  落ちる。Hi-Z を期待して他の信号源と OR 接続すると、その抵抗が効いてしまう。
- **読み出しは 5 バイト固定の並び。** 先頭の状態バイトを読み飛ばす実装にすると、DAC 値が
  1 バイトずれて 16 倍・1/16 倍のような値になる。
- **400kHz は仕様内**（standard/fast/HS 対応）だが、本カタログでは未実測。

## 出典と確度

- コマンド体系、ビット配置、アドレス、EEPROM の仕様、電気的特性: すべて Microchip
  datasheet DS20002039E（rev E, 2022）由来。
- **未確認**: 実機のキャプチャが無い。応答するアドレス、読み出し 5 バイトの実際の並び、
  400kHz / HS モードでの動作は確かめられていない。
- **未調査**: probe は read-only なので、DAC 書き込み・fast mode 書き込み・EEPROM 書き込み・
  パワーダウンモードはすべて deferred。EEPROM 書き込み時間の実測値、書き込み中の ACK の
  振る舞いも見ていない。
- M5Stack Unit DAC の出力レンジ 0〜3.3V はベンダーの記載であり、実測していない。
