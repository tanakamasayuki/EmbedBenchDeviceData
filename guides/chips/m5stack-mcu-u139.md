# Unit ACSSR (U139) — 単相 AC ソリッドステートリレー制御ユニット

> AC 24〜480V / 10A の負荷を、I2C のレジスタ 1 バイトで入切するユニット。
> **書き込みは実際に商用電源の負荷を投入する。**
>
> **確度**: ベンダーのレジスタ表 PDF は存在しない。`chips/` に載っているのは製品ページだけで、
> そこにレジスタの一覧は無い。`profiles/` のマップは **`M5Unit-ACSSR` ライブラリ v0.0.3 の
> ソースから起こした推定**（`evidence: inferred / tentative`）で、実測では未確認。
> レジスタの意味づけの根拠はライブラリのメソッド名とその実装だけである。

> ⚠️ **これは実物を動かすユニットである。** レジスタ `0x00` に `1` を書くと、端子台に繋がった
> AC 負荷に本当に通電する。試しに叩いてみる対象ではない。**本リポジトリの characterization
> probe が read-only（読み出し可能な 3 レジスタを読むだけで一切書かない）なのは、まさにこの
> ためである。** 書き込み系はすべてレビュー済みのシナリオに委ねられている。

## これは何か

単相 AC 用のソリッドステートリレー（SSR）と、それを制御する ESP32-C3 を 1 つの筐体に収めた
キット。SSR は機械接点を持たないので、開閉が速く、寿命が長く（電気的寿命 100 万回以上）、
アーク放電が出ない。

**ホストから見える I2C の相手は ESP32-C3 のファームウェアであって、SSR そのものではない。**
つまりレジスタマップはこの製品固有のものである。

操作の入口は 3 通りある。本体のボタン、I2C（Grove）、Modbus-RTU（端子台の RS485）。
本文が扱うのは I2C だけである。

本体は 80 × 45 × 31 mm、112.6g。負荷側は AC 24〜480V / 10A、制御入力は DC 3〜32V、
オン時の電圧降下 ≤1.6V、オフ時の漏れ電流 ≤5mA。RGB LED（SK6812）が状態表示に使える。

できること:

- **リレーの開閉**（`0x00` に `1` / `0`）。
- **現在の状態の読み出し**（同じ `0x00` を読む）。
- **インジケータ LED の色**の設定と読み返し。
- **I2C アドレスの変更**。
- **ファームウェアのバージョン**の読み出し。

できないこと・持っていないもの:

- **電流も電圧も測れない。** 計測機能は一切無い。「本当に流れているか」を知りたいなら
  別のユニット（電流計測系）が要る。
- **調光・PWM ができない。** できるのは全開／全閉だけ。位相制御やゼロクロスのパラメータは
  I2C からは見えない。
- **タイマ・スケジュールが無い。** 「n 秒後に切る」はホスト側の仕事。**ホストが落ちても
  リレーは入ったままである**（フェイルセーフのウォッチドッグは公開されていない）。
- **過負荷・過熱・故障の通知が無い。** 状態レジスタは「ファームが覚えている指令値」であって、
  SSR が実際に導通しているかの測定ではない。**未確認**。
- **割り込み線は無い。** 本体ボタンが押されたことも、ポーリングでしか知れない。
- **Modbus 側の設定を I2C から変えられない。** スレーブ ID の変更レジスタは I2C マップに無い。
- **ボタンを無効化するレジスタが無い。** 現地の手動操作を締め出せない。

| 負荷定格 | AC 24〜480V、10A。制御入力 DC 3〜32V / 5〜20mA。オン電圧降下 ≤1.6V、オフ漏れ ≤5mA |

## レジスタ

| アドレス | 長さ | R/W | 意味 |
|---|---|---|---|
| `0x00` | 1 | R/W | **リレー。`1` を書くと閉（負荷 ON）、`0` を書くと開（負荷 OFF）。** 読むと現在の状態が返る |
| `0x10` | 3 | R/W | インジケータ LED の色。**byte0 = R、byte1 = G、byte2 = B**。読み書きで同じ 3 バイト |
| `0x20` | 1 | W | I2C アドレス。書いた直後から新アドレスになる |
| `0xFE` | 1 | R | ファームウェアのバージョン |

リレーには「オン用」「オフ用」の別レジスタは無い。`on()` も `off()` も `status()` も、同じ `0x00` を
値違いで読み書きしているだけである。

**Modbus 側の定数について**: ライブラリのヘッダには Modbus-RTU 用のアドレス（スレーブ ID `0x04`、
リレーコイル `0x0000`、LED ホールディング `0x0000`、バージョン `0x0001`、ID ホールディング `0x0002`）も
定義されている。**しかしライブラリ内にそれらを使うコードは 1 行も無く、I2C のレジスタマップとは
別物である。** `profiles/` にも入っていない。I2C のつもりでこれらのアドレスを叩かないこと。

**転送の形**: 書き込みは「ポインタバイト + ペイロード」を 1 トランザクションで送る。読み出しは
ポインタバイトを書いて **いったん STOP を出し**、それから `requestFrom` でデータフェーズに入る。
**repeated START ではない。**

## 典型的な使い方

1. AC 側の配線が正しく、通電して差し支えない状態であることを**先に**確認する。
2. `0xFE` を読んでファームウェアのバージョンを確認する（疎通確認も兼ねる）。
3. `0x00` を読んで、現在リレーが開いているか閉じているかを確かめる。
4. 入れるなら `0x00` に `1`、切るなら `0`。
5. 状態表示に LED を使うなら `0x10` に R, G, B の 3 バイトを書く。

## 利用上の注意

- **`0x00` に `1` を書くと本当に AC が入る。** 実験用のバス scan やレジスタダンプの延長で
  書き込みを混ぜないこと。この 1 バイトの先には人が触れる配線や、動き出す機械がある。
- **ホストが落ちてもリレーは入ったまま。** 自動的に開くフェイルセーフは公開されていない。
  「通信が途絶えたら切る」という動作が必要なら、ホスト側でウォッチドッグを組んで明示的に
  `0` を書く設計にする。
- **状態レジスタは「指令値」であって「測定値」ではない可能性が高い。** `0x00` を読んで `1` が
  返ることは、ファームが ON を保持していることしか意味しない。SSR の故障（短絡モードで
  固着する等）は検出できない。**未確認**。
- **操作の入口が 3 つあり、優先順位が資料に無い。** 本体ボタン・I2C・Modbus のどれからでも
  同じリレーを動かせる。誰かが現地でボタンを押したときに I2C 側の状態表示がどう追随するか、
  競合したときにどちらが勝つかは **未確認**。ホスト側で状態を覚え込まずに、必要なタイミングで
  `0x00` を読み直す方が安全。
- **アドレス変更は即時反映。** `0x20` に書いた次のトランザクションはもう新アドレス宛に出さないと
  応答しない。書き換えた値を忘れると `0x50` を探しても見つからないユニットが手元に残る
  （復旧はバス全体を scan して探す）。**不揮発かどうかは未確認**（電源を切ると `0x50` に戻るのか
  維持されるのか、ソースからは分からない）。
- **LED の 3 バイトは読み書き対称。** 書いた順（R, G, B）と同じ順で読み返せる。Unit Scales や
  Unit Encoder の LED レジスタのような「先頭がインデックス」「4 バイト目のパディング」といった
  癖は無い。
- **ベンダーの I2C プロトコル資料が存在しない。** レジスタ表 PDF は公開されておらず、
  製品ページにも一覧は無い。したがってこのマップの根拠は**ライブラリのソースだけ**であり、
  ここに書いていないレジスタが存在する可能性は否定できない。
- **AC 側は危険電圧。** Grove 側（5V）と端子台の AC 側の絶縁は SSR に依存する。配線に触れる前に
  AC を遮断する。I2C の話とは別に、これは実配線の問題である。
- **本リポジトリの characterization probe は read-only。** `0x00` / `0x10` / `0xFE` の 3 つを読むだけで、
  書き込みは一切しない。プローブのソース冒頭にもその理由が明記されている
  （「これらのユニットでは書き込みがリレーを閉じ、サーボを動かし、モータを回すため」）。

## 出典と確度

- レジスタのアドレスと意味: `M5Unit-ACSSR` ライブラリ v0.0.3 のソースから起こした**推定**。
  4 つのアドレスはすべてヘッダの `#define` にあり、転送長とアクセス方向はメソッド本体から取った。
- **一次資料が無い**: ベンダーのレジスタ表 PDF は存在せず、製品ページにも一覧が無い。
  ライブラリ以外の裏取りができていない。
- **未確認**: 実機のキャプチャがまだ無い。状態読み出しが指令値なのか実測なのか、アドレス変更が
  不揮発かどうか、ボタン／Modbus と I2C が競合したときの挙動、バス速度の上限は確かめられていない。
- **未調査**: 書き込み側（リレー、LED、アドレス変更）は probe が read-only のため触れていない。
  **リレーの書き込みは実負荷を動かすため、意図的に触れていない。**
- **I2C マップの範囲外**: ヘッダにある Modbus のアドレスは I2C とは別系統で、本文の表にも
  `profiles/` にも含めていない。
