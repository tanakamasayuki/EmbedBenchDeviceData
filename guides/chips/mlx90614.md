# MLX90614 — 非接触赤外線温度センサ（SMBus）

> サーモパイルで物体の表面温度を非接触に測るセンサ。TO-39 缶の中に光学フィルタ、
> アンプ、DSP、EEPROM が全部入っており、ホストには 0.02K 単位の温度が数値で返る。
> **I2C ではなく SMBus** で、読み出しは必ず 3 バイト（下位・上位・PEC）である。
>
> **確度**: Melexis の datasheet（Datasheet Rev 021 / Doc server Rev 012, 2026-06-02, 58 ページ）に
> 基づく。**実測では未確認**。probe は read-only で、EEPROM 書き込みとスリープには触れていない。

## これは何か

サーモパイル（熱電対を直列にした素子）が受ける赤外線量から、物体の絶対温度を求めるセンサ。
熱電対の出力は「物体温度の 4 乗 − センサ自身の温度の 4 乗」に比例するので、チップ内の
PTAT でダイ温度 Ta を測り、そこから物体温度 To を逆算している。この計算・リニアライズ・
フィルタリングはすべて内蔵 DSP がやるので、**ホスト側は生の熱電対電圧を扱わなくてよい**。

工場出荷時に自動車グレードの全温度範囲（Ta −40〜+125°C、To −70〜+380°C）で校正されており、
0〜+50°C では確度 0.5°C。分解能は 0.02°C。

できること:

- 物体温度 To（RAM `0x07`、デュアルゾーン品なら `0x08` も）とダイ温度 Ta（RAM `0x06`）を読む。
- 放射率 ε を EEPROM に書いて対象物に合わせる（工場出荷 1.0 = `0xFFFF`）。
- SMBus アドレスを EEPROM で変更し、同じ 2 本の線に最大 127 個ぶら下げる。
- SMBus の代わりに PWM 出力（温度をデューティ比で表す）やサーモスタット出力にする。
- スリープモードに入る（3V 版のみ、2µA typ）。

できないこと・持っていないもの:

- **測っているのは表面温度であって内部温度ではない。** 人体を測れば「服の温度」が返る。
- **視野内のすべての物体が寄与する。** 単一画素のセンサなので、対象だけを見ている保証は無い。
  ケースに穴を開けて覗かせる構造にすると、穴の縁が視野に入って誤差になる（FAQ, p46）。
- **放射率を自動判別できない。** アルミのような低放射率の対象は原理的に正しく測れない。
- **割り込み線・データレディ線は無い。** 更新のタイミングを知る手段はポーリングだけ。
  （サーモスタット出力は「しきい値を超えたか」であって「新しい値が出たか」ではない。）
- **RAM に書き込めない。** 読めるだけ。設定は EEPROM 経由。
- **プレーンな I2C デバイスではない。** SMBus のうち Read Word と Write Word の 2 つしか
  実装しておらず、Quick Command / Byte 系 / Process Call / Block 転送はすべて非対応。
- **スリープから I2C トランザクションでは起こせない。** 後述。

電気的な現実:

- **クロックは 10kHz 〜 100kHz。** これは上限であって推奨ではない。**400kHz は仕様外**である。
- SDA / SCL は open-drain、プルアップは外付け（datasheet の推奨回路は 4.7kΩ 前後）。
- 電源は 2 系統の品種がある。5V 版（MLX90614Axx）は 4.5〜5.5V、3V 版（Bxx / Dxx）は 2.6〜3.6V。
  **スリープモードは 3V 版にしか無い。**
- 5V 版の SCL ピンは 5.7V のツェナーを兼ねており、クロックにアンダーシュートが乗る。
- ESD 用のクランプダイオードがあるので、**VDD がプルアップ電圧より低いとバスから電流を吸う**。
- SCL が 27ms 以上 Low のままだと、通信ブロックが自己リセットする（Timeout L）。
- 出力の整定時間は EEPROM のフィルタ設定次第で 0.10 秒〜1.33 秒（品種ごとの工場既定値、Table 12）。

M5Stack Unit NCIR (U028) / NCIR2 (U150) はこれを `0x5a` で使う。

## レジスタ / コマンド

アドレス空間は RAM（32 × 16bit）と EEPROM（32 × 16bit）の 2 面あり、**コマンドバイトの
上位 3bit でどちらを指すかが決まる**。

| オペコード | 意味 |
|---|---|
| `000x xxxx`（`0x00`〜`0x1F`） | RAM の xxxxx 番地を読む |
| `001x xxxx`（`0x20`〜`0x3F`） | EEPROM の xxxxx 番地を読む / 書く |
| `1111 0000`（`0xF0`） | Read flags。**repeated START を使わない**特別な形 |
| `1111 1111`（`0xFF`） | スリープに入る |

つまり `profiles/` にある `0x2E` は「EEPROM の `0x0E` 番地」という意味である。

| オペコード | 領域と番地 | 意味 |
|---|---|---|
| `0x04` | RAM 0x04 | 生の IR チャンネル 1（符号 + 絶対値、MSB は符号ビット） |
| `0x05` | RAM 0x05 | 生の IR チャンネル 2 |
| `0x06` | RAM 0x06 | **Ta（ダイ温度）** |
| `0x07` | RAM 0x07 | **Tobj1（物体温度）** |
| `0x08` | RAM 0x08 | Tobj2（デュアルゾーン品のみ） |
| `0x20` | EEPROM 0x00 | Tomax（PWM 出力レンジの上限） |
| `0x21` | EEPROM 0x01 | Tomin（PWM 出力レンジの下限） |
| `0x22` | EEPROM 0x02 | PWMCTRL（PWM 周期、SDA の駆動形式、PWM/サーモスタット選択） |
| `0x23` | EEPROM 0x03 | Ta range |
| `0x24` | EEPROM 0x04 | **放射率**。ε = 値 / 65535。工場出荷は `0xFFFF` = 1.0 |
| `0x25` | EEPROM 0x05 | Config Register1（フィルタ設定など） |
| `0x2E` | EEPROM 0x0E | **SMBus スレーブアドレス（下位バイトのみ有効）** |
| `0x3C`〜`0x3F` | EEPROM 0x1C〜0x1F | ID number（読み出し専用、個体識別に使える） |
| `0xF0` | — | フラグ読み出し（EEBUSY, EE_DEAD, INIT） |
| `0xFF` | — | スリープ |

**温度値の読み方**: 16bit の値を 50 で割ると Kelvin。273.15 を引いて °C。
つまり 1LSB = 0.02K。リニアライズ済みの Ta / Tobj では **MSB がエラーフラグ**で、
1 なら値は無効。生の IR データでは MSB は符号ビットで、意味が違う。

- `0x27AD` → −70.00°C
- `0x3AF7` → 15095 / 50 = 301.9K → 28.75°C
- `0x7FFF` → 382.19°C（返しうる最大値）
- `0x8XXX` → エラー

**転送の形**:

```
Read Word（RAM/EEPROM 読み出し）
  S  [SA<<1 | W]  A  [opcode]  A  Sr  [SA<<1 | R]  A  [data LSB]  A  [data MSB]  A  [PEC]  NA  P

Write Word（EEPROM 書き込み）— repeated START は要らない
  S  [SA<<1 | W]  A  [opcode]  A  [data LSB]  A  [data MSB]  A  [PEC]  A  P

Sleep
  S  [SA<<1 | W]  A  [0xFF]  A  [PEC=0xE8]  A  P      ← SA=0x5A のときの PEC
```

PEC は START / repeated START / STOP / ACK / NACK を除く全ビットに掛かる CRC-8 で、
**スレーブアドレスバイトも含む**。読み出しでは 3 バイト目として返り、書き込みでは
マスタが計算して送る。スレーブが PEC の後に NACK を返したら、そのメッセージは
届いていないので送り直す。

## 典型的な使い方

1. 電源投入後、POR 完了を待つ（フラグ `0xF0` の INIT ビットで確認できる）。
2. Ta を読む: オペコード `0x06` を書き、**repeated START** を打って 3 バイト読む。
   Arduino の `Wire` なら `endTransmission(false)` の後に `requestFrom(addr, 3)`。
3. 物体温度を読む: 同じ手順でオペコード `0x07`。
4. 受け取った 3 バイトのうち 1・2 バイト目を `LSB | (MSB << 8)` で 16bit にし、
   MSB が立っていないことを確認してから ×0.02 − 273.15 で °C にする。
5. PEC（3 バイト目）を自分で計算して照合する。合わなければ捨てて読み直す。
6. 対象物の放射率が 1.0 でないなら、EEPROM `0x24` に ε × 65535 を書く（後述の手順で）。

EEPROM を書く手順（4.1.3.3.1、p16）:

1. 対象セルに `0x0000` を書いて消去する。
2. **5ms 以上（安全側で 10ms）待つ。**
3. 読み返して `0x0000` になったことを確認する。
4. 新しい値を書く。
5. **5ms 以上（安全側で 10ms）待つ。**
6. 読み返して一致を確認する。
7. **電源を入れ直す。** 変更が実際に効くのは次回の起動から。

## 利用上の注意

- **これは I2C ではなく SMBus である。** 実装上の違いが 3 つあり、どれも「動くけれど値が
  おかしい」形で現れる。
  1. **読み出しには repeated START が必須。** STOP を打ってから読み直す実装だと、
     デバイスによっては応答するが、データシートは Figure 4（p18）で明示的に repeated START を
     求めている。
  2. **返るのは常に 3 バイト。** 2 バイトだけ要求して STOP すると PEC バイトが宙に浮く。
  3. **データは LSB first。** I2C センサの多くが MSB first なので、そのつもりで実装すると
     バイトが入れ替わる。28.75°C が 0xF73A = 63290 → 1265.8K のような値になったら、これ。
- **PEC を捨てると壊れたデータを黙って受け取る。** バスが長い、プルアップが弱い、という
  環境では PEC が唯一の検出手段である。0.02°C 分解能の値が数十度飛ぶ形で現れる。
- **400kHz は仕様外。** データシートは 10kHz〜100kHz と明記している（4.1.4.3.12, p21）。
  本カタログの probe は 100kHz と 400kHz の両方を掃くが（[`scenarios/mlx90614/p0.yaml`](https://github.com/tanakamasayuki/I2CDeviceDB/blob/38f1d82/scenarios/mlx90614/p0.yaml)）、
  400kHz で動いたとしてもそれは仕様外の動作であり、個体・温度・配線で崩れうる。
- **`0xF0`（read flags）だけは repeated START を使わない。** 他の読み出しと同じ手順で
  投げると形が違う。また 16bit のうち意味があるのは 4bit だけで、1 バイト目で通信を
  打ち切ってよい。
- **EEPROM 書き込みはアドレスを永久に変える。** `0x2E` を書き換えた個体は、電源を入れ直すと
  もう `0x5a` では応答しない。値を控え忘れると全アドレスを走査して探すことになる。
  **救済手段はある**: このデバイスは SA = `0x00`（general call）で呼ばれると、自分のアドレスに
  関係なく必ず応答する。ただしバスに 1 個しか繋がっていないときにしか使えない。
- **書き換えてはいけない EEPROM がある。** 工場校正を壊さないために、
  Config Register1 の bit14〜11 / bit7 / bit3、EEPROM `0x0F` と `0x19` は触らないこと、と
  データシートが名指ししている（p13 の NOTE）。放射率（`0x24`）は変えてよい数少ないセルの 1 つ。
- **消去せずに書くと入らない。** EEPROM は「`0x0000` を書いて消してから書く」が必須で、
  各段階に 5ms 以上の待ちが要る。待たずに続けると EEBUSY 中のアクセスになる。
- **スリープからの復帰は I2C トランザクションではできない。** `0xFF` でスリープに入った後、
  起こすには SDA / SCL を直接叩く波形が必要で、データシートは Figure 10（4.1.4.3.11, p21）に
  「33ms 以上」の区間を示している。ホストの I2C ペリフェラルではこの波形を作れないので、
  ピンを GPIO に切り替えてビットバンギングするか、電源を切って入れ直すことになる。
  **復帰後、最初の値が読めるのは typ 0.25 秒後**（この 1 回だけ IIR フィルタが飛ばされる）。
  さらにスリープは 3V 版（Bxx / Dxx）にしか無い。5V 版に `0xFF` を送っても意味がない。
- **同じアドレスの MLX90614 を 2 個同じバスに置いてはいけない。** ARP に対応していないので、
  衝突を解決する手段が無い。
- **`0x5a` は他のデバイスとぶつかる。** 本カタログでは
  [STHS34PF80](../../chips/sths34pf80.yaml)（赤外線人感センサ）が同じ `0x5a` を使う。
  ほかにも CCS811 などが `0x5a` を取る。バススキャンで `0x5a` が見えたからといって
  MLX90614 とは限らない。ID number（オペコード `0x3C`〜`0x3F`）を読めば個体まで特定できる。
- **測定値は視野と放射率で決まる。** アルミなら ε ≈ 0.18、酸化した黒いアルミでも 0.30 しか
  無い。プラスチックや塗装面は 0.85〜0.95。同じ温度の 2 つの物体が違う値で返るのは
  故障ではない。個体ごとの校正ではなく**対象ごとの放射率設定**が必要になる、という意味で
  「持ち出した数値をそのまま信じない」種類のセンサである。
- **熱勾配で誤差が出る。** 温風・冷風がセンサ缶に当たる、近くに発熱体がある、といった
  過渡状態では、パッケージとダイの温度差そのものが赤外線信号として乗る。
- **VDD が落ちているとバスから電流を吸う。** クランプダイオードがあるため、センサの電源を
  切ってプルアップだけ生きている状態にすると、SDA / SCL 経由で電流が流れる。
- **整定時間は思ったより長い。** 品種の工場既定値で 0.10〜1.33 秒。読み出し周期を詰めても
  同じ値が返るだけで、応答は速くならない。

## 出典と確度

- オペコード体系、RAM / EEPROM の番地、転送の形、PEC、温度換算、電源条件、
  フィルタと整定時間: すべて Melexis datasheet Rev 021（2026-06-02）由来。
- **未確認**: 実機のキャプチャが無い。`0x5a` で応答するか、PEC が実際に一致するか、
  LSB first が実測で確かめられるか、400kHz で通るかは確かめられていない。
- **未調査**: probe は read-only なので、EEPROM 書き込み・アドレス変更・スリープ・PWM モードは
  すべて deferred。スリープ復帰波形の SDA / SCL のレベルは Figure 10 の図から読む必要があり、
  本ガイドは抽出テキストからの読み取りなので、実装前に図そのものを確認すること。
- M5Stack Unit NCIR / NCIR2 がどの品種（Axx か Bxx か、単ゾーンか二ゾーンか、FOV）を
  載せているかは**未確認**。スリープが使えるかどうかはこれで変わる。
