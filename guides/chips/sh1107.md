# SH1107 — 128×128 OLED ドライバ兼コントローラ

> 表示 RAM を内蔵した OLED パネルの駆動 IC。I2C では**レジスタアドレスが存在しない**。
> スレーブアドレスの直後に置く control byte が「以後はコマンド」か「以後は表示 RAM のデータ」かを
> 決める、という 2 本のストリームだけで全部を表現する。
>
> **確度**: Sinowealth（Sino Wealth）の datasheet（SH1107、V2.1）に基づく。ただし
> **メーカーの公式配布ページが存在せず**、参照したのは広く流通しているミラー
> （displayfuture.com）である。**実測は無い**。`observations/sh1107/` は存在せず、
> [`profiles/sh1107.yaml`](https://github.com/tanakamasayuki/I2CDeviceDB/blob/38f1d82/profiles/sh1107.yaml) も transport（control byte の値）しか
> 持っていない。

## これは何か

有機 EL（OLED / PLED）のドットマトリクスパネルを直接駆動する、ドライバ + コントローラの
1 チップ。最大 128 セグメント × 128 コモン、つまり **128×128 ドット**まで扱える。
チップ内に 128×128 bit の SRAM（表示 RAM = GDDRAM）、発振器、DC-DC コンバータ、
256 段のコントラスト制御を持つ。

ホストがすることは 2 つしかない。

1. **コマンドを送る**（表示 ON/OFF、コントラスト、走査方向、書き込み先のページと列、など）。
2. **表示 RAM にビットパターンを書く**。

書いたビットパターンは、コントローラが勝手に走査してパネルに出し続ける。ホストが毎フレーム
送り直す必要は無い（フレームバッファはチップ側にある）。

**I2C では実質的に書き込み専用である。** datasheet 上は読み出しの記述もあるが（p.15、
「W/R ビットを 1 にすると、直前の write access の C/D に従って出力する」）、
GDDRAM の読み出しは Read-Modify-Write とダミーリードを伴うパラレル前提の機能で（p.39）、
実際のライブラリもモジュールもこれを使わない。**「今なにが表示されているか」はホスト側で
覚えておく**設計にすること。

インタフェースは IM0〜IM2 ピンで 8080 パラレル / 6800 パラレル / 3線 SPI / 4線 SPI / I2C から
選ぶ。**I2C を選ぶとピンの役割が変わる**: D0 が SCL、D1 が SDA になり、A0 ピンは SA0
（スレーブアドレスの最下位ビット）になる。モジュール上ではこの結線が固定されているので、
ホストから見えるのは「アドレス 2 択の I2C デバイス」だけである。

できること:

- 表示 ON / OFF、全点灯、白黒反転、コントラスト 256 段。
- ページアドレッシングモード（列が自動で進む）と垂直アドレッシングモード（ページが自動で進む）。
- セグメント / コモンのリマップ（上下・左右の反転）。パネルの実装方向に合わせる。
- 表示開始ラインとディスプレイオフセットの設定。垂直スクロールに使える。
- マルチプレクスレシオを 1〜128 の任意値に設定（128 未満のパネルに合わせる）。
- 内蔵 DC-DC の ON / OFF とスイッチング周波数の選択。

できないこと・持っていないもの:

- **I2C で表示内容を読み返せない**（上記）。
- **ステータスやチップ ID を I2C で読む実用的な手段が無い。** 「そこにあるのが SH1107 か
  SSD1309 か」をバスから判定できない。
- **文字も図形も描けない。** フォントも線分描画も持たない。ビットマップを作るのはホストの仕事。
- **部分更新の通知やティアリング同期が無い。** 書いた瞬間に画面に出る。
- **アドレス変更はコマンドではできない**（SA0 ピンのみ）。
- **パネルの電源（VPP 7.0〜16.5 V）はロジックとは別系統。** 内蔵 DC-DC を使うか外部から与える。

電気的な現実:

- ロジック VDD 1.65〜3.5 V、DC-DC 用 AVDD 2.4〜3.5 V、パネル駆動 VPP 7.0〜16.5 V。
  **5 V ロジックは範囲外。**
- セグメント最大 500 µA、コモン最大 64 mA。スリープ時 5 µA 未満。
- I2C は最大 400 kHz（fast mode）。
- リセットは RES ピン（Low 10 µs 以上）。**コマンドによるソフトリセットが無い**ので、
  RES ピンが引き出されていないモジュールでは、初期状態に戻す手段が電源断しかない。

## コマンドとデータストリーム

**転送の形**（datasheet p.15、Figure 9）:

```
S | slave addr + W | A | control byte | A | data byte | A | ... | P
```

control byte のビットは上位から **Co**（continuation）と **C/D**（command / data）で、残り 6 bit は 0。

- `0x00` = Co 0, C/D 0 → **これ以降のバイトはすべてコマンド**。STOP まで control byte は要らない。
- `0x40` = Co 0, C/D 1 → **これ以降のバイトはすべて表示 RAM のデータ**。
- Co = 1 にすると「次の 1 バイトのあとにまた control byte が来る」という意味になり、
  コマンドとデータを 1 トランザクション内で交互に送れる（`0x80` / `0xC0`）。
  ライブラリはほとんど使わない。本リポジトリの probe も `0x00` / `0x40` しか出していない。

**ページアドレッシング**: 表示 RAM は「ページ」という横帯に分かれている。1 ページ = 縦 8 ドット ×
128 列で、SH1107 は 128 行あるので **16 ページ**（page0〜15）ある。**データ 1 バイトが縦 8 ドット分**に
対応し、D0 が上、D7 が下（セグメントリマップが 0 のとき）。データを 1 バイト書くたびに列アドレスが
+1 され、列の終端まで行くと**先頭の列に戻る。ページは自動では進まない**。次のページに移るには
ページアドレスを設定し直す。垂直アドレッシングモード（`0x21`）に切り替えると、逆に**ページが +1** され、
列が固定になる。

主なコマンド（POR = パワーオンリセット後の値）:

| コード | 引数 | 意味 |
|---|---|---|
| `0x00`〜`0x0F` | — | 列アドレスの下位 4bit（POR `0x00`） |
| `0x10`〜`0x17` | — | 列アドレスの上位 3bit（POR `0x10`）。128 列なので上位は 0〜7 |
| `0x20` / `0x21` | — | メモリアドレッシングモード: ページ / 垂直（POR `0x20`） |
| `0x81` | 1 バイト | コントラスト 0〜255（POR `0x80`） |
| `0xA0` / `0xA1` | — | セグメントリマップ（左右反転、POR `0xA0`） |
| `0xA4` / `0xA5` | — | 表示 RAM に従う / 全点灯（POR `0xA4`） |
| `0xA6` / `0xA7` | — | 通常表示 / 白黒反転（POR `0xA6`） |
| `0xA8` | 1 バイト | マルチプレクスレシオ 1〜128（POR `0x7F` = 128） |
| `0xAD` | `0x8A` / `0x8B` ほか | DC-DC 制御。最下位が 1 で「表示 ON 時に DC-DC を使う」（POR は DC-DC 有効） |
| `0xAE` / `0xAF` | — | 表示 OFF / ON（POR `0xAE` = OFF） |
| `0xB0`〜`0xBF` | — | ページアドレス 0〜15（POR `0xB0`） |
| `0xC0` / `0xC8` | — | コモン走査方向（上下反転、POR `0xC0`） |
| `0xD3` | 1 バイト | ディスプレイオフセット（COM0 のマッピング、POR `0x00`） |
| `0xD5` | 1 バイト | 表示クロックの分周比 / 発振周波数（POR `0x50`） |
| `0xD9` | 1 バイト | ディスチャージ / プリチャージ期間（POR `0x22`） |
| `0xDB` | 1 バイト | VCOM デセレクトレベル（POR `0x35`） |
| `0xDC` | 1 バイト | 表示開始ライン 0〜127 |
| `0xE0` / `0xEE` | — | Read-Modify-Write 開始 / 終了（読み出しが要るため I2C では使わない） |
| `0xE3` | — | NOP |

**リセット直後の状態**（datasheet p.22）: 表示 OFF、128×128 モード、通常のマッピング、
列アドレスカウンタ 0、コントラスト `0x80`、通常のコモン走査方向、内蔵 DC-DC 選択。
**表示 ON になっていないので、`0xAF` を送るまで何も光らない。**

## 典型的な使い方

初期化から表示まで（datasheet p.43 の電源投入手順に沿う）:

1. VDD / AVDD を入れ、RES を Low に 10 µs 以上引いてから離す。
2. `0x00` ストリームでコマンドを送る。パネルに合わせるべきものは主に
   マルチプレクスレシオ（`0xA8`）、ディスプレイオフセット（`0xD3`）、表示開始ライン（`0xDC`）、
   セグメント / コモンのリマップ（`0xA0`/`0xA1`、`0xC0`/`0xC8`）、クロック（`0xD5`）、
   プリチャージ（`0xD9`）、VCOM（`0xDB`）、コントラスト（`0x81`）。
3. **表示 RAM の中身は電源投入時に不定である。** 全ページに 0 を書いて消す。
4. `0xAF` で表示 ON。
5. 以後、描画のたびに「ページと列を指定 → `0x40` ストリームでバイト列を流す」を繰り返す。

1 ページ分を書く最小の手順（本リポジトリの probe が実行しているもの）:

1. `0x00` ストリームで `0xAE`（表示 OFF）。
2. `0x00` ストリームで `0xB0`（ページ 0）。
3. `0x00` ストリームで `0x00`, `0x10`（列 0 = 下位 0 + 上位 0）。
4. `0x40` ストリームで n バイト流す。列アドレスが自動で進む。
5. `0x00` ストリームで `0xAF`（表示 ON）。

## 利用上の注意

- **画面の内容を読み返せない。** I2C ではフレームバッファを取り戻せないので、
  「差分だけ描く」実装をするならホスト側に同じ内容のバッファを持つしかない。
  ホストのバッファと実機がずれたときに気づく手段が無いことも意味する。
- **バスから「これは SH1107 だ」と判定できない。** `0x3C` に ACK が返るだけで、
  SSD1309 も SSD1315 も同じアドレス・同じ control byte 規則である（後述）。
  製品の BOM か基板のシルクで決めるしかない。
- **`0x00` と `0x40` は「1 バイトのプレフィクス」ではなく「以後のストリームの種別」である。**
  Co=0 の control byte を 1 個送れば、STOP までのすべてのバイトがその種別になる。
  1 バイトごとに `0x00` を付け直す実装は動くが、転送量が倍になる。逆に、コマンドの途中で
  データを混ぜたいなら Co=1（`0x80` / `0xC0`）が要る。
- **ページは自動では進まない。** ページアドレッシングモードで列の終端に達すると、列アドレスは
  先頭に戻るがページはそのままである。「1 画面ぶん流し込んだのに 1 行しか出ない」のはこれ。
  ページごとに `0xB0`+n と列アドレスを設定し直す。
- **128×128 前提のコントローラである。** 128×64 や 64×128 のパネルに載っているものが多く、
  その場合はマルチプレクスレシオ（`0xA8`）、ディスプレイオフセット（`0xD3`）、
  表示開始ライン（`0xDC`）をパネルの実寸に合わせないと、**絵が縦にずれる / 上下に分裂する /
  半分しか出ない**。SSD1306 系の初期化シーケンスを流用したときに起きる典型的な症状で、
  I2C の通信自体は成功しているので原因が分かりにくい。
- **列アドレスは 2 つのコマンドに分かれている。** 下位 4bit（`0x00`〜`0x0F`）と上位（`0x10`〜`0x17`）を
  両方送らないと、前回の値が残る。片方だけ送って「たまたま合っていた」状態になりやすい。
- **`0xDC`（表示開始ライン）は SSD1306 / SSD1309 と互換ではない。** あちらは `0x40`〜`0x7F` の
  1 バイトコマンドだが、SH1107 は `0xDC` + 値の 2 バイトである。しかも SSD 系の `0x40` は
  SH1107 では**データストリームの control byte と同じ値**なので、取り違えると
  「コマンドのつもりで送ったものが表示 RAM に書かれる」ことになる。
- **メモリアドレッシングモードの指定方法も SSD 系と違う。** SH1107 は `0x20` / `0x21` の
  1 バイトで page / vertical を選ぶ。SSD1309 は `0x20` + 引数 1 バイトの 2 バイトで、
  horizontal / vertical / page の 3 択である。**SSD 用のコードをそのまま流すと、
  `0x20` の次に送った引数バイトがコマンドとして解釈される。**
- **ソフトリセットコマンドが無い。** 状態を確実に戻したいなら RES ピンか電源断。
  モジュールが RES を引き出していない場合、初期化に失敗した状態から抜けられないことがある。
- **DC-DC の設定は表示 OFF 中に行う。** datasheet が明記している（p.32）。
- **表示 RAM の初期値は不定。** 初期化直後に `0xAF` を送ると、意味のないパターンが一瞬光る。
  クリアしてから表示 ON にする。
- **Read-Modify-Write（`0xE0` / `0xEE`）は I2C 向きではない。** 読み出しが前提の機能なので、
  書き込み専用で使っているなら触らない。`0xE0` を送ったまま `0xEE` を送り忘れると、
  列アドレスの進み方が変わる。

## 似ているチップとの見分け方

本カタログには同じ `0x3C` / `0x3D`、同じ control byte 規則（`0x00` / `0x40`）を使う
OLED コントローラが 3 つある。**I2C バスの上では区別できない。** 判断材料は次のとおり。

| | SH1107 | SSD1309 | SSD1315 |
|---|---|---|---|
| メーカー | Sinowealth | Solomon Systech | Solomon Systech |
| 最大解像度 | **128×128**（16 ページ） | 128×64（8 ページ） | 128×64（8 ページ） |
| ページアドレス | `0xB0`〜**`0xBF`** | `0xB0`〜`0xB7` | `0xB0`〜`0xB7` |
| アドレッシングモード | page / vertical の 2 択、`0x20` / `0x21` の 1 バイト | horizontal / vertical / page の 3 択、**`0x20` + 引数** | 同左 |
| 表示開始ライン | **`0xDC` + 値**（2 バイト） | `0x40`〜`0x7F`（1 バイト） | 同左 |
| マルチプレクス | 1〜128 | 16〜64 | 16〜64 |
| 昇圧 | **内蔵 DC-DC**（`0xAD`） | **内蔵チャージポンプ無し。VCC 7〜16 V を外部から** | **内蔵チャージポンプあり**（`0x8D`） |
| 固有コマンド | Read-Modify-Write `0xE0`/`0xEE` | Set Command Lock `0xFD`、GPIO `0xDC` | Fade/Blinking `0x23`、Zoom In `0xD6` |

実務的には、**モジュールの製品ページか基板のシルクを見るのが唯一確実な方法**である。
それでも分からないときの手がかりは (a) パネルが正方形に近ければ SH1107 の可能性が高い、
(b) 基板に昇圧用のインダクタ / コンデンサがあるか（SSD1309 は外部 VCC が要る）、
(c) 既存ライブラリのどの初期化シーケンスで正しく表示されるか、である。
**`0x3C` に ACK が返ることは、3 つのどれであるかを何も教えてくれない。**
