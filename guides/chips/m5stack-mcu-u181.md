# Unit BLDC Driver (U181) — センサレス 3 相 BLDC モータドライバ

> 3 相ブラシレス DC モータを I2C から回すためのドライバ。デューティを直接指令する開ループと、
> 目標回転数を与えて firmware の PID に追わせる閉ループの 2 モードを持つ。
>
> **確度**: M5Stack が Unit BLDC Driver I2C Protocol という PDF（2023-12-05、firmware V1 向け）を
> 公開しており、レジスタ表はそこと `M5Unit-BLDC` ライブラリのソースの両方に存在する。
> 本文の転送長・バイト順・アクセス方向は**ライブラリのソースから起こした推定**で、
> 実測では未確認。
>
> **安全**: **このユニットには出力イネーブルのレジスタが無い。** `0x10`（PWM デューティ）や
> `0x40`（目標 RPM）に 0 以外を書いた瞬間からモータが回り始める。止める手段は同じレジスタに
> 0 を書くか、モードを切り替えるか、電源を切るかである。試すときは**モータ軸に何も付けず、
> モータ自体を固定してから**にすること。本リポジトリの probe が read-only なのはまさに
> このためで（[docs/VERIFY.ja.md](https://github.com/tanakamasayuki/I2CDeviceDB/blob/38f1d82/docs/VERIFY.ja.md) の「アクチュエータを持つユニット」）、
> 書き込み側の挙動は一切確かめていない。

## これは何か

STM32G030F6P6 に M5Stack のファームウェアを載せ、DRV11873PWPR（3 相センサレス BLDC 用の
ゲートドライバ）を叩かせているユニット。**DRV11873 は I2C バスには出ていない**。ホストから
見える I2C の相手は STM32 だけである。つまり固定機能 IC ではなくファームウェアであり、
レジスタマップはこの製品固有のものである。

モータは**付属しない**。HT3.96-4P の端子台に 3 相センサレス BLDC モータをつなぐ。電源は
Grove の 5V だけで、モータもそこから駆動される（出力能力 DC 5V@508mA）。ホール素子や
エンコーダの入力は無い。

できること:

- **開ループ**: PWM デューティ（0〜2047）を直接指令する。
- **閉ループ**: 目標 RPM を float で与え、firmware 側の PID に追わせる。PID 係数も書き換えられる。
- 回転方向の切り替え。
- モータの実回転数と、転流パルスの周波数（Hz）を読める。それぞれ float / 整数 / 文字列の
  3 通りの表現がある。
- モータの状態（待機 / 回転中 / エラー）を読める。
- モータの極対数とモータモデル（低速 / 高速）を設定し、フラッシュに保存できる。
- I2C アドレスを変更できる。

できないこと・持っていないもの:

- **位置も角度も分からない。** センサレス駆動でエンコーダも無い。回転数は転流パルスから
  求めた推定値で、`RPM = 転流周波数 × 60 ÷ 極対数` である（vendor PDF に明記）。
  **極対数を間違えて設定すると、読める RPM も指令する RPM も比例して狂う。**
- **電流も電圧も温度も読めない。** レジスタが無い。過負荷の検出は「状態がエラーになったか」
  だけで、原因は分からない。
- **出力イネーブルが無い。** 「モータを繋いだまま安全に停止させておく」ための独立した
  スイッチがレジスタとして存在しない。
- **ブレーキ / フリーラン（惰性）の指定ができない。** 停止のさせ方を選べない。
- **PWM の周波数は変えられない。** レジスタが無い。
- **起動失敗（脱調）の検出フラグが個別に無い。** 状態レジスタが `2`（エラー）になるだけ。
- `0xE0`（最低 PWM デューティらしき名前）はライブラリのヘッダにあるだけで、
  **ライブラリのどのメソッドも触らず、vendor PDF のレジスタ表にも載っていない**。
  長さもアクセス方向も意味も**未確認**。

## レジスタ

| アドレス | 長さ | R/W | 意味 |
|---|---|---|---|
| `0x00` | 1 | R/W | 制御モード。`0`=開ループ（PWM デューティ）、`1`=閉ループ（RPM + PID）。**切り替えると PWM / RPM が自動的に 0 になる**（PDF 記載） |
| `0x10` | 2 | R/W | 開ループの PWM デューティ。**符号なし 16bit・LSB first**、0〜2047（単位は無い生の値） |
| `0x20` | 4 | R | 実測 RPM。**IEEE 754 単精度 float・リトルエンディアン**、単位は RPM |
| `0x30` | 4 | R | 実測の転流パルス周波数。**float・リトルエンディアン、単位は Hz**。`RPM = 周波数 × 60 ÷ 極対数` |
| `0x40` | 4 | R/W | 閉ループの目標 RPM。**float・リトルエンディアン**。**閉ループでのみ有効** |
| `0x50` | 12 | R/W | PID 係数。**符号付き 32bit × 3（P, I, D の順）、各 LSB first、各 100 倍**（P=50.05 なら 5005）。フラッシュ保存可 |
| `0x60` | 1 | R/W | 回転方向。`0`=正転、`1`=逆転。**反映には手順が要る**（後述） |
| `0x70` | 1 | R/W | モータモデル。`0`=低速、`1`=高速。フラッシュ保存可 |
| `0x71` | 1 | R/W | 極対数（1〜255）。ライブラリは `0x70 + 1` として叩いている。フラッシュ保存可 |
| `0x80` | 1 | R | モータ状態。`0`=待機、`1`=回転中、`2`=エラー |
| `0x90` | 4 | R | `0x20` と同じ実測 RPM の整数版。**符号付き 32bit・LSB first、単位は 1/100 RPM**（PDF 記載）。ライブラリは触らない |
| `0xA0` | 4 | R | `0x30` と同じ周波数の整数版。**符号付き 32bit・LSB first、単位は 1/100 Hz**（PDF 記載）。ライブラリは触らない |
| `0xB0` | 16 | R | 実測 RPM の文字列版。`'\0'` 終端、最大 15 文字 |
| `0xC0` | 16 | R | 周波数の文字列版。`'\0'` 終端、最大 15 文字 |
| `0xD0` | 4 | R/W | `0x40` と同じ目標 RPM の整数版。**符号付き 32bit・LSB first、単位は 1/100 RPM**（PDF 記載）。ライブラリは触らない |
| `0xE0` | ? | ? | ヘッダの名前は「最低 PWM デューティ」。**ライブラリも vendor PDF も扱っていない。すべて未確認** |
| `0xF0` | 1 | W | `1` を書くと設定をフラッシュに保存する |
| `0xFD` | 1 | W | `1` を書くとファーム更新用ブートローダに入る |
| `0xFE` | 1 | R | ファームウェアのバージョン |
| `0xFF` | 1 | W（PDF は R/W） | I2C アドレス（1〜127） |

`0x20` / `0x90` / `0xB0` は同じ実測 RPM の 3 通りの表現、`0x30` / `0xA0` / `0xC0` は同じ周波数の
3 通りの表現、`0x40` / `0xD0` は同じ目標 RPM の 2 通りの表現である。

**転送の形**: 書き込みは「ポインタバイト + ペイロード」を 1 トランザクションで。読み出しは
ポインタバイトを書いて **repeated START**（`endTransmission(false)`）を打ち、続けて必要な長さを
要求する。オートインクリメントはライブラリからは見えない（各メソッドが毎回レジスタを指定する）。

## 典型的な使い方

**先に読むこと**: 以下はいずれもモータが回る手順である。軸に何も付けず、モータを固定し、
指を近づけない状態で行うこと。

1. `0xFE` を読んでファームウェアのバージョンを確認する（通信確認も兼ねる）。
2. **モータの素性を設定する。** `0x71` に極対数、`0x70` にモータモデル。回転数の計算が
   これに依存するので、閉ループを使うなら必須。残したいなら `0xF0` に `1` を書いて保存する。
3. **モードを決める。** `0x00` に `0`（開ループ）か `1`（閉ループ）。**モードを書いた時点で
   指令値は 0 に戻る**ので、必ず設定値より先に書く。
4. 開ループなら `0x10` に 0〜2047 を LSB first で書く。閉ループなら `0x40` に目標 RPM を
   float で書く。**ここで回り始める。**
5. 様子を見るなら `0x80`（状態）と `0x20`（実測 RPM）をポーリングする。
6. 止めるときは同じレジスタに 0 を書く。

## 利用上の注意

- **出力イネーブルが無い。書いた瞬間に回る。** Roller 系のような `output` レジスタは
  このユニットには存在しない。「準備してから動かす」ことができない構造なので、
  設定を整えてから最後に指令値を書く、という順序を自分で守るしかない。
- **モードを切り替えると指令値が 0 に戻る。** vendor PDF に明記されている
  （"After switching modes, pwm or rpm will be automatically set to 0"）。逆に言えば
  設定値を書いたあとにモードを書くと、書いた設定値が消える。**順序は必ずモードが先**。
- **回転方向の変更には手順がある。** vendor PDF の脚注 [1]: (1) `0x60` に方向を書く、
  (2) PWM か RPM を 0 にする、(3) 改めて 0 以外を書く。**この 3 段を踏まないと方向が変わらない。**
  ライブラリの `setDirection()` は (1) しかしないので、呼んだだけでは効かない。
- **`getRPM()` は実測値ではない。** 名前に反して `0x40`（目標 RPM）を読んでいる。実測が
  欲しいなら `getRpmReadback()`（`0x20`）。API 名だけで判断すると、指令値をグラフに
  描いて「完璧に追従している」と勘違いする。
- **PID は 100 倍のスケール。** バス上の値は係数 ×100 の符号付き 32bit（P, I, D の順に 12 バイト
  まとめて）。ライブラリの `setPID()` / `getPID()` はこの ×100 / ÷100 をやってくれるが、
  自前の driver では自分でやる必要がある。3 係数は常に 12 バイト 1 ブロックで転送される。
- **極対数がすべての回転数に効く。** RPM は転流周波数からの逆算なので、`0x71` の値が
  実際のモータと違えば `0x20` も `0x40` も比例してずれる。「回転数が想定の 2 倍/半分」の
  ときは、まずここを疑う。
- **`0x90` / `0xA0` / `0xD0` は 100 倍の整数版。** vendor PDF が定義しているが、ライブラリは
  一切触らない。自前で読むなら 100 で割る。profile はライブラリからしか起こせなかったので
  長さ未記載になっているが、PDF では 4 バイトである。
- **`0xE0` は正体不明。** ヘッダに名前があるだけで、実装にも vendor PDF にも登場しない。
  読み書きしてよいレジスタなのかどうかも分からない。**触らない。**
- **ライブラリの既知の不具合**:
  - `M5UnitBLDC.h` のメンバ `_speed` が `uint8_t` なのに、`begin()` の引数は
    `uint32_t speed = 8000000L`。代入で下位 1 バイトに切り詰められ、**既定では
    `8000000 & 0xFF = 0` が `Wire.setClock(0)` に渡る**。どんな値を渡しても下位 8bit しか
    残らないので、`begin()` 経由でまともな I2C クロックを指定する手段が無い。
    ドライバ側が 0 を弾いて既定クロックのままになるのか、それとも失敗するのかは**未確認**。
    速度を決めたいなら `begin()` の後に自分で `Wire.setClock()` を呼ぶこと。
    （そもそも既定値の 8MHz は I2C の速度として現実的でない。）
  - `begin()` の既定ピンが `sda = 25, scl = 21` になっている。他の M5 系ライブラリの
    既定（21 / 22）と違うので、引数を省略すると通信しない基板がある。
  - `getFirmwareVersion()` は `_wire->read()` ではなくグローバルの `Wire.read()` を呼ぶ。
    `Wire1` を渡していると別のバスから読む。
- **設定はフラッシュに書くまで揮発する。** 極対数とモータモデルは `0xF0` に `1` を書くまで
  電源断で消える（ライブラリの `saveMotorDataToFlash()`）。vendor PDF によれば PID と
  I2C アドレスも保存対象である。
- **アドレス変更は即時反映。** `0xFF` に書いた次のトランザクションはもう新アドレス宛に出す。
  ライブラリは読み出し側の API を持たないので、忘れると scan で探すことになる。
- **`0xFD` に書くとブートローダに入る。** 回転中に誤って書いた場合に何が起きるかは**未確認**。

## 出典と確度

- レジスタのアドレスと意味: `M5Unit-BLDC` ライブラリ 1.0.0 のソース。ベンダーの
  Protocol PDF とも整合する。
- 単位（RPM、Hz、1/100 RPM、1/100 Hz）、モード切替時の 0 クリア、方向変更の手順、
  `RPM = 周波数 × 60 ÷ 極対数`、PID の ×100、フラッシュ保存対象: ベンダー Protocol PDF。
- 転送長・アクセス方向・バイト順: 同ライブラリのメソッド本体から起こした**推定**。
- **未確認**: 実機のキャプチャがまだ無い（`observations/m5stack-mcu-u181/` は存在しない）。
  レジスタが表のとおり応答するか、`0xE0` が何か、`0xFF` が読めるかは確かめられていない。
- **未調査**: 書き込み側の挙動全般。probe が read-only なので、モード設定・デューティ・
  RPM・方向・フラッシュ保存のいずれも実機では触っていない。モータが回る書き込みの確認は、
  可動部の安全を確保したうえで別 scenario として起こす（[docs/VERIFY.ja.md](https://github.com/tanakamasayuki/I2CDeviceDB/blob/38f1d82/docs/VERIFY.ja.md)）。
