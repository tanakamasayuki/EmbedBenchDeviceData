# Unit RollerCAN (U188) — CAN / I2C 両対応の一体型 BLDC サーボ

> モータ・ドライバ・磁気エンコーダ・OLED を 40mm 角の筐体に収めた閉ループサーボ。速度・位置・
> 電流の 3 ループと、ダイヤル入力として使うエンコーダモードを持つ。CAN と I2C は
> **同じ制御レジスタに対する 2 つの入口**で、このガイドは I2C 側だけを扱う。
>
> **確度**: レジスタマップは `M5Unit-Roller` ライブラリの `UnitRollerI2C` クラスの
> ソースから起こした**推定**で、実測では未確認。**このユニットのベンダー文書
> （"Unit-RollerCAN I2C Control Protocol"）には I2C のレジスタ表が載っていない**（後述）。
> 単位とスケールは、同じマップを持つ Roller485 (U182) 側の I2C Protocol PDF と、
> RollerCAN 文書の CAN コマンド定義の両方で裏が取れている。
>
> **安全**: **`0x00` に `1` を書いた瞬間からモータが回る。** 位置モードなら、そのとき
> `0x80` に入っている目標位置まで即座に動く。速度モードなら設定速度まで加速する。試すときは
> 出力軸に何も付けず、本体を固定してから行うこと。本リポジトリの probe が read-only なのは
> まさにこのためで（[docs/VERIFY.ja.md](https://github.com/tanakamasayuki/I2CDeviceDB/blob/38f1d82/docs/VERIFY.ja.md) の「アクチュエータを持つユニット」）、
> 書き込み側の挙動は一切確かめていない。

## U188 と U182 はレジスタマップを共有する

手元にあるのが RollerCAN (U188) でも Roller485 (U182) でも、**I2C から見える姿はほぼ同じ**である。

- ベンダーライブラリには `UnitRollerI2C` というクラスが 1 つしか無く、両ユニットがそれを使う。
  ライブラリ内にどちらのユニットかで分岐する箇所は無い。
- 既定の I2C アドレスはどちらも `0x64`。レジスタ番号・長さ・アクセス方向も同一。
- **違うのは `0x10` と `0x11` の意味だけ**である。
  - `0x10`（ノード ID）: U188 では **CAN のノード ID**、U182 では **RS485 のノード ID**。
  - `0x11`（通信速度の番号）: U188 では **CAN** の `0`=1000000 / `1`=500000 / `2`=125000 bps、
    U182 では **RS485** の `0`=115200 / `1`=19200 / `2`=9600 bps。
- **I2C からどちらのユニットかを問い合わせる方法は無い。** 型番を返すレジスタが無く、
  `0xFE`（ファームウェアバージョン）で区別できるかどうかも**未確認**。手元の実物を見て
  判断するしかない。

したがってこのガイドと [`m5stack-mcu-u182.md`](m5stack-mcu-u182.md) は、
上の 2 レジスタと物理的な構成以外は同じことを書いている。

## ベンダー文書についての注意

`chips/m5stack-mcu-u188.yaml` が指している
[Unit-RollerCAN I2C Protocol PDF](https://m5stack-doc.oss-cn-shenzhen.aliyuncs.com/779/Unit-RollerCAN-I2C-Protocol-EN.pdf)（22 ページ）は、
題名に反して**レジスタ表ではない**。中身は
`[コマンド][デバイス ID][データ 1..3][CRC8]` という **CAN のコマンドパケット**の定義集で、
最後の章が「CAN から I2C へ転送する命令」（このユニットを CAN 経由の I2C ブリッジとして
使う機能）になっている。つまり "I2C" は転送先の意味で、このユニット自身の I2C レジスタの
話ではない。

**I2C のレジスタ表が載っているのは Roller485 (U182) 側の PDF のほうである。** 上に書いた
とおりマップは共有なので、U188 を I2C で叩くときは U182 の PDF を読むことになる。
ただし RollerCAN の文書も**単位の出典としては有用**で、速度が RPM、電流が mA、
VIN が V、温度が ℃ であることはこちらに明記されている。

## これは何か

STM32G431CBU6（170MHz）に M5Stack のファームウェアを載せ、DRV8311HRRWR（3 相ドライバ）と
TLI5012BE1000（磁気角度センサ）を従えた一体型サーボ。**ドライバも角度センサも I2C バスには
出ていない**。ホストから見える I2C の相手は STM32 だけである。つまり固定機能 IC ではなく
ファームウェアであり、レジスタマップはこの製品固有のものである。

モータは D3504 200KV（Ø41mm）。連続の相電流は 0.5A、短時間で 1A まで。最大負荷 500g。
背面に 0.66 インチ 64×48 の OLED が付いていて、モードや設定値を自分で表示する。
RGB LED（WS2812-2020）が 2 個とボタンが 1 個。

電源は CAN 側の XT30 から 6〜16V、または Grove から 5V。回転側に電源を送るスリップリング付きの
Grove ポートがあり、5V/300mA まで供給できる。製品ページは「CAN と I2C の選択は自動で、
XT30 から給電すれば CAN、Grove の 5V なら I2C」という趣旨の説明をしているが、**その切り替えが
どう実装されているのか、I2C だけでモータを定格どおり回せるのかは製品ページからは
確定できない。未確認。**

CAN 側には、このユニットを**他の I2C デバイスへのブリッジ**として使う命令
（レジスタ読み書き / raw 読み書き、1 回あたり最大 16 バイト）もある。I2C からこの機能を
呼ぶ経路はレジスタマップには無い。

できること:

- **4 つのモード**を切り替えられる: `1`=速度、`2`=位置、`3`=電流、`4`=エンコーダ。
- 速度・位置・電流それぞれの目標値と、実測値の読み出し。
- 速度ループと位置ループの PID 係数を書き換えられる。
- 速度モード / 位置モードそれぞれに電流制限を設定できる。
- 電源電圧とモータ温度を読める。
- **エンコーダモード**ではモータを回さず、手で回した量をカウンタ（`0x3C`）として読む。
  つまりダイヤル入力デバイスとして使える。
- ストール（拘束）保護と位置範囲外保護の有効化、およびストール保護のリセット。
- RGB LED の色・明るさ・「システム表示かユーザ指定か」の切り替え。
- 設定をフラッシュに保存できる。
- I2C アドレス、CAN のノード ID とボーレートを変更できる。

できないこと・持っていないもの:

- **ボタンの状態を I2C から読めない。** ボタンに関するレジスタは `0x0E`（ボタンによる
  モード切替を許可するか）だけで、押下状態を返すレジスタは無い。**しかも `0x0E` を有効に
  すると、運転中に人が 5 秒長押しするだけでモードが変わる**——ホストの知らないところで
  制御モードが変わりうる、ということである。
- **OLED に好きなものを表示できない。** 表示内容を渡すレジスタが無い。
- **CAN→I2C ブリッジ機能を I2C 側から使えない。** あれは CAN のコマンドである。
- **トルクを直接指令できない。** 電流モードが最も近いが、トルク定数は資料に無い。
- **加減速（台形加速・ジャーク制限）の設定が無い。** 目標値を書けば全力で追いに行く。
- **原点復帰（ホーミング）の機能が無い。**
- **位置カウンタが電源を跨いで保持されるかどうかは未確認。**
- **エラーの詳細が 1 バイトしかない。** `0x0D` に `1`（過電圧）/ `2`（拘束）/ `4`（範囲外）が
  出るだけ。
- **CAN 側の通信状態を I2C から見られない。** ノード ID とボーレートを設定できるだけ。
- **位置の物理単位がどの資料にも書かれていない**（後述）。

## レジスタ

**単位とスケールが要注意。** 速度・位置・電流・電圧は**すべて 100 倍された整数**で、
ライブラリはこの除算をしてくれない（ベンダーのサンプルが `printf` の中で 100 で割っている）。

| アドレス | 長さ | R/W | 意味 |
|---|---|---|---|
| `0x00` | 1 | R/W | 出力。`0`=停止、`1`=駆動。**ここに `1` を書くと回り出す** |
| `0x01` | 1 | R/W | 制御モード。`1`=速度、`2`=位置、`3`=電流、`4`=エンコーダ |
| `0x0A` | 1 | R/W | 位置範囲外保護。`0`=無効、`1`=有効 |
| `0x0B` | 1 | W | `1` を書くとラッチされたストール保護を解除する |
| `0x0C` | 1 | R | システム状態。`0`=待機、`1`=運転中、`2`=エラー |
| `0x0D` | 1 | R | エラーコード。`0`=なし、`1`=過電圧、`2`=拘束、`4`=範囲外（`4` は vendor 文書のみに記載） |
| `0x0E` | 1 | R/W | ボタンによるモード切替。`0`=無効、`1`=運転中に 5 秒長押しでモード変更 |
| `0x0F` | 1 | R/W | ストール保護。`0`=無効、`1`=有効 |
| `0x10` | 1 | R/W | **CAN の**ノード ID（0〜255）。I2C アドレスとは無関係 |
| `0x11` | 1 | R/W | **CAN の**ボーレート番号。`0`=1000000、`1`=500000、`2`=125000 bps |
| `0x12` | 1 | R/W | RGB LED の明るさ、0〜100 |
| `0x20` | 4 | R/W | **位置モードの**電流制限。符号付き 32bit・LSB first、**単位は 1/100 mA**、範囲 ±120000（= ±1200mA） |
| `0x30` | 3 | R/W | RGB LED の色。**B, G, R の順**の 3 バイト（数値ではなくバイト列） |
| `0x33` | 1 | R/W | RGB の出所。`0`=システム既定（状態表示の色）、`1`=ユーザ指定。ライブラリは `0x30 + 3` として叩く |
| `0x34` | 4 | R | 電源電圧。符号付き 32bit・LSB first、**単位は 1/100 V** |
| `0x38` | 4 | R | モータ温度。符号付き 32bit・LSB first、**単位は ℃（スケールなし）** |
| `0x3C` | 4 | R/W | エンコーダモードのダイヤルカウンタ。符号付き 32bit・LSB first、単位はカウント。**エンコーダモードでのみ有効**。書けば任意の値に設定できる |
| `0x40` | 4 | R/W | 目標速度。符号付き 32bit・LSB first、**単位は 1/100 RPM**、範囲 ±2100000000 |
| `0x50` | 4 | R/W | **速度モードの**電流制限。符号付き 32bit・LSB first、**単位は 1/100 mA**、範囲 ±120000 |
| `0x60` | 4 | R | 実測速度。符号付き 32bit・LSB first、**単位は 1/100 RPM** |
| `0x70` | 12 | R/W | 速度ループ PID。符号なし 32bit × 3（P, I, D の順）、各 LSB first。**P は ×100000、I は ×10000000、D は ×100000** |
| `0x80` | 4 | R/W | 目標位置。符号付き 32bit・LSB first、**値 ÷ 100 が実際の指令値。物理単位は資料に記載なし** |
| `0x90` | 4 | R | 実測位置。符号付き 32bit・LSB first、同上 |
| `0xA0` | 12 | R/W | 位置ループ PID。`0x70` と同じスケール |
| `0xB0` | 4 | R/W | 目標電流。符号付き 32bit・LSB first、**単位は 1/100 mA**、範囲 ±120000 |
| `0xC0` | 4 | R | 実測電流。符号付き 32bit・LSB first、**単位は 1/100 mA** |
| `0xF0` | 1 | W | `1` を書くと設定をフラッシュに保存する |
| `0xF1` | 1 | W | **工場用**: `1` を書くと磁気エンコーダの角度校正を開始する |
| `0xF2` | 1 | W | **工場用**: `1` を書くと校正値を確定する |
| `0xF3` | 1 | R | 校正中フラグ。`1`=校正中、`0`=そうでない |
| `0xFE` | 1 | R | ファームウェアのバージョン |
| `0xFF` | 1 | R/W | I2C アドレス |

**転送の形**: 書き込みは「ポインタバイト + ペイロード」を 1 トランザクションで。読み出しは
ポインタバイトを書いて **repeated START**（`endTransmission(false)`）を打ち、続けて必要な長さを
要求する。

## 典型的な使い方

**先に読むこと**: 以下はモータが回る手順である。出力軸に何も付けず、本体を固定してから行うこと。

1. `0xFE` を読んでファームウェアのバージョンを確認する（通信確認も兼ねる）。
2. `0x34`（電源電圧）と `0x0C` / `0x0D`（状態とエラー）を読んで、まともに電源が入っているか、
   前回のエラーが残っていないかを見る。ストール保護がラッチされていれば `0x0B` に `1` を書く。
3. **`0x00` に `0` を書いて出力を止める。** 設定を変える前に必ず。
4. `0x01` にモードを書く。
5. そのモードの目標値と電流制限を書く。速度モードなら `0x40` と `0x50`、位置モードなら
   `0x80` と `0x20`、電流モードなら `0xB0`。**いずれも 100 倍した整数で、LSB first。**
6. **`0x00` に `1` を書く。ここで回り出す。**
7. 動いている間は `0x60` / `0x90` / `0xC0`（実測値）と `0x0C` / `0x0D`（状態）をポーリングする。
8. 止めるときは `0x00` に `0`。
9. 電源を切っても残したい設定は `0xF0` に `1` を書く。

エンコーダモード（`0x01` に `4`）だけは毛色が違う。モータは駆動されず、手で回した量が
`0x3C` に貯まる。ダイヤル入力として使う用途である。

## 利用上の注意

- **順序は「出力を止める → モード → 目標値 → 出力を入れる」。** モードや目標値は出力が
  有効なままでも書けてしまい、その場合は**書いた瞬間に反映される**。ベンダーのサンプルも
  モードを変えるたびに `setOutput(0)` を先に呼んでいる。
- **位置モードは「絶対位置へ即座に動く」。** 出力を入れる前に `0x80` に大きな値が
  残っていると、有効化した瞬間に長距離を全速で動く。**有効化の前に現在位置（`0x90`）を
  読んで、`0x80` にそれと同じ値を書いておく**のが安全な入り方である。
- **すべての数値が 100 倍。** ライブラリの getter / setter は生の整数を素通しするだけで、
  ÷100 も ×100 もしない。速度 2400RPM を指令したければ `240000` を書く。1200mA なら `120000`。
  ちなみにベンダーのサンプルは `printf("%d", getPosMaxCurrent() / 100.0f)` のように
  **`%d` に double を渡している**箇所があり、サンプルどおりに書いても正しい表示にならない。
- **PID のスケールは 3 係数で別々。** P は ×100000、I は ×10000000、D は ×100000
  （P=0.004 → 400、I=0.002 → 20000、D=16.00 → 1600000）。3 つは常に 12 バイト 1 ブロックで
  転送され、片方だけ書く経路は無い。
- **`setRGB()` は RGB888 ではなく RGB565 を受け取る。** ライブラリの実装は引数から
  5bit/6bit/5bit を切り出して 8bit に伸ばし、`{B, G, R}` の順で書いている。したがって
  **`0xFF0000` を「赤」のつもりで渡すと消灯する**。レジスタ自体は 8bit × 3 の B, G, R なので、
  自前の driver から直接書くほうが分かりやすい。
- **ユーザ指定の色を出すには `0x33` に `1` を書く。** そうしないと firmware が状態表示の色で
  上書きする。
- **設定値と実測値のレジスタが別。** `0x40` / `0x80` / `0xB0` は**指令値**で、実測は
  `0x60` / `0x90` / `0xC0`。ライブラリの `getSpeed()` / `getPos()` / `getCurrent()` は前者
  （指令値）を読んでおり、実測は `getSpeedReadback()` / `getPosReadback()` /
  `getCurrentReadback()` である。名前で取り違えると「指令に完璧に追従している」グラフができる。
- **位置の物理単位が分からない。** RollerCAN の文書は「値 ÷ 100 が実際の位置」としか書かず、
  指令の説明で "number of pulses" という表現を使っている。Roller485 の PDF も単位を
  書いていない。**未確認。** 実測で 1 回転させて差分を見るのが確実。
- **温度だけはスケールが無い。** `0x38` は ℃ の整数（RollerCAN の文書に
  "Internal reference temperature value(℃)" とある）。他が全部 100 倍なので、ここも
  割ってしまう間違いが起きやすい。
- **`0x0E` を有効にすると人がモードを変えられる。** 運転中に本体のボタンを 5 秒長押しすると
  モードが切り替わる。無人運転では無効にしておくほうがよい。
- **`0xF1` / `0xF2` は工場用の角度校正。** ライブラリのヘッダにも "internal factory register" と
  書かれている。**実行するとロータが回り、磁気エンコーダの校正値が書き換わる。**
  失敗すればサーボとしての性能が落ちる。軸を完全にフリーにしてからでなければ実行しない。
  ベンダーのサンプルは `setOutput(0)` → `0xF1` → `0xF3` が 0 になるまで待つ → `0xF2` の順。
- **設定はフラッシュに書くまで揮発する。** `0xF0` に `1` を書くまで、電源断で消える。
- **`0x10` / `0x11` は CAN 側の設定であって I2C には影響しない。** I2C アドレスは `0xFF`。
  **`0x11` に書くと CAN のボーレートが変わる**ので、CAN 側で通信中のノードがあれば
  そこから切り離される。U182 のつもりで「115200 にしよう」と `0` を書くと、
  このユニットでは 1Mbps になる。
- **アドレス変更は即時反映。** U182 / U188 を同じバスに複数繋ぐなら、1 台ずつ挿して
  `0xFF` を書き換えていく必要がある。
- **ライブラリは転送の成否を見ない。** `writeBytes()` は `endTransmission()` の戻り値を捨て、
  `readBytes()` は `requestFrom()` の戻り値を見ずに `read()` を回す。ユニットが応答しない場合、
  読み出しは `-1`（= `0xFF`）で埋まった値、つまり `-1` や `0xFFFFFFFF` として返る。
  **温度が −1 ℃、電圧が −0.01V のように見えたら、それは値ではなく通信失敗である。**
- **`getFirmwareVersion()` と `getI2CAddress()` はグローバルの `Wire.read()` を呼んでいる。**
  `Wire1` を渡していると別のバスから読む。

## 出典と確度

- レジスタのアドレスと意味: `M5Unit-Roller` ライブラリの `UnitRollerI2C` クラス
  （`collection/vendor/M5Unit-Roller` に commit 固定で取得）。
- 単位とスケール（1/100 RPM、1/100 mA、1/100 V、℃、PID の ×100000 / ×10000000 / ×100000）、
  値域、エラーコード `4`: ベンダーの RollerCAN 文書（CAN コマンドの定義部）と、
  Roller485 の I2C Protocol PDF の両方。同じ値になっている。
- 転送長・アクセス方向・バイト順: 同ライブラリのメソッド本体から起こした**推定**。
- U182 と U188 の差が `0x10` / `0x11` の意味だけであることは、`roller_bps_t` の enum
  （485 用と CAN 用の値が同じ 0/1/2 に重ねて定義されている）と、
  `UnitRollerI2C` にユニット判別の分岐が無いことによる。
- **未確認**: 実機のキャプチャがまだ無い（`observations/m5stack-mcu-u188/` は存在しない）。
- **未確認**: 位置レジスタ（`0x80` / `0x90`）の物理単位。どちらの vendor 文書も書いていない。
- **未確認**: CAN と I2C の「自動切り替え」の実体。Grove の 5V だけでモータを定格どおり
  回せるか。いずれも製品ページの記述から読み取れない。
- **未確認**: 位置カウンタが電源を跨いで保持されるか。`0xFE` で U182 / U188 を区別できるか。
- **未調査**: 書き込み側の挙動全般。probe が read-only なので、出力・モード・目標値・
  フラッシュ保存・角度校正のいずれも実機では触っていない。モータが回る書き込みの確認は、
  可動部の安全を確保したうえで別 scenario として起こす（[docs/VERIFY.ja.md](https://github.com/tanakamasayuki/I2CDeviceDB/blob/38f1d82/docs/VERIFY.ja.md)）。
