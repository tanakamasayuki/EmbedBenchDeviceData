# Unit 8Encoder (U153) — 8 チャンネル ロータリーエンコーダ入力ユニット

> 押し込みスイッチ付きのロータリーエンコーダを 8 本、トグルスイッチを 1 個、RGB LED を 9 個
> まとめて I2C 1 本で扱えるユニット。カウンタは 32bit で、絶対値と「前回読んでからの差分」の
> 両方が取れる。
>
> **確度**: M5Stack が 8Encoder I2C Protocol という PDF（**V2 firmware 向け、2024-05-22**）を公開
> しており、レジスタの配置・ストライド・読み取りクリアの有無はそこに書かれている。ただし
> `profiles/` に入っているマップは **`M5Unit-8Encoder` ライブラリのソースから起こした推定**
> （`evidence: inferred / tentative`）で、実測では未確認。**ライブラリは PDF より古く、PDF にある
> レジスタのいくつかを実装していない**（後述）。

## これは何か

30mm ピッチほどで並んだ 8 本のロータリーエンコーダ（各軸に押し込みスイッチ付き）、トグル
スイッチ 1 個、WS2812C-2020 の RGB LED 9 個を、STM32F030C8T6 に載せた M5Stack ファームウェアが
束ねているユニット。**ホストから見える I2C の相手は STM32 であって、エンコーダでも LED でもない。**
つまりレジスタマップはこの製品固有のものである。

本体は 128.0 × 24.0 × 25.0 mm、43.9g の細長い基板。5V 入力で、基板上で 3.3V に降圧している。
押し込みの寿命は 5 万回以上（製品ページ）。ミキサーのフェーダ列のように、複数のパラメータを
同時に手で調整する用途を想定した形状である。

できること:

- **8 本の 32bit カウンタ**を読める。**書き込んで任意の値にプリセットもできる。**
- **8 本の増分（前回読んでからの差分）**を読める。UI のスクロール操作向き。
- **チャンネルごとのカウンタリセット**ができる。
- **8 個の押し込みスイッチ**と**トグルスイッチ 1 個**を読める。
- **LED 9 個の色**を、1 個ずつでも全部まとめてでも指定できる（エンコーダ 8 本ぶん + トグル
  スイッチ用に 1 個）。
- **I2C アドレスを変更できる**（読み返しもできる）。
- V2 ファームなら、**ボタンのトグル回数**と、**どのチャンネルが動いたかのビットマスク**も読める
  （ライブラリは未対応、後述）。

できないこと・持っていないもの:

- **割り込み線は無い。** どのつまみが動いたかを知るにもポーリングが要る（ただし V2 ファームの
  変化フラグ `0x61` を使えば 1 バイトの読み出しで済む）。
- **回転の速度・加速度は返らない。** 必要ならホスト側で時間差から求める。
- **エンコーダの分解能（1 回転あたりのパルス数）が資料に無い。** 製品ページにも PDF にも記載が
  無く、**未確認**。
- **押し込みの長押し判定が無い。** 短押し・長押しを区別するのはホストの仕事。
- **カウンタの上下限を設定するレジスタが無い。** `int32` の範囲でラップする。
- **LED の輝度を個別に落とす仕組みが無い。** 暗くしたければ色の値を下げる。

| 電源 | 5V（Grove の赤）。基板上で 3.3V に降圧 |
| インタフェース | Grove HY2.0-4P |
| I2C 速度 | ライブラリの既定は 100kHz の**つもり**だが不具合で壊れている（後述）。上限は未実測 |
| 中身 | STM32F030C8T6 + ロータリーエンコーダ ×8（押し込み付き） + トグルスイッチ ×1 + WS2812C-2020 ×9 |
| 寸法 | 128.0 × 24.0 × 25.0 mm、43.9g |
| 割り込み | 無し（ポーリング） |
| バイト順 | 32bit の値は **LSB first**（下位バイトが先） |

## レジスタ

各行は「1 チャンネルぶん」ではなく**連続したブロック**である。ヘッダにはブロックの先頭アドレス
しか定義されておらず、ストライド（1 チャンネルあたりの幅）はメソッド本体の
`base + index * 幅` という式から起こしたものである。

| アドレス | 長さ | R/W | 意味 |
|---|---|---|---|
| `0x00` | 32 | R/W | **カウンタ 8 本。** ch n は `0x00 + n*4`。**符号付き 32bit、LSB first**。単位はカウント（物理量の単位は資料に**無い**）。範囲 -2147483648〜2147483647。書き込むとその値にプリセットされる。`0x40` へのリセット書き込みでも 0 に戻る |
| `0x20` | 32 | R | **増分 8 本。** ch n は `0x20 + n*4`。**符号付き 32bit、LSB first**。前回読んでからの差分。**読むとクリアされる** |
| `0x40` | 8 | W | **カウンタリセット。** ch n は `0x40 + n`。`1` を書くとそのチャンネルのカウンタが 0 になる |
| `0x50` | 8 | R | **押し込みスイッチ 8 個。** ch n は `0x50 + n`。値は 0 か 1。**極性は要注意**（後述） |
| `0x58` | 8 | R/W | **（V2 ファーム）ボタンのトグル回数。** ch n は `0x58 + n`。**読むとクリアされる**。**ライブラリは触らず、`profiles/` にも入っていない** |
| `0x60` | 1 | R | トグルスイッチの状態。0 か 1 |
| `0x61` | 1 | R | **（V2 ファーム）エンコーダ変化フラグ。** bit n が ch n（`0` = 変化なし、`1` = 変化あり）。**読むとクリアされる**。**ライブラリは触らず、`profiles/` にも入っていない** |
| `0x62` | 1 | R | **（V2 ファーム）押し込みスイッチ 8 個を 1 バイトにまとめたもの。** bit n が ch n。**`0` = 押下、`1` = 非押下**。**ライブラリは触らず、`profiles/` にも入っていない** |
| `0x70` | 27 | R/W | **RGB LED 9 個。** LED n は `0x70 + n*3`、**R, G, B の順**、各 0〜255。LED0〜7 がエンコーダ、**LED8 がトグルスイッチ用**。`0x70`〜`0x8A` を占める |
| `0xFE` | 1 | R | ファームウェアのバージョン |
| `0xFF` | 1 | R/W | I2C アドレス。範囲 1〜127 |

**転送の形**: 書き込みは「ポインタバイト + ペイロード」を 1 トランザクションで送る。読み出しは
ポインタバイトを書いて **いったん STOP を出し**、それから `requestFrom` でデータフェーズに入る。
**repeated START ではない。**

## 典型的な使い方

1. `0xFE` を読んでファームウェアのバージョンを確認する（疎通確認も兼ねる）。
2. UI のノブとして使うなら、`0x20 + n*4` を一定周期で読む（増分）。読むたびに 0 に戻るので、
   **読み落とすと回転量が失われる**。
3. 位置として扱うなら `0x00 + n*4` を読む（絶対値）。起点を決めたいときは `0x40 + n` に `1` を
   書いてリセットするか、`0x00 + n*4` に望みの値を 4 バイト（LSB first）で書く。
4. 押し込みは `0x50 + n`、トグルスイッチは `0x60`。極性は下記の注意を読むこと。
5. LED は `0x70 + n*3` に R, G, B の 3 バイト。全部同じ色にするなら `0x70` から 27 バイト。
6. V2 ファームなら、`0x61` を 1 バイト読んで動いたチャンネルだけ `0x20` を読む方がバス負荷が軽い。

## 利用上の注意

- **増分 `0x20` は読み取りで消費される。** 読んだ瞬間に内部カウンタがクリアされる設計なので、
  **2 か所から読むと片方が取りこぼす**。読む場所は 1 か所に決める。ベンダー PDF も
  `reset after get` と明記している。同じことが V2 の `0x58`（トグル回数）と `0x61`（変化フラグ）に
  も当てはまる。
- **押し込みスイッチの極性が食い違う可能性がある。** ベンダー PDF は 1 バイトにまとめた版
  （`0x62`）について **`0: press, 1: no press`**（アクティブ Low）と明記している。一方、
  チャンネルごとの `0x50` 台については `BNT: 0~1` としか書いておらず極性の明記が無い。同じ意味
  なら **`0` が押下**であり、ライブラリの `getButtonStatus()` は読んだバイトをそのまま `bool` に
  して返すので、**「押していないときに true」という逆の意味になる**。**未確認。** 実機で 1 回
  押して確かめるまでどちらとも言えない。
- **カウンタは書き込みでプリセットできる。** `0x00 + n*4` に 4 バイト（LSB first）。単にゼロに
  戻したいだけなら `0x40 + n` に 1 バイト書く方が短い。
- **32bit カウンタはラップする。** 飽和しない。差分を取るときは `int32_t` 同士で引き算すれば
  ラップをまたいでも正しい差になる。
- **LED は 9 個ある。** エンコーダは 8 本なのに LED は 9 個で、9 個目はトグルスイッチ用。
  `setAllLEDColor()` が 27 バイト書くのはこのためである。「8 本ぶん = 24 バイト」と思い込むと
  最後の 1 個が余る。
- **ライブラリの既知の不具合その 1: バス速度が壊れている。** `UNIT_8ENCODER` のメンバは
  `uint8_t _speed;` と宣言されているのに、`begin()` は `uint32_t speed = 100000L` を代入する。
  `100000 & 0xFF = 160` に切り詰められ、`Wire.begin(sda, scl, 160)` が呼ばれる。**既定のまま使うと
  意図した 100kHz にはならない。** Arduino コアが 160 をどう扱うかは **未確認**。速度を決めたい
  なら `begin()` の後に自分で `Wire.setClock()` を呼ぶ。（同じ不具合が `M5Unit-KMeterISO` にもある。）
- **ライブラリの既知の不具合その 2: グローバル `Wire` を読んでいる。** `getI2CAddress()` と
  `getFirmwareVersion()` は転送を自前で組む部分では `_wire` を使うのに、受信だけ
  `Wire.read()`（グローバルオブジェクト）を読んでいる。`Wire1` など既定以外のバスに繋いだ
  ときだけ壊れる。バス上に出る波形は変わらないので、これはライブラリのバグであって
  デバイスの仕様ではない。
- **ライブラリの既知の不具合その 3: `setLEDColor()` の未使用バイト。** 4 バイトのローカル配列を
  用意して 3 バイトしか送らない。バスに出るのは 3 バイトで正しく、実害は無い。
- **`profiles/` に載っていないレジスタがある。** `0x58`（ボタンのトグル回数）、`0x61`（エンコーダ
  変化フラグ）、`0x62`（押し込みの 1 バイト版）はベンダーの V2 プロトコル PDF にあるが、
  ライブラリが触らないので `profiles/` には入っていない。特に **`0x61` は「どのチャンネルが
  動いたか」を 1 バイトで取れる**ので、8 本を毎回ポーリングするより格段に軽い。使うなら PDF を
  直接見ること。
- **PDF は V2 ファーム、ライブラリは古い。** 手元の個体がどの世代かは `0xFE` で読めるが、
  **値と世代の対応表は資料に無い（未確認）**。V1 ファームに V2 のレジスタを投げたときの挙動も
  分からない。
- **アドレス変更は即時反映。** `0xFF` に書いた次のトランザクションはもう新アドレス宛に出さないと
  応答しない。不揮発かどうかは **未確認**。`0xFF` は読めるので、迷子になったら scan して見つけた
  アドレスで `0xFF` を読めば確認できる。
- **読み出しの合間に STOP が入る。** repeated START を前提にバスを解析していると、想定と違う
  波形に見える。マルチマスタ環境では STOP と次の START の間に他のマスタが割り込む余地がある。
- **本リポジトリの characterization probe は read-only。** カウンタのプリセット、リセット、LED、
  アドレス変更はすべて書き込みなので触っていない。

## 出典と確度

- レジスタのアドレス・ストライド・バイト順: `M5Unit-8Encoder` ライブラリのソース
  （`collection/vendor/M5Unit-8Encoder` に commit 固定で取得）から起こした**推定**。
  ベンダーの V2 プロトコル PDF とも突き合わせ、ブロックの配置（カウンタ `0x00`〜`0x1F`、
  増分 `0x20`〜`0x3F`、リセット `0x40`〜`0x47`、ボタン `0x50`〜`0x57`、LED `0x70`〜`0x8A`）と、
  増分が読み取りでクリアされることの一致を確認した。
- `0x58` / `0x61` / `0x62`: **ベンダー PDF にのみ存在**。ライブラリが触らないため `profiles/` には
  入っていない。本文の記述は PDF の注記そのままで、実装での裏取りは無い。
- 押し込みの極性: PDF が明記しているのは `0x62`（`0` = 押下）だけ。`0x50` 台の極性は
  **未確認**で、ライブラリの実装（反転しない）と矛盾する可能性がある。
- **未確認**: 実機のキャプチャがまだ無い。エンコーダの分解能、`0xFE` の値と firmware 世代の
  対応、アドレス変更が不揮発かどうか、V1 ファームで V2 レジスタを読んだときの応答、
  バス速度の上限は確かめられていない。
- **未調査**: 書き込み側（カウンタのプリセット、リセット、LED、アドレス変更）は probe が
  read-only のため触れていない。
