# BH1750FVI — 16bit 出力の環境光センサ（照度・lx 直読）

> フォトダイオード・積分アンプ・16bit AD 変換器を 1 チップにまとめた照度センサ。**レジスタは無く**、
> 1 バイトの命令を書いて、待って、2 バイト読むだけ。返るのは lx そのものではなく、
> **1.2 で割ると lx になる生カウント**である。
>
> **確度**: ROHM の datasheet に基づく。ただし ROHM は本品を生産終了して自社サイトから
> datasheet を削除しており（`fscdn.rohm.com/.../bh1750fvi-e.pdf` は 404）、残っているのは
> 販売店ホストのコピーだけである。**本ガイドのページ番号は Velleman がホストする
> [Rev.C（2010.04）](https://cdn.velleman.eu/downloads/29/infosheets/bh1750fvi-e_datasheet.pdf)（全 17 ページ）で確認した。**
> [`chips/bh1750.yaml`](../../chips/bh1750.yaml) はより新しい
> [Mouser ホストの Rev.D（2011.11）](https://www.mouser.com/datasheet/2/348/bh1750fvi-e-186247.pdf)も
> 記録しているが、そちらは本ガイド執筆時に参照していないので、ページ番号がずれる可能性がある。
> **ライブラリ実装から補った箇所は無い。** 実測での確認はしていない。

## これは何か

ROHM の 6 ピン（WSOF6I）環境光センサ IC。人間の目に近い分光感度（ピーク 560nm）を持つ
フォトダイオードの出力を積分し、内部で照度に換算して 16bit で返す。もともと携帯電話の
液晶バックライト自動調光向けに作られた部品で、**照度計としてそのまま使える出力**が出る
ことが特徴である。

できること:

- 1 lx 〜 65535 lx を読む（H-Resolution モード、1 lx 分解能）。
- 分解能とレスポンスを 3 段階から選ぶ: H-resolution2（0.5 lx / 約 120ms）、
  H-resolution（1 lx / 約 120ms）、L-resolution（4 lx / 約 16ms）。
- 連続測定と 1 回きりの測定（One Time）を選ぶ。One Time は測定後に自動でパワーダウンする。
- **測定時間レジスタ（MTreg）で感度を 0.45 倍〜3.68 倍に振る。** 光学窓の透過率を打ち消したり、
  暗所で 0.11 lx まで分解したりするのに使う。
- 50Hz / 60Hz の照明ノイズは積分時間で除去される（H モードの 120ms がそのために長い）。
- ADDR ピンで 2 通りのアドレスを選ぶ。

できないこと・持っていないもの:

- **レジスタが無い。** 読めるのは 16bit のデータレジスタ 1 つだけで、アドレス指定の手段が無い。
  設定値を読み返すこともできない（MTreg は書き込み専用）。
- **割り込み線が無い。** しきい値もアラートも無い。変化を知るにはポーリングする。
- **測定完了フラグが無い。** 「もう測り終わったか」を問い合わせる方法が無く、**時間で待つしかない**。
- **Hs モード（3.4MHz）が無い。** I2C は最大 400kHz。
- **色情報が出ない。** 照度（明るさ）だけで、色温度や RGB は分からない。
  それが要るなら `tcs34725` のようなカラーセンサを使う。
- 電源が 3.3V 系。VCC は 2.4V–3.6V で、**絶対最大定格が 4.5V**。5V を直接かけると壊れる。
- DVI ピン（I2C 基準電圧かつ非同期リセット）を正しく扱わないと動かない。ピンが 6 本しかない
  部品なのに 1 本がこれに割かれている。

## コマンド

`profiles/bh1750.yaml` の内容に、datasheet の測定時間と分解能を足したもの。
**書き込みは常に「1 バイトの命令コード」だけ**で、パラメータもレジスタアドレスも無い。

| key | コード | 二進 | 意味 | 測定時間 |
|---|---|---|---|---|
| `power-down` | `0x00` | `0000_0000` | 停止状態。**電源投入直後はこれ** | — |
| `power-on` | `0x01` | `0000_0001` | 測定命令待ちにする | — |
| `reset` | `0x07` | `0000_0111` | データレジスタを 0 にする。**Power Down 中は受け付けない** | — |
| `cont-hres` | `0x10` | `0001_0000` | 連続 H-resolution（1 lx） | typ 120ms / max 180ms |
| `cont-hres2` | `0x11` | `0001_0001` | 連続 H-resolution2（0.5 lx） | typ 120ms / max 180ms |
| `cont-lres` | `0x13` | `0001_0011` | 連続 L-resolution（4 lx） | typ 16ms / max 24ms |
| `onetime-hres` | `0x20` | `0010_0000` | 1 回 H-resolution。**測定後に自動 Power Down** | typ 120ms / max 180ms |
| `onetime-hres2` | `0x21` | `0010_0001` | 1 回 H-resolution2。自動 Power Down | typ 120ms / max 180ms |
| `onetime-lres` | `0x23` | `0010_0011` | 1 回 L-resolution。自動 Power Down | typ 16ms / max 24ms |
| （MTreg 上位） | `0x40`+ | `01000_MT[7:5]` | 測定時間レジスタの上位 3bit | — |
| （MTreg 下位） | `0x60`+ | `011_MT[4:0]` | 測定時間レジスタの下位 5bit | — |

**表に無いコードは送ってはいけない**（datasheet p.5 の注記）。

### 転送の形

- **書き込み**: `START` → アドレス+W → 命令バイト → `STOP`。
  **STOP を挟まずに複数の命令を続けて送ることはできない**（datasheet p.10「4) Write Format」）。
  1 命令ごとに STOP を打つ。
- **読み出し**: `START` → アドレス+R → High Byte → Low Byte → `STOP`。
  **レジスタアドレスの指定は無い**。読めば必ずデータレジスタが返る。

### MTreg（測定時間レジスタ、書き込みのみ）

- 既定値 69（`0100_0101`）。変更範囲は 31（`0001_1111`）〜 254（`1111_1110`）。
- 上位 3bit と下位 5bit を**別々の命令で 2 回に分けて書く**。
- 感度は MTreg に比例する。31 で既定の 0.45 倍、254 で 3.68 倍。
- **測定時間も比例して伸びる。** MTreg を 2 倍にすると H モードの待ち時間も 2 倍（約 240ms）になる。
- 1 カウントあたりの照度:

```
H-resolution  : lx/count = (1 / 1.2) × (69 / MTreg)
H-resolution2 : lx/count = (1 / 1.2) × (69 / MTreg) / 2
```

| MTreg | H-res の lx/count | H-res2 の lx/count |
|---|---|---|
| 31（最小） | 1.85 | 0.93 |
| 69（既定） | 0.83 | 0.42 |
| 254（最大） | 0.23 | 0.11 |

## 典型的な使い方

1. **アドレスを確認する。** ADDR ピンが L なら `0x23`、H なら `0x5C`。Unit DLight は `0x23`。
2. **（必要なら）Power On を送る。** `0x01` を 1 バイト書いて STOP。
   datasheet の測定手順図は「Power On コマンドは省略可能」と注記している（p.4）ので、
   いきなり測定命令を送ってもよい。
3. **測定命令を 1 バイト書く。** 例: One Time H-resolution なら `0x20`。
4. **待つ。** H 系なら **max 180ms**、L 系なら **max 24ms**。
   完了を問い合わせる手段が無いので、最悪値で待つのが安全である。
   連続モードでも「最初の 1 回目」は同じだけ待つ必要がある。
5. **2 バイト読む。** High Byte が上位 8bit、Low Byte が下位 8bit。
6. **1.2 で割る。** `lx = raw / 1.2`。MTreg を変えているなら上の式で係数を作る。
   H-resolution2 ではさらに 2 で割る（ビット位置が半段ずれているため）。
7. 連続モードなら 5–6 を繰り返す。**One Time モードは測定後に自動でパワーダウンする**ので、
   値を更新するには毎回 3 から繰り返す。

## 利用上の注意

- **生値をそのまま lx と呼ばない。** `raw / 1.2` が lx である。割り忘れると常に 20% 高く出る。
  この 1.2 は「測定精度」の typ 値であって、min 0.96 / max 1.44 の幅がある。
  **±20% は個体ばらつきで、校正しない限り消えない。**
- **完了フラグが無いので時間で待つしかない。** typ 120ms で読みに行くと、遅い個体では
  前回の値が返る。datasheet の測定例も「max 180ms 待て」と書いている（p.7）。
- **One Time モードは 1 回で終わる。** 測定後に自動で Power Down に落ちる。
  読み続けても同じ値が返る。更新したければ測定命令を再送する。
- **命令の連投はできない。** STOP を挟まずに 2 バイト書くと受け付けられない。
  MTreg の設定が「上位」「下位」の 2 命令に分かれているのはこのためで、
  `Wire.write()` を 2 回続けてから 1 回 `endTransmission()` する書き方では動かない。
- **`reset`（`0x07`）は Power Down 中は効かない。** 先に Power On を送る。
  またこれはデータレジスタを 0 にするだけで、MTreg や動作モードは戻らない。
- **本当のリセットは DVI ピン。** DVI は I2C の基準電圧端子であると同時に非同期リセット端子で、
  **VCC 投入後に 1µs 以上 Low にする**必要がある（datasheet p.6）。これを守らないと
  内部状態が不定になり、さらに **DVI が Low の間は ADDR / SDA / SCL が安定しない**。
  ADDR を VCC / GND に直結せず 100kΩ 程度を介せ、という指示もここにある。
  モジュール（Unit DLight など）ではこの回路は基板側で処理されているので、
  ホストのソフトから触ることはない。ただし「電源を入れ直しても直らない」不調があったら
  ここを疑う。
- **MTreg を変えたら待ち時間も変える。** MTreg 69 → 138 なら H モードの測定時間は
  120ms → 240ms になる。感度だけ上げて待ち時間を据え置くと、古い値を読む。
- **5V をかけない。** 絶対最大定格 4.5V。3.3V 系のバスに繋ぐこと。
- **暗所では H-resolution か H-resolution2 を使う。** L-resolution は 4 lx 刻みなので、
  10 lx 以下では意味のある値にならない。datasheet も 10 lx 未満なら H 系を使えと書いている。
- **400kHz が上限。** ADS111x のような Hs モードは無い。
  `scenarios/bh1750/p0.yaml` は 100kHz と 400kHz の両方を試す設定になっているが、未実測。
- **アドレス衝突。** 本リポジトリ内では `0x23` は `pca9554`（I/O エキスパンダ、`0x20`–`0x27`）と
  重なり、`0x5C` は `dht12` と `gp8413` が名乗り得る。ADDR ピンで逃げられるのは 2 択だけなので、
  逃げ場が少ない。
- **光学窓の影響は MTreg で補正する設計。** ケースの窓越しに使うと透過率のぶん暗く出るので、
  透過率 50% なら MTreg を 2 倍にする、という使い方を datasheet が想定している（p.11）。
  **この補正値は筐体ごとに違う**ので、チップ側の仕様として持ち歩けるものではない。

- 命令コード・測定時間・換算式・MTreg・電気的特性・DVI の扱い: すべて ROHM datasheet
  BH1750FVI Rev.C（2010.04）。
- [`profiles/bh1750.yaml`](https://github.com/tanakamasayuki/I2CDeviceDB/blob/38f1d82/profiles/bh1750.yaml) は `evidence.source: datasheet` /

  `command_width_bits: 8` は上記 p.10 の Read Format / Write Format の記述そのもの。
- **版のずれ**: [`chips/bh1750.yaml`](../../chips/bh1750.yaml) は Mouser がホストする
  Rev.D（2011.11）を第一の datasheet として記録しているが、**本ガイドは Rev.C（2010.04）で
  確認した**。Rev.C → Rev.D の差分は確認していないので、ページ番号と細かな規格値は
  Rev.D と一致しない可能性がある。ROHM 本体はこの部品を生産終了し、
  自社サイトから datasheet を削除している。
- **未確認**: 実機キャプチャが無い。命令の連投が本当に拒否されるか、One Time モードの
  自動パワーダウン後にどんな値が返るか、400kHz での動作は確かめられていない。
- **未調査**: [`scenarios/bh1750/p0.yaml`](https://github.com/tanakamasayuki/I2CDeviceDB/blob/38f1d82/scenarios/bh1750/p0.yaml) は
  `safety: reversible-write` で、device-detection / power-on / one-time-measurement /
  power-down しか行わない。連続モード・MTreg の書き換え・H-resolution2 は `deferred`。
- **datasheet が答えていないこと**:
  - Unit DLight の光学窓の透過率。MTreg をいくつにすれば筐体の影響が消えるかは
