# MAX30100 — パルスオキシメータ / 心拍センサ

> 赤色 LED と赤外 LED、フォトダイオード、16bit ADC を 1 パッケージに収めた光学式の
> 脈波センサ。返すのは**光量の生カウント**であって、心拍数でも SpO2 でもない。
> **SpO2 モードにすると LED が点灯し、電流が桁違いに増える。**
>
> **確度**: Maxim Integrated の datasheet **Rev 0（2014-09）、全 29 ページ**に基づく。
> `chips/max30100.yaml` が記録している analog.com の URL は 2026-08-15 時点で取得できず
> （TLS 層で自動取得が拒否される）、**M5Stack がミラーしている同一版の PDF** を取得して読んだ。
> 版（Rev 0 / 2014-09）はカタログの記録と一致している。実機のキャプチャは無い。

## これは何か

指を当てて、赤色（660 nm）と赤外（880 nm）の光を交互に当て、透過/反射してきた光量を
16bit の ADC で測り続ける IC。血液の吸光度が心拍に合わせて変動するので、その波形から
ホスト側のソフトウェアが心拍数や血中酸素飽和度を**計算する**。

できること:

- HR モード（IR のみ）と SpO2 モード（IR + 赤）の 2 つ。`0x06` の `MODE[2:0]` で選ぶ
  （`010` = HR、`011` = SpO2、p15, Table 3）。
- サンプルレート 50 / 100 / 167 / 200 / 400 / 600 / 800 / 1000 sps（p16, Table 4）。
- LED パルス幅 200 / 400 / 800 / 1600 µs。これが ADC の積分時間になり、
  分解能 13 / 14 / 15 / 16bit に対応する（p17, Table 5）。
- LED 電流を赤外・赤それぞれ 16 段で設定（0.0〜50.0 mA、p17, Table 6）。
- 16 サンプル分の FIFO（1 サンプル = IR 2 バイト + 赤 2 バイト = 4 バイト、計 64 バイト）。
- ダイ温度を 1/16 ℃ 刻みで読める（`0x16`/`0x17`）。SpO2 の補正に使う想定。
- 環境光除去回路を内蔵。直射日光（100k lux）下でも指を当てた状態のカウント寄与は 0 と
  規定されている（p2）。
- オープンドレインの割り込みピン（アクティブ Low）。

**できないこと・持っていないもの**:

- **心拍数を返さない。SpO2 も返さない。** 出てくるのは IR と赤の ADC カウントだけである。
  ピーク検出、ノイズ除去、比の計算、キャリブレーション曲線の当てはめは、
  すべてホスト側のソフトウェアの仕事。「読めば bpm が出る」センサではない。
- **医療機器ではない。** datasheet に較正曲線も精度規定も無い。SpO2 の絶対値を出すには
  自前で人体基準に対する較正が必要で、それは datasheet の範囲外である。
- **血圧・血糖・体温（体表温）は測れない。** 温度レジスタが返すのは**ダイの温度**で、
  しかも LED の発熱で最大 8 ℃ 押し上げられる（p21, Table 14）。
- **動きに弱い。** 指が動けば波形は壊れる。datasheet は「高 SNR がモーションアーチファクト
  耐性を与える」と書いているが、加速度計との併用のような外部の助けは無い。
- **アドレスを変えられない。** `0x57` 固定。同じバスに 2 個は置けない。
- **後継とレジスタ互換ではない。** MAX30102 は別のレジスタマップを持つ。混同しない。

**電気的な現実**:

- **VDD は 1.7〜2.0 V**（typ 1.8 V）。絶対最大定格でも 2.2 V（p2）。
  **3.3 V を掛けたら壊れる。** M5Stack Unit Heart の Grove 赤線は 5 V なので、
  ユニット基板上で 1.8 V まで落としている。
- **LED 側の電源は別系統**で 3.1〜5.0 V（`R_LED+` / `IR_LED+`）。ここに 5 V が来る。
- SDA / SCL / INT の絶対最大定格は 6.0 V で、`VIH` は 1.4 V（p4）。
  つまり **3.3 V ロジックのバスにそのまま繋げる**。プルアップ先は 3.3 V でよい。
- IDD 自体は小さい（SpO2 モード、200 µs / 50 sps で typ 600 µA、p2）が、
  **LED 電流はそこに含まれない**。後述。

## レジスタ

全体は datasheet p10 の Table 1。

| アドレス | 名前 | R/W | POR 値 | 意味 |
|---|---|---|---|---|
| `0x00` | Interrupt Status | R | `0x00` | `A_FULL`(b7) / `TEMP_RDY`(b6) / `HR_RDY`(b5) / `SPO2_RDY`(b4) / `PWR_RDY`(b0)。**読むと消える** |
| `0x01` | Interrupt Enable | R/W | `0x00` | 上位 4 ビットが対応する割り込みの許可。**`PWR_RDY` は禁止できない** |
| `0x02` | FIFO Write Pointer | R/W | `0x00` | 4bit |
| `0x03` | Overflow Counter | R/W | `0x00` | 4bit。取りこぼしたサンプル数。`0xF` で飽和 |
| `0x04` | FIFO Read Pointer | R/W | `0x00` | 4bit |
| `0x05` | FIFO Data | R/W | `0x00` | **読んでもアドレスが進まない**（後述） |
| `0x06` | Mode Configuration | R/W | `0x00` | `SHDN`(b7) / `RESET`(b6) / `TEMP_EN`(b3) / `MODE[2:0]` |
| `0x07` | SpO2 Configuration | R/W | `0x00` | `SPO2_HI_RES_EN`(b6) / `SPO2_SR[2:0]`(b4:2) / `LED_PW[1:0]`(b1:0) |
| `0x09` | LED Configuration | R/W | `0x00` | `RED_PA[3:0]`(b7:4) / `IR_PA[3:0]`(b3:0) |
| `0x16` | Temp Integer | R/W | `0x00` | 整数部、2 の補数、1 ℃/LSB |
| `0x17` | Temp Fraction | R/W | `0x00` | 小数部、下位 4bit、0.0625 ℃/LSB |
| `0xFE` | Revision ID | R | 個体依存 | ロットごとに違う。**識別には使えない** |
| `0xFF` | Part ID | R | `0x11` | 固定 |

`0x08`、`0x0A`〜`0x15`、`0x8D` は Reserved。

**MODE[2:0]**（`0x06`、p15, Table 3）: `010` = HR のみ、`011` = SpO2。
`000` は Unused、`001` は "Reserved (Do not use)"、`100`〜`111` は Unused。

**SPO2_SR[2:0]**（`0x07`、p16, Table 4）: `000`=50、`001`=100、`010`=167、`011`=200、
`100`=400、`101`=600、`110`=800、`111`=1000 sps。

**LED_PW[1:0]**（`0x07`、p17, Table 5）: `00`=200 µs/13bit、`01`=400 µs/14bit、
`10`=800 µs/15bit、`11`=1600 µs/16bit。

**RED_PA / IR_PA**（`0x09`、p17, Table 6）: `0000`=0.0 mA から `1111`=50.0 mA まで
おおむね 3.3 mA 刻み。**実際の LED 電流は個体でかなりばらつく**と datasheet が明記している。

## 典型的な使い方

1. `0xFF`（Part ID）を読む。`0x11` が返れば MAX30100。
2. `0x06` の `RESET`（b6）に 1 を書いて既知の状態に戻す。`RESET` は完了すると自動で 0 に戻る。
3. **FIFO のポインタを 3 本とも 0 にする**（`0x02`、`0x03`、`0x04` に `0x00`）。
   datasheet が新しい測定を始める前の推奨手順として挙げている（p13）。
4. `0x07` にサンプルレートとパルス幅を書く。SpO2 なら `SPO2_HI_RES_EN`（b6）を立てる。
5. `0x09` に LED 電流を書く。**ここで初めて消費電流が跳ね上がる準備が整う。**
6. `0x01` で必要な割り込みを許可する（FIFO がほぼ満杯の `A_FULL` を使うのが普通）。
7. **`0x06` の `MODE[2:0]` に `011`（SpO2）または `010`（HR）を書く。ここから LED が点灯し、
   サンプリングが始まる。**
8. データを取り出す:
   - `0x02`（FIFO_WR_PTR）と `0x04`（FIFO_RD_PTR）を読み、差から未読サンプル数を求める。
   - `0x05` を **4 バイト × サンプル数**だけ読む。1 サンプル = IR 上位・IR 下位・赤上位・赤下位。
   - 読み終わったら `0x04` は自動で進んでいる。通信エラーで読み直したいときだけ
     `0x04` に書き戻す（p15）。
9. 温度が要るなら `0x06` の `TEMP_EN`（b3）に 1 を書き、変換完了（約 29 ms、p3）を待って
   `0x16` と `0x17` を読む。`TEMP_EN` は自動で 0 に戻る。
10. 止めるときは `0x06` の `SHDN`（b7）を立てる。設定は保持され、消費電流は 0.7 µA になる。

心拍数と SpO2 は、ここで得た波形をホスト側で処理して求める。

## 利用上の注意

- **SpO2 モードにした瞬間に LED が光り、電流が桁違いに増える。**
  IDD 自体は typ 600 µA〜1 mA 程度（p20, Table 10）だが、**LED 電流はそれとは別**である。
  - **ピーク電流**は設定次第で **1 個あたり最大 50 mA**（p17, Table 6）。SpO2 モードでは
    赤外と赤が交互に光るので、瞬間的にはどちらか一方の 50 mA が流れる。
  - **平均電流**は「パルス幅 × サンプルレート」で決まる。datasheet の p20 Table 11 は
    `R_PA = IR_PA = 0x3`（11.0 mA 設定）での平均 LED 電流を表にしており、
    200 µs/50 sps で 0.667 mA、**1600 µs/100 sps で 9.766 mA、200 µs/1000 sps で 12.17 mA**。
    これは 11 mA 設定での値なので、**最大の 50 mA 設定にすれば数倍**になる（未検証の外挿）。
  - つまり **「レジスタを 1 バイト書いたら数十 mA が流れ始める」** デバイスである。
    電池駆動やバスパワーで動かす場合、電源の余力とサーマルバジェットを先に確認すること。
  - 使い終わったら `SHDN` を立てる。**モードを設定したまま放置しない。**

- **LED の発熱がダイ温度に乗る。** 赤色 LED を 35 mA・デューティ 32 % で焚くと、
  温度センサの読みが **最大 8 ℃** 押し上げられる（p21, Table 14）。
  `0x16`/`0x17` を「環境温度」や「体温」として使ってはいけない。
  なお Table 14 は電流設定 `0001` を 3.1 mA、`1111` を 35 mA と書いており、
  **p17 の Table 6（`0001` = 4.4 mA、`1111` = 50.0 mA）と食い違っている**。
  datasheet 内の不整合なので、どちらの数字も概算として扱う。

- **`0x00`（Interrupt Status）は読むと消える。しかも消し方が 2 通りある。**
  - `0x00` を読むと、**すべてのビットが 0 になり**、INT ピンも解放される。
  - それとは別に、**割り込みを起こしたレジスタを読んでも消える**。たとえば `SPO2_RDY` と
    `HR_RDY` は FIFO データレジスタ（`0x05`）を読んだ時点で自動的に落ちる（p11）。
  - したがって **`0x00` は FIFO を読む前に読む**。順序を逆にすると、`SPO2_RDY` が
    落ちた後の状態しか見えない。
  - **2 か所から `0x00` を読むと片方が取りこぼす。** 読む場所は 1 か所に決める。

- **`PWR_RDY`（b0）は無効化できない。** ブラウンアウトで内部状態がリセットされたことを
  ホストに必ず知らせるための設計で、`0x01` で禁止できない（p12）。
  逆に言えば、**`PWR_RDY` が立っていたら設定が全部消えている**と考えるべきである。
  電源が不安定な配線では、これを検出して初期化をやり直す必要がある。

- **`0x05`（FIFO Data）はバースト読みでアドレスが進まない、という例外。**
  他のレジスタはバースト読みでアドレスが自動インクリメントするが、`0x05` だけは
  アドレスが固定されたまま `FIFO_RD_PTR` が進む（p12-13）。
  **これは仕様であって不具合ではない。** 1 サンプル 4 バイトなので、`0x05` を 4 回読んで
  1 サンプル。N サンプルなら 4N バイトを 1 回のバースト読みで取れる。
  「同じアドレスを読んでいるのだから同じ値が返るはず」と考えて 1 サンプルずつ
  トランザクションを分けると、遅くなるだけで結果は同じである。

- **`0xFF` の先はアドレスが `0x00` に戻らない。** `0xFF` を読んだ後にさらに読み続けても、
  ポインタは `0x00` に巻き戻らず、返るデータに意味は無い（p13）。
  「レジスタ全域をダンプする」ようなコードはここで嘘のデータを掴む。

- **FIFO は 16 サンプルしかない。** 1000 sps で回すと **16 ms で満杯**になる。
  溢れた分は捨てられ、`0x03`（Overflow Counter）が増える（`0xF` で飽和するので、
  16 個以上溢れたことは分からない）。`A_FULL` 割り込みは「残り 1 サンプル分」で立つので、
  そこから次の変換までに読み切らなければならない。ポーリングでやるなら、
  レートに見合った周期を確保すること。

- **FIFO のデータは左詰め（left-justified）。** パルス幅を短くして分解能が 13bit に
  なっても、MSB は常に bit15 にある（p13）。**右シフトして正規化する必要は無い**が、
  下位ビットが無効になるだけである。

- **HR モードでは各サンプルの 3・4 バイト目が 0 になる。** FIFO の構造は変わらないので、
  4 バイト読む必要は同じ（p13）。

- **`0xFE`（Revision ID）は個体・ロットで違う。** datasheet が「あなたの製品に
  割り当てられたリビジョン ID は Maxim に問い合わせよ」と書いている（p10 の脚注）。
  デバイス識別には `0xFF`（`0x11`）を使う。

- **`0x57` は本カタログ内で `rcwl-9600` と `rcwl-9620`（超音波距離センサ）と衝突する。**
  MAX30100 のアドレスは変えられないので、同じバスには置けない。

- **`MODE[2:0]` に `001` を書かない。** datasheet が "Reserved (Do not use)" と明記している。

- **VDD の上限が 2.0 V であることを忘れない。** 生の MAX30100 をブレッドボードで
  3.3 V に繋ぐと壊れる。市販のブレイクアウト基板や M5Stack Unit Heart には
  レギュレータが載っているが、それはモジュールの機能であってチップの機能ではない。
