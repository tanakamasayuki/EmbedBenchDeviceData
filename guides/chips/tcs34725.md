# TCS34725 — IR カットフィルタ付き RGBC カラーセンサ

> 赤・緑・青と「クリア（全可視光）」の 4 チャンネルを、それぞれ 16bit の ADC カウントとして
> 返す光センサ。**レジスタ番号をそのまま送っても何も起きない。** すべてのアクセスは
> **コマンドビット `0x80` を立てたバイト**から始める必要があり、色データのブロック読みでは
> さらに自動インクリメントを指定して `0xA0` を使う。
>
> **確度**: ams-OSRAM の TCS3472 datasheet v1-04（2020-04-10）に基づく。datasheet は
> TCS34721/23/25/27 の共通文書で、M5Stack Unit Color が使うのは TCS34725。
> **実測は未着手**で、`profiles/tcs34725.yaml` の evidence は `datasheet` / `tentative`、
> `observations/tcs34725/` はまだ無い。

## これは何か

4 個のフォトダイオード（R / G / B / クリア）と、それぞれに積分型 ADC を持つカラーセンサ。
**チップ上に IR カットフィルタが載っている**ので、白熱灯や日光のような赤外を多く含む光の
下でも色の比が崩れにくい。ここがフィルタ無しの安物カラーセンサとの決定的な差である。

4 チャンネルは**同時に積分される**（§Principles of Operation, p15）。積分が終わると 4 つの
16bit 値がまとめてデータレジスタに転送される。転送はダブルバッファされており、読んでいる
最中に更新されて値が混ざることはない。

**「クリア」チャンネルの役目**: R/G/B と同じ IR フィルタ越しに、可視光全体を測る。R/G/B を
そのまま使うと「暗い赤」と「明るい茶」の区別がつかないので、実務では **R/C, G/C, B/C の比**
に直して色味（クロマティシティ）として扱う。datasheet の光学特性表も、R/G/B の値を
**クリアチャンネルに対する比**として示している（Figure 8 の注記 1, p9）。また割り込みの
しきい値判定はクリアチャンネルの値だけを見る（§Interrupts, p16）。

**できること**:

- 積分時間を 2.4ms 〜 614ms の範囲で 2.4ms 刻みに設定（ATIME）。長いほど分解能と感度が上がる。
- アナログゲインを 1x / 4x / 16x / 60x から選択（AGAIN）。
- 測定と測定の間に待ち時間を入れて平均消費電流を下げる（WTIME、最大 7.4 秒）。
- クリアチャンネルに上下しきい値を設定して INT ピンに割り込みを出す。何回連続で外れたら
  出すかも設定できる（APERS）。
- ID レジスタで型番を確認できる（`0x44` = TCS34725）。**この catalog では珍しく、
  「本当にこのチップか」をバスから確かめられる。**

**できないこと・持っていないもの**:

- **色名も色温度も返さない。** 返るのは 4 本の生の ADC カウントだけ。CCT や Lux への
  換算はホスト側の計算で、しかもその係数は datasheet に無い（ams のアプリケーション
  ノート側の話）。
- **I2C アドレスを変えられない。** `0x29` 固定で、アドレス選択ピンが無い（Ordering
  Information, p35）。同じバスに 2 個は繋がらない。TCA9548A のようなバススイッチが要る。
- **照明を持たない。** 6 ピンの FN パッケージは VDD / SCL / GND / NC / INT / SDA だけで
  （Figure 4, p6）、LED を駆動する端子が無い。モジュールに白色 LED が載っていても、
  それは基板側の回路であってこの IC が I2C 経由で点けるものではない。Unit Color の
  配線がどうなっているかは**本ガイドでは未確認**。
- **視野を絞る機構が無い。** レンズも絞りも無いので、測る対象は近づける必要がある。
- 温度センサを持たない。温度による感度変化は補正されない。

**電気的な現実**:

- VDD 2.7–3.6V（TCS34725、Figure 6, p8）。絶対最大 3.8V。**5V を直結してはいけない。**
  I2C のロジックレベルは VDD 基準（VIH = 0.7×VDD）で、Unit として使う分には基板上で
  レギュレートされている。
- 消費電流は動作時 typ 235uA / max 330uA、待機（Wait state）65uA、スリープ 2.5uA
  （Figure 7, p8）。
- I2C は標準モードと Fast モードの両方に対応し、SCL は 0–400kHz（p20 の I²C Protocol、
  および f(SCL) の規定）。
- INT はオープンドレインでアクティブ Low（Figure 4, p6）。使うならプルアップが要る。

## レジスタ・コマンド

### コマンドバイト — ここを間違えると何も読めない

I2C トランザクションの先頭に書くバイトは**レジスタ番号ではなくコマンドバイト**である
（Figure 25 Command Register, p22）。

| ビット | 名前 | 意味 |
|---|---|---|
| 7 | CMD | **必ず 1。**「これはコマンドレジスタへの書き込みである」の意 |
| 6:5 | TYPE | `00` = 同じレジスタを繰り返す / `01` = **自動インクリメント** / `10` 予約 / `11` 特殊機能 |
| 4:0 | ADDR/SF | レジスタアドレス（5bit）または特殊機能コード |

したがって実際に送るバイトは:

| やりたいこと | 送るバイト | 計算 |
|---|---|---|
| ENABLE (`0x00`) を書く | `0x80` | `0x80 \| 0x00` |
| ID (`0x12`) を読む | `0x92` | `0x80 \| 0x12` |
| STATUS (`0x13`) を読む | `0x93` | `0x80 \| 0x13` |
| CONTROL (`0x0F`) を書く | `0x8F` | `0x80 \| 0x0F` |
| **色データ 8 バイトを一気に読む** | `0xB4` | `0xA0 \| 0x14`（`0xA0` = CMD + 自動インクリメント） |
| 割り込みをクリア | `0xE6` | `0x80 \| 0x60 \| 0x06`（TYPE=`11` 特殊機能、SF=`00110`） |

**`0x14` を裸で送っても、CMD ビットが立っていないので狙ったレジスタは選ばれない。**
これがこのチップで最初につまずく点である。

TYPE = `00`（つまり `0x80 | reg`）で 2 バイト読むと、**同じレジスタを 2 回読む**ことになる
（Figure 25 の説明、p22）。16bit 値を正しく取るには `0xA0` 側を使う必要がある。

### レジスタ一覧（Figure 24, p21）

| アドレス | 名前 | R/W | リセット値 | 意味 |
|---|---|---|---|---|
| `0x00` | ENABLE | R/W | `0x00` | b0 PON（発振器 ON）/ b1 AEN（RGBC ADC 有効）/ b3 WEN（待ち有効）/ b4 AIEN（割り込み許可） |
| `0x01` | ATIME | R/W | `0xFF` | 積分時間（2 の補数）。`0xFF` = 2.4ms、`0x00` = 614ms |
| `0x03` | WTIME | R/W | `0xFF` | 待ち時間。WLONG で 12 倍になる |
| `0x04`-`0x05` | AILTL/H | R/W | `0x00` | クリアチャンネル下限しきい値（16bit、下位が先） |
| `0x06`-`0x07` | AIHTL/H | R/W | `0x00` | クリアチャンネル上限しきい値（16bit、下位が先） |
| `0x0C` | PERS | R/W | `0x00` | 何回連続で範囲外になったら割り込むか（APERS） |
| `0x0D` | CONFIG | R/W | `0x00` | WLONG（待ち時間 12 倍） |
| `0x0F` | CONTROL | R/W | `0x00` | AGAIN（b1:0）= `00` 1x / `01` 4x / `10` 16x / `11` 60x |
| `0x12` | ID | R | — | `0x44` = TCS34725 / `0x4D` = TCS34727 |
| `0x13` | STATUS | R | `0x00` | b0 AVALID（積分完了）/ b4 AINT（割り込み発生中） |
| `0x14`-`0x15` | CDATAL/H | R | `0x00` | クリアチャンネル、16bit、**下位バイトが先** |
| `0x16`-`0x17` | RDATAL/H | R | `0x00` | 赤 |
| `0x18`-`0x19` | GDATAL/H | R | `0x00` | 緑 |
| `0x1A`-`0x1B` | BDATAL/H | R | `0x00` | 青 |

**バイト順**: 色データは 16bit のリトルエンディアン（下位バイトが低いアドレス）。
`0xB4` で 8 バイト連続読みすると `C_lo C_hi R_lo R_hi G_lo G_hi B_lo B_hi` の順に返る。

**16bit 値のシャドウレジスタ**: 下位バイトを読んだ瞬間に上位 8bit がシャドウレジスタへ
退避される（p29）。だから下位と上位を読む間に積分サイクルが終わっても、上位は
「下位と同じ時刻の値」を返す。**逆に言うと、下位と上位を別々のトランザクションで読むと
この保証が働かない可能性がある。**

### 積分時間とゲイン

- 積分時間 = 2.4ms × (256 − ATIME)（§RGBC Operation, p16）。例: 100ms が欲しければ
  256 − (100 / 2.4) = 214 = `0xD6`。
- そのときの最大カウント = (256 − ATIME) × 1024、ただし 65535 で頭打ち（p24）。つまり
  **ATIME が `0xC0`（154ms）より長くても、ADC のフルスケールはもう 65535 のまま**である。
- ゲインは積分の前段（アナログ）に効く。暗いところではゲインを上げ、明るいところでは
  下げる。**両方を上げすぎるとクリアチャンネルが先に飽和する**ので、まずクリアが
  65535 に張り付いていないかを見る。

## 典型的な使い方

1. `0x92`（= `0x80 | 0x12`）を書いて 1 バイト読み、ID が `0x44` であることを確認する。
   通信の疎通確認も兼ねる。
2. `0x81`（ATIME）に積分時間を書く。まずは `0xEB`（= 50ms 相当、256−0xEB = 21 → 50.4ms）
   あたりが扱いやすい。
3. `0x8F`（CONTROL）にゲインを書く。屋内なら `0x01`（4x）か `0x02`（16x）から始める。
4. `0x80`（ENABLE）に `0x01` を書いて **PON だけを立てる**。
5. **2.4ms 以上待つ。** datasheet は「PON をアサートしてから RGBC を開始するまでに最低
   2.4ms 空けなければならない」と明記している（Enable Register の注記 2, p23）。
6. `0x80` に `0x03` を書いて **PON + AEN** にする。ここで初めて ADC が回り始める。
7. 積分時間が経過するのを待つ。あるいは `0x93`（STATUS）を読んで **AVALID（b0）が 1** に
   なるのを待つ。
8. `0xB4` を書いて 8 バイト読む。C, R, G, B が 16bit リトルエンディアンで並んでいる。
9. 色として使うなら R/C, G/C, B/C の比に直す。C が 0 のとき（真っ暗）はゼロ除算に注意。
10. 止めるときは ENABLE に `0x00` を書く。スリープに落ちて 2.5uA になる。

## 利用上の注意

- **コマンドビット `0x80` を忘れると読めない。** 最も多い失敗。`0x14` を送って 8 バイト
  読もうとして全部おかしい、という症状はまずこれ。**自動インクリメントが要る読み出しでは
  `0x80` ではなく `0xA0` を使う**（`0xA0 | 0x14 = 0xB4`）。`0x80 | 0x14 = 0x94` で 2 バイト
  読むと、datasheet の定義上は同じレジスタが 2 回返る。
- **リセット直後は PON も AEN もクリアされていて、色データは全部 0 になる。**
  ENABLE のリセット値は `0x00`（Figure 24, p21）。**これは壊れた個体ではない。**
  電源を入れただけのチップは Sleep 状態で、I2C の START を検知して Idle に上がるものの、
  PON が 0 なら再び Sleep に戻る（§System States, p14）。ID レジスタだけは読めるのに
  `0x14`〜`0x1B` が全部 0、という状態が正常な初期状態である。
- **PON の後 2.4ms の待ちは必須**（p23 注記 2）。詰めると最初の測定値が信用できない。
- **AVALID を見ずに読むと、積分の途中の値ではなく「前回の値」または初期値 0 を読む。**
  STATUS (`0x93`) の b0 を確認するか、積分時間だけ確実に待つ。
- **`0x29` は VL53L0X / VL53L1X と同じアドレス。** この catalog で `0x29` を名乗るのは
  `tcs34725`、`vl53l0x`、`vl53l1x` の 3 つ。**Unit Color と Unit ToF を同じ I2C バスに
  直結すると必ず衝突する。** 逃げ道は 2 つ:
  - VL53 系は**アドレスをソフトウェアで変更できる**（VL53L0X はレジスタ `0x8A`）。
    XSHUT で 1 個ずつ立ち上げて番号を振り直す。
  - TCS34725 側は変更できないので、**動かすなら VL53 のほう**。あるいは TCA9548A の
    別チャンネルに分ける。
- **ID レジスタは「TCS34725 か TCS34727 か」しか区別しない。** `0x44` が返ったからといって
  正規品とは限らないが、少なくとも「そこに居るのが VL53L0X ではない」ことは分かる
  （VL53L0X の `0xC0` は `0xEE` を返す）。アドレス衝突の切り分けに使える。
- **クリアチャンネルの飽和を先に疑う。** 明るい場所でゲインを上げたままだと C が 65535 に
  張り付き、R/C・G/C・B/C の比が意味を失う。R/G/B だけ見ていると気づきにくい。
- **積分時間を伸ばしてもフルスケールは 65535 で頭打ち。** ATIME `0xC0`（154ms）を超えて
  伸ばしても、最大カウントは増えない（p24 の表）。伸ばす意味はノイズ平均化のほうにある。
- **割り込みしきい値はクリアチャンネルにしか効かない**（§Interrupts, p16）。「赤が増えたら
  割り込む」はできない。
- **しきい値は下限→上限の順に評価される。** 下限を上限より上に設定すると、上限は無視されて
  下限だけが評価される（p16）。設定ミスが黙って通ってしまう。
- **割り込みは read で自動的には消えない。** クリアするには特殊機能コマンド `0xE6` を
  送る（Figure 25 の SF = `00110`、p22）。これは self-clearing。
- **5V を掛けない。** 絶対最大が 3.8V（Figure 5, p7）。Grove の赤線は 5V なので、
  Unit の外で裸のチップを扱うときは要注意。
- **400kHz は datasheet の規定内**（f(SCL) 0–400kHz）だが、**実測は未確認。**

## 出典と確度

- 参照した文書: **ams-OSRAM TCS3472 datasheet v1-04（2020-04-10）**、
  `look.ams-osram.com` の公式配布。`chips/tcs34725.yaml` にはもう 1 本、M5Stack がホストする
  v1-03（2018-03）も登録されているが、本ガイドは v1-04 を読んで書いた。
- **この datasheet は TCS3472 ファミリ（TCS34721 / 23 / 25 / 27）の共通文書**である。
  型番ごとの差は I2C のバス電圧（TCS34725 は VBUS = VDD、TCS34727 は 1.8V）と ID 値、
  パッケージのみ。M5Stack Unit Color が使うのは TCS34725。
- コマンドビット `0x80`、TYPE フィールド、`0xA0` による自動インクリメント、特殊機能 `0xE6`、
  レジスタ一覧とリセット値、ENABLE の PON / AEN、PON 後 2.4ms、積分時間の式、ゲイン、
  16bit のバイト順とシャドウレジスタ、しきい値がクリアチャンネル専用であること、
  I2C アドレス `0x29` が固定であること: **すべて datasheet に明記がある。**
