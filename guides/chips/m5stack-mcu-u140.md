# Unit DCSSR (U140) — DC ソリッドステートリレーユニット

> DC 24〜220V / 10A の負荷を無接点で開閉するリレーユニット。ボタン操作・I2C スレーブ・
> Modbus（RS485）の 3 通りで制御できる。**レジスタマップは本リポジトリには無い。**
>
> **確度**: datasheet も I2C プロトコル文書も無く、`profiles/m5stack-mcu-u140.yaml` も
> 実測も無い。**ただしベンダーの製品ページが「Unit DCSSR Arduino Library」として
> リンクしているのは兄弟機 ACSSR のライブラリ `M5Unit-ACSSR` である。**
> したがって本カタログの [`profiles/m5stack-mcu-u139.yaml`](https://github.com/tanakamasayuki/I2CDeviceDB/blob/38f1d82/profiles/m5stack-mcu-u139.yaml)
> （ACSSR のレジスタマップ）が最有力の仮説になるが、**それが DCSSR にも当てはまるという
> 確認は取れていない。** バス上で確認された挙動は一つも無い。

## これは何か

単相ソリッドステートリレー（SSR）と、それを制御する ESP32-C3 の基板を組み合わせたキット。
機械接点を持たないので、開閉に伴うアークやチャタリングが無く、寿命が接点摩耗で決まらない。
製品ページはモータ制御・温度制御・データ処理系を用途に挙げている。

**AC 用の Unit ACSSR (U139) と対になる DC 版**である。ホストから見える I2C の相手は
ESP32-C3 のファームウェアであって SSR そのものではない。**通信仕様はこの製品固有のもの**である。

3 つの動作モードを持つ:

1. **ボタン制御** — 本体のボタンだけで開閉する。ホスト不要。
2. **I2C スレーブ** — Grove（HY2.0-4P）経由。本ガイドが扱うのはここ。
3. **Modbus** — RS485 経由。デバイス ID を設定してネットワークに並べられる。
   **これは I2C とは別の物理層・別のプロトコルである。**

負荷側は HT3.96-4P の端子台が両端に 1 つずつ（入力と出力）。状態表示用に
SK6812 の RGB LED を載せている。

できると考えられること（すべて**未確認**。下記「レジスタ / コマンド」参照）:

- リレーの開閉と、現在の状態の読み出し。
- 状態表示 LED の色の指定。
- I2C アドレスの変更。
- ファームウェアバージョンの読み出し。

できないこと・持っていないもの:

- **割り込み線が無い。** 状態変化（ボタンで手動操作された等）を知るにはポーリングするしかない。
- **負荷電流・電圧の測定機能が無い。** 開閉するだけで、流れているものは見えない。
- **PWM や位相制御は無い。** ON / OFF のみ。
- **フェイルセーフの設定が無い。** I2C が切れたときにリレーをどうするかを指定する手段は
  公開されていない。**通信断のときリレーが開くのか閉じたままなのかは未確認**（下記注意）。

## レジスタ / コマンド

**本リポジトリは本機のレジスタマップを持っていない。** `profiles/m5stack-mcu-u140.yaml` は
存在せず、ベンダーは DCSSR 専用の I2C プロトコル文書も専用ライブラリも公開していない。

ただし**手掛かりは強い**。製品ページの「Unit DCSSR Arduino Library」というリンクの飛び先が
`github.com/m5stack/M5Unit-ACSSR`、すなわち**兄弟機 ACSSR (U139) のライブラリ**である。
そして ACSSR のレジスタマップは本カタログに
[`profiles/m5stack-mcu-u139.yaml`](https://github.com/tanakamasayuki/I2CDeviceDB/blob/38f1d82/profiles/m5stack-mcu-u139.yaml) として入っている。

| アドレス | 長さ | R/W | 意味（**ACSSR のもの**） |
|---|---|---|---|
| `0x00` | 1 | R/W | リレー状態。`1` を書くと閉、`0` で開。読むと現在の状態 |
| `0x10` | 3 | R/W | 表示 LED の色。R, G, B の順 |
| `0x20` | 1 | W | I2C アドレス設定 |
| `0xFE` | 1 | R | ファームウェアバージョン |

**この表を DCSSR の仕様として使ってはいけない。** これは ACSSR のものであり、
本機に当てはまるという確認は無い。当てはまりそうだと考える根拠と、疑う根拠を並べておく。

**当てはまりそうな根拠**:

- ベンダー自身が DCSSR の製品ページからこのライブラリをリンクしている。
- どちらも ESP32-C3 で、既定アドレスが同じ `0x50`。
- どちらも「SSR 1 回路 + RGB LED + ボタン + I2C/Modbus」という同一の構成で、
  機能セットが一致する。AC 版と DC 版で firmware を共通化するのは自然である。

**疑う根拠**:

- `M5Unit-ACSSR` のリポジトリ README も、ライブラリ内の `src/M5_ACSSR.h` / `.cpp` も、
  **DCSSR に一言も言及していない。** 定数名はすべて `ACSSR_*` で、リンク先も
  `docs.m5stack.com/en/unit/acssr` を指す。**製品ページ側の一方的なリンクである。**
- ACSSR の Modbus スレーブ ID は `0x04` と決め打たれている。同一バスに ACSSR と DCSSR を
  並べる前提なら、どちらかは違う値でなければならない。**firmware が完全に同一とは考えにくい。**
- DCSSR の製品ページ自体にはレジスタ表が無い。ACSSR 側には
  [`M5Unit-ACSSR-Internal-FW`](https://github.com/m5stack/M5Unit-ACSSR-Internal-FW) という
  firmware/レジスタのリポジトリが README からリンクされているが、
  **DCSSR に対応するものは見当たらない。**

**何があればこれが確定するか**（有用な順）:

1. **`M5Unit-ACSSR` を DCSSR の実機に当ててキャプチャすること。** `0xFE` を読んで
   値が返るか、`0x00` の読み書きでリレーが実際に動くかを見れば、
   **「ベンダーのリンクは正しいのか」という本機の唯一の中心的な問いが決着する。**
   これが本機で最も価値の高い一手である。
2. **`M5Unit-ACSSR-Internal-FW` を読むこと。** ACSSR 側の firmware に DC 版の分岐や
   共通化の痕跡があれば、共有の度合いが分かる。
3. **UIFlow が DCSSR を叩くところのキャプチャ。** UIFlow はブロックとして DCSSR を
   サポートしているので、ライブラリとは独立した第 2 の実装になる。
4. **ESP32-C3 の flash 吸い出し。** 分解が要るうえ、リレーユニットの分解は
   負荷側の配線を外してからでないと危険。

**レジスタを捏造しないこと。** 上の 4 レジスタは ACSSR の実装から起こしたものであって、
DCSSR で観測されたものではない。

## 典型的な使い方

**以下は「ACSSR と同じである」という未確認の仮説に基づく手順である。**
実機で試す場合は、**必ず負荷を接続しない状態から始めること。**

1. Wire を 100kHz で開く（ACSSR のライブラリがこのレートを使う）。
2. `0xFE` を読む。**何かが返れば少なくとも通信は成立している。** ここで応答が無ければ、
   仮説そのものが外れているか、ユニットが I2C モードになっていない（下記注意）。
3. `0x00` を読んで現在のリレー状態を確認する。
4. `0x00` に `1` / `0` を書いて開閉する。**負荷を外した状態で、本体の LED と
   カチッという音（SSR なので無音のはず）で確認する。**
5. 状態表示を変えたければ `0x10` に R, G, B の 3 バイトを書く。

**読み出しは、ポインタバイトを書いたあと STOP を打ってから読む**（repeated START ではない）。
これも ACSSR のライブラリ実装に基づく。

## 利用上の注意

- **OFF は「電気的に切れている」という意味ではない。** 仕様上の OFF 時漏れ電流は
  **≤ 5mA** である。SSR は半導体なので完全には遮断しない。
  **負荷側の配線を触る前に、必ず元電源を落とすこと。** ソフトウェアで OFF にしただけの
  状態を「安全」と扱ってはいけない。これは本機で最も重大な注意点である。
- **DC 220V / 10A を扱う。** 本カタログの他のユニットとは危険度の桁が違う。
  DC は AC と違ってゼロクロスが無いため、遮断時のアークが切れにくい。
  **配線・端子台の締め付け・放熱を製品ページの指示どおりに行うこと。**
  重量 112.6g は放熱器の分であり、10A を流すなら発熱する。
- **モードによって I2C が応答しない可能性がある。** 本機はボタン制御 / I2C / Modbus の
  3 モードを持つ。CardKB2（[`chips/m5stack-mcu-u215.yaml`](../../chips/m5stack-mcu-u215.yaml)）は
  「I2C データはユニットが I2C モードのときにしか存在しない」という作りになっており、
  **本機も同様である可能性がある。** `0x50` が ACK しないときは、まずモード設定を疑う。
  **モードの切り替え方と、モードが I2C 応答に影響するかは未確認。**
- **通信断時のリレーの挙動が未確認。** ホストが落ちたとき、あるいは Grove ケーブルが
  抜けたときにリレーが開くのか、最後の状態を保持するのかは公開されていない。
  **保持する（＝閉じたままになる）と仮定して設計すること。** 安全側に倒すなら、
  ホスト側のウォッチドッグではなく外部の遮断手段を用意する。
- **`0x00` への書き込みはレジスタマップの仮説に依存する。** 仮説が外れていた場合、
  `0x00` に `1` を書く行為が何を引き起こすかは分からない。**負荷を接続した状態で
  未検証のレジスタに書き込まないこと。**
- **本カタログ内の `0x50` 衝突**:
  - [`chips/m5stack-mcu-u139.yaml`](../../chips/m5stack-mcu-u139.yaml)（Unit ACSSR）が
    **同じ `0x50`**。しかも構成もレジスタも同じである疑いが濃いので、
    **同じバスに ACSSR と DCSSR を並べると、アドレスでも応答内容でも区別できない。**
    片方のアドレスを `0x20` で変えるしかない（それができるかも未確認）。
    [ACSSR のガイド](m5stack-mcu-u139.md)も参照。
  - [`chips/st25r3916.yaml`](../../chips/st25r3916.yaml) — ST25R3916 NFC フロントエンドが
    I2C モードで `0x50`。**M5Stack の NFC 系ユニットと同時に使えない。**
  - **24Cxx 系 I2C EEPROM の基準アドレスが `0x50`** である。本カタログの
    [`chips/eeprom.yaml`](../../chips/eeprom.yaml) は `0x51` / `0x53` だけを登録しているが、
    一般的な EEPROM モジュールを混ぜると `0x50` で当たる可能性が高い。
- **Modbus は I2C とは別物。** ACSSR のライブラリのヘッダは Modbus 側のアドレス
  （スレーブ ID `0x04`、リレーコイル `0x0000`、LED ホールディング `0x0000`、
  バージョン `0x0001`、ID `0x0002`）も持っているが、
  [`profiles/m5stack-mcu-u139.yaml`](https://github.com/tanakamasayuki/I2CDeviceDB/blob/38f1d82/profiles/m5stack-mcu-u139.yaml) の notes が書くとおり
  **ライブラリ内にそれを駆動するコードは無く、I2C のレジスタマップとも無関係である。**
  混同しないこと。
- **I2C 速度が不明。** ACSSR のライブラリは 100kHz で駆動する。ESP32-C3 のスレーブは
  400kHz でも動きそうだが、**本機で確かめられていない。** 100kHz から始める。
- **本ガイドに書かれたことのうち、レジスタに関する記述はすべて他機種からの流用であり、
  本機で確認されたものは一つも無い。** 寸法・重量・電気定格だけが製品ページ由来の
  確かな情報である。

- **datasheet: 無い。** [`chips/m5stack-mcu-u140.yaml`](../../chips/m5stack-mcu-u140.yaml) の

  `collection/vendor/` にも DCSSR のエントリは無い。M5Unified / M5GFX にも
  このユニットを扱うコードパスは無い。
  **製品ページがリンクしているのは兄弟機 ACSSR のライブラリ `M5Unit-ACSSR` である。**
  これが本機について見つかった唯一のコードへの手掛かりであり、
  **その正当性はベンダー側のリンク 1 本だけに支えられている。**
- **`profiles/`: 無い。キャプチャ: 無い。**
- アドレス `0x50`、ESP32-C3、SK6812、3 つの動作モード、負荷定格（DC 24〜220V / 10A、
  ON 時降下 ≤1.6V、OFF 時漏れ ≤5mA）、制御電圧 DC 3〜32V、寸法・重量:
  **製品ページに基づく。ここは確かである。**
- レジスタ `0x00` / `0x10` / `0x20` / `0xFE`、100kHz、読み出しが repeated START ではなく
  STOP を挟むこと: **`M5Unit-ACSSR` v0.0.3 のソースから起こした推定であり、
  しかもそれは ACSSR (U139) についての推定である。**
  [`profiles/m5stack-mcu-u139.yaml`](https://github.com/tanakamasayuki/I2CDeviceDB/blob/38f1d82/profiles/m5stack-mcu-u139.yaml) 自身が
  `evidence.source: inferred` / `confidence: tentative` である点にも注意。
  **本機に適用するとき、推定が二重になっている。**
- **未確認**: レジスタが本機に存在するか。動作モードが I2C 応答に影響するか。
  通信断時のリレーの挙動。アドレス変更が可能か。ACSSR と DCSSR を
  同一バスで区別する手段があるか。
- **次にやるべき最も有用な一手**: **`M5Unit-ACSSR` を DCSSR の実機に当てて、
