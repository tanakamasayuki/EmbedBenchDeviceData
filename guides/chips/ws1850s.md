# WS1850S — 13.56MHz RFID / NFC リーダ（MFRC522 互換とされる）

> 13.56MHz の非接触カード読み書き IC。**レジスタマップを記載した datasheet が存在しない。**
> 公開されている文書は 9 ページの「Preliminary」で、ピン配置・応用回路・電気的特性しか
> 書かれていない。`profiles/ws1850s.yaml` のレジスタ表は **NXP MFRC522 のものを流用した推定**で、
> 根拠は「ベンダーのドライバが MFRC522 のレジスタ定義をそのまま使って動いている」ことだけ。
>
> **確度**: **本 catalog で最も証拠が薄い部類**。RCWL-9600 / RCWL-9620 と並ぶ。
> レジスタが本当にそこにあるかも、バージョンレジスタが何を返すかも、**誰も測っていない。**
> `profiles/ws1850s.yaml` の evidence は `inferred` / `tentative`。

## これは何か

深圳前海维晟智能技术（Shenzhen Qianhai WiseSun Intelligence Technology）の 13.56MHz
非接触読み書き IC。ISO/IEC 14443 Type A / Type B に対応し、MIFARE / NTAG 系のカードを
扱う。M5Stack Unit RFID2 (U031-B) が `0x28` で使っており、MFRC522 を使った旧 Unit RFID の
後継にあたる。

**datasheet が言っていること**（WS1850S QFN-32、Preliminary Rev 1.1、2018-06）:

- 電源電圧 2.0–5.5V の広い範囲で動作（§4.1, p7）。
- 通信速度 106 / 212 / 424 kbit/s。
- **ホストインタフェースは 3 通り**: SPI（10Mbit/s）、**I2C（標準モード 100kbps）**、
  UART（1228.8kbit/s）。ピンで選ぶ（§3.2 表 2, p6）。
- 送受信ともに **64 バイトの FIFO**。
- プログラマブルタイマ、CRC コプロセッサ（ISO/IEC 14443 と CCITT 準拠）、パリティ。
- **内蔵温度センサ**を持ち、チップ温度が上がりすぎると自動的に RF 送信を止める（p1）。
- 低消費電力カード検出（LPCD）。
- ハードウェア掉電・ソフトウェア掉電・送信部掉電の複数の省電力モード。
- 有効読み取り距離 8〜10cm（メーカーの主張、p1）。
- 外部に 27.12MHz の水晶が要る。

**datasheet が言っていないこと**:

- **レジスタが 1 本も載っていない。** アドレスも、ビット割り当ても、リセット値も、
  初期化手順も、コマンドコードも、何も書かれていない。**9 ページ全部読んでも
  ソフトウェアは 1 行も書けない。**
- バージョンレジスタが何を返すか。
- MFRC522 との互換性について、文書は一言も触れていない。「MFRC522 互換」は
  **ドライバが動くという事実からの逆算**であって、メーカーの主張ではない。
- Type B に対する具体的な制御方法。**Type A / Type B 両対応を謳っているが、レジスタが
  無いので確かめようがない。**（参考までに、レジスタ表の出どころである MFRC522 は
  NXP の文書上は「MIFARE と NTAG のフロントエンド」で、Type B の記載は無い。）

**できないこと・持っていないもの**（MFRC522 互換という前提での話）:

- **プロトコルスタックを内蔵していない。** アンチコリジョン、SELECT、認証、
  ブロック読み書きの手順はすべてホスト側のソフトウェアが行う。IC は FIFO 越しに
  フレームを出し入れするだけ。
- **暗号鍵を安全に保管する仕組みは無い。** MIFARE Classic の鍵はホストから毎回送る。
- カードの UID を勝手に読んでレジスタに置いてくれる、といった便利機能は無い。
- 13.56MHz 専用。125kHz の LF タグ（EM4100 など）は読めない。

**電気的な現実**（§4, p7-8）:

- 電源は複数系統（DVDD / AVDD / TVDD / PVDD）で、`PVDD = DVDD ≤ AVDD ≤ TVDD` という
  順序の制約がある。2.0–3.3–5.5V（min–typ–max）。
- 消費電流は 3.3V で待機 2.4mA、**キャリア連続送信時 typ 60mA / max 100mA**。
  5V では typ 90mA / max 150mA。**Grove の 5V から取る場合、送信中の電流は無視できない。**
- ハードウェア掉電時は 0.02uA、ソフトウェア掉電（RF レベル検出 ON）で 0.5uA。
- パワーオンリセット電圧 1.5V、水晶の起動時間 700us。
- 動作温度 -40〜+85℃。

## レジスタ・コマンド

### まずこの節の位置づけ

**以下は WS1850S の datasheet には一切書かれていない。** NXP MFRC522 の datasheet
（Rev 3.9、2016-04-27）の内容を、「ベンダーのドライバが MFRC522 のレジスタ定義を
そのまま使って I2C で動作している」という事実だけを根拠に当てはめたものである。

`profiles/ws1850s.yaml` に載っているのも、ドライバが実際に触る 5 本だけである。

| アドレス | 名前 | 意味（MFRC522 での定義） |
|---|---|---|
| `0x01` | CommandReg | コマンドレジスタ。IC に実行させる動作を指定 |
| `0x09` | FIFODataReg | FIFO への入出力。読み書きとも同じアドレス |
| `0x0A` | FIFOLevelReg | FIFO に溜まっているバイト数 |
| `0x0D` | BitFramingReg | ビットフレーミング / 送信開始 |
| `0x37` | VersionReg | バージョンレジスタ |

**MFRC522 の VersionReg (`0x37`) は `0x91`（version 1.0）または `0x92`（version 2.0）を返す**
（MFRC522 datasheet §9.3.4.8 VersionReg register, p66）。**WS1850S が何を返すかは分かっていない。**
`scenarios/ws1850s/p0.yaml` の `version` 出力は、まさにこれを確かめるためのものである。

### I2C でのレジスタアクセス（MFRC522 の規定）

MFRC522 の I2C アクセスは、一般的な I2C センサとかなり違う（MFRC522 datasheet
§8.1.4.6 / §8.1.4.7, p19-20）:

```
書き込み: S | 0x28+W | レジスタアドレス | データ | データ | ... | P
読み出し: S | 0x28+W | レジスタアドレス | P
          S | 0x28+R | データ | データ | ... | P
```

要点が 2 つある。

1. **レジスタアドレスは素の 8bit 値をそのまま送る。** SPI モードのようにアドレスを
   1 ビット左シフトして bit7 に方向を入れる、という変換は**しない**。SPI 用に書かれた
   コードを I2C に流用するとここで必ずずれる。
2. **1 フレーム内の複数バイトは、すべて同じレジスタに対して読み書きされる。**
   自動インクリメントは無い。これは 64 バイト FIFO（`0x09`）を高速に出し入れするための
   設計であって、「連続するレジスタをまとめて読む」ためのものではない。
   **`0x01` から 8 バイト読んでも、`0x01` を 8 回読んだ結果が返る。**

**これが WS1850S でも同じである保証は無い。** 検証されていない。

## 典型的な使い方

**MFRC522 互換であるという前提**での手順。実機で確かめられていない。

1. NRSTPD を解放（またはソフトリセット）してから、`0x37`（VersionReg）を読む。
   **ここで何が返るかが、このチップに関する最初の実測データになる。**
   `0x91` / `0x92` なら MFRC522 そのものと同じ、`0x00` や `0xFF` なら通信が
   成立していない、それ以外なら WS1850S 固有の値ということになる。
2. アンテナドライバを有効化する（MFRC522 では `TxControlReg` の `Tx1RFEn` / `Tx2RFEn`）。
   **このレジスタは `profiles/ws1850s.yaml` に載っていない。** ドライバのソースを見る
   必要がある。
3. `0x01`（CommandReg）に Transceive を指示し、`0x09`（FIFODataReg）に送りたいバイトを
   書き、`0x0D`（BitFramingReg）の StartSend で送信を開始する。
4. 応答は `0x0A`（FIFOLevelReg）でバイト数を確認してから `0x09` から読む。
5. カード検出（REQA / WUPA）→ アンチコリジョン → SELECT → 認証 → ブロック読み書き、という
   ISO14443A の手順はすべてホスト側で組む。

## 利用上の注意

- **このチップに関する記述は、ほぼ全部が推定である。** レジスタが本当にそのアドレスに
  あるのか、リセット値が何なのか、`0x37` が何を返すのか、どれも確認されていない。
  **本ガイドの「レジスタ」節と「典型的な使い方」節は、実機で 1 度も走らせていない。**
- **`0x28` は MFRC522 と同じアドレス。** この catalog で `0x28` を名乗るのは `mfrc522` と
  `ws1850s` の 2 つで、それぞれ Unit RFID と Unit RFID2 に載っている。
  **両方を同じバスに繋ぐと衝突する。** さらに厄介なことに、**両者は同じレジスタ表で
  動くとされているので、通信は成立してしまう。** 「1 台のつもりで 2 台繋がっている」
  状態にバス側から気づく手がかりが乏しい。
- **I2C は 100kbps しか保証されていない。** WS1850S の datasheet は「I2C接口，标准模式速率为
  100kbps/s」（I2C インタフェース、標準モードの速度は 100kbps）としか書いていない（p1）。
  **400kHz は根拠が無い。** 参考までに MFRC522 のほうは Fast モード 400kBd と High-speed
  3400kBd に対応すると明記している。**同じチップだと思って 400kHz で叩くのは、
  この 1 点だけを見ても危うい。** `scenarios/ws1850s/p0.yaml` が 100kHz と 400kHz の
  両方を掃くのは、まさにここを確かめるためである。
- **自動インクリメントが無い（MFRC522 の規定）。** 汎用の I2C ダンプツールで
  「`0x00` から 64 バイト読む」と、`0x00` を 64 回読んだ結果が返る。レジスタマップを
  実測で起こそうとするなら、**1 バイトずつ別トランザクションで読む**必要がある。
- **レジスタアドレスをシフトしない。** SPI 用のコード（`(addr << 1) | 0x80`）を
  そのまま持ち込むと動かない。
- **送信中の電流が大きい。** 3.3V で typ 60mA / max 100mA、5V なら typ 90mA / max 150mA
  （§4.2, p7-8）。Grove ケーブル経由で他のユニットと電源を共有していると、
  カード読み取りの瞬間に電圧が落ちて別のデバイスがリセットする、という形で出る。
- **温度で勝手に送信が止まる。** 内蔵温度センサがチップの過熱を検出すると RF 送信を
  自動停止する（p1）。連続ポーリングで熱くなった場合、ソフトウェア側からは
  「急にカードを認識しなくなった」ように見える。
- **電源投入順序に制約がある。** `PVDD = DVDD ≤ AVDD ≤ TVDD`（§4.1, p7）。Unit として
  使う分には基板が面倒を見ているが、裸のチップを扱うときは注意。
- **Type B 対応は確かめようがない。** datasheet は対応を謳うが、レジスタが公開されて
  いないので制御方法が分からない。MFRC522 のレジスタ表を借りている以上、
  **実質的に Type A（MIFARE / NTAG）しか扱えないと考えるのが安全。**

## 出典と確度

- 参照した文書: **WS1850S QFN-32、Preliminary Rev 1.1（2018-06）、全 9 ページ、中国語。**
  入手元は M5Stack がホストするコピー
  （`m5stack.oss-cn-shenzhen.aliyuncs.com/.../WS1850S%20QFN-32.PDF`）。
  **WiseSun は自社サイトでこの文書を配布していない。** 他に流通しているのは
  LCSC / JLCPCB のような流通業者のミラーだけである。
- **「Preliminary」と表紙に書かれたまま 8 年近く更新されていない。** より新しい版が
  存在するかどうかも確認できない。
- datasheet から取れたこと: 対応規格、通信速度、FIFO 64 バイト、**I2C は標準モード
  100kbps**、ホストインタフェースの選択方法、ピン配置、電源電圧と消費電流、
  POR 電圧、水晶起動時間、温度保護、LPCD。
- **datasheet に無いこと（= 推定であること）**: レジスタのアドレス、意味、ビット割り当て、
  リセット値、初期化手順、コマンドコード、バージョンレジスタの値。
  これらは**すべて NXP MFRC522 datasheet Rev 3.9（2016-04-27）からの流用**であり、
  流用の唯一の根拠は「ベンダーのドライバが MFRC522 のレジスタ定義をそのまま使って
  I2C で動いている」という事実である。**メーカーが互換性を主張しているわけではない。**
- **未確認（実測なし）**: `0x28` が実際に ACK するか、`0x37` が何を返すか、
  リセット直後の各レジスタが MFRC522 と同じ値か、`0x09` / `0x0A` / `0x0D` が本当に
  FIFO とビットフレーミングなのか、自動インクリメントの有無、400kHz で通るか。
  **どれ 1 つとして測られていない。** `observations/ws1850s/` はまだ無い。
- **未調査**: `scenarios/ws1850s/p0.yaml` では `antenna-enable`、`fifo-write-read`、
  `card-transaction`、`full-register-map-discovery` がすべて deferred。
  カードを 1 枚も読んでいない。
- **本 catalog における位置づけ**: レジスタマップが一次資料に存在せず、互換性の主張すら
  第三者の推定である、という点で **RCWL-9600 / RCWL-9620 と並んで最も証拠が薄い**。
  ここに書かれたレジスタの記述を、実測で確かめずに信用してはならない。
