# PAJ7620U2 — ジェスチャ認識センサ（赤外イメージャ + 認識エンジン）

> 940nm の赤外 LED で手を照らし、内蔵の小さなイメージセンサで撮って、9 種類の
> ジェスチャを認識してレジスタに立てるセンサ。**素の状態では何も認識しない**。
> ウェイク → バンク選択 → 約 200 行のベンダー初期化テーブル、を経て初めて動く。
>
> **確度**: PixArt の datasheet 2 版に基づく。M5Stack がホストしている rev 1.2（2016-02、28 ページ）は
> **7 章「Register Tables」の途中で終わっており、レジスタ表も初期化手順も載っていない**。
> Seeed がホストしている rev 1.5（2022-01-05、66 ページ）は完全だが "Confidential" と
> 明記された文書である。PixArt 自身は公開版を出していない。**実測では未確認**。

## これは何か

「近接センサ」でも「モーションセンサ」でもなく、**中身は小さなカメラ**である。
9bit の A/D を持つセンサアレイ（イメージモードでは 30×30 または 60×60 画素で読み出せる）と、
940nm の赤外 LED ドライバ、それに DSP の認識エンジンが載っている。ジェスチャモードでは
画像そのものはホストに出さず、認識結果だけがレジスタのビットとして返る。

できること:

- 9 種類のジェスチャ認識: 上・下・左・右・前（近づく）・後（遠ざかる）・時計回り・
  反時計回り・ウェーブ。結果は Bank0 の `0x43` / `0x44` に 1bit ずつ立つ。
- 検出距離 5〜15cm、視野角は対角 60°。
- Normal モード（更新 120Hz、手の角速度 60〜600°/s）と Fast / Gaming モード
  （240Hz、60〜1200°/s）の切り替え。
- 近接検出（Proximity, PS）モード。更新 10Hz で、対象の接近・離脱をヒステリシス付きで返す。
- カーソルモード（物体の位置を返す）。
- イメージモード（30×30 / 60×60 の生画像）。ただし**出力は SPI で、I2C ではない**。
- サスペンド（15µA typ）と復帰。
- INT_N ピンによる割り込み（極性はレジスタで反転可）。

できないこと・持っていないもの:

- **初期化しないと何も返らない。** 電源投入直後のレジスタ値は「工場出荷値」であって、
  ジェスチャ認識が動く設定ではない。後述のベンダー初期化テーブルが必須。
- **ジェスチャの種類を増やせない / 学習させられない。** 認識エンジンは固定である。
- **画像を I2C で取り出せない。** イメージモードは SPI 専用で、22〜48MHz の外部 SPI クロックが要る。
- **距離を数値で返さない。** 近接モードで返るのは「明るさ（物体の大きさ）」と、しきい値との
  比較結果であって、cm 単位の距離ではない。
- **5V トレラントではない。** I2C ピンのプルアップ電圧 VBUS は 1.8〜3.3V。
- **アドレスをピンで選べない。** 品種としては `0x13, 0x1B, 0x23, 0x2B, 0x5B, 0x63, 0x6B, 0x73` の
  8 通りが存在するが、**PAJ7620U2 の既定は `0x73` 固定**であり、実装後に選び直す手段は無い。

電気的な現実:

- VDD 2.8〜3.6V、LED 電源 VLED 3.0〜4.2V、I2C / INT_N のプルアップ電圧 VBUS 1.8〜3.3V。
  **VBUS は VDD より先に立ち上げること**（6.1.2）。
- LED のピーク電流は 360〜430mA（パルス幅 500µs 未満、デューティ 5% 未満）。
  データシートの消費電流の項は「LED ピーク 760mA を含む」と書いており、
  **電源には瞬間的に大きな電流が流れる**。デカップリングが効かないと自分のノイズで誤動作する。
- 通常動作 2.82mA、Standby1 2.3mA、Standby2 1.5mA、近接検出 0.2mA、サスペンド 15µA。
- I2C は typ 100kbit/s、max 400kbit/s。**クロックストレッチは行わない。**
  SDA / SCL は open-drain でプルアップは外付け（バス電流は 5mA まで）。
- 電源投入から 700µs（T1）待ってウェイク、さらに 400µs（T2）待ってから初期化設定を書く。

M5Stack Unit Gesture (U127) はこれを `0x73` で使う。

## レジスタ / コマンド

レジスタ空間は **2 バンク**あり、`0xEF` に書いた値で切り替える。**同じアドレスでも
バンクが違えば別のレジスタ**なので、バンクを確定させずに読んだ値には意味が無い。

| バンク | アドレス | 名前 | 既定値 | 意味 |
|---|---|---|---|---|
| 0/1 | `0xEF` | R_RegBankSel | `0x00` | バンク選択（0 = Bank0、1 = Bank1）。Bank1 では `0x7F` でも同じことができる |
| 0 | `0x00` | PartID[7:0] | `0x20` | パート ID 下位 |
| 0 | `0x01` | PartID[15:8] | `0x76` | パート ID 上位 |
| 0 | `0x02` | VersionID | `0x01` | バージョン ID |
| 0 | `0x03` | SW_Suspend_EnL | `0x01` | `0`（rev 1.5）を書くとソフトサスペンド |
| 0 | `0x40` | R_MCU_IntFlagGClr / IntFlagInv | `0x01` / `0x00` | bit1 = **I2C 読み出し後にフラグを自動クリア**（既定 ON）、bit4 = INT ピン極性 |
| 0 | `0x41` | R_Int_1_En | `0xFF` | 割り込みマスク（bit0 Up, 1 Down, 2 Left, 3 Right, 4 Forward, 5 Backward, 6 CW, 7 CCW） |
| 0 | `0x42` | R_Int_2_En | `0xFF` | 割り込みマスク（bit0 Wave, 1 Proximity, 2 Has Object, 3 Wake up, 7 No Object） |
| 0 | `0x43` | **IntFlag_1** | — | **ジェスチャ検出フラグ**。ビット割り当ては `0x41` と同じ |
| 0 | `0x44` | **IntFlag_2** | — | ウェーブ / 近接 / カーソル系のフラグ。割り当ては `0x42` と同じ |
| 0 | `0x83` | R_LightThd | `0x20` | 明るさしきい値（これを超えた画素だけ物体とみなす） |
| 0 | `0xEE` | R_RegBank Reset ほか | `0x01` | Bank0 / Bank1 / DSP のソフトリセット |
| 1 | `0x72` | — | — | **エンジンの有効化。`0x01` で動作、`0x00` で停止** |
| 1 | `0x7E` | — | — | SPI 出力の有効化（イメージモード用） |

**注意**: `0x41` / `0x42` のビット割り当ては datasheet の版で記述が食い違っている。
rev 1.2 の 6.1.1（p21）は bit0 = Left, bit1 = Right … の順、rev 1.5 の 7.4（p34）は
bit0 = Up, bit1 = Down … の順で書かれている。**実装するなら実機で確かめること。**

**転送の形**:

```
書き込み:  S [SlaveID|W] A [addr] A [data] A P
単発読み:  S [SlaveID|W] A [addr] A P   S [SlaveID|R] A [data] NA P
連続読み:  S [SlaveID|W] A [addr] A P   S [SlaveID|R] A [data0] A [data1] A … NA P
                                                       ← アドレスは自動インクリメント
ウェイク:  S [SlaveID|W] P            ← データを一切送らない
```

読み出しの図（Figure 13, rev 1.5 p20）は、アドレスを書いたあとに **STOP を打ってから
改めて START** する形になっている。repeated START でも通ることが多いが、データシートの
記載はこちらである。

**ウェイクは「アドレスだけ送って STOP」というトランザクション**で、レジスタもデータも無い。
ウェイク完了前は **NACK が返る**（応答しない）ので、バススキャンで見つからないことがある。

## 典型的な使い方

1. 電源投入。**VBUS を VDD より先に立ち上げる。**
2. 700µs（T1）待つ。
3. **ウェイクする。** スレーブ ID だけを書くトランザクションを送るか、レジスタ読み出しを
   投げる。datasheet の推奨は「Bank0 `0x00` を読んで `0x20` が返るまで繰り返す」。
   ウェイクが済むまでは ACK すら返らないので、1 回目が NACK でも異常ではない。
4. 400µs（T2）待つ。
5. **バンクを選ぶ。** `0xEF` に `0x00` を書いて Bank0 にする。
6. **Part ID を確認する。** Bank0 の `0x00` = `0x20`、`0x01` = `0x76`。ここまでやって初めて
   「PAJ7620U2 が居る」と言える。
7. **ベンダー初期化テーブルを流し込む。** `{レジスタ, 値}` の並びを頭から順に書く。
   途中で `0xEF` が現れてバンクが切り替わるので、**順番を変えたり並べ替えたりしてはいけない。**
8. ジェスチャモードにする設定を書き、Bank1 の `0x72` に `0x01` を書いてエンジンを有効化する。
9. INT_N の割り込みか一定周期のポーリングで、Bank0 の `0x43` / `0x44` を読む。
   ビットが立っていればそのジェスチャが検出された。**読んだ時点でフラグはクリアされる。**
10. サスペンドするなら Bank1 `0x72` に `0x00`、続いて Bank0 `0x03` に書く。
    復帰は「ウェイク → Bank1 `0x72` に `0x01`」+ ベンダーの resume テーブル（`0xEE` の
    書き込みの間に 500µs の待ちが挟まる）。

## 利用上の注意

- **初期化テーブルの中身は完全には公開されていない。** これがこのデバイスで最も重要な事実である。
  - M5Stack がホストしている **rev 1.2 の PDF は 28 ページで、7 章 Register Tables の
    冒頭で切れている**。レジスタ表の大部分も、初期化手順を書いた 8 章も入っていない。
    このコピーだけでは動くコードは書けない。
  - Seeed がホストしている **rev 1.5 には 8.1 に `initial_register_array` が載っており、
    エントリ数は 70**（そのあとモード切り替え用に 30 行前後が続く）。ただしこの文書は
    表紙に "Confidential" とあり、PixArt が公開しているものではない。
  - 実際に流通しているドライバ（Seeed の `Gesture_PAJ7620`、`RevEng_PAJ7620` など）は、
    **200 行前後のより大きなテーブル**を自前で持っている。datasheet の 70 行と一致しない。
  - つまり **「どのレジスタに何を書くと何が起きるか」は完全には分からないまま、
    ベンダー由来のテーブルを丸ごと信用して流し込む**のが実情である。この点を伏せた
    解説記事が多いが、隠しても実装は楽にならない。テーブルは既存ドライバから
    そのまま持ってくるのが唯一現実的な方法である。
- **ウェイクしないと Part ID は意味を持たない。** 電源投入直後に `0x00` を読んでも、
  ウェイクが済んでいなければ NACK か不定値が返る。「`0x73` に何も居ない」ように見える
  原因の筆頭。本カタログの probe が `safety: reversible-write` になっていて
  wake → bank-select → identity-read の順に踏むのはこのため
  （[`scenarios/paj7620u2/p0.yaml`](https://github.com/tanakamasayuki/I2CDeviceDB/blob/38f1d82/scenarios/paj7620u2/p0.yaml)）。
- **バンクを確定させないと読んだ値は無意味。** `0xEF` を書かずに `0x00` を読んだとき、
  それが Bank0 の Part ID なのか Bank1 の Cmd_HSize なのかは分からない。
  初期化テーブルの途中でバンクが切り替わるので、**テーブルを流したあとにどちらのバンクに
  居るかを意識する**必要がある。
- **ジェスチャフラグは読み出しで消える（read-to-clear）。** `0x40` の bit1 が既定で 1 に
  なっており、`0x43` / `0x44` を I2C で読むと自動でクリアされる。
  **2 か所から読むと片方が取りこぼす。読む場所は 1 か所に決める。**
  逆に、割り込み駆動にしていてフラグを読まないと、次の割り込みが上がらない。
- **`0x43` / `0x44` は 2 バイトまとめて読む。** ジェスチャの一部（ウェーブ、近接）は `0x44` 側に
  出るので、`0x43` だけ読む実装は取りこぼす。連続読みでアドレスが自動インクリメントするので
  1 トランザクションで済む。
- **`0x73` は I2C マルチプレクサとぶつかる。** 本カタログの
  [TCA9548A](../../chips/tca9548a.yaml) / [PCA9548A](../../chips/pca9548a.yaml) は
  A2=GND, A1=VCC, A0=VCC のとき `0x73` になる。マルチプレクサとジェスチャセンサを
  同じバスに置く設計では実際に衝突しうる。しかも PAJ7620U2 側はアドレスを変えられないので、
  逃げるのはマルチプレクサ側である。
- **モジュールの向きが上下左右の定義になる。** 基板を回して取り付けると「上」が「右」に
  なる。datasheet はレジスタ側で直せとは言っておらず、**ホスト側でリマップする**ことを
  前提にしている（6.1.1）。
- **940nm の外乱光に弱い。** 太陽光や白熱灯、他の赤外リモコン・測距センサは同じ帯域に
  エネルギーを持つ。カバーガラスの仕様（厚さ 0.7mm 以下、透過率 90% 以上、IR インクの
  スペクトル）が datasheet に明記されており、これを外すと検出距離が落ちる。
- **LED のパルス電流が大きい。** ピーク 360〜430mA（消費電流の表では 760mA ピーク条件も
  挙がっている）。電源のインピーダンスが高いとリップルで自分のロジックを揺らす。
- **クロックストレッチしない。** ホスト側がクロックを止めない限り待ってくれない。
  逆に言えばバスをハングさせにくい。
- **400kHz は仕様内**（max 400kbit/s）だが、本カタログでは未実測。
- **`0x03`（サスペンド）の値が版で食い違う。** rev 1.2 の 6.1.3.4（p23）は
  「Bank0 `0x03` に `0x01`」と書き、6.2.2（p25）は「`0x00`」と書いている。rev 1.5 の
  7.15（p50）は「0: software suspend」で、8.6 の `suspend_register_array` は `{0x03, 0x01}` を
  使っている。**一次資料の中で矛盾しているので、サスペンドを使うなら実機で確かめること。**

  M5Stack がホストする rev 1.2 は 7 章の途中で切れており、レジスタ表と初期化手順を欠く。

  公開されている rev 0.8 も存在する。**どれも「メーカーが公開した完全な一次資料」ではない。**

  実際のドライバは 200 行前後のテーブルを使う。**その差分の出所と根拠は本カタログでは
  未確認**であり、各レジスタの意味も 7 章に全部が説明されているわけではない。
- **未確認**: 実機のキャプチャが無い。`0x73` で応答するか、ウェイク前に本当に NACK が
  返るか、Part ID が `0x7620` を返すか、400kHz で通るかは確かめられていない。
- **未調査**: probe は wake → bank select → identity → Bank0 の既定値読みまで。
  ベンダー初期化テーブルの実行、ジェスチャモード、近接モード、Bank1 のレジスタは
  すべて deferred。
- `0x41` / `0x42` のビット割り当てが版によって食い違う点、`0x03` の
  サスペンド値が食い違う点は、**どちらが正しいか本カタログでは判断していない**。
