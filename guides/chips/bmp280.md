# BMP280 — 気圧・温度センサ

> ピエゾ抵抗式の気圧センサと温度センサを 1 チップにした固定機能 IC。**生の出力は
> そのままでは数値として意味を持たず、個体ごとの補償係数を読んで計算して初めて
> hPa と °C になる。**
>
> **確度**: Bosch Sensortec のメーカー datasheet
> BST-BMP280-DS001-26 **Revision 1.26**（2021 年 10 月）に基づく。レジスタ・ビット
> 定義・単位・バイト順・タイミングはすべてこの文書由来。**未確認**: 実機のキャプチャは
> まだ無く、`observations/bmp280/` は存在しない。M5Stack がホストしている
> コピーは Revision 1.14（2015 年 5 月）で内容が古い。

## これは何か

気圧を測るためのセンサ。中身はピエゾ抵抗式の感圧素子と、それを読む ASIC である。
ASIC が A/D 変換と、出荷時に書き込まれた個体固有の補償係数の保持を担当する。
温度センサが同居しているのは、気圧の補償計算に温度が必要だからであって、
「温度計としても使える」のは副産物にすぎない。

できること:

- 気圧を 300〜1100 hPa の範囲で測れる。フル精度は 0〜65 °C で絶対確度 ±1.0 hPa、
  相対確度（700〜900 hPa, 25〜40 °C）は ±0.12 hPa（高度に直すと約 ±1.0 m）。
- 温度を測れる。25 °C で ±0.5 °C。
- オーバーサンプリング（×1〜×16）を気圧・温度で独立に選べる。分解能・測定時間・
  消費電流のトレードオフを設定で振れる。
- IIR フィルタ（係数 0〜16）が内蔵されていて、ドアの開閉のような短時間の外乱を
  ハードウェア側で潰せる。
- 3 つの電源モード（sleep / forced / normal）。forced は 1 回測って sleep に戻る、
  normal は測定と待機を自動で繰り返す。
- I²C と SPI の両方に対応（本リポジトリが扱うのは I²C）。

できないこと・持っていないもの:

- **湿度は測れない。** 湿度チャンネルを持つのは BME280 という別のチップで、
  id もレジスタマップも違う。
- **割り込み線が無い。** ピンは 8 本（VDD, VDDIO, GND, CSB, SDI, SCK, SDO）だけで、
  INT も DRDY も出ていない（datasheet Table 29, p.34）。測定完了を知るには
  `status`(0xF3) の `measuring` ビットをポーリングするか、測定時間だけ待つ。
- **補償計算をチップ内でやってくれない。** 出力は 20bit の生の ADC 値で、
  hPa / °C への変換はすべてホスト側の仕事。
- **アドレスは 2 択しかない。** 同じバスに 3 個以上は載らない。
- 内蔵の温度センサは基板温度とセルフヒーティングの影響を受け、**外気温より高めに出る**
  のが普通（datasheet 脚注 3, p.8）。気温計として使う設計ではない。
- FIFO が無い。読み落とした測定値は消える。

電気的な条件:

- VDD 1.71〜3.6 V（typ 1.8 V）、インタフェース側の VDDIO 1.2〜3.6 V。5 V 直結は不可。
- SDA / SCL は外部プルアップが必要（SDI はオープンドレイン、SCL はクロック
  ストレッチをしない high-Z 入力）。
- SDO でアドレスを選ぶ。**フローティングは禁止**（アドレスが不定になる）。
- CSB はインタフェース選択。I²C を使うなら VDDIO に直結する。
- 電源投入から最初の通信まで最大 2 ms（tstartup）。

## レジスタ

`profiles/bmp280.yaml` の内容に、datasheet 由来の単位・バイト順・ビット定義を足したもの。

| アドレス | 長さ | R/W | 意味 |
|---|---|---|---|
| `0x88`–`0xA1` | 26 | R | 補償係数 `calib00`–`calib25`。**16bit ワードごとに LSB が先** |
| `0xD0` | 1 | R | `id`。`0x58` が返る |
| `0xE0` | 1 | W | `reset`。`0xB6` を書くと POR 相当のリセット。他の値は無視。読むと常に `0x00` |
| `0xF3` | 1 | R | `status`。bit3 = `measuring`、bit0 = `im_update` |
| `0xF4` | 1 | R/W | `ctrl_meas`。bit7-5 = `osrs_t`、bit4-2 = `osrs_p`、bit1-0 = `mode` |
| `0xF5` | 1 | R/W | `config`。bit7-5 = `t_sb`、bit4-2 = `filter`、bit0 = `spi3w_en` |
| `0xF7`–`0xF9` | 3 | R | `press_msb / press_lsb / press_xlsb`。20bit 符号なし、**MSB first** |
| `0xFA`–`0xFC` | 3 | R | `temp_msb / temp_lsb / temp_xlsb`。20bit 符号なし、**MSB first** |

**設定しなければならないフィールド**

- `mode[1:0]`（0xF4 bit1-0）: `00` = sleep（POR 後の既定）、`01`/`10` = forced、`11` = normal。
  **POR 直後は sleep なので、ここを書かないと永遠に測定が始まらない。**
- `osrs_p[2:0]`（0xF4 bit4-2）/ `osrs_t[2:0]`（0xF4 bit7-5）: `000` = skipped、
  `001`〜`101` = ×1, ×2, ×4, ×8, ×16。**skipped にすると該当チャンネルの出力は
  `0x80000` に固定される。**
- `t_sb[2:0]`（0xF5 bit7-5）: normal mode の待機時間。0.5 / 62.5 / 125 / 250 / 500 /
  1000 / 2000 / 4000 ms。
- `filter[2:0]`（0xF5 bit4-2）: IIR フィルタ係数（off, 2, 4, 8, 16）。
- `spi3w_en`（0xF5 bit0）: 3 線 SPI 用。I²C では触らない。

**データの組み立て方**

生の気圧 `up` は `press_msb << 12 | press_lsb << 4 | press_xlsb >> 4` の 20bit。
温度 `ut` も同様に `temp_msb / temp_lsb / temp_xlsb` から作る。xlsb は上位 4bit
（bit7-4）だけが有効で、下位 4bit は 0 である。

**補償係数のマップ**（datasheet Table 17, p.21）。アドレスの若い方が LSB。

| アドレス（LSB/MSB） | 名前 | 型 |
|---|---|---|
| `0x88`/`0x89` | `dig_T1` | unsigned short |
| `0x8A`/`0x8B` | `dig_T2` | signed short |
| `0x8C`/`0x8D` | `dig_T3` | signed short |
| `0x8E`/`0x8F` | `dig_P1` | unsigned short |
| `0x90`/`0x91` … `0x9E`/`0x9F` | `dig_P2` … `dig_P9` | signed short |
| `0xA0`/`0xA1` | reserved | — |

## 典型的な使い方

1. `0xD0` を読んで `0x58` が返ることを確認する（通信確認も兼ねる）。
2. 必要なら `0xE0` に `0xB6` を書いてソフトリセットし、既定状態から始める。
   リセット後は sleep mode で、`status` の `im_update` が落ちるまで NVM の
   コピーが走っている。
3. **`0x88` から 26 バイトを一括で読み、補償係数を取り出す。**
   個体ごとに違う値なので、電源投入ごと（あるいは初期化時に 1 回）必ず読む。
4. `0xF5`（`config`）を書く。t_sb と IIR フィルタを決める。**sleep mode のうちに書く。**
5. `0xF4`（`ctrl_meas`）を書く。osrs_t / osrs_p / mode を 1 バイトで同時に設定する。
   forced mode ならここで測定が 1 回走る。
6. 測定完了を待つ。forced なら Table 13（p.18）の最大測定時間だけ待つか、
   `0xF3` の `measuring` が 0 になるのを見る。normal なら Table 14（p.19）の ODR に
   合わせて読む。
7. **`0xF7` から 6 バイトをバースト読み出しする。** 気圧が先、温度が後である。
8. まず温度を補償計算して `t_fine` を作り、次にその `t_fine` を使って気圧を計算する。
   **順番は逆にできない。**
9. forced mode で次の測定が要るなら、5 に戻って `ctrl_meas` を書き直す。

## 利用上の注意

- **補償係数を読まずに生値を使うと、出てくる数字は完全に無意味である。** 0x88〜0xA1 の
  26 バイトは製造時に NVM へ書き込まれた**個体固有**の値で、隣の個体とは違う。
  「だいたい合っている値」にはならず、桁から違う。ライブラリを使わずに自分で叩くなら、
  ここを飛ばした時点で結果は捨てるしかない。
- **補償係数のバイト順は測定値と逆である。** 測定値（0xF7〜）は MSB first だが、
  補償係数は 16bit ワードごとに **LSB が先**（Table 17 のアドレス欄が
  「LSB / MSB」になっている）。ここを取り違えるとエラーにならず、それらしくない値が出る。
- **符号の有無を間違えやすい。** `dig_T1` と `dig_P1` だけが unsigned short で、
  残り（`dig_T2`, `dig_T3`, `dig_P2`〜`dig_P9`）は signed short である。
- **温度を先に計算しないと気圧が出ない。** 気圧の補償式は温度補償の途中で作られる
  `t_fine` を使う（§3.11.3, p.21-22）。したがって `osrs_t` を `000`（skipped）に
  すると温度が `0x80000` 固定になり、**気圧も計算できなくなる**。「気圧だけ欲しいから
  温度は要らない」は成立しない。
- **データレジスタは 1 回のバースト読み出しで読む。** normal mode では測定と読み出しが
  同期していないので、レジスタを個別に読むと前後の測定が混ざる。シャドウレジスタによる
  一貫性保証は「1 回のバースト読み出しの間」だけ有効で、I²C では STOP コンディションが
  バーストの終わりと見なされる（§3.9, §3.10, p.20）。
- **forced mode は 1 回で sleep に戻る。** 次の測定が欲しければ毎回 `ctrl_meas` を
  書き直す。書き忘れると、同じ古い値をずっと読み続けることになる（エラーは出ない）。
- **`config`(0xF5) への書き込みは normal mode では無視されることがある。** datasheet が
  明記している（§4.3.5, p.26）。フィルタや t_sb を変えるときは、いったん sleep mode に
  落としてから書く。
- **CSB を一度でも Low にすると、次の POR まで I²C が無効になる。** これは SPI トラフィックを
  I²C として誤解釈しないための仕様（§5.1, p.27）。CSB を GPIO 経由で VDDIO につないでいる
  基板では、その GPIO が電源投入時点で High になっていないと、チップは SPI モードに
  入ったまま I²C に一切応答しない。
- **SDO をフローティングにしてはいけない。** アドレスが不定になる（§5.2, p.28）。
- `0x80000`（= `press_msb`/`temp_msb` のリセット値 `0x80` から始まる並び）が読めたら、
  それは「測定値」ではなく **オーバーサンプリングが skipped である** か、
  まだ一度も測定していないかのどちらかである。
- **`0xE0` を読んでも `0xB6` は返らない。** 常に `0x00` である。書き込み専用レジスタを
  読み戻して検証する設計にはできない。
- **BME280 と間違えない。** 湿度チャンネルがあるのは BME280 で、id もレジスタマップも
  別物である。BMP280 に湿度レジスタは存在しない。
- M5Stack がホストしている PDF は Revision 1.14（2015 年）である。ファイル名は
  `BMP280-DS001-11` だが本文の版表記は 1.14 で、現行の Bosch 版 1.26 より古い。
  レジスタ表そのものは変わっていないが、参照するなら版を意識する。
