# QMP6988 — 絶対圧・温度センサ

> QST 製の絶対圧センサ。30〜110kPa を測り、温度も一緒に返す。出力は 24bit の生値で、
> **個体ごとに焼き込まれた補償係数を読んでホスト側で多項式を計算しないと、物理量にならない**。
>
> **確度**: QST の datasheet（Document# 13-52-13, Rev C, 2020-11-17）があり、レジスタ表と
> 補償式はそこに載っている。加えて **100kHz での実測がある**（observation
> `qmp6988-p0-100k-nominal-0283eb57c7a7c010` ほか 1 件）。chip ID `0x5C`、リセット既定値、
> 25 バイトの補償係数、forced / normal 測定は実機で確認済み。400kHz、SPI、
> オーバーサンプリング掃引、補償計算の結果は未確認。
>
> **本カタログで唯一「独立実装が存在しない」と確定しているデバイス**でもある。詳細は
> 下の「利用上の注意」を参照。

## これは何か

MEMS の絶対圧センサ。気圧を 30〜110kPa の範囲で測り、同じチップの温度センサの値も返す。
I2C でも SPI でも使える。M5Stack では Unit ENV-III（`0x70`）と Unit Mini BPS v1.1（`0x56`）に
載っている。

**このセンサは Pa も °C も出力しない。** 出るのは 24bit のオフセットバイナリの生値だけで、
そこから物理量を得るには次の 2 段階が要る。

1. OTP に焼かれた**個体固有の補償係数** 25 バイト（`0xA0`〜`0xB8`）を読む。
2. その係数を使って、ホスト側で温度 → 気圧の順に多項式を評価する。

温度は 2 次式、気圧は温度と気圧の 3 次までの項を含む 9 項の式。**係数は個体ごとに違う**ので、
1 個の実機で読んだ値を他の個体に使い回すことはできない。生値だけを保存しても、後から
物理量に戻せない。

### できないこと・持っていないもの

- **チップ内で補償計算をしない。** BMP280 などと同じく、生値と係数を出すところまでが
  センサの仕事。Pa への変換はホストの責任。
- **高度は出さない。** 気圧から高度を求めるのはホスト側の計算で、しかも海面気圧の入力が要る。
- **湿度は測らない。** Unit ENV-III では SHT30（`0x44`）が別の I2C デバイスとして同居している。
- **データレディの割り込み線が無い。** 測定完了を知るには `DEVICE_STAT`（`0xF3`）の
  measure ビットをポーリングするしかない。
- **補償係数は書き換えられない。** 読み出し専用の OTP。
- **VPP ピン（9 番）は内部専用。** 他のピンに繋ぐと動作しない。開放にすること。
- **液体・腐食性ガス・結露の下では使えない。** さらに datasheet は
  **「超音波を含む高周波振動下で使わないこと」**を明記している（7. Precautions (2) 10)）。

### 電気的な現実

- **VDD 1.71〜3.6V。絶対最大 4.0V。5V は入らない。** VDDIO は 1.2〜3.6V。
  Grove の赤線は 5V なので、裸のチップを Grove に直結してはいけない。
- 消費電流は測定モードで 640µA typ（気圧）、スリープで 1.1µA typ。1 サンプル/秒の
  forced mode（Ultra High Accuracy）で平均 21.4µA。
- SDO ピンの H / L で I2C アドレスが `0x56` / `0x70` に決まる。基板で固定されるので、
  ソフトから変えることはできない。
- CSB を VDDIO に上げると I2C、GND に落とすと SPI。**一度 SPI に落ちると、POR か
  非同期リセットまで I2C には戻らない。**
- 電源投入から使えるまで最大 10ms。
- 圧力の絶対最大は 800kPa。

## レジスタ / コマンド

レジスタは 8bit、読み出しは自動インクリメントする（`0xFF` に達するとそれ以降は `0xFF` を
返し続ける）。

| アドレス | 長さ | R/W | 意味 |
|---|---|---|---|
| `0xA0`〜`0xB8` | 25 | R | 補償係数（OTP）。**個体固有**。`COE_b00_1` から `COE_b00_a0_ex` まで |
| `0xD1` | 1 | R | `CHIP_ID` = `0x5C` |
| `0xE0` | 1 | W | `RESET`。**`0xE6` を書いたときだけ**ソフトリセット。他の値では何も起きない |
| `0xF1` | 1 | R/W | `IIR`。bit2:0 = フィルタ係数。既定 `0x00` |
| `0xF2` | 1 | R/W | `I2C_SET`。bit2:0 = I2C 高速モードのマスタコード。既定 `0x01` |
| `0xF3` | 1 | R | `DEVICE_STAT`。bit3 = `measure`、bit0 = `otp_update` |
| `0xF4` | 1 | R/W | `CTRL_MEAS`。bit7:5 = 温度平均回数、bit4:2 = 気圧平均回数、bit1:0 = power mode |
| `0xF5` | 1 | R/W | `IO_SETUP`。bit7:5 = standby 時間、bit2 = `spi3_sdim`、bit0 = `spi3w` |
| `0xF7`〜`0xF9` | 3 | R | 気圧の生値。`0xF7` が上位（MSB first） |
| `0xFA`〜`0xFC` | 3 | R | 温度の生値。`0xFA` が上位（MSB first） |

`0xF7` から 6 バイトを burst read すると、**気圧 3 バイト → 温度 3 バイト**の順で取れる。
`profiles/qmp6988.yaml` の `raw-data` はこの形。

### `CTRL_MEAS`（`0xF4`）のビット

- bit7:5 温度の平均回数、bit4:2 気圧の平均回数。どちらも
  `000`=skip / `001`=1 / `010`=2 / `011`=4 / `100`=8 / `101`=16 / `110`=32 / `111`=64。
  `skip` はその測定を行わない。
- bit1:0 power mode。`00`=sleep / `01`,`10`=forced / `11`=normal。

実測で使った値: `0x25` = 温度 1 回・気圧 1 回・forced、`0x27` = 同じ平均回数で normal、
`0x24` = 同じ平均回数で sleep。

### `IO_SETUP`（`0xF5`）の standby

bit7:5 で `000`=1ms / `001`=5ms / `010`=50ms / `011`=250ms / `100`=500ms / `101`=1s /
`110`=2s / `111`=4s。normal mode で測定と測定の間に入る時間。

### `IIR`（`0xF1`）の係数

bit2:0 で `000`=off / `001`=N=2 / `010`=N=4 / `011`=N=8 / `100`=N=16 / `101`〜`111`=N=32。
既定は off。

### 生値から物理量へ

```
Dt = (TEMP_TXD2 << 16 | TEMP_TXD1 << 8 | TEMP_TXD0) − 2^23
Dp = (PRESS_TXD2 << 16 | PRESS_TXD1 << 8 | PRESS_TXD0) − 2^23

Tr = a0 + a1·Dt + a2·Dt²                                     … 単位は 256×℃
Pr = b00 + bt1·Tr + bp1·Dp + b11·Tr·Dp + bt2·Tr² + bp2·Dp²
     + b12·Dp·Tr² + b21·Dp²·Tr + bp3·Dp³                     … 単位は Pa
```

**`Tr` の単位は ℃ ではなく 256×℃**（datasheet の表記は `[256 degreeC]`）。また `Pr` の式に
`Tr` が入るので、**温度を先に計算する**という順序が決まっている。

`a0`〜`bp3` は OTP の生バイトそのものではなく、係数ごとの変換係数 A / S を使って換算する。
**その換算式自体は datasheet の p.15 に図として埋め込まれており、テキスト抽出では A / S の
表しか残らない。実装するときは PDF の 15 ページを直接見ること。**

## 典型的な使い方

1. `0xD1` を読んで `0x5C` を確認する（存在確認を兼ねる）。
2. 必要なら `0xE0` に `0xE6` を書いてソフトリセットする。リセット後は I2C モードに戻り、
   レジスタが既定値になる（実測では `0xF1`〜`0xF5` が `00 01 00 00 00`）。
3. `0xA0` から **25 バイトを burst read** して補償係数を取る。datasheet 4.3 ② のとおり、
   **POR 後に 1 回で足りる**。
4. 必要なら `0xF1`（IIR）と `0xF5`（standby）を設定する。
5. **単発なら** `0xF4` に「温度平均・気圧平均・power_mode=`01`」を書く。1 回測ったら
   自動で sleep に戻る。
6. `0xF3` の bit3（measure）が 0 に戻るまで待つ。実測では平均 1 回の forced で約 4.7ms。
7. `0xF7` から 6 バイト burst read する。
8. 2^23 を引いて `Dp` / `Dt` を作り、**温度 → 気圧**の順に補償する。

**連続測定なら** 5. で power_mode=`11`（normal）を書き、standby 時間ごとに更新される値を
`0xF7` から読み続ける。止めるときは power_mode=`00`（sleep）を書く。

## 利用上の注意

- **独立実装が存在しない。** Arduino Library Manager のインデックスを全文検索しても、
  QMP6988 を叩けるライブラリは **M5Stack 自身の `M5Unit-ENV` ただ 1 つ**しか出てこない
  （確認日 2026-08-15、`profiles/qmp6988.yaml` の notes）。つまり **「2 つの独立した実装を
  突き合わせて解釈の正しさを裏取りする」という手が使えない**。Arduino 以外（Tasmota、Zephyr）
  には実装があるが、それを移植しても「自分で書いたドライバ」が増えるだけで、独立した証拠には
  ならない。ライブラリの解釈が間違っていても気づく手段が無い前提で扱うこと。
  同じ理由から、本カタログの library probe の比較軸はこのチップについてだけ空いている。
- **生値は係数無しでは無意味で、係数は個体固有。** 実測した個体の 25 バイトは
  `52DC0DA7F4820DDC0CD201E6FC86F9C9FAA2F72B0CBB03D8BB` だが、**これはこの個体だけの値**である。
  ファームに焼き込んだり、別の個体で使い回したりしてはいけない。生値だけをログに残すと、
  後から Pa に戻せない。
- **forced mode は 1 回測ると sleep に戻る。** 測定のたびに `CTRL_MEAS` を書き直す必要がある。
  書かずに `0xF7` を読むと、前回の値がそのまま返る（エラーにはならない）。
- **normal mode の更新はホストと同期しない。** 6 バイトを別々のトランザクションで読むと、
  途中で値が更新されて気圧と温度の時刻がずれる。**1 回の burst read で 6 バイトまとめて読む。**
- **`IIR`（`0xF1`）に書くとフィルタが初期化される。** datasheet が明記している。設定を
  「読んで書き戻す」だけでも初期化されるので、read-modify-write のつもりで触ると
  フィルタの内部状態が飛ぶ。
- **予約ビットは 0 のまま保つ。** `IO_SETUP` の bit4:3 と bit1、`DEVICE_STAT` の bit7:4 と
  bit2:1、`I2C_SET` の bit7:3、`IIR` の bit7:3 が予約。read-modify-write のときに壊さないこと。
- **共有バスで 400kbit/s 超のときは 1ms 空ける。** datasheet 4.9 が、他のセンサと通信した後
  QMP6988 に話しかけるまで **1ms 以上の待ち時間**を推奨している。Unit ENV-III はまさに
  SHT30（`0x44`）と同じバスに同居する構成なので、該当する。**本カタログの実測は 100kHz のみ**で、
  400kHz でこの問題が出るかは確かめていない。
- **アドレス `0x70` は PaHub とぶつかる。** 本カタログでは `pca9548a` / `tca9548a`
  （Unit PaHub）が `0x70` を使う。ENV-III を PaHub の**下流**に付けるのは正しい使い方だが、
  PaHub と同じ階層に並べると衝突する。`0x56` 側（Mini BPS）は `m5stack-mcu-u189`
  （Unit TimerPWR）と衝突する。SDO ピンで選べるのはこの 2 通りだけなので、逃げ場が狭い。
- **5V を掛けない。** VDD の絶対最大が 4.0V。M5Stack の Unit として使う分には基板側で
  処理されているが、チップ単体を扱うときは注意する（Unit の電源構成そのものは未確認）。
- **RST ピンを開放にしない。** 使わないなら GND に落とす。VPP（9 番）は内部専用で、
  他のピンと繋ぐと動作しない。
- **測定時間はオーバーサンプリング設定で 6 倍違う。** 5.5ms（気圧 2×/温度 1×）から
  33.7ms（気圧 32×/温度 4×）まで。固定待ち時間で実装するなら遅い方に合わせるか、
  `DEVICE_STAT` をポーリングする。
- **「Yamaha の設計」という通説には根拠が無い。** 公式 datasheet に該当する記述は無く、
  製造元は QST Corporation（矽睿、上海）である（`chips/qmp6988.yaml` の notes）。
- **datasheet 内で係数名の表記が揺れている。** 4.4 のレジスタ一覧では `COE_b12_*` /
  `COE_b21_*` だが、4.3 の変換係数表では `C0E_bp12_*` / `C0E_bp21_*` と書かれている。
  同じものを指している。

## 出典と確度

- レジスタ表、ビット定義、補償式、タイミング: **QMP6988 Datasheet, Document# 13-52-13,
  Rev C（2020-11-17）**。QST の公式サイトには生きた URL が無く（製品ページが 404）、
  M5Stack がホストしているコピーが本物の QST 文書である（Doc# と Rev が入っている）。
- **実測で確認済み**: `observations/qmp6988/qmp6988-p0-100k-nominal-0283eb57c7a7c010.yaml`
  および `...-a6ec5b99888f5897.yaml`。`0x70` の presence、chip ID `0x5C`、リセット後の
  `0xF1`〜`0xF5` = `00 01 00 00 00`、25 バイトの補償係数（個体固有）、forced 測定
  （`CTRL_MEAS`=`0x25`、約 4.7ms で完了、measure ビットの 0→1→0 を観測）、
  normal 測定 10 サンプル。**いずれも 100kHz、nominal 条件のみ。**
- `conversions` の `raw-offset-binary`（24bit オフセットバイナリ、offset 8388608）は
  datasheet 由来で `confidence: tentative`。
- **未確認**: 400kHz および 3.4MHz の高速モード、SPI モード、オーバーサンプリング掃引、
  IIR 掃引、standby 掃引、予約ビットへの書き込み（`scenarios/qmp6988/p0.yaml` の `deferred`）。
- **未確認**: 補償計算の結果。生値と係数は取れているが、算出した Pa / ℃ を外部の基準と
  突き合わせていない。係数の bit packing・符号・エンディアンの展開も未検証。
- **未確認**: 係数の換算式そのもの。datasheet p.15 の図として埋め込まれており、
  テキスト抽出では A / S の表しか残っていない。
- **未確認**: Unit ENV-III / Unit Mini BPS の基板上の電源構成（Grove の 5V をどう扱っているか）。
