# ST25R3916 — NFC / HF RFID フロントエンド

> 13.56MHz の NFC リーダ / ライタ / カードエミュレーション用アナログフロントエンド。
> **レジスタ空間が A と B の 2 面に分かれていて、コマンドで切り替える。**したがって
> 「アドレス → 意味」の平坦なレジスタ表ではこのチップを記述できない。同じアドレス `0x0B` が、
> 空間 A では受信設定 1、空間 B では P2P 受信設定 1 を指す。
>
> **確度**: STMicroelectronics の datasheet **DS12484 Rev 8（2023-05）**に基づく。
> **実測は未着手**で、`profiles/st25r3916.yaml` の evidence は `datasheet` / `tentative`、
> `observations/st25r3916/` はまだ無い。さらに後述のとおり、**M5Stack Unit NFC の配線では
> ST 公式の Arduino ドライバを動かせない**という制約がある。

## これは何か

NFC の物理層とフレーミングを丸ごと引き受ける IC。アンテナを直接駆動する送信ドライバ、
受信の復調・復号、512 バイトの FIFO、CRC、各種タイマ、そしてカード検出用の低消費電力
センサまでが 1 チップに入っている。ホストはプロトコルの上位（コマンドの組み立て、
アンチコリジョンの手順、アプリケーション層）を担当する。

**できること**（Features, p1 / Table 1, p11）:

- NFC-A / ISO14443A、NFC-B / ISO14443B（いずれも最大 848kbit/s）、NFC-F / FeliCa（424kbit/s）、
  NFC-V / ISO15693（53kbit/s）のリーダ動作。
- **カードエミュレーション**（NFC-A / NFC-F）と、**能動・受動のピアツーピア**（ISO18092）。
  ここが単なるリーダ IC との差である。
- EMVCo 3.0 のアナログ / デジタル要件に適合。決済端末向けの設計。
- アンテナの自動同調（AAT）、動的出力制御（DPO）、波形整形（AWS）、ノイズ抑圧受信（NSR）。
- カードが近づいたことを、**RF フィールドを出さずに**検出する（静電容量センサ、
  あるいはアンテナ振幅・位相の測定）。低消費電力の待ち受けができる。
- アンテナ電圧の振幅・位相、RSSI、内部電源電圧の測定。

**できないこと・持っていないもの**:

- **MIFARE Classic の暗号（Crypto1）を内蔵していない。** datasheet は「MIFARE Classic 準拠
  またはその他の独自プロトコルを実装するための低レベルモード」と書いている（Features, p1）。
  つまり**暗号処理はホスト側の実装**であり、このチップは生のフレームを出し入れするだけ。
  MFRC522 のように「認証コマンドを投げれば済む」わけではない。
- **プロトコルスタックを内蔵していない。** アンチコリジョン、SELECT、上位のタグ操作は
  すべてホストのソフトウェア（ST の RFAL ライブラリなど）が行う。
- **タグのメモリを直接読む機能は無い。** FIFO 越しにフレームを送受信するだけ。
- **平坦なレジスタマップを持たない**（後述）。
- **本ユニットの配線では割り込み線が使えない。** ST25R3916 は IRQ ピンで完了通知を出す
  設計で、直接コマンドの一部は「完了するまで I2C にアクセスしてはならない」（§4.3.4
  Direct command mode, p57）。**M5Stack Unit NFC の Grove コネクタには SDA / SCL / 5V / GND
  しか出ていない。**

**電気的な現実**:

- VDD 2.4–5.5V（-20〜105℃、-40℃ まで見るなら 2.6V 以上）、周辺 IO 電圧 VDD_IO は
  1.65–5.5V（§2 Description, p12）。**電源系統が複数に分かれている**（VDD、VDD_TX、
  VDD_A、VDD_RF、VDD_AM）ので、単体で回路を起こすのは易しくない。
- 27.12MHz ではなく**水晶発振器**を持ち、これが安定するまで送受信できない（§4.2, p23）。
  安定通知は割り込みで来る。
- I2C を使うには **I2C_EN ピンを VDD_D に引く**必要がある（Table 12, p54）。SPI にするなら
  GND。基板上で決まっている。
- **IRQ はアクティブ High の CMOS 出力**（Table 9, p47）。オープンドレインではない。

## レジスタ・コマンド

### 平坦なレジスタ表では書けない、という話

datasheet はこう書いている（§4.5, p68）:

> ST25R3916/7 は 2 つのレジスタ空間を持ち、それぞれ最大 64 本のレジスタを `00h`〜`3Fh` の
> アドレス範囲に持つ。1. レジスタ空間 A（Rs-A）、2. レジスタ空間 B（Rs-B）。

**同じアドレスに 2 つの意味がある。** 例:

| アドレス | 空間 A | 空間 B |
|---|---|---|
| `0x05` | ISO14443A / NFC 106kb/s 設定 | EMD 抑圧設定 |
| `0x06` | ISO14443B 設定 1 | サブキャリア開始タイマ |
| `0x0B` | 受信設定 1 | P2P 受信設定 1 |
| `0x0C` | 受信設定 2 | 相関器設定 1 |

空間 B は空間 A ほど密ではなく、飛び飛びに定義されている（Table 18, p70 以降）。

したがって `profiles/st25r3916.yaml` は**レジスタ一覧を持たず**、`register_spaces` という
形で「空間の切り替えをモデル化しないと駆動できない」ことだけを記録している。これは
coverage の不足ではなく、**このチップの構造をそのまま反映した意図的な記述**である。

### トランザクションの形

I2C では、スレーブアドレスの後に **SPI と共通のモードバイト**を置く（§4.3.4, p55）。
モードバイトの上位 2 ビットが操作の種類、下位 6 ビットがレジスタアドレスまたはコマンド
コードである（Table 11, p50）。

| モード | 上位 2bit | 残り 6bit | 続くもの |
|---|---|---|---|
| レジスタ書き込み | `00` | アドレス A5-A0 | データ 1 バイト以上（自動インクリメント） |
| レジスタ読み出し | `01` | アドレス A5-A0 | repeated START の後にデータ |
| FIFO ロード | `10` | `000000` | FIFO へ書くデータ |
| FIFO 読み出し | `10` | `011111` | FIFO から読むデータ |
| PT_memory 各種 | `10` | 個別のパターン | パッシブターゲット用メモリ |
| 直接コマンド | `11` | コマンドコード C5-C0 | 無し |

**空間 B へのアクセス**（§4.3.4「I2C access to register space-B」, p57、Figure 26）:

```
書き込み: S | 0x50+W | 0xFB | モードバイト(レジスタアドレス) | データ... | P
読み出し: S | 0x50+W | 0xFB | モードバイト(レジスタアドレス) | Sr | 0x50+R | データ... | P
```

**`0xFB` を挟んだ後、空間 B は STOP コンディションを受け取るまで有効なまま**である。
ホスト側のドライバが「STOP を出す前に別のことをする」と、意図せず空間 B の側を
叩くことになる。

### 直接コマンド（§4.4 / Table 13, p59-60）

レジスタ書き込みとは別に、モードビット `11` で送る「直接コマンド」がある。主なもの:

| コード | 名前 | 備考 |
|---|---|---|
| `C0`/`C1` | Set default | パワーアップ直後の状態に戻す |
| `C2`/`C3` | Stop all activities | 送受信・コマンド実行・タイマを止める |
| `C4` | Transmit with CRC | CRC 自動付加で送信 |
| `C5` | Transmit without CRC | |
| `C6` / `C7` | Transmit REQA / WUPA | ISO14443A 専用 |
| `C8` / `C9` | NFC initial / response field ON | RF 衝突回避をしてフィールドを出す。**完了時に割り込み** |
| `D3` | Measure amplitude | 結果は A/D 変換出力レジスタへ。**完了時に割り込み** |
| `D9` | Measure phase | **完了時に割り込み** |
| `FB` | Register space-B access | 上記の空間切り替え（Table 13 にも載っている） |
| `FC` | Test access | 後述の初期化手順で使う |

**一部の直接コマンドは実行に時間がかかり、その間 I2C にアクセスしてはならない**
（§4.3.4, p57）。完了は**割り込みで通知される**。つまり IRQ が使えない構成では、
これらのコマンドは「終わったかどうか分からないまま待つ」ことになる。

### 割り込みレジスタは read で消える

割り込みレジスタは 4 本ある（Main / Timer and NFC / Error and wake-up / Passive target、
空間 A の `0x1A`〜`0x1D`）。**読むと内容が 0 にリセットされる**（§4.3.1, p47）。
IRQ ピンは、High にした原因のビットが全部読まれた時点で Low に戻る。

マスクされた割り込みも、IRQ ピンは動かないがステータスビットは立つ。**読み出しは
マスクされたビットも同時にクリアする**（§4.3.1, p47）。

## 典型的な使い方

datasheet §4.1「Power-on sequence」（p23）が定める順序:

1. 電源投入。デバイスは Power-down モードに入り、全レジスタが既定値になる。
2. **`FCh` / `04h` / `10h` の 3 バイトフレームを送る。** datasheet はこれを
   「内部の過熱保護がジャンクション温度以下でトリガするのを防ぐため、電源投入後および
   Set default コマンドの後に送らなければならない」と書いている。**これは省略できない
   初期化手順であり、どの Set default の後にも要る。**
3. IO configuration register 1 / 2（空間 A の `0x00` / `0x01`）を適切に設定する。
4. 内部レギュレータを設定する。直接コマンド「Adjust regulators」（`D6`）を使うことが
   推奨されている。
5. AAT を使うなら同調手順を行う。

ここまで済んで初めて動作可能な状態になる。その後は Operation control register（`0x02`）の
`en` ビット（b7）を立てて Ready モードに上げ、水晶が安定した旨の割り込みを待つ
（§4.2, p23）。送信 `tx_en` と受信 `rx_en` は独立に有効化できる。

**デバイスがそこに居るかの確認だけなら、もっと簡単な方法がある。** モードバイトを
省略してスレーブアドレスの直後にいきなり読むと、**まず `FFh` が返り、続いてアドレス `01h`
からのレジスタダンプが流れてくる**（§4.3.4 Figure 27, p58）。datasheet 自身が
「I2C デバイスの検出を容易にするために用意した機能で、通常運用で使うものではない」と
説明している。`scenarios/st25r3916/p0.yaml` の `device-detection` / `space-a-bytes` は
この経路を想定している。

IC の素性は空間 A の `0x3F`（IC identity register, Table 117, p135）で分かる。
**上位 5 ビット `ic_type` が `00101` なら ST25R3916/7**。下位 3 ビットが版数で、
表に載っている既定値は `010`（rev 3.1）。

## 利用上の注意

- **空間 A / B の切り替えを忘れると、静かに間違ったレジスタを叩く。** アドレスは両方に
  存在するので、エラーにはならない。**値がおかしいだけ**である。`0xFB` を挟んだ後の
  有効範囲が「次の STOP まで」であることも合わせて、ドライバの実装で最も事故が起きる箇所。
- **存在しないレジスタを読むと all 0 が返る**（§4.3.4, p55）。**NACK ではない。**
  レジスタスキャンをしても「空きかどうか」が値からは判別できない。書き込みのほうは、
  SPI の書き込みモードの説明（§4.3.3, p50）に「定義されたアドレスのレジスタが存在しない、
  または読み出し専用の場合、書き込みは行われない」とある。**I2C 側に同じ記述は無い**が、
  モードバイトが共通である以上、同じ振る舞いとみるのが自然。
- **割り込みレジスタ `0x1A`〜`0x1D` は read で消える**（§4.3.1, p47）。2 か所から読むと
  片方が取りこぼす。読む場所を 1 つに決める。デバッグ用に「とりあえずダンプ」する
  コードを入れると、本来のハンドラが割り込みを見失う。
- **モードバイトを省略した read はレジスタダンプになる**（Figure 27, p58）。
  「1 バイトだけ読んで疎通確認」のつもりのコードが、`FFh` + `01h` からのダンプの
  先頭 1 バイト（= `FFh`）を読んでいる、ということが起きる。
- **`FCh 04h 10h` を送らないと過熱保護が誤作動しうる**（§4.1, p23）。電源投入後だけでなく
  **Set default（`C0`/`C1`）の後にも必要**。ライブラリの初期化を自前で書き換えるときに
  落としやすい。
- **時間のかかる直接コマンドの実行中は I2C を触ってはいけない**（§4.3.4, p57）。
  完了は割り込みで通知される。IRQ を配線していない環境では、時間で待つしかない。
- **`0x50` は EEPROM の定番アドレス帯（`0x50`-`0x57`）の先頭。** この catalog でも
  `0x50` を名乗るのは ST25R3916 のほかに Unit ACSSR コントローラ（`m5stack-mcu-u139`）と
  Unit DCSSR コントローラ（`m5stack-mcu-u140`）がある。24Cxx 系の EEPROM を同じバスに
  載せると衝突する可能性が高い。**ST25R3916 側にアドレス変更の記載は datasheet に無い。**
- **速度の記述が文書内で食い違っている。** 表紙の Features（p1）は「I2C は Fast モード
  400kbit/s まで」、§4.3.4（p54）は「標準 100kHz / Fast 400kHz / Fast+ 1MHz /
  High-speed 3.4MHz」。**安全側に倒すなら 400kHz まで**とみなすのが妥当。
  `scenarios/st25r3916/p0.yaml` も 100kHz / 400kHz だけを対象にしている。
- **IRQ を使えない構成では機能の大半が使えない。**（次節）

### Unit NFC で ST 公式 Arduino ドライバが動かない理由

`profiles/st25r3916.yaml` の `notes` に記録済みの調査結果（2026-08-15 時点）:

- ST は Arduino 向けドライバを公開している（[stm32duino/ST25R3916](https://github.com/stm32duino/ST25R3916)）。
  **I2C にも対応している** — `RfalRfST25R3916Class` は `TwoWire` を取るコンストラクタを持つ。
- しかしこのドライバは **ST25R3916 の IRQ 線を必須としている。**
  `st25r3916CheckForReceivedInterrupts` が `while (digitalRead(int_pin) == HIGH)` で
  **タイムアウト無しにスピンする**。IRQ が繋がっていなければ、そこでスケッチが固まる。
- **M5Stack Unit NFC の Grove コネクタは SDA / SCL / 5V / GND の 4 本しか出していない。**
  IRQ パッドは外に出ていない。ベンダーのライブラリが I2C でポーリングする作りに
  なっているのも、おそらく同じ理由である。
- したがって**「ST 公式ドライバ vs ベンダーライブラリ」の比較キャプチャは、
  IRQ パッドを引き出す配線を実機に施さない限り取れない。** ハードウェアが手元に
  必要な作業であり、現時点では未着手。

これは「ドライバが無い」のではなく「**このユニットの配線ではドライバの前提が満たせない**」
という制約である。ガイドとしてはここが最も実用上重要な注意点になる。

## 出典と確度

- 参照した文書: **ST25R3916 / ST25R3917 datasheet DS12484 Rev 8（2023-05）**。
  ただし入手元は ST の公式サイトではなく、**M5Stack がホストしているコピー**
  （`m5stack-doc.oss-cn-shenzhen.aliyuncs.com/1229/st25r3916_datasheet.pdf`）。
  文書自体は ST の正規の DS12484 Rev 8 である。
- I2C アドレス `0x50`、モードバイトの構造、空間 A / B と `0xFB` による切り替え、
  空間切り替えが STOP まで有効なこと、存在しないレジスタが all 0 を返すこと、
  モードバイト省略時のレジスタダンプ、割り込みレジスタが read でクリアされること、
  電源投入時の `FCh 04h 10h`、IC identity register の値、直接コマンド一覧:
  **すべて datasheet に明記がある。**
- **未確認（実測なし）**: `0x50` が実際に ACK するか、モードバイト省略の read が本当に
  `FFh` + ダンプを返すか、`0x3F` が返す実際の値（特に版数フィールド）、400kHz で動くか。
  `observations/st25r3916/` はまだ無い。
- **未調査**: `scenarios/st25r3916/p0.yaml` では `space-b-select`、`direct-commands`、
  `rf-field-enable`、`register-map-confirmation` がすべて deferred。つまり
  **空間 B の切り替えも直接コマンドも、一度も実機で試していない。**
- **datasheet では確認できなかったこと**: `chips/st25r3916.yaml` の注記にある
  「1.4W ドライバ」という数値は、本 datasheet の抽出テキストからは見つけられなかった。
  ST の製品ページ由来の表現と思われる。datasheet が言っているのは
  「高い RF 出力でアンテナを直接高効率に駆動する」という定性的な記述だけ（§2, p12）。
- **ハードウェアの制約**: ST 公式 Arduino ドライバ（stm32duino/ST25R3916）は I2C に
  対応しているが、`st25r3916CheckForReceivedInterrupts` がタイムアウト無しで IRQ ピンを
  スピン待ちするため、IRQ が未結線の Unit NFC では使えない。Unit NFC の Grove コネクタは
  SDA / SCL / 5V / GND の 4 本のみ。**この確認は 2026-08-15 時点のもの**で、
  `profiles/st25r3916.yaml` の `notes` に記録済み。**IRQ パッドを引き出さない限り、
  ドライバ比較のキャプチャは取得できない。**
