# BME688 — ガス・温度・湿度・気圧の複合センサ（加熱プロファイル付き）

> BME680 に「ガススキャナ」機能を足した 4-in-1 環境センサ。**そのまま読める値は 1 つも無い。**
> 気圧も温度も湿度も、個体ごとに違う補正パラメータを EEPROM から読んで多項式に通して初めて
> 物理量になる。ガス側はヒータの温度と加熱時間をユーザが設計する必要がある。
>
> **確度**: Bosch Sensortec の datasheet
> [BST-BME688-DS000-03 Revision 1.3（2024-02）](https://www.bosch-sensortec.com/media/boschsensortec/downloads/datasheets/bst-bme688-ds000.pdf)
> に基づく。本文のレジスタアドレス・ビット定義・補正式の変数名はすべてこの文書由来で、
> **ライブラリ実装から補った箇所は無い。** 実測での確認はしていない
> （`observations/bme688/` は未取得）。

## これは何か

Bosch Sensortec の 3.0 × 3.0 × 0.93 mm の金属蓋 LGA パッケージに、
金属酸化物式ガスセンサ・気圧センサ・湿度センサ・温度センサを詰め込んだ複合センサ。
ガスセンサは「加熱したホットプレートの上に載った感応膜の抵抗値」を測る方式で、
**何 ppm の何が居るか**ではなく **Ω の抵抗値**が返る。

できること:

- 気圧 300–1100 hPa、湿度 0–100 %r.H.、温度 −40〜+85°C を測る。
- VOC（揮発性有機化合物）・VSC（揮発性硫黄化合物）・CO・H2 などによるガス抵抗の変化を測る。
- 温度・気圧・湿度それぞれに ×1〜×16 のオーバーサンプリングを設定する。
- 温度・気圧に IIR フィルタ（係数 0〜127）をかける。
- **最大 10 段のヒータプロファイル**（目標温度と加熱時間の組）を登録し、ホストの介入なしに
  順番に実行させる（parallel mode）。
- Forced mode で 1 回だけ測って自動的に sleep に戻る、という低消費な使い方をする。
- SDO ピンでアドレスを 2 通り選ぶ。

できないこと・持っていないもの:

- **補正パラメータを読まずに使えない。** 生の ADC 値を温度・気圧・湿度に直すには
  `par_t*` `par_p*` `par_h*` を読む必要があり、**これらは個体ごとに違う**。
  さらに厄介なことに、**これらのレジスタは datasheet のメモリマップ（Table 22）に載っていない。**
  各補正式の説明の中の Table 13 / 14 / 15 に散らばって書かれている。
- **IAQ（空気質指数）や CO2 相当値は出ない。** datasheet が定義しているのはガス抵抗（Ω）まで。
  IAQ・bVOC・CO2 相当は Bosch の BSEC ソフトウェア（別配布、§4）が計算するもので、
  チップの出力ではない。
- **AI ガススキャナも同様。** BME AI-Studio で学習したモデルをホスト側で走らせる話であり、
  チップが分類結果を返すわけではない。
- **割り込み線が I2C では使えない。** `spi_3w_int_en` は SPI 3 線モード専用。
  I2C では `new_data` ビットをポーリングする。
- **ガス濃度の絶対値が出ない。** 抵抗値は温度・湿度・エージングで動く。
  比較や傾向は見えるが、校正なしに「何 ppm」とは言えない。
- **CSB がフロートすると I2C に応答しない。** CSB を一度でも Low に引くと、
  次の電源投入まで I2C が無効化される（SPI と誤認しないための設計）。

## レジスタ

[`profiles/bme688.yaml`](https://github.com/tanakamasayuki/I2CDeviceDB/blob/38f1d82/profiles/bme688.yaml) が抜き出している代表レジスタに、
datasheet のビット位置と単位を足したもの。**すべて 8bit 幅。**
アドレスは I2C のもの（SPI ではページ切り替えが要るが、I2C では `0x00`–`0xFF` が平坦に見える）。

### 識別・制御

| アドレス | key | 名前 | R/W | 中身 |
|---|---|---|---|---|
| `0xD0` | `chip-id` | Chip_Id | R | `0x61` 固定 |
| `0xF0` | — | Variant_Id | R | BME688 は `0x01`（BME680 と区別する） |
| `0xE0` | `reset` | Reset | W | **`0xB6` を書くと電源投入と同じソフトリセット** |
| `0x72` | `ctrl-hum` | Ctrl_hum | R/W | bit6 = `spi_3w_int_en`（SPI 用）、bit2:0 = `osrs_h` |
| `0x74` | `ctrl-meas` | Ctrl_meas | R/W | bit7:5 = `osrs_t`、bit4:2 = `osrs_p`、**bit1:0 = `mode`** |
| `0x75` | `config` | Config | R/W | bit4:2 = `filter`（IIR 係数）、bit0 = `spi_3w_en` |
| `0x70` | — | Ctrl_gas_0 | R/W | bit3 = `heat_off`（ヒータ停止） |
| `0x71` | `ctrl-gas-1` | Ctrl_gas_1 | R/W | **bit5 = `run_gas`**、bit3:0 = `nb_conv`（使うヒータステップ数 / 番号） |

`osrs_h` / `osrs_t` / `osrs_p` の値はいずれも同じ:
`000`=スキップ（出力は `0x8000` 固定） / `001`=×1 / `010`=×2 / `011`=×4 / `100`=×8 / `101` 以上=×16。

`mode`: `00`=Sleep（既定） / `01`=Forced / `10`=Parallel。

`filter`: `000`=0（フィルタ無し） / `001`=1 / `010`=3 / `011`=7 / `100`=15 / `101`=31 / `110`=63 / `111`=127。
**IIR は温度と気圧にだけ効く。湿度とガスには効かない。**

### ヒータ制御

| アドレス | key | 名前 | 中身 |
|---|---|---|---|
| `0x5A`–`0x63` | `res-heat-0` は `0x5A` | Res_heat_0..9 | 目標ヒータ抵抗のレジスタ値。**温度から計算して書く**（後述） |
| `0x64`–`0x6D` | `gas-wait-0` は `0x64` | Gas_wait_0..9 | Forced mode では bit5:0 = 1ms 刻みのタイマ値、**bit7:6 = 倍率（`00`=1 / `01`=4 / `10`=16 / `11`=64）**。Parallel mode では 8bit 全体が TPHG シーケンスの繰り返し回数 |
| `0x6E` | — | Gas_wait_shared | Parallel mode の各 TPHG シーケンス前の待ち時間 |
| `0x50`–`0x59` | — | Idac_heat_0..9 | 初期ヒータ電流（任意。指定しなくても制御ループが収束する） |

### 測定データ（フィールド）

データは 3 つの「フィールド」に格納される。**Forced mode では field 0 だけ**、
Parallel mode では 0 → 1 → 2 と FIFO 順に埋まる。

| フィールド | 先頭 | 長さ | 内訳 |
|---|---|---|---|
| field 0 | `0x1D` | 17 バイト | 下表 |
| field 1 | `0x2E` | 17 バイト | field 0 と同じ並びで +`0x11` |
| field 2 | `0x3F` | 17 バイト | field 0 と同じ並びで +`0x22` |

field 0 の内訳（`profiles/bme688.yaml` の `data-field0` が指しているもの）:

| アドレス | 中身 |
|---|---|
| `0x1D` | meas_status: **bit7 = `new_data`**、bit6 = `gas_measuring`、bit5 = `measuring`、bit3:0 = `gas_meas_index` |
| `0x1E` | sub_meas_index（TPHG シーケンス番号） |
| `0x1F` / `0x20` / `0x21`<7:4> | press_adc（MSB / LSB / XLSB）。**20bit、符号なし** |
| `0x22` / `0x23` / `0x24`<7:4> | temp_adc（MSB / LSB / XLSB）。**20bit、符号なし** |
| `0x25` / `0x26` | hum_adc（MSB / LSB）。**16bit** |
| `0x2C` / `0x2D`<7:6> | gas_adc（10bit） |
| `0x2D`<5> | `gas_valid_r`（本物のガス変換か、ダミーか） |
| `0x2D`<4> | `heat_stab_r`（ヒータが目標温度に達したか） |
| `0x2D`<3:0> | `gas_range_r`（ガス抵抗の ADC レンジ） |

**バイト順は「MSB が先のアドレス」**（`0x1F` が press の MSB）。
20bit 値は `(msb << 12) | (lsb << 4) | (xlsb >> 4)` で組む。

### 補正パラメータ（メモリマップに載っていない）

| 変数 | アドレス（LSB / MSB） |
|---|---|
| `par_t1` | `0xE9` / `0xEA` |
| `par_t2` | `0x8A` / `0x8B` |
| `par_t3` | `0x8C` |
| `par_p1`–`par_p10` | `0x8E`–`0xA0`（飛び番あり。Table 14, p.25） |
| `par_h1`–`par_h7` | `0xE1`–`0xE8`（`par_h1` と `par_h2` は `0xE2` のニブルを分け合う。Table 15, p.26） |
| `par_g1` / `par_g2` / `par_g3` | `0xED` / `0xEB`,`0xEC` / `0xEE` |
| `res_heat_range` | `0x02`<5:4> |
| `res_heat_val` | `0x00`（符号付き、−128〜127） |

**これらは全部、個体ごとに違う工場書き込み値である。** 起動時に一度読んで保持する。

## 典型的な使い方

Forced mode（1 回測って sleep に戻る）の手順。datasheet §3.5 の Quick start（p.19）に沿う。

1. **`0xD0` を読んで `0x61` を確認する。** 疎通確認を兼ねる。`0xF0` が `0x01` なら BME688、
   そうでなければ BME680 系の別品種。
2. **補正パラメータを読む。** `0x8A`–`0xA0` と `0xE1`–`0xEE`、それに `0x00` と `0x02`。
   **ここを飛ばすと以降の数値に意味が無い。**
3. **オーバーサンプリングを設定する。** まず `0x72`（`osrs_h`）を書き、
   続いて `0x74` に `osrs_t` / `osrs_p` / `mode` をまとめて書く。
   datasheet は「`osrs_h` を先に、`osrs_t` と `osrs_p` は 1 回の書き込みで」と明示している。
4. **ヒータを設定する。**
   - `gas_wait_0`（`0x64`）に加熱時間。例えば 100ms なら `0x59`（`01`=×4 倍率 + 25ms）。
   - `res_heat_0`（`0x5A`）に目標温度から計算したレジスタ値。計算には `par_g1..3`、
     `res_heat_range`、`res_heat_val`、そして**周囲温度**が要る（datasheet p.27–28 の式）。
   - `nb_conv`（`0x71` bit3:0）に `0x0` を書いてステップ 0 を選ぶ。
   - `run_gas`（`0x71` bit5）を `1` にする。
5. **測定を開始する。** `0x74` の `mode` に `01`（Forced）を書く。
   **このとき `osrs_t` / `osrs_p` も同じバイトなので、一緒に書き直すことになる。**
6. **待つ。** TPH の変換時間（オーバーサンプリング依存）＋ `gas_wait_0` の加熱時間。
   ヒータが目標温度に達するのに 20〜30ms かかるので、加熱時間はそれ以上にする。
7. **`0x1D` から 17 バイトまとめて読む。** 自動インクリメントが効くので 1 トランザクションでよい。
8. **`new_data`（bit7）を確認する。** 立っていなければまだ終わっていない。
   ガスを使ったなら `gas_valid_r` と `heat_stab_r` も確認する。
   `heat_stab_r` が `0` なら「加熱時間が足りない」か「目標温度が高すぎて届かなかった」。
9. **補正計算する。** 温度 → `t_fine` → 気圧・湿度、の順（温度が他の補正に使われる）。
   ガスは `gas_adc` と `gas_range` から Ω を計算する。
10. Forced mode なので、チップは自動で sleep に戻っている。次の測定には 5 からやり直す。

## 利用上の注意

- **補正パラメータを読まないと数値にならない。** これがこのチップ最大の落とし穴で、
  しかも **datasheet のメモリマップ（Table 22, p.33–34）にはこれらのレジスタが載っていない。**
  Table 22 で「Reserved」に見える領域に補正値が入っている。アドレスは補正式の説明の中の
  Table 13（p.23）/ Table 14（p.25）/ Table 15（p.26）/ Table 16（p.28）にしか書かれていない。
- **補正パラメータは個体ごとに違う。** 別の個体で読んだ値を使い回してはいけない。
  ダンプを比較して「値が違う」ことを不具合と誤認しないこと。
- **`ctrl_meas`（`0x74`）は 1 バイトに `osrs_t` / `osrs_p` / `mode` が同居している。**
  mode を書くつもりでこのバイトを書くと、オーバーサンプリング設定も一緒に上書きされる。
  read-modify-write するか、常に 3 つまとめて書く。
- **測定中の制御レジスタ書き込みは無視される。** モード変更コマンドは実行中の測定が終わるまで
  遅延され、**その間に送った他の制御レジスタへの書き込みは捨てられる**（datasheet §3.4, p.17）。
  「全部の制御レジスタを設定してから mode を書く」順序を守る。
  ガス関連レジスタ（`gas_wait_*` / `res_heat_*` / `idac_heat_*`）も測定中に変えてはいけない
  （§5.3.6.2, p.43）。
- **Forced mode は 1 回きり。** 測定後に自動で sleep に戻る。同じ値を読み続けても更新されない。
- **`gas_wait_x` は単純な ms 値ではない。** 下位 6bit がタイマ値、上位 2bit が ×1 / ×4 / ×16 / ×64 の
  倍率。`100` を書いても 100ms にはならない。
- **ヒータの立ち上がりに 20〜30ms かかる。** それより短い `gas_wait` を設定すると
  `heat_stab_r` が `0` になり、抵抗値は目標温度での値ではない。
- **`heat_stab_r` と `gas_valid_r` を確認しないとガス値は信用できない。** Parallel mode では
  タイミングを揃えるためのダミーのガス変換が挟まる。`gas_valid_r` が `0` のものは捨てる。
- **IIR フィルタは温度と気圧だけ。** 湿度とガスには効かない。
  また `osrs_x = 000`（スキップ）にすると該当の結果レジスタは `0x80000` にリセットされるが、
  フィルタメモリは前回値を保持する。スキップを解除した最初の値はフィルタ済みの値になる。
- **アドレス衝突。** `0x77` は本リポジトリ内でも `bmp280` と、さらに I2C マルチプレクサ
  `pca9548a` / `tca9548a`（`0x70`–`0x77`）と重なる。`0x76` も同じ顔ぶれ。
  ENV-Pro を `0x77` で使いつつ、同じバスにマルチプレクサを A2A1A0 = 111 で挿すと衝突する。
- **SDO をフロートさせない。** アドレスが不定になる。
- **CSB を VDDIO に固定する。** CSB が一度でも Low に引かれると（クロックが来ていなくても）
  **次の電源投入まで I2C が無効になる**（§6.1, p.45）。CSB を GPIO で駆動する設計なら、
  電源投入時点でその GPIO が VDDIO レベルを出していることを保証する必要がある。
  モジュールでは基板側で固定されているのが普通だが、「電源を入れ直すまで応答しない」
  症状が出たらここを疑う。
- **`0x1D` から 17 バイトの一括読み出しには意味がある。** 気圧・温度・湿度・ガスの各レジスタが
  同時に更新される保証は、シャドウレジスタによって「1 回の読み出しの間」に対してだけ与えられている
  （§5.3.5, p.41）。バラバラに読むと別の測定の値が混ざり得る。
- **ソフトリセットは `0xE0` に `0xB6`。** 他の値を書いても何も起きない。
- **IAQ が欲しいなら BSEC が要る。** datasheet が定義しているのはガス抵抗（Ω）まで。
  ppm や指数は Bosch の閉じたライブラリの出力であって、レジスタから読めるものではない。

## 出典と確度

- レジスタアドレス・ビット位置・補正パラメータのアドレス・動作モード・I2C の振る舞い:
  すべて Bosch Sensortec datasheet BST-BME688-DS000-03 Revision 1.3（2024-02）。
  [`chips/bme688.yaml`](../../chips/bme688.yaml) の `datasheets:` に記録された版と一致する。
- [`profiles/bme688.yaml`](https://github.com/tanakamasayuki/I2CDeviceDB/blob/38f1d82/profiles/bme688.yaml) は `evidence.source: datasheet` /
  `confidence: tentative`。`register_width_bits: 8` / `burst_read: true` /
  `data-field0` の `addr: "0x1D"`, `len: 17` は上記 Table 22 と §5.3.5 の記述と一致する。
- **未確認**: 実機キャプチャが無い。`0xD0` が本当に `0x61` を返すか、リセット直後の各レジスタが
  Table 22 のリセット値どおりか、3.4MHz や 400kHz での動作は確かめられていない。
- **未調査**: [`scenarios/bme688/p0.yaml`](https://github.com/tanakamasayuki/I2CDeviceDB/blob/38f1d82/scenarios/bme688/p0.yaml) は read-only で、
  device-detection / identity-read / reset-default-read / idle-field-read しか行わない。
  soft-reset・forced measurement・ヒータプロファイル・ガス測定・オーバーサンプリング掃引は
  すべて `deferred`。**したがって本ガイドの「典型的な使い方」は datasheet の手順であって、
  この環境で走らせて確かめた手順ではない。**
- **datasheet が答えていないこと**:
  - **TPH の変換時間の表が無い。** BME680 の datasheet にあったような
    「オーバーサンプリング設定ごとの測定時間」の一覧が本文書には見当たらず、
    Forced mode で何 ms 待てばよいかは書かれていない。Bosch の BME68x-Sensor-API の
    `bme68x_get_meas_dur()` に頼ることになる。
  - **補正パラメータのレジスタがメモリマップに列挙されていない。** Table 22 では
    該当領域が Reserved 扱いで、アドレスは補正式の各 Table を突き合わせて集めるしかない。
  - `par_*` の各値のビット幅・符号の有無は、式の中の型キャスト（`int32_t` など）から
    推測するしかない箇所がある。
  - ガス抵抗から濃度・IAQ への変換は BSEC の領分で、アルゴリズムは公開されていない。
