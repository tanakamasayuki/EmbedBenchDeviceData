# RCWL-9600 — 超音波距離センサ IC

> 40kHz の超音波で距離を測り、結果を I2C（`0x57`）で返すワンチップ。トリガのバイトを
> 1 つ書いて、待って、3 バイト読むだけ。
>
> **確度: 本カタログで最も証拠の弱いデバイス。** RCWL-9600 という測距 IC そのものの
> datasheet は公開されていない。`chips/rcwl-9600.yaml` が挙げている PDF は **TC40-10T/R
> という振動子（超音波の送受信素子）の納入仕様書**であって、IC の資料ではない。I2C の
> コマンドと応答の形は **M5Stack のドライバ実装から起こした推定**で（`profiles` の evidence は
> `inferred` / `tentative`）、datasheet でも実測でも裏付けられていない。
> **ここに書いてあることは、実装前に自分の手元で確かめること。**

## これは何か

超音波の飛行時間から距離を求める測距 IC。送信・受信・復調・処理・計算・出力を 1 チップで
行い、ホストからは I2C デバイスとして見える。M5Stack Unit Ultrasonic（U098）に載っていた
（製品は EOL で、RCWL-9620 版の Unit Ultrasonic-I2C に置き換わっている）。

ホスト側の手順は 3 段階しか無い。

1. `0x01` を 1 バイト書く（測距開始）。
2. 待つ。
3. 3 バイト読む（距離）。

### 分かっていること

- I2C アドレスは `0x57`。
- 応答は 3 バイト、MSB first の 24bit 値（`profiles/rcwl-9600.yaml` の `transport`）。
- 40kHz。有効範囲はおよそ 30〜150cm（`chips/rcwl-9600.yaml` の notes。出典は M5Stack の
  製品情報で、測定条件は明記されていない）。
- 振動子は TC40-10T（送信）/ TC40-10R（受信）の 2 素子。この 2 素子については納入仕様書があり、
  中心周波数 40.0±1.0kHz、指向性 80°±15°（-6dB）、音圧レベル 108dB min（送信）、
  感度 -68dB min（受信）、静電容量 2200pF±20%、最大入力 40Vp-p、反射での検出距離 0.2〜3m、
  動作温度 -20〜+70℃。**これは振動子だけの仕様であり、IC と組み合わせた測距性能ではない。**

### 分かっていないこと

- **レジスタマップが無い。** そもそもコマンドが `0x01` の 1 個しか知られていない。
  他にコマンドがあるのか、あるとしたら何かは不明。
- **3 バイトの単位とスケールが確認できていない。** 姉妹品 RCWL-9620 の datasheet では
  `(H<<16 | M<<8 | L) / 1000` が mm、つまり生値は µm。RCWL-9600 も同じだと**推定している**が、
  9600 の資料でそれを確認したわけではない。
- **トリガから結果が有効になるまでの時間が不明。** 9620 は 100ms 待てと明記しているが、
  9600 の適正値は分からない。
- **測距失敗時に何が返るかが不明。** エラー値、範囲外の扱い、盲区（近すぎる場合）の挙動、
  いずれも記載が無い。
- **電源電圧・消費電流・動作温度範囲が不明。** IC の資料が無いため。
- **温度補償の有無が不明。** M5Stack は「9620 は 9600 より温度補償が良い」と説明しているが、
  9600 に温度補償が入っているのかどうかは分からない。
- **I2C の速度上限が不明。**

### 電気的・物理的な現実

- **トリガを書くと実際に超音波のバーストが出る。** 人には聞こえないが、これは
  「レジスタを読むだけ」の probe とは性質が違う操作である。40kHz に反応するもの
  （一部の動物、他の超音波センサ、超音波式の距離計や加湿器、そして
  **datasheet で「超音波を含む高周波振動下で使うな」と明記されている QMP6988**）が
  近くにあれば影響する。
- **反射で測るので、返ってこない対象がある。** 吸音する物（布・スポンジ）、斜めを向いた面、
  細い物は返らない。指向性が 80°±15° と広いので、狙った物より横にある物を先に拾うこともある。
- **音速は温度で変わる。** 0〜40℃ で約 7% 違う。9600 の内部で補正しているかは不明なので、
  絶対値が要るならホスト側で補正するか、実測して確かめるしかない。
- **振動子は開放型で防水ではない。** 液体中不可。結露、粉塵、有機溶剤、腐食性ガス、
  強い衝撃・振動の下では使えない（納入仕様書 5. NOTES）。

## レジスタ / コマンド

レジスタは無い。以下はすべて**推定**である。

| 方向 | 内容 | 意味 |
|---|---|---|
| 書き込み | `0x01`（1 バイト） | 測距を開始する。超音波バーストが出る |
| 読み出し | 3 バイト | 距離。MSB first。`BYTE_H`, `BYTE_M`, `BYTE_L` |

**転送の形**（推定）: 書き込みは `S` → `0x57`+W → `0x01` → `P`。読み出しは
`S` → `0x57`+R → 3 バイト → NACK → `P`。レジスタポインタを書く手順は無い。

## 典型的な使い方

以下の手順自体が推定であることに注意。

1. `0x57` に ACK が返ることを確認する。
2. `0x01` を 1 バイト書く。**この時点で超音波が出る。**
3. 待つ。9620 の datasheet に倣うなら 100ms 以上。9600 の適正値は不明なので、
   短くしていって値が壊れる境界を探すのが現実的。
4. 3 バイト読む。MSB first で 24bit の値を組む。
5. 9620 と同じスケールだと仮定するなら 1000 で割って mm。**この仮定は未検証。**
6. 次の測距までは間隔を空ける。残響とマルチパスを避けるため。9620 の測定周期が 50ms
   なので、それより速く叩いても意味は無いと思われる。

## 利用上の注意

- **本カタログで最も証拠の弱いデバイス。** ここに書いてあるプロトコルは datasheet ではなく、
  ベンダのドライバ実装と姉妹品からの類推である。しかも**そのドライバ自体、本リポジトリには
  取り込まれていない**（`collection/vendor/` に該当ディレクトリが無く、`libraries/` にも
  エントリが無い）ので、根拠となったソースをローカルで読み直すこともできない。
- **トリガには物理的な副作用がある。** 読み出しだけの probe とは違い、`0x01` を書くと
  超音波が出る。同じ部屋で他の超音波センサを動かしていると相互に干渉する。「安全な
  読み出しテスト」のつもりで叩くべきコマンドではない。
- **待ち時間を守らないと何が返るか分からない。** 古い値なのか、途中の値なのか、
  NACK なのかは記載が無い。
- **単位が推定である。** 3 バイトをそのまま mm や cm と解釈すると 1000 倍ずれる。
  実測して、既知の距離と突き合わせて確かめること。
- **RCWL-9620 とバス上で区別できない。** アドレス（`0x57`）もコマンド（`0x01`）も
  応答長（3 バイト）も同じ。I2C だけでどちらが繋がっているかを判別する方法は知られていない。
  製品のラベルで見分けるしかない。
- **アドレス `0x57` は MAX30100 と衝突する。** 本カタログでは `max30100`（Unit Heart）が
  `0x57` 固定。`0x57` は EEPROM の定番アドレス帯（`0x50`〜`0x57`）の端でもある。
  RCWL-9600 側にアドレス変更手段は知られていないので、衝突したら mux を挟むしかない。
- **温度で結果がずれる。** 音速が 0〜40℃ で約 7% 変わる。内部補償の有無が不明なので、
  精度が要る用途では温度を変えて実測すること。
- **測れない対象がある。** 吸音材、斜めの面、細い物。返らなかったときに何が出るかは不明。
- **防水ではない。** 屋外、結露、粉塵、有機溶剤、腐食性ガス、強い衝撃・振動はいずれも不可。
- **製品は EOL。** 新規に選ぶ理由は無い。後継は RCWL-9620 版
  （Unit Ultrasonic-I2C, U098-B1）で、そちらには IC の datasheet がある。

## 出典と確度

- **測距 IC の一次資料は無い。** `chips/rcwl-9600.yaml` が挙げる PDF は
  **Ceramic Ultrasonic Sensor TC40-10T/R Delivery Specification No. CNE-TC-10-C1**（全 3 ページ、
  発行日の記載なし）で、振動子の納入仕様書である。RCWL（深圳日晨物联科技 / 旧・无锡日晨）は
  どちらの資料も公開サイトに置いていないため、M5Stack がホストするコピーが唯一の入手先になる。
- I2C のコマンド（`0x01` トリガ）と応答（3 バイト MSB first）は **M5Stack のドライバ実装から
  起こした推定**（`profiles/rcwl-9600.yaml` の `evidence.source: inferred`,
  `confidence: tentative`）。そのドライバは本リポジトリに取り込まれていない。
- 有効範囲 30〜150cm は M5Stack の製品情報由来で、測定条件（対象物・温度・反射面）が
  明記されていない。
- 単位（µm）と待ち時間（100ms）は、**RCWL-9620 の datasheet からの類推**であって
  RCWL-9600 について確認された事実ではない。
- **未確認**: 実機のキャプチャがまだ無い。presence、トリガから結果までの時間、距離バイトの
  中身、単位、エラー値、他のコマンドの有無、400kHz での動作、繰り返し測距の最短周期は
  いずれも未実測（`scenarios/rcwl-9600/p0.yaml` の `outputs` と `deferred` がそのまま残っている）。
