# Unit Mini Scales (U177) — ロードセル内蔵の小型はかり

> 5kg のロードセルと HX711 を内蔵し、校正済みの重量を I2C から読めるようにしたユニット。
> 同じ重量が float・整数・文字列の 3 通りで並んでいるのが特徴。
>
> **確度**: M5Stack が Unit MiniScale I2C Protocol という PDF（2023-12-07、PDF 自身の表記は
> firmware **V3** 向け。catalog の note は V1 と書いており食い違う）を公開しており、レジスタ表は
> そこと `M5Unit-Miniscale` ライブラリのソースの両方に存在する。本文の転送長・バイト順・
> アクセス方向は**ライブラリのソースから起こした推定**で、実測では未確認。

## これは何か

ロードセル（秤量 5kg）、HX711（24bit のロードセル用 ADC）、SK6812 の RGB LED、押しボタンを、
STM32F030F4P6 に載せた M5Stack ファームウェアが束ねているユニット。**HX711 は I2C バスには
出ていない**。ホストから見える I2C の相手は STM32 だけで、HX711 は STM32 が読んでいる。
つまり固定機能 IC ではなくファームウェアであり、レジスタマップはこの製品固有のものである。

上面に M3 のナットが埋まっていて、皿や治具をねじ止めできる。Grove から 5V をもらう。

できること:

- 校正前の**生の ADC カウント**（32bit）を読める。
- 校正後の**重量**を 3 通りで読める: float（グラム）、整数（グラム×100）、ASCII 文字列。
- **風袋引き（ゼロ点合わせ）**を 1 バイト書くだけで実行できる。
- **スケール係数（GAP）**を書き換えて校正できる。
- ローパス / 移動平均 / 指数移動平均の 3 つのフィルタを個別に設定できる。
- 押しボタンの状態を読める。
- RGB LED の色を指定できる。
- I2C アドレスを変更できる。

できないこと・持っていないもの:

- **データレディのフラグが無い。** 新しい変換が終わったかどうかは分からず、読めばいつでも
  「最後の値」が返る。HX711 の変換レート（10 / 80 SPS）も設定できないし読めない。
- **割り込み線が無い。** 変化を知るにはポーリングするしかない。
- **ロードセルの生の電圧は読めない。** 読めるのは HX711 のカウントから先。
- **HX711 のゲイン（チャンネル A/B、128/64/32 倍）を選べない。** レジスタが無い。
- **温度補償が無い。** 温度を測る手段もユニット側に無い。
- **オフセット（風袋の値）を読めない。** 書ける操作は「いまの値を 0 にする」だけで、
  現在のオフセット値を取得したり、任意の値を設定したりはできない。
- 校正の単位は「グラム」に固定されているわけではない。GAP を何グラム基準で求めたかで決まる。
  ベンダーの手順は 100g 基準なので、それに従えば `0x10` はグラムになる。

## 早見表

| 項目 | 値 |
|---|---|
| I2C アドレス | `0x26`（既定）。**Unit Weight-I2C (U180) と同じ**なので同一バスに 2 つ挿すなら片方を変更する |
| アドレス変更 | レジスタ `0xFF` に書き込み（値の範囲 1〜127）。**書いた直後から新アドレスで応答する** |
| 電源 | 5V（Grove の赤） |
| インタフェース | Grove HY2.0-4P |
| I2C 速度 | **ライブラリの `begin()` は 400kHz を強制する**（遅くする引数が無い） |
| 中身 | STM32F030F4P6 + HX711 + SK6812 RGB LED + ボタン + 5kg ロードセル |
| 秤量 | 5kg |
| 割り込み | 無し（ポーリング） |
| バイト順 | 数値はリトルエンディアン（LSB first）。RGB だけは R, G, B の順で数値ではない |

## レジスタ

| アドレス | 長さ | R/W | 意味 |
|---|---|---|---|
| `0x00` | 4 | R | 校正前の生 ADC カウント。**符号付き 32bit・LSB first**（単位なし、生の数） |
| `0x10` | 4 | R | 校正後の重量。**IEEE 754 単精度 float・リトルエンディアン**。vendor PDF は「グラム」と明記 |
| `0x20` | 1 | R | ボタンの状態。**`0`=押下、`1`=非押下（アクティブ Low）** |
| `0x30` | 3 | R/W | RGB LED。**R, G, B の順**の 3 バイト（数値ではなくバイト列） |
| `0x40` | 4 | R/W | GAP（スケール係数）。**IEEE 754 単精度 float・リトルエンディアン** |
| `0x50` | 1 | W | `1` を書くと風袋引き（いまの値を新しいゼロ点にする） |
| `0x60` | 4 | R | 同じ重量の整数版。**符号付き 32bit・LSB first、単位は 1/100 g**（実重量 = 値 ÷ 100） |
| `0x70` | 16 | R | 同じ重量の文字列版。PDF によれば `'\0'` 終端で最大 15 文字 |
| `0x80` | 1 | R/W | ローパスフィルタ有効。`0`/`1`（既定 `1`） |
| `0x81` | 1 | R/W | 移動平均の窓。**単位はサンプル数**、0〜50（既定 10） |
| `0x82` | 1 | R/W | 指数移動平均の係数 α。0〜99（既定 10、単位は資料に記載なし） |
| `0xFD` | 1 | W | `1` を書くとファーム更新用ブートローダに入る |
| `0xFE` | 1 | R | ファームウェアのバージョン |
| `0xFF` | 1 | R/W | I2C アドレス（1〜127） |

`0x10` / `0x60` / `0x70` は**同じ量の 3 通りの表現**で、その裏にある校正前の値が `0x00` である。

フィルタの 3 バイトはライブラリでは `UNIT_SCALES_FILTER_REG`、`+1`、`+2` として扱われていて、
それぞれ 1 バイトずつ独立に読み書きされる。ブロックとして 3 バイトまとめて転送する経路は無い。

**転送の形**: 書き込みは「ポインタバイト + ペイロード」を 1 トランザクションで。読み出しは
ポインタバイトを書いて **repeated START** を打ち、続けて必要な長さを要求する。ただし
`getFirmwareVersion()` と `getI2CAddress()` だけは STOP を打ってから読んでいる。

## 典型的な使い方

1. `0xFE` を読んでファームウェアのバージョンを確認する（通信確認も兼ねる）。
2. **校正する。** ベンダーの手順（PDF の脚注）はこの順:
   1. `0x50` に `1` を書いて風袋引きする。
   2. 何も載せない状態で `0x00`（生 ADC）を読む → `RawADC_0g`。
   3. 100g の分銅を載せて `0x00` を読む → `RawADC_100g`。
   4. `GAP = (RawADC_100g − RawADC_0g) / 100` を計算する。
   5. `0x40` に GAP を float で書く。
3. 以後は `0x10`（float、グラム）を読む。整数で扱いたければ `0x60` を読んで **100 で割る**。
4. 値が暴れるならフィルタを設定する。`0x80` にローパスの有無、`0x81` に平均サンプル数、
   `0x82` に EMA 係数。
5. 皿を載せ替えたときなど、ゼロ点を取り直したければ `0x50` に `1` を書く。

## 利用上の注意

- **`0x60` は 100 倍された値。** 実重量 = 値 ÷ 100（単位は 1/100 g）。**ライブラリの
  `getWeightInt()` はこの除算をしていない**ので、返り値をそのままグラムとして表示すると
  100 倍の重さになる。vendor PDF には "Actual weight = Weight Int/100" と明記されている。
- **`0x10` の単位は GAP をどう決めたかで変わる。** ベンダーの手順（100g 基準）で校正すれば
  グラムになる、というだけである。校正していない個体を読むと、前回の校正が残した係数で
  換算された値が出る。**「読めた = 正しい」ではない。**
- **校正の順序は「風袋 → 生 ADC の測定 → GAP 計算 → GAP 書き込み」。** profile の notes は
  「GAP を書いてから `0x50` で風袋」と読める書き方をしているが、ベンダーの手順書は
  風袋が先である。GAP の計算にゼロ点が要るので、手順書の順序に従うのが筋が通る。
- **`setGapValue()` は書き込みのあと 100ms ブロックする。** firmware 側がその間は応答しない
  という意味なので、自前の driver でも `0x40` への書き込み後は同じだけ待つこと。
- **ボタンはアクティブ Low。** `0x20` が `0` のときが押下。ライブラリは生の値を返す。
- **ボタンは firmware 側でも使われている。** 製品ページはこのボタンを「ゼロ点校正と風袋の
  ためのボタン」と説明している。つまり**ホストが何も書かなくても、人が押せばオフセットが
  変わりうる**。押されたことを検知するだけのつもりでいると、重量が飛ぶ理由が分からなくなる。
  ただし押下で実際に何が起きるかは製品ページの記述だけが根拠で、**未確認**。
- **`0x70` の文字列は 16 バイト固定読み。** PDF は `'\0'` 終端で最大 15 文字と書いているが、
  ライブラリは読んだ 16 バイトをそのまま Arduino の `String` コンストラクタに渡している。
  firmware が 16 バイト全部を埋めた場合、終端を探して**バッファの外まで読みに行く**。
  自前の driver では 16 バイトで打ち切ること。
- **読み出し失敗時に未初期化の値が返る。** `getWeight()` と `getGapValue()` は
  `readBytes()` が false を返したときにローカルの float を初期化しないまま返す。
  転送の成否を自分で確かめること。
- **RGB は数値ではない。** ライブラリの API が `uint32_t` を取るので 24bit 整数だと思いがちだが、
  バス上は R, G, B の順の 3 バイトである。`getLEDColor()` も同じ順で組み立て直している。
- **`begin()` が 400kHz を強制する。** `M5Unit-Miniscale` の `begin()` は
  `Wire.begin(sda, scl, 400000UL)` を呼び、遅くする引数を持たない。長いケーブルや
  複数ユニットで 400kHz が苦しいバスでは、`begin()` の後に自分で `setClock()` を呼び直す。
  （同じマップの Unit Weight-I2C 側は既定 100kHz で、呼び出し側が選べる。）
- **`getI2CAddress()` と `getFirmwareVersion()` はグローバルの `Wire.read()` を呼んでいる。**
  `Wire1` を渡していると別のバスから読む。
- **アドレスが Unit Weight-I2C (U180) と同じ `0x26`。** 両方を同じバスに挿すなら、
  片方の `0xFF` を書き換えてからにする。しかも**マップがほぼ同一**なので、
  scan だけではどちらが応答しているか区別できない。区別したければ `0x20`（ボタン）と
  `0x30`（LED）の有無を見るのが唯一の手がかりだが、U180 でそこを読んだときの応答は**未確認**。
- **アドレス変更は即時反映。** `0xFF` に書いた次のトランザクションはもう新アドレス宛に出す。
- **`0xFD` に書くとブートローダに入る。** 通常のアプリケーションから触る理由は無い。

## 出典と確度

- レジスタのアドレスと意味: `M5Unit-Miniscale` ライブラリのソース（`collection/vendor/M5Unit-Miniscale` に
  commit 固定で取得）。ベンダーの Protocol PDF とも整合する。
- 単位（グラム、1/100 g、サンプル数）、フィルタの値域と既定値、校正手順、ボタンの極性:
  ベンダー Protocol PDF。
- 転送長・アクセス方向・バイト順: 同ライブラリのメソッド本体から起こした**推定**。
- **未確認**: 実機のキャプチャがまだ無い（`observations/m5stack-mcu-u177/` は存在しない）。
  レジスタが表のとおり応答するか、`0x70` の文字列が本当に終端されるか、400kHz 以外で
  動くかは確かめられていない。
- **未確認**: ボタン押下で firmware が風袋引きを実行するかどうか（製品ページの記述のみ）。
- **注記**: `chips/m5stack-mcu-u177.yaml` は datasheet の note に "firmware version V1" と
  書いているが、PDF 自身の表紙は V3（2023/12/7）である。
- **未調査**: 書き込み側の挙動全般（GAP、風袋、LED、フィルタ、アドレス変更）は probe が
  read-only のため触れていない。
