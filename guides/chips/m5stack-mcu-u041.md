# Unit PbHub (U041) — Port.B 6 分岐 IO 拡張ユニット

> 1 本の Grove ポートを 6 本の Port.B（GPIO）に分岐させるユニット。分岐先の 2 本の IO を
> デジタル入出力・PWM・ADC・RGB LED として I2C から叩く。**バスの分岐器ではなく、
> ファームウェアが載った IO エキスパンダである。**
>
> **確度**: M5Stack が `M5Unit-PbHub` リポジトリに Protocol PDF を置いており、
> レジスタ表・値域・チャンネル配置はそれに基づく。転送長・バイト順・アクセス方向は
> `M5Unit-PbHub` v1.0.0 のソースから起こした**推定**で、実測では未確認。
> **本機（U041、ATmega328 版）と U041-B（STM32 版）の差はレジスタ表の注記からしか
> 分かっておらず、実機で確かめられていない。**

## これは何か

ATmega328 に M5Stack のファームウェアを載せ、6 系統の Port.B（黒い Grove、GPIO 2 本 +
電源）に分岐させるユニット。ホストから見える相手は ATmega であって、分岐先のデバイスではない。

**名前に "Hub" と付くが、I2C のハブ（PaHUB / TCA9548A のようなバス切り替え器）ではない。**
分岐先はあくまで GPIO であり、ホストは PbHub の firmware に「このチャンネルのこのピンを
HIGH にしろ」と頼む形になる。したがって:

- **タイミングに依存するプロトコルは通せない。** 製品ページが明記しているとおり、
  HX711 を積んだ Weight Unit のような「アナログ読み + 厳密なタイミング」を要求する
  ユニットは PbHub 越しには使えない。
- **PaHUB のような多段接続もできない。**

できること（チャンネルあたり）:

- IO0 / IO1 のデジタル出力・デジタル入力
- IO0 / IO1 の PWM 出力（デューティ 0〜255）
- IO0 のアナログ入力（**本機は 10bit、0〜1023**）
- IO0 に繋いだ WS2812 系 LED ストリップの制御（本数設定・1 個指定・範囲塗りつぶし・輝度）

できないこと・持っていないもの:

- **割り込み線は無い。** 入力の変化を知るにはポーリングするしかない。
- **IO1 のアナログ入力は無い。** ADC は各チャンネルの IO0 だけ。
- **サーボ制御は無い。** レジスタ表の `0x0C`〜`0x0F`（角度・パルス）は
  **STM32 版で追加された機能**で、ATmega328 版には無い。ライブラリ（`M5UnitPbHub`）は
  ハードウェア世代を区別せずこれらのメソッドを提供してしまうので、本機で呼ぶと
  黙って何も起きないか、未定義の動作になる。
- **ファームウェアバージョンの読み出し（`0xFE`）は無い。** これも STM32 版で追加された機能。
- **レジスタによる I2C アドレス変更（`0xFF`）は無い。** 本機のアドレス変更は
  基板上の A0 / A1 / A2 のはんだジャンパで行い、`0x61`〜`0x68` の範囲で選ぶ。
- **ADC の電圧換算に必要な情報が公開されていない。** 入力レンジは製品ページに
  0〜5V と書かれているが、返る値は 0〜1023 のカウントであり、**単位は無い**。
  さらに製品ページ自身が「5V 未満の信号では最大値 1023 に届かない」と注意している。
- **LED ストリップのタイミング切り替え（`0xFA`）は無い。** FW V2 で追加された機能。

## レジスタ

レジスタバイトは **上位ニブルがチャンネル、下位ニブルが機能コード**である。
`reg = ((ch + 4) << 4) | function` で、ただし**チャンネル 5 だけ 6 に読み替える**。
結果としてチャンネルのベースアドレスは次のようになる。

| チャンネル | ベース |
|---|---|
| 0 | `0x40` |
| 1 | `0x50` |
| 2 | `0x60` |
| 3 | `0x70` |
| 4 | `0x80` |
| 5 | **`0xA0`**（`0x90` は使わない） |

機能コード（ベースからのオフセット）:

| オフセット | 長さ | R/W | 意味 |
|---|---|---|---|
| `+0x00` | 1 | W（PDF は R/W） | IO0 デジタル出力 |
| `+0x01` | 1 | W（PDF は R/W） | IO1 デジタル出力 |
| `+0x02` | 1 | W（PDF は R/W） | IO0 PWM デューティ 0〜255 |
| `+0x03` | 1 | W（PDF は R/W） | IO1 PWM デューティ 0〜255 |
| `+0x04` | 1 | R | IO0 デジタル入力 |
| `+0x05` | 1 | R | IO1 デジタル入力 |
| `+0x06` | 2 | R | IO0 アナログ入力。**16bit LSB first**。本機の有効値域は 0〜1023 |
| `+0x07` | — | — | 予約（PDF が reserve と明記。ライブラリも未使用） |
| `+0x08` | 2 | W（PDF は R/W） | LED の個数。16bit LSB first、既定 74 |
| `+0x09` | 5 | W（PDF は R/W） | LED 1 個の色。16bit インデックス（LSB first）+ R, G, B |
| `+0x0A` | 7 | W（PDF は R/W） | LED 範囲塗りつぶし。16bit 開始（LSB first）+ 16bit 個数（LSB first）+ R, G, B |
| `+0x0B` | 1 | W（PDF は R/W） | LED 輝度 |
| `+0x0C` | 1 | W | IO0 サーボ角度 — **STM32 版専用。本機には無い** |
| `+0x0D` | 1 | W | IO1 サーボ角度 — **STM32 版専用。本機には無い** |
| `+0x0E` | 2 | W | IO0 サーボパルス幅 — **STM32 版専用。本機には無い** |
| `+0x0F` | 2 | W | IO1 サーボパルス幅 — **STM32 版専用。本機には無い** |

チャンネル横断のレジスタ（`0xFE` ファームウェアバージョン、`0xFF` アドレス変更）は
いずれも **STM32 版専用**で、本機には無い。

**転送の形**: 書き込みは「レジスタバイト + ペイロード」を 1 トランザクション。
読み出しはレジスタバイトを書いて STOP を打ち、改めて読み出しトランザクションを起こす。

## 典型的な使い方

1. `0x61` に ACK が返ることを確認する（本機にはバージョンレジスタが無いので、
   通信確認はアドレスへの空トランザクションで行う）。
2. デジタル入力を読むなら、チャンネル c の IO0 は `ベース + 0x04` を 1 バイト読む。
3. デジタル出力なら `ベース + 0x00` に 0 か 1 を書く。
4. アナログ入力は `ベース + 0x06` から 2 バイト読み、`data[1] << 8 | data[0]` で組む。
   得られるのは 0〜1023 のカウント。
5. LED ストリップを使うなら、まず `ベース + 0x08` に本数を書き、
   `ベース + 0x09` で 1 個ずつ、または `ベース + 0x0A` で範囲を塗る。

## 利用上の注意

**このユニットは実際の出力を駆動する。** デジタル出力・PWM・LED への書き込みは、
繋がっている先を実際に動かす。本リポジトリの probe が read-only
（`scenarios/m5stack-mcu-u041/p0.yaml` の `safety: read-only`）なのはこのためで、
書き込み系の操作はすべて `deferred` に置かれている。何が繋がっているか分からない
状態で書き込みを試さないこと。

- **チャンネル 5 のベースは `0xA0`。`0x90` ではない。** `0x40 + ch * 0x10` と素直に
  計算すると 5 番だけ外れる。ライブラリは `if (ch == 5) ch++;` という一行でこれを吸収している。
  ベンダーの PDF も `0x90` 行を持たない。
- **1 バイトのペイロードでも、多バイトの数値はリトルエンディアン。** アナログ入力
  （読み）、LED 個数、LED インデックス、範囲の開始と個数、サーボパルス（STM32 版）は
  すべて下位バイトが先。
- **LED の色バイトだけ順序が逆。** `+0x09` / `+0x0A` のペイロード内では、数値部分は
  リトルエンディアンなのに色は **R → G → B**（`0xRRGGBB` の上位バイトから）で並ぶ。
  1 つのペイロードの中でエンディアンが混在している。
- **LED インデックスは実質 8bit。** ライブラリの `setLEDColor()` / `fillLEDColor()` は
  インデックス・開始位置・個数を `uint8_t` で受けてから 2 バイトに広げるので、
  上位バイトは常に 0 になる。ワイヤフォーマット上は 16bit 分の場所があるのに、
  ライブラリ経由では 256 個目以降に届かない。
- **サーボ系のメソッドを本機で呼ばない。** ライブラリはハードウェア世代を区別しない。
  `setServoAngle()` / `setServoPulse()` は STM32 版で追加された機能なので、
  ATmega328 版の本機では効かない。効かないだけで済むのか、別のレジスタを踏むのかは**未確認**。
- **読み出し失敗が LOW と区別できない。** ライブラリの `digitalRead()` は内部の
  `readByte()` が失敗時に `0` を返すのをそのまま通す。`analogRead()` も失敗時 `0`。
  通信エラーが「入力が LOW」「アナログ値 0」に化ける。
- **ADC の値を電圧に読み替えない。** 0〜1023 のカウントに対する換算係数が公開されていない。
  加えて、入力レンジが 0〜5V であるため 3.3V 系のセンサを繋ぐと上限に届かない
  （製品ページの注記）。
- **タイミング依存のユニットは繋がらない。** Port.B の黒いコネクタが付いていても、
  HX711 のように厳密なタイミングを要求するものは動かない。PbHub 越しにできるのは
  「基本的なデジタル・アナログの読み書き」だけ、というのがベンダーの説明である。
- **アドレスははんだで決める。** A0 / A1 / A2 のパターンをはんだで short して
  `0x61`〜`0x68` を選ぶ。ソフトウェアから変える手段は無いので、複数台をぶら下げる場合は
  実装時に決めておく必要がある。
- **搭載 MCU の表記が資料間で食い違っている。** 製品ページの仕様表は MCU を
  STM32F030F4P6 と書きながら、同じページの注記では「内蔵 MEGA328」と書いている。
  本リポジトリは U041 を ATmega328、U041-B を STM32F030 として記録している。
  **どちらの silicon が手元にあるかで ADC 幅（10bit / 12bit）とサーボの有無が変わる**ので、
  区別は実用上の意味がある。**未確認**の点として扱うこと。
- **PDF の表題に惑わされない。** `docs/V1/` に置かれている PDF は表題が
  "PBHub v1.1 I2C Protocol / V1 (FW Version)" で、V1・V2 は**ハードウェア世代ではなく
  ファームウェア版**を指す。ATmega328 版と STM32 版の差は、同じ表の脚注として
  書き分けられている。

## 出典と確度

- チャンネルのベースアドレス（`0x90` を飛ばすこと）、機能コードの割り当て、
  各レジスタの長さと R/W、ADC 幅（ATmega328 版 10bit / STM32 版 12bit）、
  サーボとバージョンとアドレス変更が STM32 版専用であること、LED 上限 74 個:
  **ベンダーの Protocol PDF に基づく**。
- 転送長・バイト順・レジスタバイトの計算式: `M5Unit-PbHub` v1.0.0 の
  `src/M5UnitPbHub.cpp` から起こした**推定**。このライブラリにはレジスタの `#define` が
  一切なく、すべてメソッド本体の中でインラインに計算されている。
- **未確認**: 実機のキャプチャがまだ無い。ATmega328 版が本当にサーボ系レジスタを
  無視するのか、`0x07` に何が起きるのか、読み戻し（PDF 上は多くが R/W）が実際にできるのか、
  400kHz で安定するかは確かめられていない。
- **未確認**: 製品ページの MCU 表記（STM32F030F4P6）と注記（MEGA328）が食い違っている。
- **未調査**: 書き込み側の挙動全般（デジタル出力・PWM・LED・サーボ）は
  `scenarios/m5stack-mcu-u041/p0.yaml` が `safety: read-only` のため触れていない。
- ADC の電圧換算係数は**一次資料に記載が無い**。
