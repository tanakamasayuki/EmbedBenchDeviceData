# Unit CardKB v1.1 (U035-B) — カード型 QWERTY キーボードユニット

> 名刺サイズの 50 キーキーボードを I2C で読むユニット。**出荷時のファームウェアには
> レジスタが無く**、ポインタバイトを持たない 1 バイト読み出しで押されたキーの ASCII が
> 返るだけ。レジスタマップは、M5Stack が別途配布する差し替え firmware を書き込んだ場合にだけ現れる。
>
> **確度**: 出荷時プロトコル（1 バイト読み + キーコード表）は M5Stack の
> **User Manual PDF に基づく**。差し替え firmware のレジスタマップは
> `M5Unit-KEYBOARD` ライブラリのソースと同梱の firmware スケッチから起こした**推定**で、
> 実測では未確認。バス上で確認された挙動は一つも無い。

## これは何か

88 × 54 × 5mm のカード型キーボード。マトリクススキャンを ATmega8A が行い、その結果を
I2C で返す。ホストから見える相手は ATmega であって、キーマトリクスではない。
**つまりレジスタマップ（がある場合）はこの製品固有のもの**である。

キーは 50 個。うち 47 個がスキャンマトリクス上の通常キーで、残り 3 個が修飾キー
（Shift / Sym / Fn）。修飾キーは押しっぱなしで使うのではなく、**次に押すキーの意味を変える**
ワンショット方式で、ダブルクリックするとロックされる（ロック中は本体の RGB LED が点灯、
ワンショット中は点滅する）。

このユニットは**ファームウェア次第で 2 つの別のプロトコルを喋る**。

### 出荷時ファームウェア（conventional）

レジスタポインタが存在しない。ホストは単に 1 バイト読むだけで、押されたキーに対応する
ASCII コードが返る。何も無ければ `0x00`。これがプロトコルのすべてである。

できないこと:

- **キーの押下と離上を区別できない。** 返るのはコードだけで、イベント種別が無い。
  なお User Manual は「キーが押されたとき」に出力すると書き、`M5Unit-KEYBOARD` の
  ソースとその README は「離されたキー」を返すと書いている。**どちらが正しいかは未確認。**
- **同時押しが表現できない。** 1 バイトに 1 キーしか乗らない。
- **修飾キーの状態を直接読めない。** Shift / Sym / Fn は返るコードに溶け込んでいる
  （`a` が `A` になる、といった形）。今どのモードなのかは I2C からは分からない。
- **長押し・リピートが無い。** ホスト側で作るしかないが、押下継続が見えないので作りようがない。
- **バッファは 1 バイト分しかない。** 読むのが遅いとキーを取りこぼし、速いと `0x00` ばかり返る。
- **LED を制御できない。** firmware が修飾キーの状態表示に使っている。
- **I2C アドレスを変更できない。**
- **割り込み線が無い。** ポーリングのみ。

### 差し替えファームウェア（`M5Unit-KEYBOARD` 同梱スケッチ）

`examples/firmware/CardKB_Firmware/CardKB_Firmware.ino` を ATmega に書き込むと、
下表の 4 レジスタが現れる。**書き込みには外部のプログラマが必要で、出荷時 firmware は失われる。**

できるようになること:

- 48 ビットのスキャン結果をまとめて読める。**同時押しが分かる。**
- 修飾キーの状態を独立したビットとして読める。修飾キーを押しながらの入力ができる。
- 出荷時互換モード（レジスタ `0x20` = `0x00`）と併存できる。

それでもできないこと:

- **割り込み線は無い。** 相変わらずポーリング（ライブラリの既定は 10ms 周期）。
- **同時に押されたキーの順序は分からない。** firmware が返すのは瞬間のビットだけ。
- **長押し・リピートは firmware に無い。** ホスト側の実装で、`M5Unit-KEYBOARD` の既定は
  ホールド 800ms・リピート 400ms。
- **LED は相変わらず I2C から制御できない。**
- **アドレス変更レジスタは無い。**

## 早見表

| 項目 | 値 |
|---|---|
| I2C アドレス | `0x5F`（固定。変更手段なし） |
| I2C 速度 | **100kHz**（User Manual が明記。ライブラリも 100kHz で駆動する） |
| 電源 | 5V（Grove の赤） |
| インタフェース | Grove HY2.0-4P |
| 中身 | ATmega8A + M5Stack ファームウェア + RGB LED ×1 |
| キー数 | 50（通常キー 47 + 修飾キー 3） |
| 割り込み | 無し（ポーリング） |
| 出荷時プロトコル | ポインタ無しの 1 バイト読み。キーの ASCII、無ければ `0x00` |
| 寸法 / 重量 | 88.0 × 54.0 × 5.0mm / 14.3g |

**ハードウェアタイプ**: `0x01` が SKU U035（初代、ATmega328）、`0x11` が SKU U035-B
（v1.1、ATmega8A）。本チップは `0x11` 側。

## レジスタ（差し替え firmware を書き込んだ場合のみ）

| アドレス | 長さ | R/W | 意味 |
|---|---|---|---|
| `0x10` | 7 | R | スキャン結果。byte0–5 がキー 48 ビット、byte6 が修飾ビット |
| `0x20` | 1 | R/W | 動作モード。`0x00` 出荷時互換、`0x01` スキャンモード |
| `0xFD` | 1 | R | ハードウェアタイプ（`0x01` / `0x11`） |
| `0xFE` | 1 | R | ファームウェアバージョン（上位ニブル major、下位ニブル minor） |

`0x10` の 7 バイトの内訳:

- byte0 の bit0 がキーインデックス 0（ESC）、byte0 の bit7 がインデックス 7、
  … byte5 の bit7 がインデックス 47（SPACE）。**バイト内は LSB がインデックスの小さい側**。
- インデックス 23 は空き（`NO_KEY`）。だから通常キーは 47 個。
- byte6 が修飾ビット。`0x01` = Shift、`0x02` = Sym、`0x04` = Function。
  これは firmware が正規化した値で、ATmega のポート上の生ビット（Shift `0x10`、
  Sym `0x80`、Fn `0x40`）とは別物である。個体差を吸収するためにわざと揃えてある。

キーインデックスと物理キーの対応は firmware スケッチの README にある表が正本
（0=ESC, 1〜10=数字 1〜0, 11=BS, 12=TAB, 13〜22=Q〜P, 23=空き, 24=LEFT, 25=UP,
26〜34=A〜L, 35=ENTER, 36=DOWN, 37=RIGHT, 38〜44=Z〜M, 45=`,`, 46=`.`, 47=SPACE）。

**転送の形**: レジスタ読み出しはポインタバイトを 1 バイト書き、STOP を打ってから
必要な長さを読む。出荷時プロトコルの読み出しはポインタバイトを書かず、いきなり 1 バイト読む。

## 典型的な使い方

### 出荷時のまま使う

1. 一定周期で 1 バイト読む。
2. `0x00` なら何も無かったということ。それ以外は ASCII コード。カーソルキーは
   `0xB4` 左 / `0xB5` 上 / `0xB6` 下 / `0xB7` 右。Fn を絡めると `0x80`〜`0xAF` の
   カスタム値が返る。
3. モード（Shift / Sym / Fn）はデバイス側が管理しているので、ホストは返ってきた
   コードをそのまま文字として扱えばよい。

### 差し替え firmware で使う

1. `0xFE` を読む。**`0` なら出荷時 firmware**で、レジスタは無いと判断する。
2. `0xFD` を読み、`0x01` か `0x11` でなければ CardKB ではないと判断する。
3. `0x20` に `0x01` を書いてスキャンモードにする。
4. 一定周期（10ms 程度）で `0x10` から 7 バイト読み、前回との差分でエッジ・ホールド・
   リピートをホスト側で判定する。

## 利用上の注意

- **出荷時の個体はポインタバイトを無視する。** どのアドレスを指しても、返るのは
  「キーの ASCII か `0x00`」である。`0xFE` を読んだつもりの 1 バイトが、実は直前に
  押されたキーのコードだった、ということが起こりうる。`M5Unit-KEYBOARD` の `begin()` が
  **最初に 1 バイト読んで捨てる**のはこのためで、残っていたキー値を版数と誤認しないようにしている。
  それでも「読んだ瞬間にキーが押されていた」ケースは防げない。判定は複数回行うのが安全。
- **差し替え firmware ではポインタバイトが「使い捨て」。** firmware 側は 1 回の読み出しで
  ポインタ変数をクリアする。ポインタを書かずに読むと、出荷時互換モードならキーバイトが返り、
  スキャンモードなら firmware は何も送らない（バスがアイドルのまま `0xFF` を読むことになる）。
  **1 回の読み出しごとに必ずポインタを書く。**
- **スキャン結果は 1 周期前のバッファ。** firmware はダブルバッファで、送信するのは
  書き込み中でない側である。したがって `0x10` の読み値には常に 1 スキャン分の遅れがある。
- **`0x10` は途中から読める。** firmware は指定アドレスから末尾までを送るので、
  `0x16` を指せば修飾バイトだけ 1 バイト読める。逆に 7 バイトより多く要求しても
  意味のあるデータは来ない。
- **`0x20` への書き込みは状態をリセットする。** モードを書き換えると firmware 側の
  押下・離上・モードロックの状態が全部クリアされる。モードの往復を頻繁に行わないこと。
- **`0x20` を書けるのは差し替え firmware だけ。** ライブラリの `writeMode()` は
  ファームウェアバージョンが 0 でない（＝差し替え済み）ときしか書き込みを行わない。
- **修飾キーのビットは正規化された値。** firmware スケッチのソースを読むと、ATmega の
  ポート上の生ビットは Shift `0x10` / Sym `0x80` / Fn `0x40` だが、I2C に出るのは
  `0x01` / `0x02` / `0x04` に変換された値である。回路図から生ビットを推測して当てにいくと外れる。
- **firmware の差し替えは戻せる作業ではない。** 出荷時 firmware のバイナリを別途
  用意しない限り、元の挙動には戻らない。書き込み時のボード設定は U035（初代）が
  ATmega328、**U035-B（本機）が ATmega8** である。
- **ドキュメントのレジスタアドレス表記に注意。** firmware スケッチの README にある
  プロトコル表は、ハードウェアタイプ行とファームウェアバージョン行のアドレス欄が
  どちらも `0xF0` と書かれている。これは表が「行のベースアドレス + 列位置」で読む
  グリッド形式だからで、列まで数えると `0xFD` と `0xFE` になり、firmware スケッチと
  ホスト側クラスの `#define`（`0xFD` / `0xFE`）と一致する。**実装の値を使えばよい。**
  （`profiles/m5stack-mcu-u035-b.yaml` の `notes` はこれを「矛盾」として記録しているが、
  列位置まで読むと矛盾ではない。同じ表記形式は M5Stack の他ユニットの Protocol PDF にも見られる。）
- **`0x10` の 64bit への畳み込みでビット 48〜55 は空く。** ライブラリは 7 バイトを
  64bit 語にするとき byte6 をビット 56 以上に置く。自前で組む場合、修飾バイトの位置を
  ライブラリと揃えないと混乱する。
- **100kHz で使う。** User Manual が通信レートとして 100kHz を明記している。
  より速いバスで動くかは**未確認**。

## 出典と確度

- 出荷時プロトコル（アドレス `0x5F`、100kHz、1 バイト読みで ASCII / `0x00`）と
  全キーコード表、修飾キーのワンショット・ダブルクリックロックの挙動:
  **M5Stack の User Manual PDF に基づく**。
- 差し替え firmware のレジスタ `0x10` / `0x20` / `0xFD` / `0xFE`、スキャンのビット配置、
  修飾ビットの正規化、ポインタバイトの使い捨て、ダブルバッファ:
  `M5Unit-KEYBOARD` v0.1.0 のホスト側実装と同梱 firmware スケッチから起こした**推定**。
- **未確認**: 実機のキャプチャがまだ無い。「押されたキー」なのか「離されたキー」なのかは
  User Manual とライブラリで記述が食い違っており決着していない。差し替え firmware を
  書き込んだ個体も本リポジトリでは扱っていないため、レジスタが実在するかは確かめられていない。
- **未調査**: `0x20` への書き込みは `scenarios/m5stack-mcu-u035-b/p0.yaml` が
  `safety: read-only` のため触れていない。
- **注意**: 出荷時の個体に対してレジスタマップを前提とした読み出しを行っても、
  返るのはキーバイトである。本ガイドのレジスタ表は「差し替え firmware を書き込んだ場合」
  にのみ有効であることを、読むたびに確認すること。
