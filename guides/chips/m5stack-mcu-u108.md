# Unit Scales (U108) — ロードセル式のはかりユニット

> ロードセルと HX711 を載せた台ばかり。ホストからは「生の ADC 値」と「ファームが校正した重量」を
> レジスタとして読む。校正・風袋引き・LED・ボタンもレジスタ越しに扱う。
>
> **確度**: M5Stack が Unit Scales I2C Protocol という PDF（V1 firmware 向け、2022-09-09）を公開しており、
> レジスタ表はそこと `M5Unit-Scales` ライブラリのソースの両方にある。ただし `profiles/` に入っている
> マップは**ライブラリのソースから起こした推定**（`evidence: inferred / tentative`）で、実測では未確認。
> さらに **PDF とライブラリが食い違っている箇所が 3 つある**（0x21/0x22 の割り当て、0x18 の R/W、
> 0x32 の単位）。どちらが正しいかは実機で確かめるまで決まらない。

## これは何か

ロードセル（ひずみゲージ）と HX711（24bit の秤量用 ADC）を、STM32F030F4P6 に載せた M5Stack
ファームウェアが読み、I2C レジスタとして見せているユニット。**ホストから見える I2C の相手は
STM32 であって、HX711 でもロードセルでもない**。HX711 は MCU の裏側にいて I2C バスには出て
こない。つまりこのレジスタマップは HX711 の datasheet とは何の関係も無く、この製品固有のもの
である。

本体は 56.0 × 40.0 × 41.0 mm のプラスチック筐体で、上面が計量皿になっている。秤量は 20kg
（製品ページ）。RGB LED（SK6812）が 1 個と、風袋引き用のボタンが 1 個ついている。

できること:

- **生の ADC 値**を読める（`0x10`、32bit）。フィルタや校正を自分でやりたい場合の入口。
- **校正済みの重量**を読める（`0x14`、符号付き 32bit、1/100 g 単位）。
- **2 点校正**ができる。皿を空にして零点を決め、既知の分銅を載せてスパンを決める。
- **風袋引き（tare）が 2 通り**。現在値をオフセットとして採用させる方法と、オフセット値を明示的に
  書き込む方法。ユニットのボタンにも同じ動作を割り当てられる。
- **ボタンの押下回数・長押し回数・現在の状態**を読める。
- **LED の色**を指定できる。重量に応じてファーム側が明るさを変えるモードもある。
- **I2C アドレスを変更できる**（内部 Flash に保存される）。

できないこと・持っていないもの:

- **割り込み線は無い。** 重量が変わったこともボタンが押されたことも、ポーリングでしか知れない。
- **校正係数（scale）を読み返すレジスタが無い。** 「このユニットは校正済みか」を I2C から確認する
  手段が無いので、`0x14` の値が意味を持つかどうかはホスト側が覚えているしかない。
- **単位の切り替えが無い。** 返るのは常に 1/100 g。kg や oz への変換はホスト側の仕事。
- **サンプリング周期・平均化・HX711 のゲイン設定は見えない。** HX711 は 10 SPS（製品ページ）で
  動いているが、それを変えるレジスタは公開されていない。
- **過負荷・エラーのフラグが無い。** 秤量を超えたことも、ロードセルが外れたことも通知されない。
- **ボタンのイベントを取りこぼさない仕組みが無い。** 回数カウンタを読むだけで、タイムスタンプは無い。

## レジスタ

| アドレス | 長さ | R/W | 意味 |
|---|---|---|---|
| `0x10` | 4 | R | 生の HX711 値。**MSB first**。ライブラリは符号なしとして扱う。単位は無い（ADC のカウント） |
| `0x14` | 4 | R | 校正済み重量。**符号付き 32bit、MSB first**。単位は **1/100 g**（`2536` = 25.36 g） |
| `0x18` | 4 | R（PDF）/ W（ライブラリ） | 風袋オフセット。**MSB first**。単位は生の ADC カウント。**PDF はこの行全体を R としているが、ライブラリは書き込む**（後述） |
| `0x20` | 1 | R | ボタンの短押し回数。0〜255 |
| `0x21` | 1 | R | **PDF: ボタンの現在状態 / ライブラリ: 長押し回数**（食い違い、後述） |
| `0x22` | 1 | R | **PDF: 長押し回数 / ライブラリ: ボタンの現在状態**（食い違い、後述） |
| `0x23` | 1 | R/W | `1` でユニットのボタン自身に風袋引きをさせる。`0` で無効 |
| `0x24` | 1 | R/W | 風袋引きトリガ。`1` を書くと現在の読みをオフセットとして採用する |
| `0x25` | 1 | R/W | `1` でファームが重量に応じて LED の明るさを変える。`0` でホスト側の指定が生きる |
| `0x30` | 2 | R/W | 零点校正トリガ。ライブラリは `0x00, 0x00` の 2 バイトを書く。**書くこと自体がトリガ** |
| `0x32` | 2 | R/W | スパン校正用の既知荷重。**16bit、LSB first**。範囲 0〜65535。**単位が資料間で食い違う**（後述） |
| `0x50` | 3 | R/W | RGB LED。R, G, B の順。各 0〜255 |
| `0xFE` | 1 | R | ファームウェアのバージョン |
| `0xFF` | 1 | R/W | I2C アドレス。範囲 `0x01`〜`0x80`、既定 `0x26` |

PDF が書いている換算式:

```
Cal Data = (Offset - RawADC) / (Scale × 10000)
```

`Scale` は校正で内部に決まる係数で、レジスタとしては公開されていない。

**転送の形**: 書き込みは「ポインタバイト + ペイロード」を 1 トランザクションで送る。読み出しは
ポインタバイトを書いて **いったん STOP を出し**（`endTransmission()` を引数なしで呼ぶ）、それから
`requestFrom` でデータフェーズに入る。repeated START ではない。

## 典型的な使い方

1. `0xFE` を読んでファームウェアのバージョンを確認する（疎通確認も兼ねる）。
2. **初回だけ校正する。** 皿を空にして `0x30` に `0x00, 0x00` を書く（零点）。次に既知の分銅を載せて
   `0x32` にその質量を 2 バイト（LSB first）で書く（スパン）。ここを通すまで `0x14` の値に意味は無い。
3. 使い始めに風袋を引く。`0x24` に `1` を書けば、その瞬間の読みが基準になる。
4. `0x14` を 4 バイト読む。MSB first で符号付き 32bit として組み立て、100 で割ればグラム。
5. ボタンを使うなら `0x20`（短押し回数）と長押し・状態のレジスタを読む。ただし `0x21`/`0x22` の
   割り当ては資料が割れているので、両方読んで実際の値で判別するのが安全。
6. LED を自分で光らせるなら、先に `0x25` に `0` を書いて重量連動を切ってから `0x50` に R, G, B を書く。

## 利用上の注意

- **`0x14` の単位は 1/100 g であってグラムではない。** そのまま表示すると 100 倍になる。逆に
  ライブラリの `getWeight()` は `int` のまま `/100` しているので、**小数以下が切り捨てられる**。
  0.01 g の分解能が欲しいなら、生の 32bit を自分で読んで自分で割る。
- **`0x14` は符号付き。** 風袋より軽い状態では負の値が返る。`uint32_t` で受けると 42 億付近の
  巨大な値に化ける。
- **32bit は MSB first、`0x32` だけ LSB first。** 同じデバイスの中でバイト順が混在している。
  片方の流儀で全部を書くと校正だけが壊れる。
- **`0x32` の単位が資料間で食い違う。** ライブラリの API は `setCalGram(uint16_t g)` で「グラム」の
  つもり。一方ベンダー PDF の注記は `load : Tare weight (unit: 10mg)` で 10mg 単位と読める。
  範囲は 0〜65535 なので、10mg 単位なら最大 655.35 g にしかならず 20kg の秤には足りない。
  グラム単位なら 65.5kg で辻褄が合う。**未確認**。分銅を載せて実測するまでどちらとも言えないので、
  校正結果が 100 倍ずれたらここを疑う。
- **`0x21` と `0x22` の割り当てが資料間で入れ替わっている。** ベンダー PDF の REG MAP は
  `0x20`=Press Count / `0x21`=Press Status / `0x22`=Long Press Count と並べている。ライブラリの
  `#define` は `0x21`=長押し回数 / `0x22`=状態。**未確認**。ボタンを押しながら両方を読めばすぐ判る
  （状態レジスタは押している間だけ変わり、カウンタは単調に増える）。`profiles/` はライブラリ側の
  解釈を採っている。
- **ボタンの状態レジスタはアクティブ Low。** ライブラリの `getBtnStatus()` が読んだバイトを反転して
  返しているのが根拠で、`0` が押下。真偽値にそのまま変換すると意味が逆になる。
- **押下回数カウンタが読み出しでクリアされるかは未確認。** `profiles/` は「前回読んでからの回数」と
  書いているが、PDF にはそう書いていない（`value: 0~255` としか無い）。もし読み取りで消費される
  なら、2 か所から読むと片方が取りこぼす。読む場所は 1 か所に決めておくのが安全。
- **`0x18` は PDF では読み出し専用に見える。** PDF は `0x10` の行（RawADC / Cal Data / Offset）を
  まとめて `R` と記している。にもかかわらずライブラリの `setOffset(uint32_t)` はここに書き込む。
  **未確認**。書いても効かない可能性がある。
- **ライブラリの既知の不具合**: `setOffset(uint32_t offset)` は 4 バイトのペイロードを送るのに、
  オフセットの下位 24bit を先頭 3 バイトに詰めて 4 バイト目を `0` のまま残している。デバイスが
  MSB first の 32bit として受け取るなら、**届く値は意図した値を 8bit 左シフトしたもの（256 倍）**に
  なる。明示オフセットを使うなら、自分でバイトを組んで書いた方がよい。`0x24` の
  「現在値を採用」パスにはこの問題は無い。
- **LED は 3 バイトで足りる。** PDF の表は `RGB_R, RGB_G, RGB_B` の 3 バイトだが、ライブラリは
  4 バイト書き、読み出しも 4 バイト要求して先頭 3 バイトしか使わない。バスに 4 バイト目
  （常に `0`）が出るのはライブラリの都合であって、デバイスの仕様ではない。
- **`0x25` が `1` だと LED の色指定は上書きされる。** 重量連動モードが有効なままだと、ファームが
  重量から明るさを塗り直す。自分で色を出したいなら先に `0` を書く。
- **PDF は「LED を有効にした後、電圧が安定するまで約 50ms 待ってから更新せよ」と書いている。**
  電源投入直後に立て続けに色を書くなら、この待ちを入れる。
- **アドレス変更は内部 Flash に保存され、即時反映される。** `0xFF` に書いた次のトランザクションは
  もう新アドレス宛に出さないと応答しない。電源を切っても戻らない。書き換えた値を忘れると
  `0x26` を探しても見つからないユニットが手元に残る（復旧はバス全体を scan して探す）。
  PDF は Flash 寿命について「頻繁に書くな」「同じ値なら書き込みはスキップされる」と注記している。
- **書き込みは実際にデバイスの状態を変える。** 校正（`0x30`/`0x32`）は不揮発の設定を書き換えるし、
  アドレス変更は通信相手そのものを変える。**本リポジトリの characterization probe は read-only** で、
  読み出し可能な 7 レジスタを読むだけで一切書かないのはこのため。書き込み側の挙動はレビュー済みの
  シナリオに委ねられている。

## 出典と確度

- レジスタのアドレスと意味: `M5Unit-Scales` ライブラリのソース（`collection/vendor/M5Unit-Scales` に
  commit 固定で取得）。ベンダーの Protocol PDF とも突き合わせた。
- 転送長・アクセス方向・バイト順: 同ライブラリのメソッド本体から起こした**推定**。
- **資料間の不一致（いずれも未確認）**: `0x21`/`0x22` の割り当て、`0x18` が書けるかどうか、
  `0x32` の単位（g か 10mg か）。PDF とライブラリのどちらが実機と合うかは確かめていない。
- **未確認**: 実機のキャプチャがまだ無い。押下回数カウンタが読み取りでクリアされるか、
  400kHz で動くか、未使用アドレスがどう振る舞うかは確かめられていない。
- **未調査**: 書き込み側の挙動全般（校正、風袋、LED、アドレス変更）は probe が read-only の
  ため触れていない。
