# EEPROM — 型番未特定の校正用 EEPROM（プレースホルダ）

> **これは実在の型番を指すエントリではない。** M5Stack Unit AMeter (U086) と
> Unit VMeter (U087) の基板に載っている小容量の校正用 EEPROM を、部品が特定されるまでの間
> 仮に置いておくための枠である。M5Stack は型番を公開していない。
>
> **確度**: **datasheet は存在しない。** 分かっているのは I2C アドレス（`0x51` / `0x53`）と、
> M5Stack のブロック図・製品ページに書かれていること、そして「工場出荷時に校正パラメータが
> 書き込まれている」「書き込むな」という警告だけである。
> レジスタマップは無く、`profiles/eeprom.yaml` も存在しない。
> **本ガイドは、他のガイドより意図的にずっと短い。**

## これは何か

M5Stack の電流計ユニット / 電圧計ユニットに載っている、数バイト〜数百バイト程度と思われる
I2C EEPROM。中身は**その個体の校正パラメータ**で、工場で書き込まれている。

M5Stack が公開しているブロック図（製品ページの回路図画像）から読み取れる構成:

- ユニットは **CA-IS3020S でディジタル絶縁されている**。
- **ADS1115（ADC）は絶縁側**にある（GND B）。AMeter で `0x48`、VMeter で `0x49`。
- **EEPROM は絶縁されていないホスト側**にある（GND A）。Port.A の I2C に直結し、
  3.3V の LDO で給電されている。AMeter で `0x51`、VMeter で `0x53`。

つまり **EEPROM は絶縁バリアの内側ではなく外側**にいる。ホストから見ると、
絶縁チップを介さずそのままバス上に居る。

**何が分かっていないか**:

- **型番が分からない。** M5Stack の資料は "E²PROM" とだけ書き、部品番号を出していない。
- **容量が分からない。** 24C01（128 バイト）なのか 24C02（256 バイト）なのか、
  それ以上なのかは不明。
- **アドレス指定が 1 バイトか 2 バイトかが分からない。** 24C01〜24C16 系なら 1 バイト、
  24C32 以上なら 2 バイト。これは容量が分かるまで決まらない。
- **ページサイズが分からない。** 書き込みのページ境界も、書き込み完了までの時間も不明。
- **校正データのフォーマットが分からない。** どのアドレスに何バイトで、どんな
  エンコーディングで入っているかは公開されていない。M5Stack のライブラリを読めば
  読み出し側の解釈は分かるはずだが、本ガイドでは確認していない。
- **書き込み保護（WP ピン）の状態が分からない。** ハードで保護されているのか、
  単に「書くな」と言われているだけなのかは不明。

**仮定していること**:

`chips/eeprom.yaml` の注記が置いている仮定は 1 つだけ ——
**24 シリーズ相当の、アドレスポインタ + データという素直な形**である。
つまり「アドレスを書いてから読む」「アドレスに続けてデータを書く」という
一般的な I2C EEPROM の作法が通じるだろう、という程度の想定であって、
検証された事実ではない。

## レジスタ・コマンド

**レジスタマップは無い。**

推測でそれらしい表を作ることはできるが、それは EEPROM 一般の作法を書き写しただけの
ものになり、このデバイスについて何も言っていない。**書かない。**

分かっているのは、`0x51` / `0x53` に I2C デバイスが居ることだけである。

## 典型的な使い方

**触らないこと。**

M5Stack の製品ページは AMeter・VMeter の両方で明示的に警告している ——
「EEPROM に書き込まないでください。校正データが上書きされ、測定結果が不正確になります」。

- **校正データは個体ごとに違う。** 消したら、同じユニットの別個体からコピーしても意味が無い。
- **M5Stack は校正データを再配布していない。** 消した場合の復旧手段は公開されていない。
- 読み出しは（EEPROM である限り）無害だと考えられるが、**それも検証されていない**。

ADS1115 側を使いたいだけなら、EEPROM には一切アクセスする必要が無い。

## 利用上の注意

- **`0x51` は本カタログ内で `hym8563`（M5Stack Unit RTC の RTC）と
  `m5stack-mcu-u026`（Unit 16-Key Capacitive Touch）と衝突する。**
  Unit AMeter と Unit RTC を同じ Port.A に繋ぐと、両方が `0x51` で応答する。
  HYM8563 のアドレスは固定なので、**この組み合わせは I2C マルチプレクサ
  （`pca9548a` / `tca9548a`）で分ける以外に回避できない**。

- **`0x53` は本カタログ内で `adxl345`（M5Stack Unit Accel、SDO/ALT = GND のとき）と
  衝突する。** ADXL345 のアドレスもピンで固定されているので、同じく分離が必要。

- **バススキャンで `0x51` や `0x53` に何かが居ても、それが EEPROM とは限らない。**
  上の衝突相手のどれかかもしれない。**アドレスだけでデバイスを同定してはいけない**
  という、このリポジトリ全体に共通する教訓がそのまま当てはまる典型例である。

- **絶縁の意味を勘違いしない。** AMeter / VMeter の絶縁は ADS1115 側の測定回路を
  ホストから切り離すためのもので、**EEPROM はホスト側にある**。EEPROM にアクセスしても
  絶縁バリアは越えない。逆に言えば、ADS1115 へのアクセスだけが CA-IS3020S を通る。

- **書き込み保護の有無が不明である以上、「書いても保護されているから大丈夫」と
  仮定してはいけない。** 実際に書けてしまう可能性がある。

- **書き込み中は ACK を返さない期間がある**のが 24 シリーズ EEPROM の普通の挙動だが、
  この部品がそうかは**未確認**。バススキャンのタイミング次第で「居たり居なかったり」
  するデバイスに見える可能性はあるが、確かめていない。

## この部品を特定するには

このエントリを本物のチップエントリに置き換えるには、次のどちらかが要る。

1. **実物のキャプチャ。** ロジックアナライザでホストと EEPROM のやり取りを記録すれば、
   ワードアドレスが 1 バイトか 2 バイトかが分かり、そこから容量帯（24C01〜24C16 か、
   24C32 以上か）が絞れる。M5Stack のライブラリが校正値をどのアドレスから何バイト
   読んでいるかも同時に分かる。**これだけでも「24 シリーズ相当」という仮定の
   真偽は判定できる。**
2. **基板の目視（分解）。** ユニットを開けて EEPROM のマーキングを読む。
   この種のパッケージ（SOT-23-5 や SOIC-8）はマーキングが省略コードのことが多いので、
   コードからメーカーを引き当てる手間は要る。

1 の方が非破壊で、しかも本リポジトリの収集フロー
（[docs/VERIFY.ja.md](https://github.com/tanakamasayuki/I2CDeviceDB/blob/38f1d82/docs/VERIFY.ja.md)）にそのまま乗る。ただし
**校正データを壊さないよう read-only に徹すること**。

## 出典と確度

- **一次資料は無い。型番が特定できていないので、datasheet を探すこともできない。**
  `chips/eeprom.yaml` の `datasheets:` が空リストなのはそのためで、
  `tools/datasheet_text.py` も「no PDF datasheet recorded」を返す。
- I2C アドレス `0x51` / `0x53` は `chips/eeprom.yaml` と
  `products/m5stack-u086.yaml` / `products/m5stack-u087.yaml`。
- 「工場出荷時に校正パラメータが書き込まれている」「書き込むと測定が不正確になる」は
  M5Stack の Unit AMeter / Unit VMeter 製品ページの記述（2026-08-15 に閲覧）。
- **バス上の位置（絶縁バリアのホスト側）と 3.3V の LDO 給電は、M5Stack が製品ページに
  載せているブロック図画像を読んで得た**（`ameter_sch_01.webp` / `vmeter_sch_01.webp`、
  2026-08-15 に取得）。両ユニットで構成は同一で、違いは EEPROM のアドレス（`0x51` / `0x53`）と
  ADS1115 のアドレス（`0x48` / `0x49`）だけである。
  なお**これはブロック図であって回路図ではない**。ピン接続や WP の扱いは読み取れない。
- M5Stack の GitHub `M5_Hardware` リポジトリには U086 / U087 のディレクトリが無く、
  回路図は公開されていない（2026-08-15 に確認）。
- **24 シリーズ相当のアドレッシングという仮定は `chips/eeprom.yaml` の注記に書かれた
  仮定であり、検証されていない。** 容量・ワードアドレス幅・ページサイズ・
  書き込み時間・WP の有無は、すべて **不明**。
- **未確認・未調査**: このデバイスに対する読み出しも書き込みも、一度も行っていない。
  probe も scenario も存在しない。応答するかどうかすら実測していない。
