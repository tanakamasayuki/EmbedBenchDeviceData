# SSD1309 — 128×64 OLED ドライバ兼コントローラ

> 表示 RAM を内蔵した OLED パネルの駆動 IC。I2C では**レジスタアドレスが存在せず、読み出しも
> できない**。スレーブアドレスの直後に置く control byte が「以後はコマンド」か
> 「以後は表示 RAM のデータ」かを決める、2 本のストリームだけで全部を表現する。
>
> **確度**: Solomon Systech の datasheet（SSD1309 Rev 1.1、2011-07）に基づく。ただし
> **メーカーが datasheet を公開しておらず**（ダウンロードは営業窓口経由）、参照したのは
> 広く流通しているミラー（hpinfotech.ro）である。**実測は無い**。
> `observations/ssd1309/` は存在せず、[`profiles/ssd1309.yaml`](https://github.com/tanakamasayuki/I2CDeviceDB/blob/38f1d82/profiles/ssd1309.yaml) も
> transport（control byte の値）しか持っていない。

## これは何か

有機 EL（OLED / PLED）のドットマトリクスパネルを駆動する、ドライバ + コントローラの 1 チップ。
**128 セグメント × 64 コモン**、つまり 128×64 ドット固定。チップ内に 128×64 bit の
表示 RAM（GDDRAM）、発振器、256 段のコントラスト制御を持つ。SSD1306 とほぼ同じコマンド体系で、
ライブラリの多くが「SSD1306 互換」として扱う。

ホストがすることは 2 つ。

1. **コマンドを送る**（表示 ON/OFF、コントラスト、走査方向、書き込み先のページと列、など）。
2. **表示 RAM にビットパターンを書く**。

書いたパターンはコントローラが走査してパネルに出し続ける。フレームバッファはチップ側にあるので、
ホストが毎フレーム送り直す必要は無い。

**I2C では書き込み専用である。** datasheet が明言している: I2C の節は
「I2C-bus **Write** data」しか定義しておらず（8.1.5.1、p.20）、データ読み出しについては
「シリアルモードではデータ読み出しは提供されない」（9.6、p.35）と書かれている。
ステータスレジスタ読み出しも GDDRAM 読み出しも 6800 / 8080 パラレル専用である。しかも
I2C モードでは **D/C# ピンが SA0（アドレス選択）に転用される**ので、読み出しに必要なピンが
そもそも残っていない。**「今なにが表示されているか」はホストが覚えておく**設計にすること。

インタフェースは BS0〜BS2 ピンで 6800 / 8080 パラレル、3線 / 4線 SPI、I2C から選ぶ。
I2C を選ぶと D0 が SCL、D1 が SDAIN、D2 が SDAOUT になる。

できること:

- 表示 ON / OFF、全点灯、白黒反転、コントラスト 256 段。
- 3 種類のアドレッシングモード: ページ（既定）、水平、垂直。
- セグメント / コモンのリマップ、表示開始ラインとオフセット、マルチプレクスレシオ 16〜64。
- ハードウェアの連続スクロール（水平・垂直・両方）。
- コマンドロック（`0xFD`）で、以後 `0xFD` 以外のコマンドとメモリアクセスを拒否させる。
- GPIO ピンの制御（`0xDC`）。

できないこと・持っていないもの:

- **I2C で一切読み出せない**（上記）。表示内容もステータスも。
- **チップ ID を読む手段が無い。** 「そこにあるのが SSD1309 か SH1107 か SSD1315 か」を
  バスから判定できない。
- **文字も図形も描けない。** フォントも線分描画も持たない。ビットマップを作るのはホストの仕事。
- **内蔵チャージポンプが無い。** パネル駆動用の VCC 7.0〜16.0 V を外部から与える必要がある。
  SSD1306 / SSD1315 の `0x8D`（Charge Pump Setting）に相当するコマンドが存在しない。
- **アドレス変更はコマンドではできない**（D/C# = SA0 ピンのみ）。
- **ソフトリセットコマンドが無い。** RES# ピンか電源断のみ。

電気的な現実:

- ロジック VDD 1.65〜3.3 V、パネル駆動 VCC 7.0〜16.0 V。**両方要る。**
- セグメント最大 320 µA、コモン最大 40 mA。
- IREF 端子と VSS の間の抵抗でセグメント電流を決める。10 ± 2 µA が推奨で、VCC 12 V なら
  約 900 kΩ。**モジュールの実装で決まっているので通常は触らない。**
- **ACK が返らないモジュールがありうる。** datasheet は SDAIN と SDAOUT を外部で結んで
  SDA にすることを求めており、「SDAOUT を未接続にすると I2C の ACK が無視される」と書いている
  （8.1.5 b、p.19）。さらに ITO 配線の抵抗とプルアップが分圧して、ACK が有効な Low に
  ならない場合があるとも警告している。**I2C スキャンで見つからないディスプレイは実在する。**

## コマンドとデータストリーム

**転送の形**（datasheet 8.1.5.1〜8.1.5.2、p.20）:

```
S | slave addr + W(=0) | A | control byte | A | data byte | A | ... | P
```

control byte のビットは上位から **Co**（continuation）と **D/C#**、残り 6 bit は 0。

- `0x00` = Co 0, D/C# 0 → **これ以降のバイトはすべてコマンド**。STOP まで control byte は要らない。
- `0x40` = Co 0, D/C# 1 → **これ以降のバイトはすべて表示 RAM のデータ**。書き込むたびに
  列アドレスポインタが +1 される。
- Co = 1（`0x80` / `0xC0`）にすると「次の 1 バイトのあとにまた control byte が来る」という意味になり、
  1 トランザクション内でコマンドとデータを交互に送れる。本リポジトリの probe は
  `0x00` / `0x40` しか出していない。

**ページアドレッシング**: 表示 RAM は 8 ページ（PAGE0〜7）に分かれ、1 ページ = 縦 8 ドット × 128 列。
**データ 1 バイトが縦 8 ドット分**で、D0 が上、D7 が下（リマップ無しのとき）。ページアドレッシング
モードでは、データを書くたびに列アドレスが +1 され、列の終端に達すると**列の先頭に戻る。
ページは自動では進まない**。ポインタを置き直す手順は datasheet 10.3（p.36）に明記されている:

1. `0xB0`〜`0xB7` でページを指定する。
2. `0x00`〜`0x0F` で列アドレスの下位ニブルを指定する。
3. `0x10`〜`0x1F` で列アドレスの上位ニブルを指定する。

水平アドレッシングモード（`0x20` + `0x00`）では列の終端で**ページが +1** され、
垂直モード（`0x20` + `0x01`）ではページの終端で列が +1 される。全画面を一気に流し込むなら
水平モードにして `0x21`（列範囲）と `0x22`（ページ範囲）を設定するのが速い。

主なコマンド（RESET = リセット後の値）:

| コード | 引数 | 意味 |
|---|---|---|
| `0x00`〜`0x0F` | — | 列アドレス下位ニブル（ページモード専用） |
| `0x10`〜`0x1F` | — | 列アドレス上位ニブル（ページモード専用） |
| `0x20` | 1 バイト | アドレッシングモード: `0x00` 水平 / `0x01` 垂直 / `0x02` ページ（RESET） |
| `0x21` | 2 バイト | 列の開始・終了アドレス（水平 / 垂直モード専用、RESET 0 と 127） |
| `0x22` | 2 バイト | ページの開始・終了アドレス（水平 / 垂直モード専用、RESET 0 と 7） |
| `0x26` / `0x27` | 6 バイト | 連続水平スクロールの設定（右 / 左） |
| `0x40`〜`0x7F` | — | 表示開始ライン 0〜63（RESET 0） |
| `0x81` | 1 バイト | コントラスト 0〜255（RESET `0x7F`） |
| `0xA0` / `0xA1` | — | セグメントリマップ（RESET `0xA0`） |
| `0xA4` / `0xA5` | — | 表示 RAM に従う（RESET） / 全点灯 |
| `0xA6` / `0xA7` | — | 通常表示（RESET） / 白黒反転 |
| `0xA8` | 1 バイト | マルチプレクスレシオ 16〜64（RESET 63 = 64MUX） |
| `0xAE` / `0xAF` | — | 表示 OFF（RESET） / ON |
| `0xB0`〜`0xB7` | — | ページアドレス 0〜7（ページモード専用） |
| `0xC0` / `0xC8` | — | コモン走査方向（RESET `0xC0`） |
| `0xD3` | 1 バイト | ディスプレイオフセット 0〜63（RESET `0x00`） |
| `0xD5` | 1 バイト | 表示クロックの分周比 / 発振周波数 |
| `0xD9` | 1 バイト | プリチャージ期間（RESET `0x22`） |
| `0xDA` | 1 バイト | COM ピンのハードウェア構成（RESET は alternative 構成） |
| `0xDB` | 1 バイト | VCOMH デセレクトレベル（RESET `0x34`） |
| `0xDC` | 1 バイト | **GPIO の設定**（RESET は出力 Low） |
| `0xE3` | — | NOP |
| `0xFD` | 1 バイト | **コマンドロック**。`0x16` でロック、`0x12` でロック解除（RESET は解除） |

**リセット直後は表示 OFF、ページアドレッシングモード、コントラスト `0x7F`。**
`0xAF` を送るまで何も光らない。

## 典型的な使い方

初期化から表示まで:

1. VDD を入れ、RES# を Low にしてから離す。その後 VCC を入れる（datasheet 8.8、p.26 に
   電源投入・遮断の順序が図示されている。**VCC を先に落とすと VDD より先に切ってはいけない**などの
   制約がある）。
2. `0x00` ストリームでコマンドを送る。少なくともマルチプレクスレシオ（`0xA8`）、
   ディスプレイオフセット（`0xD3`）、表示開始ライン（`0x40`〜`0x7F`）、セグメント / コモンの
   リマップ（`0xA0`/`0xA1`、`0xC0`/`0xC8`）、COM ピン構成（`0xDA`）、クロック（`0xD5`）、
   プリチャージ（`0xD9`）、VCOMH（`0xDB`）、コントラスト（`0x81`）をパネルに合わせる。
3. **表示 RAM の中身は電源投入時に不定である。** 8 ページ全部に 0 を書いて消す。
4. `0xAF` で表示 ON。
5. 以後、描画のたびに「ページと列を指定 → `0x40` ストリームでバイト列を流す」を繰り返す。

1 ページ分を書く最小の手順（本リポジトリの probe が実行しているもの）:

1. `0x00` ストリームで `0xAE`（表示 OFF）。
2. `0x00` ストリームで `0xB0`（ページ 0）。
3. `0x00` ストリームで `0x00`, `0x10`（列 0 = 下位 0 + 上位 0）。
4. `0x40` ストリームで n バイト流す。列アドレスが自動で進む。
5. `0x00` ストリームで `0xAF`（表示 ON）。

## 利用上の注意

- **I2C では読み出せない。** これは「使わないほうがよい」ではなく「機能が無い」である
  （datasheet 9.6、p.35）。差分描画をするならホスト側に同じ内容のバッファを持つしかなく、
  そのバッファと実機がずれても気づく手段は無い。
- **I2C スキャンに出てこないことがある。** SDAOUT を結線していないモジュールでは ACK が
  返らない（datasheet 8.1.5 b、p.19）。加えて ITO 配線の抵抗とプルアップの分圧で ACK が
  有効な Low にならないケースも datasheet が警告している。**「スキャンに出ない = 壊れている」
  とは限らない**ので、書き込みだけ試して画面が変わるかを見る。逆に、ACK が返らない構成では
  ホスト側の I2C API がエラーを返し続けるため、**エラーを無視して書き込みを続ける**実装が要る。
- **バスから「これは SSD1309 だ」と判定できない。** `0x3C` に ACK が返るだけで、SH1107 も
  SSD1315 も同じアドレス・同じ control byte 規則である（後述）。
- **`0x00` と `0x40` は「1 バイトのプレフィクス」ではなく「以後のストリームの種別」である。**
  Co=0 の control byte を 1 個送れば、STOP までのすべてがその種別になる。1 バイトごとに
  `0x00` を付け直す実装も動くが、転送量が倍になる。
- **ページアドレッシングモードではページが自動で進まない。** 列の終端で列アドレスだけが先頭に戻る。
  「1 画面ぶん流し込んだのに 1 行しか出ない」のはこれ。全画面を一度に送るなら水平アドレッシング
  モード（`0x20` `0x00`）にして `0x21` / `0x22` で範囲を決める。
- **`0x21` / `0x22` はページアドレッシングモードでは効かない。** 逆に `0x00`〜`0x0F` /
  `0x10`〜`0x1F` / `0xB0`〜`0xB7` はページアドレッシングモード専用である。
  datasheet が各コマンドに注記している。モードと使うコマンドを取り違えると、**エラーは出ないまま
  ポインタが動かない**。
- **チャージポンプが無い。** SSD1306 / SSD1315 用の初期化シーケンスをそのまま流すと、
  `0x8D` `0x14`（チャージポンプ有効）が**未定義コマンドとして解釈される**。datasheet は
  「コマンド表に無いパターンを入力してはならない、予期しない結果が起きうる」と明記している
  （9.5 節の Note 1、p.35）。SSD1306 用ライブラリを流用するときの最大の落とし穴で、
  症状は「初期化は通るのに真っ暗」あるいは「表示が不安定」になる。
  SSD1309 はパネル用の VCC を外部から与える前提である。
- **`0xDC` は GPIO であって表示開始ラインではない。** SH1107 では `0xDC` が表示開始ラインの
  2 バイトコマンドなので、SH1107 用のコードを流すと GPIO の設定を書き換えることになる。
- **表示開始ラインは 1 バイトコマンド（`0x40`〜`0x7F`）である。** そして `0x40` は
  **データストリームの control byte と同じ値**でもある。コマンドストリームの中の `0x40` は
  「開始ライン 0」、control byte としての `0x40` は「以後データ」。文脈が違うだけで
  バイトは同じなので、キャプチャを読むときは control byte の位置を必ず数える。
- **`0xFD`（コマンドロック）に `0x16` を書くと、以後 `0xFD` 以外のコマンドとメモリアクセスが
  すべて拒否される。** 誤って書くと画面が更新できなくなり、しかも読み出して確認する手段が無い。
  復旧は `0xFD` `0x12` かハードウェアリセット。
- **表示 RAM の初期値は不定。** クリアしてから `0xAF` を送る。
- **電源の投入・遮断に順序がある。** VDD と VCC の関係、RES# のタイミングが datasheet 8.8 節に
  規定されている。**VCC を VDD より後に落としてはいけない**などの制約は、モジュールの外側からは
  守れないことも多い（Grove の 1 系統から作っている場合など）。モジュール任せにするならそれでよいが、
  自分で基板を起こすなら必ず読むこと。
- **M5Stack の製品名に注意。** Unit Glass2（U158-B）は **SSD1309 が直接 I2C バスに出ている**が、
  型番の似た Unit Glass（U158）は中に STM32 が入っていて、ホストから見えるのは SSD1309 では
  なくファームウェアの描画コマンドである（[`m5stack-mcu-u158.md`](m5stack-mcu-u158.md)）。
  「SSD1309 のつもりで control byte を送ったのに何も起きない」場合は、まずどちらの製品かを確認する。

## 似ているチップとの見分け方

本カタログには同じ `0x3C` / `0x3D`、同じ control byte 規則（`0x00` / `0x40`）を使う
OLED コントローラが 3 つある。**I2C バスの上では区別できない。** 判断材料は次のとおり。

| | SSD1309 | SSD1315 | SH1107 |
|---|---|---|---|
| メーカー | Solomon Systech | Solomon Systech | Sinowealth |
| 解像度 | 128×64（8 ページ） | 128×64（8 ページ） | **最大 128×128（16 ページ）** |
| ページアドレス | `0xB0`〜`0xB7` | `0xB0`〜`0xB7` | `0xB0`〜**`0xBF`** |
| アドレッシングモード | `0x20` + 引数で 3 択 | 同左 | **`0x20` / `0x21` の 1 バイトで 2 択** |
| 表示開始ライン | `0x40`〜`0x7F`（1 バイト） | 同左 | **`0xDC` + 値**（2 バイト） |
| 昇圧 | **内蔵チャージポンプ無し。VCC 7〜16 V を外部から** | **内蔵チャージポンプあり**（`0x8D`） | 内蔵 DC-DC（`0xAD`） |
| 固有コマンド | **Set Command Lock `0xFD`、Set GPIO `0xDC`** | **Fade/Blinking `0x23`、Zoom In `0xD6`**（`0xFD` / `0xDC` は無い） | Read-Modify-Write `0xE0` / `0xEE` |
| datasheet | Rev 1.1 (2011-07) | Rev 1.1 (2017-04) | V2.1 |

実務的には、**モジュールの製品ページか基板のシルクを見るのが唯一確実な方法**である。
それでも分からないときの手がかりは (a) パネルが正方形に近ければ SH1107、
(b) 基板に昇圧用のインダクタ / コンデンサが載っていれば SSD1309（外部 VCC が要る）で、
逆に載っていなければ SSD1315 か SH1107、(c) 既存ライブラリのどの初期化シーケンスで
正しく表示されるか、である。**`0x3C` の ACK は 3 つのどれであるかを何も教えてくれない。**

## 出典と確度

- control byte の規則、コマンド、RESET 値、読み出しの可否、ACK の注意、電源シーケンス、
  電気仕様: **SSD1309 Rev 1.1（2011-07）**。
- **datasheet の出所そのものが弱い。** Solomon Systech は自社サイトで PDF を配布しておらず
  （営業窓口経由のリクエストが必要）、参照したのは hpinfotech.ro のミラーである。
  [`chips/ssd1309.yaml`](../../chips/ssd1309.yaml) の `source` も `reseller` になっている。
  **この PDF が最新版であることは確認できていない。**
- SSD1315 との比較（`0x8D` の有無、`0x23` / `0xD6` / `0xFD` / `0xDC` の有無）は、
  同じくミラー版の SSD1315 Rev 1.1（2017-04）のコマンド表と突き合わせて確認した。
  SH1107 との比較は SH1107 datasheet V2.1 のコマンド表による。
- **未確認（実測なし）**: `observations/ssd1309/` は存在しない。`0x3C` が ACK を返すか
  （上記のとおり返らない可能性がある）、`0x00` / `0x40` ストリームが実機で期待どおりに
  解釈されるか、400 kHz で動くか、いずれも確かめられていない。
- **未調査**: [`scenarios/ssd1309/p0.yaml`](https://github.com/tanakamasayuki/I2CDeviceDB/blob/38f1d82/scenarios/ssd1309/p0.yaml) では
  完全な初期化シーケンス、コントラストの掃引、アドレッシングモードの切り替え、
  全画面書き込み、Co ビットの変種が `deferred`。Unit Glass2（U158-B）の実装で
  SDAOUT がどう結線されているかも**確認していない**。
