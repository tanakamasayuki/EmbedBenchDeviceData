# Unit Weight-I2C (U180) — 外付けロードセル用の重量変換ユニット

> 手持ちのロードセル（ひずみゲージ）を端子台につないで、校正済みの重量を I2C から読める
> ようにするユニット。Mini Scales (U177) からロードセル・ボタン・LED を取り去り、
> 変換部分だけを残した構成になっている。
>
> **確度**: M5Stack が Unit Weight I2C Protocol という PDF（2023-12-11、PDF 自身の表記は
> firmware **V3** 向け。catalog の note は V1 と書いており食い違う）を公開しており、レジスタ表は
> そこと `M5Unit-WeightI2C` ライブラリのソースの両方に存在する。本文の転送長・バイト順・
> アクセス方向は**ライブラリのソースから起こした推定**で、実測では未確認。

## これは何か

HX711（24bit のロードセル用 ADC）と STM32F030F4P6 を載せた小さな基板。**HX711 は I2C バスには
出ていない**。ホストから見える I2C の相手は STM32 だけで、HX711 は STM32 が読んでいる。つまり
固定機能 IC ではなくファームウェアであり、レジスタマップはこの製品固有のものである。

ロードセルは**付属しない**。HT3.96-4P の端子台に自分で用意したひずみゲージ式のセルを
つなぐ。したがって秤量は「つないだセル次第」で、製品としての最大重量は規定されていない。
Grove から 5V をもらう。動作温度 0〜40℃。

できること:

- 校正前の**生の ADC カウント**（32bit）を読める。
- 校正後の**重量**を 3 通りで読める: float（グラム）、整数（グラム×100）、ASCII 文字列。
- **風袋引き（ゼロ点合わせ）**を 1 バイト書くだけで実行できる。
- **スケール係数（GAP）**を書き換えて校正できる。つないだセルに合わせるにはこれが必須。
- ローパス / 移動平均 / 指数移動平均の 3 つのフィルタを個別に設定できる。
- I2C アドレスを変更できる。

できないこと・持っていないもの:

- **ボタンも LED も無い。** Mini Scales にはある `0x20`（ボタン）と `0x30`（LED）が、
  この製品ではハードウェアごと存在しない。ライブラリのヘッダには残骸が残っている（後述）。
- **データレディのフラグが無い。** 読めばいつでも「最後の値」が返る。
- **割り込み線が無い。** ポーリングのみ。
- **HX711 のゲイン（チャンネル A/B、128/64/32 倍）や変換レートを選べない。** レジスタが無い。
- **ロードセルの生の電圧・励起電圧は読めない。**
- **温度補償が無い。** 温度を測る手段もユニット側に無い。
- **オフセット（風袋の値）を読めない。** できるのは「いまの値を 0 にする」だけ。
- **過負荷・断線の検出が無い。** セルを外しても、それを示すレジスタは無い。

## 早見表

| 項目 | 値 |
|---|---|
| I2C アドレス | `0x26`（既定）。**Unit Mini Scales (U177) と同じ**なので同一バスに 2 つ挿すなら片方を変更する |
| アドレス変更 | レジスタ `0xFF` に書き込み（値の範囲 1〜127）。**書いた直後から新アドレスで応答する** |
| 電源 | 5V（Grove の赤） |
| インタフェース | Grove HY2.0-4P（I2C）+ HT3.96-4P（ロードセル） |
| I2C 速度 | ライブラリの既定 100kHz。`begin()` の引数で変えられる |
| 中身 | STM32F030F4P6 + HX711（24bit） |
| 秤量 | つないだロードセル依存（製品としては規定なし） |
| 割り込み | 無し（ポーリング） |
| バイト順 | 数値はリトルエンディアン（LSB first） |

## レジスタ

| アドレス | 長さ | R/W | 意味 |
|---|---|---|---|
| `0x00` | 4 | R | 校正前の生 ADC カウント。**符号付き 32bit・LSB first**（単位なし、生の数） |
| `0x10` | 4 | R | 校正後の重量。**IEEE 754 単精度 float・リトルエンディアン**。vendor PDF は「グラム」と明記 |
| `0x40` | 4 | R/W | GAP（スケール係数）。**IEEE 754 単精度 float・リトルエンディアン** |
| `0x50` | 1 | W | `1` を書くと風袋引き（いまの値を新しいゼロ点にする） |
| `0x60` | 4 | R | 同じ重量の整数版。**符号付き 32bit・LSB first、単位は 1/100 g**（実重量 = 値 ÷ 100） |
| `0x70` | 16 | R | 同じ重量の文字列版。PDF によれば `'\0'` 終端で最大 15 文字 |
| `0x80` | 1 | R/W | ローパスフィルタ有効。`0`/`1`（既定 `1`） |
| `0x81` | 1 | R/W | 移動平均の窓。**単位はサンプル数**、0〜50（既定 10） |
| `0x82` | 1 | R/W | 指数移動平均の係数 α。0〜99（既定 10、単位は資料に記載なし） |
| `0xFD` | 1 | W | `1` を書くとファーム更新用ブートローダに入る |
| `0xFE` | 1 | R | ファームウェアのバージョン |
| `0xFF` | 1 | R/W | I2C アドレス（1〜127） |

`0x20` と `0x30` は**この製品には無い**。Mini Scales (U177) では前者がボタン、後者が LED である。

`0x10` / `0x60` / `0x70` は**同じ量の 3 通りの表現**で、その裏にある校正前の値が `0x00` である。

フィルタの 3 バイトはライブラリでは `WEIGHT_I2C_FILTER_REG`、`+1`、`+2` として扱われていて、
それぞれ 1 バイトずつ独立に読み書きされる。

**転送の形**: 書き込みは「ポインタバイト + ペイロード」を 1 トランザクションで。読み出しは
ポインタバイトを書いて **repeated START** を打ち、続けて必要な長さを要求する。ただし
`getFirmwareVersion()` と `getI2CAddress()` だけは STOP を打ってから読んでいる。

## 典型的な使い方

1. ロードセルを HT3.96-4P に配線する。**ここを間違えると以降の値はすべて無意味**なので、
   セル側の線色（E+/E−/A+/A−）を先に確認する。
2. `0xFE` を読んでファームウェアのバージョンを確認する（通信確認も兼ねる）。
3. **校正する。** ベンダーの手順（PDF の脚注）はこの順:
   1. `0x50` に `1` を書いて風袋引きする。
   2. 何も載せない状態で `0x00`（生 ADC）を読む → `RawADC_0g`。
   3. 100g の分銅を載せて `0x00` を読む → `RawADC_100g`。
   4. `GAP = (RawADC_100g − RawADC_0g) / 100` を計算する。
   5. `0x40` に GAP を float で書く。
4. 以後は `0x10`（float、グラム）を読む。整数で扱いたければ `0x60` を読んで **100 で割る**。
5. 値が暴れるならフィルタを設定する。`0x80` / `0x81` / `0x82`。

## 利用上の注意

- **ヘッダに宣言だけあって実体の無い関数が 3 つある。** `M5UnitWeightI2C.h` は
  `getBtnStatus()` / `setLEDColor()` / `getLEDColor()` を宣言しているが、
  `M5UnitWeightI2C.cpp` はそのどれも**定義していない**。ヘッダには BUTTON / RGB_LED の
  レジスタ定義も無い。呼ぶとコンパイルは通ってリンクで落ちる（undefined reference）。
  これは `M5Unit-Miniscale` からコピーしたときの消し残りで、**この製品にボタンや LED が
  あることを意味しない**。ヘッダを見て「使えるはず」と思わないこと。
  なおレジスタ `0x20` / `0x30` を直接読んだときに firmware が何を返すかは**未確認**。
- **`0x60` は 100 倍された値。** 実重量 = 値 ÷ 100（単位は 1/100 g）。**ライブラリの
  `getWeightInt()` はこの除算をしていない**ので、返り値をそのままグラムとして表示すると
  100 倍の重さになる。vendor PDF には "Actual weight = Weight Int/100" と明記されている。
- **校正しないと `0x10` は意味を持たない。** ロードセルが付属しない製品なので、
  出荷時の GAP は手元のセルとは無関係である。Mini Scales と違い、**校正は任意ではなく必須**。
- **校正の順序は「風袋 → 生 ADC の測定 → GAP 計算 → GAP 書き込み」。** profile の notes は
  「GAP を書いてから `0x50` で風袋」と読める書き方をしているが、ベンダーの手順書は
  風袋が先である。
- **`setGapValue()` は書き込みのあと 100ms ブロックする。** firmware 側がその間は応答しない
  という意味なので、自前の driver でも `0x40` への書き込み後は同じだけ待つこと。
- **`0x70` の文字列は 16 バイト固定読み。** PDF は `'\0'` 終端で最大 15 文字と書いているが、
  ライブラリは読んだ 16 バイトをそのまま Arduino の `String` コンストラクタに渡している。
  firmware が 16 バイト全部を埋めた場合、終端を探して**バッファの外まで読みに行く**。
- **読み出し失敗時に未初期化の値が返る。** `getWeight()` と `getGapValue()` は
  `readBytes()` が false を返したときにローカルの float を初期化しないまま返す。
- **`getI2CAddress()` と `getFirmwareVersion()` はグローバルの `Wire.read()` を呼んでいる。**
  `Wire1` を渡していると別のバスから読む。
- **アドレスが Unit Mini Scales (U177) と同じ `0x26`。** マップも `0x20` / `0x30` を除いて
  同一なので、scan だけではどちらが応答しているか区別できない。
- **アドレス変更は即時反映。** `0xFF` に書いた次のトランザクションはもう新アドレス宛に出す。
- **`0xFD` に書くとブートローダに入る。** 通常のアプリケーションから触る理由は無い。

## 出典と確度

- レジスタのアドレスと意味: `M5Unit-WeightI2C` ライブラリのソース（`collection/vendor/M5Unit-WeightI2C` に
  commit 固定で取得）。ベンダーの Protocol PDF とも整合する。
- 単位（グラム、1/100 g、サンプル数）、フィルタの値域と既定値、校正手順: ベンダー Protocol PDF。
- ボタン / LED が無いこと: ライブラリのヘッダにレジスタ定義が無く、.cpp に実装が無く、
  vendor PDF のレジスタ表にも `0x20` / `0x30` の行が無い、という 3 点の一致による。
- 転送長・アクセス方向・バイト順: 同ライブラリのメソッド本体から起こした**推定**。
- **未確認**: 実機のキャプチャがまだ無い（`observations/m5stack-mcu-u180/` は存在しない）。
  レジスタが表のとおり応答するか、`0x20` / `0x30` を読んだときに何が返るか、
  `0x70` の文字列が本当に終端されるかは確かめられていない。
- **注記**: `chips/m5stack-mcu-u180.yaml` は datasheet の note に "firmware version V1" と
  書いているが、PDF 自身の表紙は V3（2023/12/11）である。
- **未調査**: 書き込み側の挙動全般（GAP、風袋、フィルタ、アドレス変更）は probe が
  read-only のため触れていない。
