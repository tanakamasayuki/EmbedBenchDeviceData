# Unit HBridge (U160) — DC モータ用 H ブリッジドライバ

> DC モータ 1 個を正転・逆転・PWM 速度制御で駆動する H ブリッジを、I2C のレジスタ
> 書き込みで操作できるようにしたユニット。電源電圧のモニタ用 ADC も持つ。
>
> **⚠️ これは出力デバイスである。書き込むとモータが回る。** 実験する前に負荷（モータ）を
> 外すこと。本リポジトリの probe が read-only なのは、まさにこの理由による。
>
> **確度**: [`profiles/m5stack-mcu-u160.yaml`](https://github.com/tanakamasayuki/I2CDeviceDB/blob/38f1d82/profiles/m5stack-mcu-u160.yaml) の
> レジスタマップは `M5Unit-Hbridge` ライブラリのソースから起こした推定
> （`evidence.source: inferred` / `confidence: tentative`）で、**実測では未確認**。
> ベンダーは protocol PDF を出しておらず、製品ページに貼られた画像 1 枚がレジスタ表の
> すべてである。本文の値域（方向 0/1/2、PWM 周波数 100〜10000Hz など）とアドレス選択
> スイッチの表はその画像から読み取った。実機のキャプチャはまだ無い。

## これは何か

DC モータドライバ IC（RZ7899）と、それを制御する STM32F030F4P6 を載せたユニット。
ホストから見えるのは STM32 であって、ドライバ IC ではない。**つまり I2C の相手は固定機能 IC
ではなくファームウェアであり、レジスタマップはこの製品固有のもの**である。

モータと外部電源は Grove ではなく **HT3.96-4P のねじ端子**に繋ぐ。外部入力は最大 12V、
モータ電流は最大 3A。6〜12V 入力を 5V に落とす DC/DC を内蔵しており、5V モータも駆動できる。

用途は「マイコンから DC モータを 1 個回す」。ロボットの車輪、ポンプ、ファン、リニア
アクチュエータなど。

できること:

- 方向を 停止 / 正転 / 逆転 で指定できる。
- PWM のデューティを 8bit（0〜255）か 16bit（0〜65535）で指定できる。
- PWM の周波数を 100〜10000Hz で指定できる（既定 1000Hz）。
- 外部入力電圧（VIN）を ADC で読める。8bit と 12bit の 2 通り。
- 設定した方向・デューティ・周波数を読み返せる。
- I2C アドレスを基板上のスイッチで `0x20`〜`0x2F` の 16 通りから選べる。

できないこと・持っていないもの:

- **モータ電流を測れない。** 電流測定は v1.1（U160-V11）で追加された機能で、この v1.0 には無い。
  → [`m5stack-mcu-u160-v11.md`](m5stack-mcu-u160-v11.md)
- **エンコーダ入力が無い。** 速度も位置もフィードバックできない。回転数が要るなら別の
  センサをホスト側に付ける。
- **割り込み線・エラー通知が無い。** ドライバ IC は過電流・過電圧・過熱の保護を持つが、
  **保護が働いたことをホストに知らせるレジスタは無い**。異常を検出する手段が無いまま
  止まる（あるいは止まらない）ことになる。
- **ソフトウェアでは I2C アドレスを変更できない。** アドレスレジスタ `0xFF` は読み出し専用で、
  ライブラリにも書き込みメソッドが無い。変えたければ基板上のスイッチを操作する。
- **ADC の値は生の数値で、電圧ではない。** 単位に直すにはホスト側で係数を掛ける（後述）。
- **ブレーキとフリーラン（惰性）の区別が無い。** 方向レジスタにあるのは `0`（停止）だけで、
  それが電気ブレーキなのか出力遮断なのかはどの資料にも書かれていない（**未確認**）。

## レジスタ

`0x00`〜`0x05` は 1 つの連続した設定ブロックである。ライブラリも `HBRIDGE_CONFIG_REG`（`0x00`）
からのオフセットとして扱っている。

| アドレス | 長さ | R/W | 意味 |
|---|---|---|---|
| `0x00` | 1 | R/W | 方向。`0` = 停止（既定） / `1` = 正転 / `2` = 逆転 |
| `0x01` | 1 | R/W | PWM デューティ 8bit。0〜255 |
| `0x02` | 2 | R/W | PWM デューティ 16bit。0〜65535、**2 バイト LSB first** |
| `0x04` | 2 | R/W | PWM 周波数。100〜10000（**単位 Hz**）、既定 1000、**2 バイト LSB first** |
| `0x10` | 1 | R | VIN の ADC 値（8bit）。0〜255。**生の数値で、電圧ではない** |
| `0x20` | 2 | R | VIN の ADC 値（12bit）。0〜4095、**2 バイト LSB first**。**生の数値で、電圧ではない** |
| `0xFE` | 1 | R | ファームウェアのバージョン |
| `0xFF` | 1 | R | 応答している I2C アドレス |

**転送の形**: 書き込みは「ポインタバイト + ペイロード」を 1 トランザクションで送る。
読み出しは repeated START を使わず、**ポインタバイトを書いて STOP を打ち、改めてアドレス
指定して読む 2 トランザクション**になる（`M5UnitHbridge::readBytes` が `endTransmission()` を
既定の STOP 付きで呼んでいるため。M5Stack の他ユニットのライブラリはここが
`endTransmission(false)` で、このライブラリだけ違う）。

### VIN の電圧への直し方

ライブラリは係数を一切適用しない。ベンダーのサンプルは 12bit 値に対して次の式を使っている。

```
電圧[V] = raw / 4095.0 * 3.3 / 0.09
```

`0.09` は基板上の分圧比で、フルスケールは約 36.7V に相当する。**この係数はサンプルコードに
しか書かれておらず、レジスタ表にも API にも出てこない。** 8bit 側（`0x10`）については
分母を 255 に置き換えるのが自然だが、それを裏づける記述はどこにも無い（**未確認**）。

## 典型的な使い方

1. **モータを外した状態で** `0xFE` を読み、ファームウェアのバージョンと通信を確認する。
2. 必要なら `0x04` に PWM 周波数を書く（2 バイト LSB first）。既定の 1000Hz で足りることが多い。
3. デューティを書く。**8bit（`0x01`）か 16bit（`0x02`）のどちらかに決めて、混ぜない。**
4. `0x00` に方向を書く。**ここで初めてモータが回る。**
5. 止めるときは `0x00` に `0` を書く。デューティを 0 にするだけでも止まるが、
   方向レジスタが `1` / `2` のままなら「デューティ 0 で回転指示中」という状態が残る。
6. 電源電圧を見たいなら `0x20` を 2 バイト読み、上の式で V に直す。

## 利用上の注意

### 安全

- **書き込むとモータが回る。** 台の上でユニットだけを繋いで実験するときは、必ず端子から
  モータを外すか、回っても危なくない状態にすること。
- **モータは誘導性負荷である。** 停止・反転の瞬間に逆起電力が発生する。ドライバ IC 側に
  保護はあるが、電源側にも十分な容量のコンデンサを置き、電源ラインを長く引き回さないこと。
- **正転から逆転へ直接切り替えられてしまう。** レジスタは `1` → `2` の書き込みを拒まない。
  高速回転中に反転を書くと、モータと電源に大きな電流が流れる。減速を挟むかどうかは
  ホスト側の責任になる。
- **ホストが落ちてもモータは止まらない可能性が高い。** レジスタは書かれた値を保持する設計で、
  ライブラリにもタイムアウトやウォッチドッグの気配は無い。firmware 側に停止機構があるかは
  **未確認**。ホストのリセットで暴走させたくないなら、外部電源を切れるようにしておく。
- **外部入力は最大 12V、電流は最大 3A。** これを超える電源やモータを繋がない。
- **本リポジトリの probe（`scenarios/m5stack-mcu-u160/p0.yaml`）は `safety: read-only`。**
  書き込みレジスタは 1 つも叩かない。書き込み側の挙動は `deferred` として保留してある。

### プロトコル

- **方向とデューティは独立している。** デューティを書いてもモータは回らない。`0x00` に
  `1` か `2` を書いて初めて回る。逆に、方向を書いてからデューティを書けば、書いた瞬間に
  その速度になる。
- **8bit デューティと 16bit デューティは別レジスタである。** 同じ値の 2 つの見え方ではない。
  両方に書いたときにどちらが有効かは、ライブラリからもレジスタ表からも判断できない
  （**未確認**）。**どちらか一方に決めて使うこと。**
- **多バイト値はすべて LSB first。** ライブラリは `data[0] | (data[1] << 8)` で組み立て、
  下位バイトから送る。
- **ADC の値には係数が要る。** `getAnalogInput()` が返すのは生の数値。V だと思って
  そのまま表示すると 4095 V などと出る。上の式を自分で掛ける。
- **`0x10` と `0x20` は同じ VIN の別解像度。** 別々の入力ではない。
- **読み出しに repeated START を使わない。** ポインタバイトの書き込みと読み出しの間に STOP が
  入るので、その隙に同じバスの別トランザクションが割り込むとポインタが失われる可能性がある。
- **ライブラリのバグ: I2C 速度が化ける。** `M5UnitHbridge` のメンバは `uint8_t _speed;` なのに、
  `begin()` は `uint32_t speed = 100000L` を受け取ってそこへ代入する。100000 は 8bit に
  切り詰められて **160** になり、その値がそのまま `Wire.begin(sda, scl, 160)` に渡る。
  つまり既定の呼び方（ベンダーのサンプルを含む）をすると、**バスが 100kHz ではなく 160Hz に
  設定される**。ホスト側で改めて `Wire.setClock()` を呼ぶか、ライブラリを直すこと。
  デバイスの仕様ではなくライブラリの都合である。
- **アドレスはハードウェアで決まる。** `0xFF` は読むだけ。応答が無いときは基板上のスイッチを
  確認する。`0x20`〜`0x2F` を scan すれば必ず見つかる。
- **`0x30` と `0xFD` は v1.0 には無い。** ライブラリはこの 2 つ（電流値とブートローダ移行）を
  持っているが、ソース中に「Only V1.1 can use this」とコメントされている。v1.0 のユニットで
  `getMotorCurrent()` を呼ぶと、表に無いアドレスを読むことになる。何が返るかは**未確認**。

## 出典と確度

- レジスタのアドレスと転送長: `M5Unit-Hbridge` ライブラリのソース
  （`collection/vendor/M5Unit-Hbridge` に commit 固定で取得）。
- 値域（方向 0/1/2、8bit デューティ 0〜255、16bit デューティ 0〜65535、PWM 周波数
  100〜10000Hz・既定 1000Hz、ADC 0〜255 / 0〜4095）、レジスタ名が「VIN ADC」であること、
  および `0x20`〜`0x2F` のアドレス選択スイッチの対応表: ベンダーが製品ページに貼っている
  レジスタ表の**画像**から読み取った。**この製品には protocol PDF が無い。**
- ADC → 電圧の係数（`/4095 * 3.3 / 0.09`）: ベンダーのサンプルコードのみが出典。
  レジスタ表にも API にも記述が無い。
- 転送長・アクセス方向・バイト順: ライブラリのメソッド本体から起こした**推定**。
- **未確認**: 実機のキャプチャがまだ無い。8bit と 16bit のデューティを両方書いたときの
  優先順位、`0` が電気ブレーキかフリーランか、8bit ADC の係数、ホストが黙ったあとの
  firmware の挙動、v1.0 で `0x30` を読んだときの応答、400kHz で動くかは確かめられていない。
- **未調査**: 書き込み側の挙動全般（方向・速度・周波数）は probe が read-only のため
  触れていない。これは意図的な制限であり、書き込みがモータを回すためである。
