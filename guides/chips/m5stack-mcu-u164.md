# Unit AC Measure (U164) — 単相 AC 電力計測ユニット

> AC 100〜240V の単相電源の電圧・電流・電力・力率・積算電力量を測り、I2C で読めるように
> したユニット。同じ値を「ASCII 文字列」と「整数」の 2 通りで返す。
>
> **⚠️ このユニットの端子には商用電源が直接入る。感電すれば死ぬ電圧である。**
> 通電中は端子に触れない。配線は必ず電源を切ってから行い、通電したまま実験しない。
> 本リポジトリの probe が read-only なのは、こうしたユニットに書き込みを行わないためである。
>
> **確度**: [`profiles/m5stack-mcu-u164.yaml`](https://github.com/tanakamasayuki/I2CDeviceDB/blob/38f1d82/profiles/m5stack-mcu-u164.yaml) の
> レジスタマップは `M5Unit-ACMeasure` ライブラリのソースから起こした推定
> （`evidence.source: inferred` / `confidence: tentative`）で、**実測では未確認**。
> 本文の**単位とスケール（すべて 1/100）はベンダーの protocol PDF（firmware V1、2023-03-24）
> 由来**で、ライブラリのソースにはその記述が無い。実機のキャプチャはまだ無い。

## これは何か

計量 IC の **HLW8032** が実際の測定を行い、その結果を STM32G030F6P6 が UART で受け取って
I2C レジスタとして公開している、という二段構えのユニット。HLW8032 は I2C バスには出ていない。
ホストから見えるのは STM32 のファームウェアだけである。**つまりレジスタマップはこの製品固有の
もの**であり、HLW8032 のデータシートを読んでも I2C の話は出てこない。

商用電源は Grove ではなく **HT3.96-4P のねじ端子**に繋ぐ。端子の並びは L / PE / L / N で、
測りたい負荷を直列に通す形になる。絶縁は B0505ST16-W5（絶縁 DC/DC）と EL357NB
（フォトカプラ）で確保されている。

ベンダーは「AC 100〜240V@10A でなければ正しく動作しない」と明記している。つまり
**商用電源が繋がっていない状態では意味のある値は返らない**。

できること:

- 実効電圧[V]、実効電流[A]、有効電力[W]、皮相電力[VA]、力率、積算電力量[kWh] を読める。
- 同じ 6 つの値を、firmware が整形した ASCII 文字列としても読める。
- 積算電力量を書き込んで、任意の値に設定（あるいは 0 に）できる。
- 電圧と電流の校正係数を読み書きし、不揮発に保存できる。
- 測定値が有効かどうかのフラグ（Data Ready）を読める。
- I2C アドレスを変更できる。

できないこと・持っていないもの:

- **割り込み線は無い。変化を知るにはポーリングするしかない。**
- **周波数・力率の符号（進み/遅れ）・無効電力・波形・高調波は返らない。**
- **三相は測れない。単相のみ。**
- **過電流・過電圧の警報が無い。** しきい値の設定もアラーム出力も無い。判定はホスト側の仕事。
- **HLW8032 の生のフレームを覗けない。** UART 側は firmware の中で閉じている。
- **測定の更新周期が資料に無い。** Data Ready フラグがあることから、値は非同期に更新されると
  分かるが、周期は**未確認**。
- **校正係数の意味（何倍を表すか、既定値は何か）が資料に無い。** PDF は「係数 / 100」とだけ
  書いている。

## レジスタ

同じ 6 つの量が、`0x00`〜`0x50`（ASCII）と `0x60`〜`0xB0`（数値）に並んでいる。
対応は 電圧 `0x00`/`0x60`、電流 `0x10`/`0x70`、有効電力 `0x20`/`0x80`、
皮相電力 `0x30`/`0x90`、力率 `0x40`/`0xA0`、電力量 `0x50`/`0xB0`。

### ASCII 側（firmware が整形済み。**終端バイトは付かない**）

| アドレス | 長さ | R/W | 意味 |
|---|---|---|---|
| `0x00` | 7 | R | 実効電圧。`NNNN.NN`（V） |
| `0x10` | 7 | R | 実効電流。`NNNN.NN`（A） |
| `0x20` | 7 | R | 有効電力。`NNNN.NN`（W） |
| `0x30` | 7 | R | 皮相電力。`NNNN.NN`（VA） |
| `0x40` | 4 | R | 力率。`N.NN` |
| `0x50` | 11 | R | 積算電力量。`NNNNNNNN.NN`（kWh） |

### 数値側（**すべて実値 × 100**、リトルエンディアン）

| アドレス | 長さ | R/W | 意味 |
|---|---|---|---|
| `0x60` | 2 | R | 実効電圧。16bit LSB first。**V × 100** |
| `0x70` | 2 | R | 実効電流。16bit LSB first。**A × 100** |
| `0x80` | 4 | R | 有効電力。32bit LSB first。**W × 100** |
| `0x90` | 4 | R | 皮相電力。32bit LSB first。**VA × 100** |
| `0xA0` | 1 | R | 力率。1 バイト。**力率 × 100**（力率 1.00 なら 100） |
| `0xB0` | 4 | R/W | 積算電力量。32bit LSB first。**kWh × 100**。書き込むと積算値を上書きできる |

### 設定・制御

| アドレス | 長さ | R/W | 意味 |
|---|---|---|---|
| `0xC0` | 1 | R/W | 電圧の校正係数。1 バイト。**係数 × 100** |
| `0xD0` | 1 | R/W | 電流の校正係数。1 バイト。**係数 × 100** |
| `0xE0` | 1 | W | `1` を書くと `0xC0` / `0xD0` を不揮発に保存する |
| `0xFC` | 1 | R | Data Ready。`1` = 測定値が有効 / `0` = まだ無効 |
| `0xFD` | 1 | W | `1` を書くとファーム更新用ブートローダに入る |
| `0xFE` | 1 | R | ファームウェアのバージョン |
| `0xFF` | 1 | R/W | I2C アドレス。**書くと即時に切り替わる** |

**転送の形**: 書き込みは「ポインタバイト + ペイロード」を 1 トランザクションで送る。
読み出しはポインタバイトを書いて **repeated START**（`endTransmission(false)`）を打ち、続けて
必要な長さを要求する。ただし `getFirmwareVersion()` と `getI2CAddress()` の 2 つだけは
repeated START ではなく STOP を挟む。

## 典型的な使い方

1. **通電前に配線を済ませ、端子カバー等を戻してから**電源を入れる。
2. `0xFE` を読んでファームウェアのバージョンを確認する（通信確認も兼ねる）。
3. **`0xFC`（Data Ready）を読む。`0` の間は `0x00`〜`0xB0` の値を信じない。**
4. 表示するだけなら ASCII 側（`0x00`〜`0x50`）が楽。計算に使うなら数値側
   （`0x60`〜`0xB0`）を読み、**100 で割る**。
5. 積算値をリセットしたいときは `0xB0` に 0 を書く。
6. 校正するときは `0xC0` / `0xD0` に係数を書き、**その後 `0xE0` に `1` を書く**。
   書かなければ電源断で失われる。

## 利用上の注意

### 安全

- **端子には商用電源がそのまま入る。100〜240V、最大 10A。** 通電中は端子・端子まわりの
  はんだ面・電線の被覆の切れ目に絶対に触れない。
- **配線は必ずブレーカを落としてから行う。** 通電したまま端子を締めたり外したりしない。
- **絶縁境界を跨がない。** AC 側（HT3.96-4P）と I2C 側（Grove）はフォトカプラと絶縁 DC/DC で
  分離されている。テスタのプローブやオシロの GND クリップで両側を橋渡しすると、絶縁が
  無くなるだけでなく測定器を壊し、人が危険に晒される。**I2C 側の波形を観測するときは、
  AC を外してから行う。**
- **AC を外したままでも I2C は生きている。** ロジック側は Grove の 5V で動くので、
  **AC を繋がずにレジスタマップだけを確かめることができる**。その場合 `0xFC` は `0` の
  ままになるはずで、測定値には意味が無い。転送の形とアドレスの確認はこの状態で行うのが安全。
- **`0xFD` に書くとブートローダに入る。** 通常のアプリケーションから触る理由は無い。
  誤って書くと I2C の応答が変わる。
- **本リポジトリの probe（`scenarios/m5stack-mcu-u164/p0.yaml`）は `safety: read-only`。**
  `0xE0`（係数の保存）と `0xFD`（ブートローダ）は `deferred` として明示的に除外してある。

### プロトコル

- **`0xFC` を先に読む。** 測定値は HLW8032 から UART でフレームが届いて初めて埋まる。
  電源投入直後や AC 未接続では、`0x00`〜`0xB0` に何が入っているか分からない。
  ベンダーのサンプルも `getReady()` が真のときだけ値を表示している。
- **数値レジスタはすべて 100 倍値。** PDF の例がそのまま分かりやすい —— 実際の電圧が
  100.55V なら、読める値は `100.55 * 100 = 10055` である。**ライブラリの API は割り算をしない。**
  `getVoltage()` の戻り値をそのまま V として表示すると 100 倍になる。
- **力率も 100 倍。** 1 バイトなので、力率 1.00 は `100` として読める。0〜255 の値域に対し
  意味があるのは 0〜100 だけ。
- **ASCII フィールドは終端されない。** 7 バイト（力率は 4、電力量は 11）がすべて文字であり、
  NUL の余地が無い。ライブラリはゼロ初期化したバッファに読み込んだあと固定長で `memcpy`
  するだけなので、**呼び出し側は 1 バイト余分に確保して自分で終端を付ける**。
- **`getPowerFactorString()` のバッファ長に注意。** 内部バッファは 7 バイトで宣言され、
  読み込むのは 4 バイトだけだが、`memcpy` は 7 バイト分行われる。つまり
  **呼び出し側は 4 バイトではなく 7 バイト以上のバッファを渡す必要がある**（意味があるのは
  先頭 4 バイト）。これがレジスタ長を 4 と判断した根拠でもある。
- **校正係数は書いただけでは残らない。** `0xC0` / `0xD0` は RAM 上の値で、`0xE0` に `1` を
  書くまで不揮発化されない。校正してそのまま電源を切ると元に戻る。
- **`0xB0` への書き込みはベンダーの表に無い。** PDF は `0xB0` を R（読み出しのみ）と
  している。書けるという主張はライブラリの `setKWH()` だけが根拠であり、**未確認**である。
- **`setKWH()` はホストのバイト順に依存している。** `uint32_t` の生のバイト列をそのまま
  送るので、リトルエンディアンのホスト（ESP32 など）でしか正しくならない。
- **32bit / 16bit 値はすべて LSB first。**
- **アドレス変更は即時反映。** `0xFF` に書いた次のトランザクションはもう新アドレス宛に
  出さないと応答しない。復旧は scan で全アドレスを舐めることになる。
- **ライブラリのバグ: I2C 速度が化ける。** `UNIT_ACMEASURE` のメンバは `uint8_t _speed;` なのに、
  `begin()` は `uint32_t speed = 100000L` を受け取ってそこへ代入する。100000 は 8bit に
  切り詰められて **160** になり、その値がそのまま `Wire.begin(sda, scl, 160)` に渡る。
  つまり既定の呼び方（ベンダーのサンプルを含む）をすると、**バスが 100kHz ではなく 160Hz に
  設定される**。ホスト側で改めて `Wire.setClock()` を呼ぶか、ライブラリを直すこと。
- **ライブラリのバグ: 一部のメソッドがグローバルの `Wire` から読む。**
  `getFirmwareVersion()` と `getI2CAddress()` は書き込みを `_wire` で行うのに、読み出しだけ
  `Wire.read()`（グローバル）を使っている。`begin()` に `Wire1` を渡した構成では、
  この 2 つだけ別のバスから読もうとして壊れる。

## 出典と確度

- レジスタのアドレスと転送長: `M5Unit-ACMeasure` ライブラリのソース
  （`collection/vendor/M5Unit-ACMeasure` に commit 固定で取得）。
- **単位とスケール（V / A / W / VA / kWh、およびすべてが実値 × 100 であること）**、
  ASCII フィールドの桁構成（`NNNN.NN` など）、Data Ready の `1` / `0` の意味、
  `0xE0` が電圧・電流係数を保存すること: ベンダーの Unit ACMeasure I2C Protocol PDF
  （V1、2023-03-24）。**ライブラリのソースにはスケールも単位も書かれておらず、
  profile が「単位不明」と記録しているのはそのためである。** PDF は具体例
  （100.55V → 10055）も示している。
- 転送長・アクセス方向・バイト順: ライブラリのメソッド本体から起こした**推定**。
- **ライブラリと PDF の差**: PDF は `0xB0`（積算電力量）を読み出し専用としているが、
  ライブラリには `setKWH()` がある。profile は書けるものとして記録している。**未確認**。
- **PDF 側の誤り**: PDF の表は Data Ready・Firmware Version・I2C Address の 3 つをすべて
  `0xF0` と書いている。1 つのアドレスに 3 つのレジスタは置けない。ライブラリの
  `0xFC` / `0xFE` / `0xFF` が正しいとみて本文はそちらを採った（M5Stack の他ユニットの
  protocol PDF にも同じ誤植がある）。また PDF の有効電力の計算式は 2 バイト分しか書いて
  いないが、同じ行のバイト割り当ては byte0〜byte3 の 4 バイトである。電力量の式が
  4 バイトぶん展開されていることから、有効電力・皮相電力も 4 バイトと読んだ。
- **未確認**: 実機のキャプチャがまだ無い。測定の更新周期、校正係数の既定値と意味、
  `0xB0` が書けるか、AC 未接続時に各レジスタが何を返すか、400kHz で動くかは
  確かめられていない。
- **未調査**: 書き込み側の挙動全般（積算値の設定、校正係数、その保存、アドレス変更、
  ブートローダ移行）は probe が read-only のため触れていない。これは意図的な制限であり、
  このユニットが商用電源に接続されるためである。
