# Unit 4Relay (U097) — 4 回路リレーユニット

> AC250V/10A まで扱える機械式リレー 4 個と、それぞれのステータス LED を I2C で操作する
> アクチュエータ。**レジスタは 2 つしかない**が、その 1 つにリレーと LED が同居しているため
> 落とし穴が多い。
>
> **確度**: レジスタ表とビット割り当ては **M5Stack の製品ページの Protocol 節に基づく**。
> 転送長・アクセス方向は `M5Unit-RELAY` v0.0.2 のソースから起こした**推定**で、
> 実測では未確認。

> ⚠️ **書き込むと本物の接点が動く。** このユニットへの書き込みは AC100V / 200V 系の
> 負荷をその場で入り切りする。試しに叩いてみる、という対象ではない。本リポジトリの probe が
> read-only（`scenarios/m5stack-mcu-u097/p0.yaml` の `safety: read-only`）なのはこのためで、
> 書き込みの挙動は一切確かめていない。

## これは何か

STM32F030F4P6 に M5Stack のファームウェアを載せ、4 個の機械式リレーとその状態表示 LED を
束ねているユニット。ホストから見える相手は STM32 であって、リレーそのものではない。
高圧側と低圧側は基板上で物理的に分離されている。

接点は HT3.96-4P の端子台に出ている。定格は AC250V / DC28V、10A（瞬時最大 16A）。
112 × 23 × 18mm、40g で、LEGO 互換の取り付け穴が 2 つある。

できること:

- 4 個のリレーを個別に、あるいは一括で ON / OFF する。
- 4 個のステータス LED を、リレーとは独立に光らせる（マニュアルモード）か、
  リレーの状態に追従させる（オートモード）。
- 現在の状態を `0x11` から読み戻す。

できないこと・持っていないもの:

- **割り込み線は無い。**
- **接点そのものの状態を検出する手段は無い。** `0x11` から読めるのは firmware が
  保持している指令値であり、リレーが実際に動いたか（コイル断線、接点溶着など）は分からない。
  **指令値ではなく実測値だという根拠も無い**ので、この点は未確認として扱うのが安全。
- **電流・電圧の測定機能は無い。** 負荷の様子は一切見えない。
- **I2C アドレスを変更するレジスタが無い。** `0x26` 固定。同一バスに 2 台は載らない。
- **ファームウェアバージョンを読むレジスタが無い。** 通信確認はアドレスへの ACK で行う。
- **パルス出力・タイマ・ラッチ機能は無い。** 「1 秒だけ ON」といった動作は
  ホストが状態を保持して自分で消す。
- **電源投入直後の状態が資料に書かれていない。** ライブラリの `Init()` が `0x11` を
  クリアするまで、firmware が持っている初期状態のままである。

## レジスタ

| アドレス | 長さ | R/W | 意味 |
|---|---|---|---|
| `0x10` | 1 | R/W（ライブラリは書きのみ） | bit0 が LED 同期モード。`0` = マニュアル（LED を独立制御）、`1` = オート（LED がリレーに追従）。bit1–7 は未使用 |
| `0x11` | 1 | R/W | リレーと LED のビットマップ。`1` = ON、`0` = OFF |

`0x11` のビット割り当て（**ベンダーのビット番号とリレー番号は逆順**）:

| ビット | 対象 |
|---|---|
| bit7 | LED1 |
| bit6 | LED2 |
| bit5 | LED3 |
| bit4 | LED4 |
| bit3 | RELAY1 |
| bit2 | RELAY2 |
| bit1 | RELAY3 |
| bit0 | RELAY4 |

多バイトの値は存在しないので、バイト順の問題は無い。値に物理単位も無い（ビットフラグのみ）。

**転送の形**: 書き込みは「レジスタバイト + 1 バイト」を 1 トランザクション。
読み出しはレジスタバイトを書いて STOP を打ち、改めて 1 バイト読む。

## 典型的な使い方

1. `0x10` に `0`（マニュアル）か `1`（オート）を書いてモードを決める。
2. `0x11` に `0x00` を書いて、リレーも LED も全部 OFF の既知の状態から始める。
   ライブラリの `Init(mode)` はこの 1 と 2 をまとめて行う。**`begin()` は Wire を
   開始するだけで、`0x11` には触れない。**
3. 1 個だけ変えるときは `0x11` を読み、該当ビットだけ立てるか落として書き戻す
   （read-modify-write）。
4. 全部まとめて変えるときは `0x0F`（全リレー ON）や `0xF0`（全 LED ON）を書く。
   **ただし下の注意を読むこと。**

## 利用上の注意

- **書き込みは本物の接点を動かす。** 何が繋がっているか分からない状態で `0x11` に
  書き込まないこと。本リポジトリはこの理由で probe を read-only にしており、
  書き込み側の挙動は一切検証していない。
- **番号とビットが逆順。** ベンダーの表では bit3 が RELAY1、bit0 が RELAY4 である。
  一方 `M5Unit-RELAY` の `relayWrite(number, state)` は**ビット番号 `number` を立てる**ので、
  `relayWrite(0, true)` が点けるのは RELAY1 ではなく **RELAY4**。LED も同様で、
  `ledWrite(0, true)` は LED4 を点ける。基板のシルクどおりに番号を渡すと 1 と 4、2 と 3 が入れ替わる。
- **`0x11` はリレーと LED が同居する 1 バイト。一括系の呼び出しは片方を消す。**
  ライブラリの `relayAll(true)` は `0x0F` を書くので、**同時に LED ニブルが全部 0 になる**。
  `ledAll(true)` は `0xF0` を書くので、**同時にリレーが全部 OFF になる**。
  「LED を全部点けたらリレーが全部切れた」という事故はこれ。個別制御
  （`relayWrite` / `ledWrite`）は read-modify-write なのでこの問題は起きない。
- **`Init()` を呼ばないと初期状態が不明。** `begin()` は `Wire` を開始するだけで
  （しかもクロックに 0 を渡している）、`0x11` は firmware の電源投入時の値のまま。
  既知の状態から始めたいなら `Init()` か `0x11` への `0x00` 書き込みが要る。
- **オートモードでは LED ビットへの書き込みが無意味になる。** `0x10` を `1` にすると
  firmware が LED ニブルをリレーニブルから駆動するので、bit4–7 に書いても上書きされる。
  LED を独立に使いたいならモードは `0`。
- **ライブラリはアドレスを `0x26` に決め打ちしている。** `UNIT_4RELAY_ADDR` が
  全メソッドに直接埋め込まれており、インスタンスごとにアドレスを変える手段が無い。
  そもそもアドレス変更レジスタも無いので、同一バスに 2 台は載せられない。
- **ライブラリの `ledWrite()` はビットマスクではなくレジスタ定数をシフトしている。**
  `StateFromDevice |= (UNIT_4RELAY_REG << number)` という式で、`UNIT_4RELAY_REG` は
  モードレジスタのアドレス `0x10` である。結果としては `number` が 0〜3 の範囲なら
  `0x10 / 0x20 / 0x40 / 0x80` となり LED ニブルのビットに一致するので、
  **ドキュメントされた範囲では正しく動く**。`number` が 4 以上だとバイトから溢れて何も起きない。
  意図が読み取れない書き方なので、写経して別の定数に置き換えると壊れる。
  （`profiles/m5stack-mcu-u097.yaml` の `notes` はこれを「1〜3 で溢れて無効になる不具合」と
  記録しているが、ソースを追う限り 0〜3 では溢れない。実機で確認すべき点として残っている。）
- **`0x10` はライブラリからは読まれない。** ベンダーの表では R/W なので読めるはずだが、
  ライブラリが読まないので実際に読めるかは**未確認**。現在のモードが分からなくなったら
  書き直すのが確実。
- **`0x11` の読み値が指令値なのか実測値なのかは分からない。** 接点が溶着していても
  「OFF」と読める可能性がある。安全に関わる用途では、この値をフィードバックとして
  信用してはいけない。
- **接点は機械式。** 開閉には数ミリ秒かかり、寿命は開閉回数で決まる。高頻度の
  スイッチングには向かない。誘導性負荷を切るときのサージ対策は利用者側の責任。

## 出典と確度

- レジスタ `0x10` / `0x11` のアドレス、`0x11` のビット割り当て（bit7–4 = LED1–4、
  bit3–0 = RELAY1–4）、`0x10` bit0 のマニュアル / オートの意味、両レジスタが R/W であること:
  **M5Stack の製品ページの Protocol 節に基づく**。
- 転送長・アクセス方向・一括系呼び出しが他方のニブルを消すこと・`Init()` の内容:
  `M5Unit-RELAY` v0.0.2 のソースから起こした**推定**。
- **未確認**: 実機のキャプチャがまだ無い。`0x11` の読み値が指令値か実測値か、
  `0x10` が実際に読めるか、電源投入直後の状態、400kHz で動くかは確かめられていない。
- **未調査**: **書き込み側の挙動は一切検証していない。**
  `scenarios/m5stack-mcu-u097/p0.yaml` は `safety: read-only` で、`write-mode` と
  `write-behaviour` が `deferred` に置かれている。実際に接点を動かす検証は、
  負荷を外した状態で意図して行うべきものである。
