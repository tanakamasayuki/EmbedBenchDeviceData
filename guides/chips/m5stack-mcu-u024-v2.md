# Unit Joystick2 (U024-V2) — ホール素子式ジョイスティックユニット

> 2 軸のスティックと押し込みスイッチ、RGB LED を I2C で読み書きする入力デバイス。
> 生の ADC 値のほかに、キャリブレーション境界から firmware が計算した「中心を 0 とする
> 符号付きの値」も読める。
>
> **確度**: M5Stack は製品ページ内に I2C Protocol の**画像**（V1 FW、2024-01-10 付）を
> 掲載しているが、PDF は無い。`profiles/` のレジスタマップは `M5Unit-Joystick2` ライブラリの
> ソースから起こした推定で、上記の画像とは突き合わせ済み。**転送長・バイト順・
> アクセス方向は実測では未確認。**

## これは何か

ホール素子式のジョイスティック（接点が擦れないので摩耗しない）と、押し込みスイッチ、
WS2812C の RGB LED を、STM32G030F6P6 に載った M5Stack ファームウェアが束ねているユニット。
ホストから見える相手は STM32 であって、ADC でもスイッチでもない。**レジスタマップは
この製品固有のもの**である。

旧 Unit Joystick (v1.1) とは中身が別物で、アドレスも違う（旧 `0x52` / 本機 `0x63`）。

できること:

- X / Y の生の ADC 値を読める。8bit（各 1 バイト）と 16bit（各 2 バイト、LSB first）の 2 通り。
- **中心を 0 とする符号付きの値**を読める。12bit 相当（−4095〜4095）と 8bit 相当（−127〜127）。
  これは firmware がキャリブレーション境界から計算した値で、UI でそのまま使いやすい。
- **キャリブレーション境界を読み書きできる。** X/Y それぞれについて、負側の最小/最大、
  正側の最小/最大の 4 組、合計 8 個の 16bit 値。M5Stack の firmware 定義ユニットとしては
  珍しく、内部の補正パラメータが露出している。
- 押し込みスイッチの状態を読める。
- RGB LED の色を読み書きできる。
- I2C アドレスを変更できる。ブートローダ / ファームウェアのバージョンも読める。

できないこと・持っていないもの:

- **割り込み線は無い。** 変化を知るにはポーリングするしかない。
- **キャリブレーションを自動で取る命令が無い。** `0x40` は境界値の置き場でしかないので、
  スティックを一周させて端点を集める処理はホスト側で書く。
- **デッドゾーンの設定レジスタが無い。** 中心付近の遊びは自分で作る。
- **書いた境界値が電源を切っても保持されるか（flash に焼かれるか）は未確認。**
- **スイッチの押下エッジ・チャタリング除去・長押し判定は無い。** 現在の状態が読めるだけ。
- **LED の輝度レジスタは無い。** 色の RGB 値で明るさを作る。LED は 1 個だけ。
- **ADC 値に物理単位は無い。** 角度でも電圧でもない、生のカウント値である。換算係数は
  ベンダー資料に記載が無い。

## 早見表

| 項目 | 値 |
|---|---|
| I2C アドレス | `0x63`（既定） |
| アドレス変更 | レジスタ `0xFF` に書き込み。**書いた直後から新アドレスで応答する** |
| 電源 | 5V（Grove の赤） |
| インタフェース | Grove HY2.0-4P |
| I2C 速度 | ライブラリの既定は 400kHz。上限は未実測 |
| 中身 | STM32G030F6P6（Flash 32KB / SRAM 8KB）+ ホール素子ジョイスティック + WS2812C ×1 |
| 割り込み | 無し（ポーリング） |
| バイト順 | 数値はすべてリトルエンディアン（LSB first）。RGB は **B, G, R, 未使用** の順 |
| 寸法 / 重量 | 40.0 × 24.0 × 23.9mm / 10.0g |

## レジスタ

| アドレス | 長さ | R/W | 意味 |
|---|---|---|---|
| `0x00` | 4 | R | 生の ADC。X が `0x00`（L, H）、Y が `0x02`（L, H）。各 16bit 符号なし、**LSB first**。単位なし |
| `0x10` | 2 | R | 生の ADC の 8bit 版。X が `0x10`、Y が `0x11`。各 1 バイト、0〜255 |
| `0x20` | 1 | R | 押し込みスイッチ。**アクティブ Low**（`0` が押下、`1` が非押下） |
| `0x30` | 4 | R/W | RGB LED。`0x30`=B, `0x31`=G, `0x32`=R, `0x33`=未使用 |
| `0x40` | 16 | R/W | キャリブレーション境界。16bit ×8、すべて LSB first。並びは下記 |
| `0x50` | 4 | R | 中心基準の符号付き値（12bit 相当）。X が `0x50`、Y が `0x52`。**−4095〜4095**、LSB first |
| `0x60` | 2 | R | 中心基準の符号付き値（8bit 相当）。X が `0x60`、Y が `0x61`。**−127〜127**、各 1 バイト |
| `0xFC` | 1 | R | ブートローダのバージョン |
| `0xFE` | 1 | R | ファームウェアのバージョン |
| `0xFF` | 1 | R/W | I2C アドレス |

`0x40` の 16 バイトの並び（各 2 バイト、LSB first）:

| オフセット | 内容 |
|---|---|
| `0x40` | X 負側の最小値 |
| `0x42` | X 負側の最大値 |
| `0x44` | X 正側の最小値 |
| `0x46` | X 正側の最大値 |
| `0x48` | Y 負側の最小値 |
| `0x4A` | Y 負側の最大値 |
| `0x4C` | Y 正側の最小値 |
| `0x4E` | Y 正側の最大値 |

**転送の形**: 読み出しはポインタバイトを書いて **repeated START**（`endTransmission(false)`）を
打ち、続けて必要な長さを要求する。書き込みは「ポインタバイト + ペイロード」を 1 トランザクション。

X と Y は別々にも読める。`0x00` から 4 バイト読めば両軸、`0x00` から 2 バイトなら X だけ、
`0x02` から 2 バイトなら Y だけになる。

## 典型的な使い方

1. `0xFE` を読んでファームウェアのバージョンを確認する。通信確認も兼ねる。
2. UI としてスティックを使うなら `0x50`（12bit 符号付き）か `0x60`（8bit 符号付き）を
   一定周期で読む。中心が 0 になっているので、そのまま方向と量として扱える。
3. 生の値が要るなら `0x00`（16bit）または `0x10`（8bit）を読む。キャリブレーションの
   影響を受けない代わりに、中心値は個体ごとにずれている。
4. 押し込みは `0x20`。**`0` が押下**なので、素直に真偽値へ変換すると意味が反転する。
5. LED を光らせるなら `0x30` に 4 バイト書く。**先頭が青**である点に注意。
6. 自前でキャリブレーションするなら、スティックを一周させて各方向の端点を集め、
   8 個の 16bit 値を `0x40` に 16 バイトまとめて書く。

## 利用上の注意

- **押し込みスイッチはアクティブ Low。** `0x20` の値をそのまま「押されている」と解釈すると
  逆になる。ライブラリの `get_button_value()` は生のバイトを返すだけで、反転は呼び出し側の仕事。
- **`0x30` のバイト順は B, G, R。** ベンダーの Protocol 画像がそう明記している。
  ライブラリは `uint32_t` の `0xRRGGBB` をそのまま 4 バイト `memcpy` して送るので、
  **リトルエンディアンのホストでは**結果的に B, G, R, 未使用の順になって辻褄が合う。
  ペイロードを手で組み立てる場合は青を先頭にすること。ビッグエンディアンのホストで
  ライブラリをそのまま使うと色が入れ替わる。
- **`0x50` / `0x60` はキャリブレーション値に依存する。** `0x40` に不正な境界を書くと、
  中心基準の値だけが壊れて生の ADC（`0x00` / `0x10`）は正常なまま、という状態になる。
  値がおかしいときは両方を見比べる。
- **レジスタ名の「12bits」を鵜呑みにしない。** ライブラリの定数名は
  `JOYSTICK2_ADC_VALUE_12BITS_REG` だが、ベンダーの Protocol 画像も製品ページも
  この値を **16bit（0〜65535）** と書いている。どちらが実機の挙動かは**未確認**。
  上位ビットが実際に使われているかは実測で確かめるべき箇所である。
- **ライブラリの既知の不具合（バス取り違え）**: `get_firmware_version()`,
  `get_bootloader_version()`, `get_i2c_address()` の 3 つは、送信は `_wire` に対して
  行うのに**受信だけグローバルの `Wire` から読んでいる**。`Wire1` などを渡して使うと、
  この 3 つだけ別のバスから読んだゴミが返る。他のアクセサは `read_bytes()` 経由なので影響しない。
- **アドレス変更は即時反映。** `0xFF` に書いた次のトランザクションはもう新アドレス宛に
  出さないと応答しない。ライブラリの `set_i2c_address()` は送信完了を待たずに内部の
  アドレス変数を更新するが、トランザクション自体は旧アドレス宛に発行されているので
  動作としては正しい。書き換えた値を忘れると `0x63` を探しても見つからない個体が残る。
- **無効な列挙値を渡すと未初期化の値が返る。** `get_joy_adc_value_x()` /
  `get_joy_adc_value_y()` は `adc_mode_t` が想定外だった場合に何も代入せずローカル変数を
  返す。定数以外を渡さないこと。
- **ADC 値を角度や電圧に読み替えない。** 換算係数がベンダー資料に無い。
- **割り込みが無いので、素早い操作はポーリング周期で取りこぼす。** ただし
  Unit Scroll のような「読むと消える」レジスタは無いので、取りこぼしても値が失われる
  わけではなく、単に中間の位置が見えないだけである。

## 出典と確度

- レジスタのアドレスと意味: `M5Unit-Joystick2`（`collection/vendor/` に commit 固定で取得）の
  `src/m5_unit_joystick2.hpp` / `.cpp`。ベンダーの Protocol 画像とも突き合わせた。
- 値域（生 ADC 0〜65535、8bit 0〜255、`0x50` の −4095〜4095、`0x60` の −127〜127）と
  `0x30` のバイト割り当て、`0x20` の 0=押下: **ベンダーの Protocol 画像由来**。
- 転送長・アクセス方向・バイト順: ライブラリのメソッド本体から起こした**推定**。
- **未確認**: 実機のキャプチャがまだ無い。生 ADC が本当に 16bit 全域を使うのか
  （ライブラリの定数名は 12bit を示唆する）、`0x40` に書いた値が電源断で保持されるか、
  400kHz で安定するかは確かめられていない。
- **未調査**: 書き込み側の挙動全般（`0x30` の LED、`0x40` のキャリブレーション、
  `0xFF` のアドレス変更）は `scenarios/m5stack-mcu-u024-v2/p0.yaml` が
  `safety: read-only` のため触れていない。
