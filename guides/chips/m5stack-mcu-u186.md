# Unit Scroll (U186) — スクロールホイール入力ユニット

> マウスのホイールのような操作を I2C 1 本で読めるようにした入力デバイス。回転量・
> 押し込み・LED 色を、ホスト側からはレジスタの読み書きとして扱う。
>
> **確度**: M5Stack が Unit Scroll Protocol という PDF を公開しており、レジスタ表はそこと
> `M5Unit-Scroll` ライブラリのソースの両方に存在する。本文のバイト順・転送長・
> アクセス方向は**ライブラリのソースから起こした推定**で、実測では未確認。

## これは何か

ロータリーエンコーダ（EC10E、押し込みスイッチ付き）と RGB LED（WS2812C）を、
STM32F030F4P6 に載せた M5Stack ファームウェアが束ねているユニット。ホストから見える
のは STM32 であって、エンコーダでも LED でもない。**つまり I2C の相手は固定機能 IC
ではなくファームウェアであり、レジスタマップはこの製品固有のもの**である。

できること:

- ホイールの回転を**絶対値**（電源投入以降の累積）と**相対値**（前回読んでからの差分）の
  両方で読める。UI のスクロール操作なら相対値、位置決めなら絶対値が向く。
- 押し込みスイッチの状態を読める。
- LED の色を指定できる。
- I2C アドレスを変更できる（複数台を同じバスに並べられる）。

できないこと・持っていないもの:

- 割り込み線は無い。**変化を知るにはポーリングするしかない。**
- 回転の速度・加速度は返さない。必要ならホスト側で時間差から求める。
- エンコーダの分解能や機械的なクリック数は firmware からは読めない。

## 早見表

| 項目 | 値 |
|---|---|
| I2C アドレス | `0x40`（既定） |
| アドレス変更 | レジスタ `0xFF` に書き込み。**書いた直後から新アドレスで応答する** |
| 電源 | 5V（Grove の赤）。内部で 3.3V へ降圧 |
| インタフェース | Grove HY2.0-4P |
| I2C 速度 | 100kHz / 400kHz（未実測。上限は firmware 依存） |
| 中身 | STM32F030F4P6 + EC10E ロータリーエンコーダ + WS2812C |
| 割り込み | 無し（ポーリング） |
| バイト順 | 数値はリトルエンディアン（LSB first） |

## レジスタ

| アドレス | 長さ | R/W | 意味 |
|---|---|---|---|
| `0x10` | 2 | R/W | エンコーダ絶対値。符号付き 16bit、LSB first。書き込むと任意の値に設定できる |
| `0x20` | 1 | R | 押し込みスイッチ。**アクティブ Low**（`0` が押下） |
| `0x30` | 4 | R/W | RGB LED。byte0 が LED インデックス、byte1-3 が R, G, B |
| `0x40` | 1 | W | `1` を書くとエンコーダ値を 0 に戻す |
| `0x50` | 2 | R | エンコーダ相対値。前回読んでからの差分。符号付き 16bit、LSB first |
| `0xFC` | 1 | R | ブートローダのバージョン |
| `0xFD` | 1 | W | `1` を書くとファーム更新用ブートローダに入る |
| `0xFE` | 1 | R | ファームウェアのバージョン |
| `0xFF` | 1 | R/W | I2C アドレス |

**転送の形**: 書き込みは「ポインタバイト + ペイロード」を 1 トランザクションで送る。
読み出しはポインタバイトを書いて **repeated START**（`endTransmission(false)`）を打ち、
続けて必要な長さを要求する。

## 典型的な使い方

1. `0xFE` を読んでファームウェアのバージョンを確認する（通信が成立しているかの確認も兼ねる）。
2. スクロール操作を追うなら `0x50`（相対値）を一定周期で読む。読むたびに 0 に戻るので、
   **読み落とすと回転量が失われる**。
3. 位置として扱うなら `0x10`（絶対値）を読む。起点を決めたい場面で `0x40` に `1` を書いてリセットする。
4. 押し込みは `0x20`。`0` が押下なので、素直に真偽値に変換すると反転する。
5. LED を光らせるなら `0x30` に `{index, R, G, B}` を書く。

## 利用上の注意

- **相対値 `0x50` は読み取りで消費される。** 読んだ瞬間に内部カウンタがクリアされる設計
  なので、2 か所から読むと片方が取りこぼす。読む場所は 1 か所に決める。
- **押し込みスイッチはアクティブ Low。** `0x20` の値をそのまま「押されている」と解釈すると
  意味が逆になる。
- **`0x30` の byte0 は色ではなくインデックス。** 読み出したときも byte0 はインデックスなので、
  色として使うのは byte1-3。
- **アドレス変更は即時反映。** `0xFF` に書いた次のトランザクションはもう新アドレス宛に
  出さないと応答しない。書き換えた値を忘れると、`0x40` を探しても見つからないユニットが
  手元に残る。復旧は scan で全アドレスを舐めて探すことになる。
- **`0xFD` に書くとブートローダに入る。** 通常のアプリケーションから触る理由は無い。
  誤って書くと I2C の応答が変わる。
- **ライブラリの既知の不具合**: `M5Unit-Scroll` の `setEncoderValue()` は `int16_t` を
  4 バイト書き込みに渡しているため、エンコーダ値の後ろにスタックのゴミ 2 バイトがバスに出る。
  キャプチャを見ると `0x10` への書き込みが 4 バイトになっているが、上位 2 バイトに意味は無い。
  読み出しは 2 バイトで正しい。デバイスの仕様ではなくライブラリの都合である。
- **割り込みが無いので、速い回転はポーリング周期で取りこぼす。** UI 用途では周期を
  詰めるか、相対値を使って積算する。

## 出典と確度

- レジスタのアドレスと意味: `M5Unit-Scroll` ライブラリのソース（`collection/vendor/M5Unit-Scroll` に
  commit 固定で取得）。ベンダーの Protocol PDF とも整合する。
- 転送長・アクセス方向・バイト順: 同ライブラリのメソッド本体から起こした**推定**。
- **未確認**: 実機のキャプチャがまだ無い。レジスタが本当に表のとおり応答するか、
  未使用アドレスがどう振る舞うか、400kHz で動くかは確かめられていない。
- **未調査**: 書き込み側の挙動全般（`0x10` への書き込み、LED、アドレス変更）は
  probe が read-only のため触れていない。
