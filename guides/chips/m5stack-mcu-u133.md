# Unit KMeter (U133) — K 型熱電対の温度計ユニット（無印・非絶縁）

> K 型熱電対を MAX31855 で読み、ESP32-C3 のファームウェアが I2C レジスタとして見せるユニット。
> 返ってくるのは MAX31855 の生のデータ語そのままで、℃ への換算はホスト側でやる。
>
> **確度**: ベンダーのレジスタ表 PDF は存在しない。`chips/` に載っているのは製品ページだけで、
> そこには「0x66 から 4 バイト読む」という最小限の説明しかない。`profiles/` のマップは
> **`M5Unit-KMeter` ライブラリ v0.1.1 のソースから起こした推定**（`evidence: inferred / tentative`）で、
> 実測では未確認。書き込み側（アドレス変更・スリープ）は製品ページに記載が無く、根拠は
> ライブラリのコードとその doxygen コメントだけである。

## これは何か

K 型熱電対（サーモカップル）用の温度計。熱電対の起電力は数十 µV/℃ しかなく、冷接点補償も要る
ので、専用 IC の **MAX31855KASA+T** が担当する。その MAX31855 を **ESP32-C3** に載った M5Stack
ファームウェアが SPI で読み、結果を I2C レジスタとして公開している。**ホストから見える I2C の
相手は ESP32-C3 であって、MAX31855 ではない。** MAX31855 は I2C バスには出てこない。

本体は 56 × 24 × 9.6 mm、5V@24mA。熱電対は標準的な平型銅プラグで挿し替えられる。付属プローブは
-50℃〜250℃ だが、MAX31855 自体は -200℃〜1350℃ に対応する（分解能 0.25℃、精度 ±2%）。

できること:

- **熱電対の温度**を読める（`0x00`、0.25℃ 刻み）。
- **冷接点（内部）の温度**を読める（`0x02`、0.0625℃ 刻み）。
- **断線・GND 短絡・VCC 短絡のフォルト判定**ができる。フォルトコードは内部温度の語に埋め込まれている。
- **I2C アドレスを変更できる**（不揮発。電源を入れ直すと新アドレスで動く）。
- **ディープスリープに入れられる**（firmware v1.0 以降）。指定秒数で自動的に起きるほか、
  SCL の Low で起こす設定もある。

できないこと・持っていないもの:

- **割り込み線は無い。** 温度が変わったことは通知されない。
- **LED もボタンも無い。** 表示要素は何も持っていない。
- **ファームウェアのバージョンを読むレジスタが無い。** ところがスリープ機能は firmware v1.0 以降に
  しか無いので、**手元の個体がスリープに対応しているかを I2C から判別できない**。
- **変換完了フラグ（Ready）が無い。** 読めた値が新しいものか、前回と同じものかは分からない。
- **℃ への換算をファームがやってくれない。** 返るのは MAX31855 の生のビット列で、シフトと係数
  の適用はホスト側の仕事。華氏も文字列形式も無い。
- **校正・オフセットの設定が無い。** 読み返せる補正値も無い。
- **書き込みレジスタは読み返せない。** `0x08`（アドレス）も `0x0E`（スリープ秒数）も書くだけ。

### Unit KMeter-ISO（U133-V11）との違い

同じ「K 型熱電対を I2C で読む」という製品だが、**中身もレジスタマップも別物**である。手元のどちらか
一方しか無い読者が多いので、要点だけ並べる。詳細は
[m5stack-mcu-u133-v11.md](m5stack-mcu-u133-v11.md) を参照。

| | **U133 Unit KMeter（この文書）** | U133-V11 Unit KMeter-ISO |
|---|---|---|
| MCU | ESP32-C3 | STM32F030F4P6 |
| 絶縁 | 無し | CA-IS3641HW でセンサ側とホスト側を絶縁 |
| I2C アドレス | `0x66` | `0x66`（**同じ**） |
| 返る値 | MAX31855 の生データ語（0.25℃ / 0.0625℃ 刻み） | ファームが変換済みの **1/100 ℃** の符号付き 32bit |
| バイト順 | **MSB first** | **LSB first** |
| 華氏 | 無し | 有り |
| 文字列形式 | 無し | 有り（8 バイト ASCII ×4） |
| エラー通知 | 温度語に埋め込み（フォルトコード） | 専用レジスタ `0x20` |
| ファーム版数 | 読めない | `0xFE` で読める |
| アドレス変更 | `0x08`、**補数バイトが必要**、不揮発、**電源再投入で有効** | `0xFF`、1 バイト、**即時** |
| スリープ | 有り（`0x0E` / `0x10`） | 無し |
| ライブラリ | `M5Unit-KMeter` | `M5Unit-KMeterISO` |

**どちらも `0x66` なので、アドレス scan だけでは見分けられない。** 見分けるなら、`0x00` から 6 バイト
読んで末尾 2 バイトが `0x31 0x85` なら無印（この文書のユニット）、`0xFE` を読んでバージョンらしき
値が返れば ISO 版。基板上に絶縁 IC があるかどうかでも判る。

## レジスタ

| アドレス | 長さ | R/W | 意味 |
|---|---|---|---|
| `0x00` | 2 | R | 熱電対温度。**MSB first**。bit15..2 が符号付き 14bit の値で、**1 カウント = 0.25℃**。bit0（下位バイトの最下位）が立っていると「原因不明のエラー」 |
| `0x02` | 2 | R | 冷接点（内部）温度。**MSB first**。bit15..4 が符号付き 12bit の値で、**1 カウント = 0.0625℃**。下位 3bit がフォルトコード（`1`=断線、`2`=GND 短絡、`4`=VCC 短絡） |
| `0x04` | 2 | R | 固定の識別値。`0x31`, `0x85` が返る。読み取りが正しく成立したかの検査に使う |
| `0x08` | 2 | W | I2C アドレス変更。1 バイト目が新アドレス（`0x08`〜`0x77`）、2 バイト目がその**ビット反転**。不揮発 |
| `0x0E` | 2 | W | スリープ秒数。**MSB first**。**単位は秒**。ユニットの NVS に保存され復帰時に復元される（firmware v1.0 以降） |
| `0x10` | 1 | W | スリープ実行。`0xEE` = タイマでのみ起きる、`0xEF` = I2C の SCL が Low になっても起きる（firmware v1.0 以降） |

これは MAX31855 のデータ語の並びをファームがそのまま通しているもので、`0x00`〜`0x03` の 4 バイトが
MAX31855 の 32bit 語に相当する。

**転送の形**: 読み出しは、ポインタバイト `0x00` を書いて **repeated START**（`endTransmission(false)`）を
打ち、続けて **6 バイトを一括で要求する**。ライブラリは `0x00` / `0x02` / `0x04` を個別に読むことは
無く、常にこの 6 バイトのバーストである。書き込みは「ポインタバイト + ペイロード」を 1 トランザクション。

## 典型的な使い方

1. **`Wire` を自分で `begin()` しておく。** `M5_KMeter::begin()` はポインタとアドレスを覚えるだけで、
   バスの初期化も疎通確認もしない。
2. `0x00` から **6 バイト**読む。
3. 末尾 2 バイトが `0x31`, `0x85` であることを確認する。違えば読み直す（ライブラリは最大 3 回）。
4. バイト 3 の下位 3bit を見る。`0` 以外なら熱電対の値は使わない（`1`=断線、`2`=GND 短絡、`4`=VCC 短絡）。
5. `0` でも、バイト 1 の bit0 が立っていれば「原因不明のエラー」なので、やはり値は使わない。
6. 冷接点温度 = `0.0625 × (int16(byte2, byte3) >> 4)`。
7. 熱電対温度 = `0.25 × (int16(byte0, byte1) >> 2)`。**符号付き整数として右シフトする**のがポイント。

## 利用上の注意

- **6 バイト一括で読む前提の設計。** 末尾に固定 ID（`0x31 0x85`）が付いてくる形で読み取りの完全性を
  検査している。`0x00` から 2 バイトだけ読む使い方は資料にも実装にも無く、**動くかどうか未確認**。
- **符号は算術右シフトで取り出す。** `int16_t` に入れてから `>> 2` / `>> 4` する。`uint16_t` のまま
  シフトすると負の温度が壊れる。なお C の符号付き右シフトの挙動は本来実装定義だが、このライブラリは
  算術シフトであることに依存している。
- **フォルトが立っている間、熱電対の温度は更新されない。** ライブラリは `err_ok` のときだけ内部の
  `_temperature` を書き換えるので、`getTemperature()` は**前回の値を返し続ける**。エラーコードを
  見ずに温度だけ表示すると、**熱電対が断線したのに最後の温度が固まったまま出続ける**。冷接点温度の
  ほうはエラーでも更新される。自分でレジスタを叩く場合も同じ罠がある。
- **エラー情報が 2 か所に分かれている。** バイト 3 の下位 3bit（フォルトコード）と、バイト 1 の bit0
  （原因不明）。片方だけ見ると見落とす。
- **アドレス変更には補数バイトが要る。** `0x08` に「新アドレス, ~新アドレス」の 2 バイトを書く。
  1 バイトだけ書いても受け付けられない。範囲は `0x08`〜`0x77` で、ライブラリは範囲外を送信前に弾く。
- **アドレス変更は即時ではなく、電源再投入で有効になる。** しかも `changeAddr()` はライブラリ内部の
  `_addr` を更新しないので、**書いた直後は古いアドレスで通信し続け、電源を入れ直すと突然新アドレス
  になる**。ここは KMeter-ISO（即時反映）と逆なので、両方触る人はほぼ確実に間違える。
- **アドレスは不揮発。** 書き換えた値を忘れると `0x66` を探しても見つからないユニットが手元に残る。
  復旧はバス全体を scan して探すことになる。
- **`0x10` に書くとディープスリープに入る。** 書いた瞬間からユニットはバス上から消える。`0xEE` なら
  `0x0E` で設定した秒数が経つまで戻ってこない。`0x0E` を先に書いていない場合に何秒で起きるかは
  **未確認**。`0xEF` を書いておけば SCL を Low にして起こせる。**誤って書くと通信できなくなる。**
- **スリープは firmware v1.0 以降の機能。** ところがバージョンを読むレジスタが無いので、対応の
  有無を I2C から確認できない。古いファームに `0x10` を書いたときの挙動は**未確認**。
- **バス速度はホスト任せ。** `begin()` が `Wire.begin()` を呼ばないので、他のライブラリが設定した
  速度がそのまま使われる。上限は**未確認**。
- **本リポジトリの characterization probe は read-only。** 読み出し可能なレジスタを読むだけで、
  アドレス変更もスリープも触っていない。どちらも「不揮発の設定が変わる」「バスから消える」という
  取り返しの付きにくい副作用があるため、レビュー済みシナリオに委ねられている。

## 出典と確度

- レジスタのアドレスと意味: `M5Unit-KMeter` ライブラリ v0.1.1 のソースから起こした**推定**。
  読み出し側（`0x00`〜`0x05`）は製品ページの Protocol 節の記述（4 バイトと換算式）とも整合する。
- 書き込み側（`0x08` / `0x0E` / `0x10`）: **ライブラリのコードと doxygen コメントだけが根拠**。
  ベンダーの表には載っていない。値の意味（`0xEE` / `0xEF`、補数バイト）も同様。
- フィールドの分解・フォルトコードの意味: ライブラリの `update()` の実装から。MAX31855 の
  データ語の仕様と一致する。
- **未確認**: 実機のキャプチャがまだ無い。6 バイト以外の読み方、スリープの復帰、アドレス変更の
  タイミング、バス速度の上限は確かめられていない。
- **未調査**: 書き込み側の挙動全般は probe が read-only のため触れていない。
