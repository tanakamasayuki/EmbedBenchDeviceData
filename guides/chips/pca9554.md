# PCA9554 — 8 bit I2C IO エキスパンダ

> I2C 経由で汎用の入出力ピンを 8 本増やすデバイス。レジスタ 4 本（入力・出力・極性反転・
> 方向）だけの単純な構成で、入力の変化を知らせる割り込み出力を持つ。
>
> **名前の似た PCA9548A とは別物**である。PCA9548A は I2C バスそのものを 8 系統に切り替える
> マルチプレクサで、こちらは IO ピンを増やす部品。型番だけで選ぶと確実に間違える。
>
> **確度**: NXP の datasheet Rev. 10（2017-11-08）に基づく。`profiles/pca9554.yaml` の
> evidence は `datasheet` / `tentative` で、**実機のキャプチャはまだ無い**。出力の駆動、
> 方向変更、極性反転の書き込みはいずれも probe の対象外（`deferred`）で未実測。

## これは何か

I2C につながる 8 本の汎用 IO。ピンごとに入力・出力を選べて、入力側には読み値を反転する
機能が付いている。マイコンのピンが足りないとき、スイッチ・LED・リレー・センサの
イネーブル線などを I2C 1 本の先に逃がすために使う。

内部にあるのは 8 bit のレジスタが 4 本だけ。

- **Input Port（0x00）**: ピンの実際の電圧レベル。出力に設定したピンでも、実際のレベルが読める。
- **Output Port（0x01）**: 出力に設定したピンから出す値。
- **Polarity Inversion（0x02）**: 1 を立てたビットは Input Port の読み値が反転される。
- **Configuration（0x03）**: 1 = 入力、0 = 出力。

さらに **INT ピン**（オープンドレイン、アクティブ Low）があり、入力に設定したピンの状態が
変わると Low になる。ホストがポーリングしなくても変化に気づける。

### できないこと・持っていないもの

- **オートインクリメントが無い。** コマンドバイト（レジスタポインタ）を 1 回送ったら、
  次にコマンドバイトを送るまで**同じレジスタを読み続ける**。4 本まとめて 4 バイト読む、
  ということができない。PCA9555 や MCP23017 から移植すると必ずここで詰まる。
- **割り込みのマスクもエッジ選択も無い。** 入力に設定した全ピンの、あらゆる変化が INT を
  Low にする。「立ち上がりだけ」「このピンだけ」という設定は無い。
- **変化をラッチしない。** INT は「Input Port を読む」か「入力が元の値に戻る」のどちらかで
  解除される。**ポーリング周期より短いパルスは、戻った時点で INT も消えて痕跡が残らない。**
- **出力はプッシュプル固定。** オープンドレインにする設定は無い。ワイヤード OR を作りたい
  なら外付けが要る。
- **Output Port を読んでもピンの実状態は分からない。** 内部フリップフロップの値が返るだけで、
  外部に引っ張られていても気づけない。実レベルは Input Port（0x00）で読む。
- **極性反転は入力側にしか効かない。** 出力の値は反転されない。
- **リセット手段が無い。** ソフトリセットのコマンドも RESET ピンも存在しない。確実に初期化
  したければ VDD を 0.2V 未満まで落とすしかない。
- **PWM も ADC もデバウンスも無い。** ピンの H / L だけを扱う。

### 電気的な現実

- 電源 2.3〜5.5V。**I/O は VDD より高い電圧を入れてよく、5.5V まで許容される**。
  3.3V 駆動のまま 5V 系の信号を読む、といった使い方ができる。
- 入力に設定したピンは Hi-Z + **内部 100kΩ typ の弱プルアップ**（VDD へ）。外付けプルアップ
  なしでスイッチを直結できるが、100kΩ はノイズには弱い。
- 出力はシンクもソースもできる。VOL 0.5V で 8mA min、VOL 0.7V で 10mA min のシンク。
  ソースは 8mA で VOH がだいたい VDD - 0.5V。
- **電流の上限が 3 段ある**: 1 ピンあたり 25mA、ソース側の合計 85mA、デバイス全体 100mA。
  LED を 8 本直結すると簡単に超える。
- **出力に設定したピンに外から電圧をかけてはいけない。** プッシュプルなので、VDD か VSS への
  低インピーダンス経路ができる（datasheet 6.4 が明示的に警告している）。
- POR 直後は**全ピン入力・弱プルアップ**、Output Port は 0xFF、Polarity は 0x00。

## レジスタ / コマンド

コマンドバイト（第 1 バイト）がレジスタポインタとして働く。

| アドレス | 長さ | R/W | 意味 |
|---|---|---|---|
| `0x00` | 1 | R | **Input Port**。ピンの実際のレベル。方向設定に関係なく実レベルが読める。書いても効果なし。**読み出しで INT が解除される** |
| `0x01` | 1 | R/W | **Output Port**。出力に設定したピンが出す値。入力に設定したピンには影響しない。読み出しは内部 FF の値であってピンの値ではない。POR 既定 `0xFF` |
| `0x02` | 1 | R/W | **Polarity Inversion**。1 のビットは Input Port の読み値を反転する。出力には効かない。POR 既定 `0x00` |
| `0x03` | 1 | R/W | **Configuration**（方向）。**1 = 入力**（Hi-Z + 弱プルアップ）、**0 = 出力**。POR 既定 `0xFF` |

すべてビット n が IO*n* に対応する。

**転送の形**:

- 書き込み: `S` → アドレス + W → コマンドバイト → データ → `P`。1 トランザクションで送る。
- 読み出し: `S` → アドレス + W → コマンドバイト → **repeated START** → アドレス + R →
  データ → NACK → `P`（datasheet Fig 13）。
- **コマンドバイトを送り直さない限り、同じレジスタを読み続ける。** datasheet Fig 14 は、
  コマンドバイト無しで 4 バイト読むと Input Port が 4 回返る様子をそのまま図示している。

## 典型的な使い方

1. `0x03`（Configuration）を読んで `0xFF` が返ることを確認する。存在確認を兼ねる。
2. **出力にするピンは、先に `0x01` へ出したい値を書いてから** `0x03` で出力に切り替える。
   POR 直後の Output Port は `0xFF` なので、順序を逆にすると切り替えた瞬間に H が出る。
3. 入力は `0x00` を読む。アクティブ Low のスイッチなら、`0x02` に該当ビットを立てておくと
   読み値をそのまま真偽値として扱える。
4. INT を使うなら、INT が Low になったら `0x00` を読む。読んだ時点で INT が解除される。
5. 同じレジスタを繰り返し読むなら、コマンドバイトは最初の 1 回でよい。別のレジスタに移る
   ときは必ずコマンドバイトを書き直す。

## 利用上の注意

- **PCA9548A と混同しない。** あちらはバスマルチプレクサ。
- **オートインクリメントが無い。** `0x00` を指定して 4 バイト読んでも `0x00` が 4 回返るだけで、
  `0x01`〜`0x03` は取れない。レジスタごとにコマンドバイトを送り直す。他の IO エキスパンダ
  から移植したコードは、まずここで壊れる。
- **Output Port の読み出しはピンの状態ではない。** 内部フリップフロップの値。ピンが外部に
  引っ張られていても、読み値は書いた値のまま。実レベルを見るなら `0x00`。
- **INT は読み出しでクリアされ、入力が戻っても解除される。** 短いパルスは、ホストが読む前に
  入力が元に戻れば INT も消えて完全に見逃す。エッジをラッチする仕組みは無いので、
  「押した / 離した」を取りこぼしなく拾う用途には向かない。
- **方向を出力→入力に変えると偽の割り込みが出ることがある**（datasheet 6.3 が明記）。
  ピンの状態が Input Port レジスタの内容と一致しないと発生する。
- **極性反転は入力にしか効かない。** `0x02` を書いても出力の論理は変わらない。
- **PCA9554A は別物として扱う。** 型番末尾の A の有無でアドレスが `0x20` 台か `0x38` 台かが
  変わる。機能とレジスタは同一。本カタログが持っているのは無印の PCA9554。
- **PCF8574 とはピン互換だがソフトは互換でない。** PCF8574 はレジスタを持たない
  quasi-bidirectional 方式で、1 バイト書けばそれが出力、1 バイト読めば入力。PCA9554 に
  そのコードを流すと、コマンドバイトがデータとして解釈されて意味不明な動きになる
  （datasheet 1. General description が AN469 を参照している）。
- **アドレス衝突**: 本カタログでは `0x20` が `m5stack-mcu-u160`（Unit HBridge）と
  `m5stack-mcu-u160-v11` に重なる。Unit EXT.IO が使う `0x27` はカタログ内では単独。
  A2/A1/A0 で `0x20`〜`0x27` の 8 通りに逃げられるが、8 個より多く並べるには
  PCA9554A（`0x38`〜`0x3F`）を混ぜるか、mux が要る。
- **電流の上限に注意。** 1 ピン 25mA、ソース合計 85mA、デバイス合計 100mA。LED を 8 本
  直結すると超える。抵抗を入れるか、シンク側で駆動する。
- **出力ピンに外から電圧をかけない。** プッシュプル出力なので、外部電圧と出力段が
  ぶつかると低インピーダンス経路ができる。
- **リセットする手段が無い。** ソフトリセットも RESET ピンも無いので、状態が分からなく
  なったら電源を 0.2V 未満まで落とすしかない。中途半端な電圧まで下がるだけの電源断では
  レジスタが残る。
- **400kHz は datasheet の値。** 本カタログでは未実測。

## 出典と確度

- レジスタの定義、アドレス、電気特性、タイミング: NXP **PCA9554; PCA9554A Product data sheet
  Rev. 10（2017-11-08）**。
- `profiles/pca9554.yaml` は datasheet のレジスタ表から起こしたもので、`confidence: tentative`。
- **未確認**: 実機のキャプチャがまだ無い。レジスタが表のとおり応答するか、POR 既定値が
  実際に `0xFF` / `0xFF` / `0x00` / `0xFF` か、オートインクリメントが無いことが実測で
  確認できるか、400kHz で動くかは確かめられていない。
- **未調査**: probe は read-only なので、出力の駆動、方向変更、極性反転の書き込みは
  一切触れていない（`scenarios/pca9554/p0.yaml` の `deferred`）。INT ピンについても、
  Unit EXT.IO の Grove コネクタから触れるかどうかを含めて未確認。
- **未確認**: M5Stack Unit EXT.IO の基板上で A2/A1/A0 がどう結線されているか。製品としての
  アドレスが `0x27` であることは `chips/pca9554.yaml` の notes と製品情報による。
