# Unit PbHub v1.1 (U041-B) — Port.B 6 分岐 IO 拡張ユニット（STM32 版）

> 1 本の Grove ポートを 6 本の Port.B（GPIO）に分岐させるユニット。分岐先の 2 本の IO を
> デジタル入出力・PWM・ADC・サーボ・RGB LED として I2C から叩く。**バスの分岐器ではなく、
> ファームウェアが載った IO エキスパンダである。**
>
> **確度**: M5Stack が `M5Unit-PbHub` リポジトリに Protocol PDF（FW V1 と V2）を置いており、
> レジスタ表・値域・チャンネル配置はそれに基づく。転送長・バイト順・アクセス方向は
> `M5Unit-PbHub` v1.0.0 のソースから起こした**推定**で、実測では未確認。
> **ライブラリは初代（U041、ATmega328）と本機（STM32F030）を区別しないので、
> ライブラリのソースだけからは本機固有の機能が読み取れない。**

## これは何か

STM32F030 に M5Stack のファームウェアを載せ、6 系統の Port.B（黒い Grove、GPIO 2 本 +
電源）に分岐させるユニット。初代 Unit PbHub（U041、ATmega328）の後継で、レジスタ表は
同じ形をしているが**機能が増えている**。

**名前に "Hub" と付くが、I2C のハブ（PaHUB / TCA9548A のようなバス切り替え器）ではない。**
分岐先はあくまで GPIO であり、ホストは PbHub の firmware に「このチャンネルのこのピンを
HIGH にしろ」と頼む形になる。したがって:

- **タイミングに依存するプロトコルは通せない。** HX711 を積んだ Weight Unit のような
  「アナログ読み + 厳密なタイミング」を要求するユニットは PbHub 越しには使えない。
- **PaHUB のような多段接続もできない。**

できること（チャンネルあたり）:

- IO0 / IO1 のデジタル出力・デジタル入力。**入出力レベルは 3.3V**（初代は 5V 系）
- IO0 / IO1 の PWM 出力（デューティ 0〜255）
- IO0 のアナログ入力。**本機は 12bit（0〜4095）**
- IO0 / IO1 のサーボ制御。角度 0〜180 度、またはパルス幅 500〜2500 マイクロ秒
- IO0 に繋いだ WS2812 系 LED ストリップの制御（最大 74 個、1 個指定・範囲塗りつぶし・輝度）

初代 U041 に無く本機にあるもの（Protocol PDF が「STM32 版の新機能」と注記している）:

- サーボ角度 / サーボパルス（`+0x0C`〜`+0x0F`）
- ファームウェアバージョンの読み出し（`0xFE`）
- **レジスタによる I2C アドレス変更（`0xFF`、1〜127）**。初代ははんだジャンパだった
- LED 制御タイミングの切り替え（`0xFA`、**FW V2 以降**）

できないこと・持っていないもの:

- **割り込み線は無い。** 入力の変化を知るにはポーリングするしかない。
- **IO1 のアナログ入力は無い。** ADC は各チャンネルの IO0 だけ。
- **ADC の電圧換算に必要な情報が公開されていない。** 返るのは 0〜4095 のカウントで、
  **単位は無い**。基準電圧も記載が無い。
- **LED ストリップは 1 チャンネルあたり 74 個が上限**（Protocol PDF の注記）。
- **ライブラリ（`M5UnitPbHub` v1.0.0）は `0xFA` / `0xFE` / `0xFF` を実装していない。**
  アドレス変更もファームウェアバージョン読み出しも、ライブラリ経由ではできない。
- **手元の個体の firmware が V1 か V2 かは `0xFE` を読むまで分からない。**
  V2 は SK6812 対応と I2C IAP アップグレードの追加版である。

## レジスタ

レジスタバイトは **上位ニブルがチャンネル、下位ニブルが機能コード**である。
`reg = ((ch + 4) << 4) | function` で、ただし**チャンネル 5 だけ 6 に読み替える**。
結果としてチャンネルのベースアドレスは次のようになる。

| チャンネル | ベース |
|---|---|
| 0 | `0x40` |
| 1 | `0x50` |
| 2 | `0x60` |
| 3 | `0x70` |
| 4 | `0x80` |
| 5 | **`0xA0`**（`0x90` は使わない） |

機能コード（ベースからのオフセット）:

| オフセット | 長さ | R/W | 意味 |
|---|---|---|---|
| `+0x00` | 1 | W（PDF は R/W） | IO0 デジタル出力。0=LOW, 1=HIGH |
| `+0x01` | 1 | W（PDF は R/W） | IO1 デジタル出力 |
| `+0x02` | 1 | W（PDF は R/W） | IO0 PWM デューティ 0〜255 |
| `+0x03` | 1 | W（PDF は R/W） | IO1 PWM デューティ 0〜255 |
| `+0x04` | 1 | R | IO0 デジタル入力 |
| `+0x05` | 1 | R | IO1 デジタル入力 |
| `+0x06` | 2 | R | IO0 アナログ入力。**16bit LSB first**、有効値域 0〜4095。単位なし |
| `+0x07` | — | — | 予約（PDF が reserve と明記。ライブラリも未使用） |
| `+0x08` | 2 | W（PDF は R/W） | LED の個数。16bit LSB first、既定 74、上限 74 |
| `+0x09` | 5 | W（PDF は R/W） | LED 1 個の色。16bit インデックス（LSB first）+ R, G, B |
| `+0x0A` | 7 | W（PDF は R/W） | LED 範囲塗りつぶし。16bit 開始（LSB first）+ 16bit 個数（LSB first）+ R, G, B |
| `+0x0B` | 1 | W（PDF は R/W） | LED 輝度 |
| `+0x0C` | 1 | W（PDF は R/W） | IO0 サーボ角度。**0〜180 度** |
| `+0x0D` | 1 | W（PDF は R/W） | IO1 サーボ角度 |
| `+0x0E` | 2 | W（PDF は R/W） | IO0 サーボパルス幅。**500〜2500 マイクロ秒**、16bit LSB first |
| `+0x0F` | 2 | W（PDF は R/W） | IO1 サーボパルス幅 |

チャンネル横断のレジスタ（ライブラリは未実装、PDF のみ）:

| アドレス | 長さ | R/W | 意味 |
|---|---|---|---|
| `0xFA` | 1 | R/W | LED 制御タイミング。**FW V2 以降**。`0`（既定）= WS2812 / WS2815 / WS2816 / SK6812、`1` = SK6822 / APA106 / PL9823 |
| `0xFE` | 1 | R | ファームウェアバージョン |
| `0xFF` | 1 | R/W | I2C アドレス。1〜127 |

**転送の形**: 書き込みは「レジスタバイト + ペイロード」を 1 トランザクション。
読み出しはレジスタバイトを書いて STOP を打ち、改めて読み出しトランザクションを起こす。

## 典型的な使い方

1. `0xFE` を読んでファームウェアバージョンを確認する。通信確認も兼ねる
   （初代 U041 にはこのレジスタが無いので、世代の判別にも使える）。
2. デジタル入力を読むなら、チャンネル c の IO0 は `ベース + 0x04` を 1 バイト読む。
3. デジタル出力なら `ベース + 0x00` に 0 か 1 を書く。
4. アナログ入力は `ベース + 0x06` から 2 バイト読み、`data[1] << 8 | data[0]` で組む。
   得られるのは 0〜4095 のカウント。
5. サーボは `ベース + 0x0C` に角度（0〜180）、または `ベース + 0x0E` に 2 バイトで
   パルス幅（500〜2500us、LSB first）。
6. LED ストリップを使うなら、まず `ベース + 0x08` に本数を書き、
   `ベース + 0x09` で 1 個ずつ、または `ベース + 0x0A` で範囲を塗る。
   WS2812 系以外の LED を使うなら先に `0xFA` を設定する（FW V2 以降）。

## 利用上の注意

**このユニットは実際の出力を駆動する。** デジタル出力・PWM・サーボ・LED への書き込みは、
繋がっている先を実際に動かす。**サーボは物理的に動く。** 本リポジトリの probe が read-only
（`scenarios/m5stack-mcu-u041-b/p0.yaml` の `safety: read-only`）なのはこのためで、
書き込み系の操作はすべて `deferred` に置かれている。何が繋がっているか分からない
状態で書き込みを試さないこと。

- **チャンネル 5 のベースは `0xA0`。`0x90` ではない。** `0x40 + ch * 0x10` と素直に
  計算すると 5 番だけ外れる。ライブラリは `if (ch == 5) ch++;` という一行でこれを吸収している。
  ベンダーの PDF も `0x90` 行を持たない。
- **1 つのペイロードの中でエンディアンが混在する。** `+0x09` / `+0x0A` では、
  インデックス・開始位置・個数といった数値部分がリトルエンディアンなのに、
  色は **R → G → B**（`0xRRGGBB` の上位バイトから）で並ぶ。
- **LED インデックスは実質 8bit。** ライブラリの `setLEDColor()` / `fillLEDColor()` は
  インデックス・開始位置・個数を `uint8_t` で受けてから 2 バイトに広げるので、
  上位バイトは常に 0 になる。ワイヤフォーマット上は 16bit 分の場所があるのに、
  ライブラリ経由では 256 個目以降に届かない。実用上は LED 上限が 74 個なので影響は小さい。
- **アドレス変更はライブラリからはできないが、レジスタは存在する。** `0xFF` に書けば
  変わる。**書いた直後から新アドレスで応答する**はずなので（`0xFF` は他の M5Stack
  ユニットと同じ扱い。ただし本機については**未確認**）、書き換えた値を忘れると
  `0x61` を探しても見つからない個体が残る。有効値は 1〜127。
- **読み出し失敗が LOW と区別できない。** ライブラリの `digitalRead()` は内部の
  `readByte()` が失敗時に `0` を返すのをそのまま通す。`analogRead()` も失敗時 `0`。
  通信エラーが「入力が LOW」「アナログ値 0」に化ける。
- **ADC の値を電圧に読み替えない。** 0〜4095 のカウントに対する換算係数が公開されていない。
- **IO レベルは 3.3V。** 初代 U041（ATmega328）は 5V 系だったので、5V 前提で作った
  周辺回路をそのまま繋ぐと期待どおりに動かないことがある。Protocol PDF が
  「STM32 版の GPIO 入出力電圧は 3.3V」と明記している。
- **タイミング依存のユニットは繋がらない。** Port.B の黒いコネクタが付いていても、
  HX711 のように厳密なタイミングを要求するものは動かない。
- **`0xFA` は FW V2 以降にしか無い。** WS2812 以外（SK6822 / APA106 / PL9823）を使う
  つもりなら、先に `0xFE` で版数を確かめること。
- **ライブラリのソースだけでは本機と初代の区別がつかない。** `M5Unit-PbHub` v1.0.0 は
  世代を一切区別せず、同じメソッドを両方に提供する。**このガイドの「STM32 版だけの機能」
  という区別は Protocol PDF の脚注が唯一の根拠であり、実機では確かめられていない。**

## 出典と確度

- チャンネルのベースアドレス（`0x90` を飛ばすこと）、機能コードの割り当て、
  各レジスタの長さと R/W、ADC 幅 12bit、サーボの値域（0〜180 度 / 500〜2500us）、
  LED 上限 74 個、`0xFA` / `0xFE` / `0xFF` の存在と意味、IO レベル 3.3V:
  **ベンダーの Protocol PDF に基づく**。
- 転送長・バイト順・レジスタバイトの計算式: `M5Unit-PbHub` v1.0.0 の
  `src/M5UnitPbHub.cpp` から起こした**推定**。このライブラリにはレジスタの `#define` が
  一切なく、すべてメソッド本体の中でインラインに計算されている。
  `profiles/` に記録されているマップは初代 U041 と同一である。
- **未確認**: 実機のキャプチャがまだ無い。本機が Protocol PDF どおりのマップで応答するか、
  `0xFF` への書き込みが即時反映されるか、読み戻し（PDF 上は多くが R/W）が実際にできるか、
  `0x07` に何が起きるか、400kHz で安定するかは確かめられていない。
- **未確認**: 手元の個体の firmware が V1 か V2 か。`0xFA` の有無がこれで変わる。
- **未調査**: 書き込み側の挙動全般（デジタル出力・PWM・サーボ・LED）は
  `scenarios/m5stack-mcu-u041-b/p0.yaml` が `safety: read-only` のため触れていない。
- ADC の電圧換算係数は**一次資料に記載が無い**。
