# TCA9548A — 8 チャンネル I2C バススイッチ

> 1 本の I2C バスを 8 本に分岐し、どれを繋ぐかをソフトウェアで選べるようにするスイッチ。
> **レジスタは無く**、アドレスの直後に置く 1 バイトがそのまま「どのチャンネルを開くか」に
> なる（1 ビット = 1 チャンネル）。**同じアドレスのセンサを 2 個以上ぶら下げる**ための部品。
>
> **確度**: Texas Instruments の datasheet SCPS207H（Rev H、2024-09）に基づく。レジスタ表が
> 存在しないデバイスなので、記述の中心はトランザクションの形と電源投入時の状態。
> **実測は未着手**で、`profiles/tca9548a.yaml` の evidence は `datasheet` / `tentative`、
> `observations/tca9548a/` はまだ無い。

## これは何か

上流の SCL/SDA を、下流の 8 組（SC0/SD0 〜 SC7/SD7）へ切り替えて繋ぐ双方向アナログスイッチ。
中に信号処理は無く、**選ばれたチャンネルは上流と電気的に導通するだけ**である（§7.1, p12）。

**これが解く問題**: I2C アドレスが固定で変更できないセンサを、同じバスに 2 個以上つけたい
とき。たとえば TCS34725 は `0x29` 固定で、アドレス選択ピンを持たない。2 個並べれば
必ず衝突する。TCA9548A の別々のチャンネルに 1 個ずつ繋げば、**ホストは「今どちらの
チャンネルを開いているか」で相手を選ぶ**ことができる。アドレスは両方とも `0x29` のままでよい。

**できること**:

- 8 チャンネルのうち任意の組み合わせを開く。**1 個だけでなく、複数を同時に開ける**
  （§7.5.4, p17）。全部閉じることもできる。
- 制御バイトを読み返せる。今どのチャンネルが開いているかが分かる。
- **電圧変換**。チャンネルごとに別のプルアップ電圧を使えるので、3.3V のホストから 5V の
  デバイス、あるいはその逆を扱える（§7.1, p12）。スイッチがパスゲートなので、レベルは
  プルアップ抵抗の先の電圧で決まる。
- RESET ピンで、下流のバスが Low に張り付いて固まったときに復帰できる（§7.4.1, p14）。

**できないこと・持っていないもの**:

- **バッファではない。** 信号を再生成しないので、**上流と下流の容量は合算される。**
  チャンネルを開けば開くほどバスの容量が増え、立ち上がりが鈍る。datasheet の I2C バス
  容量規定は 400pF（Table 5.6, p7-8）で、これは開いているチャンネルの合計に効く。
- **アドレス変換はしない。** 下流のデバイスは元のアドレスのまま見える。同じアドレスの
  デバイスを**同時に 2 チャンネル開けば、やはり衝突する。**
- **クロックストレッチや調停を仲介しない。** 下流で起きたことはそのまま上流に伝わる。
- レジスタポインタが無い。「レジスタ 0 番を読む」といった操作は存在しない。
- 割り込み出力が無い。TCA9548A に兄弟品 (TCA9545A 等) のような割り込み集約機能は無い。
- 電源が切れると設定は消える。**不揮発ではない。**

**電気的な現実**:

- VCC 1.65–5.5V（-40〜85℃、Table 5.3, p4）。85℃ を超える範囲では 1.65–3.6V。
- スイッチのオン抵抗 RON は VCC で変わる。5V で typ 10Ω / max 20Ω、1.8V では typ 25Ω /
  max 70Ω（Table 5.5, p7）。**この抵抗はプルアップと直列に入る**ので、低電圧かつ強い
  プルアップだと Low レベルが持ち上がる。
- 標準モード 100kHz と Fast モード 400kHz に対応（§7.3, p13 / Table 5.6, p7）。それ以上の
  規定は無い。
- アドレスは A2/A1/A0 の 3 ピンで `0x70`〜`0x77` の 8 通り（Table 7-1, p15）。つまり
  **マルチプレクサ自身を 8 個までカスケードできる。**

## レジスタ・コマンド

**レジスタは 1 つも無い。** datasheet 自身がそう説明している — 「レジスタを持たない
デバイスもある。単純なデバイスはレジスタが 1 つだけで、レジスタ番号を送らずアドレスの
直後にレジスタのデータを送る。TCA9548A はその例である」（§7.5.3, p16）。

### 制御バイト（§7.5.4 / Table 7-2, p17-18）

| ビット | 意味 |
|---|---|
| b7 | 1 でチャンネル 7 を接続 |
| b6 | 1 でチャンネル 6 を接続 |
| … | … |
| b0 | 1 でチャンネル 0 を接続 |

`0x00` = 全切断（電源投入時 / RESET 後の値）。`0x01` = チャンネル 0 のみ。`0x03` =
チャンネル 0 と 1 を**同時に**接続。`0xFF` = 全接続。

### 書き込み

```
S | 0x70+W | 制御バイト | P
```

**チャンネルは STOP コンディションが出た後に実際に有効になる**（§7.5.4, p17）。datasheet に
よれば、これは接続の瞬間に全 SCn/SDn が High であることを保証し、偽のスタート条件などを
作らないためである。したがって **STOP を出さずに repeated START で下流を叩くことはできない。**

### 読み出し

```
S | 0x70+R | 制御バイト | NACK | P
```

レジスタ番号を書く手順は無い。**アドレスを read で叩けばいきなり制御バイトが返る**
（Figure 7-5, p17）。

## 典型的な使い方

1. 電源投入直後は `0x00`、つまり**全チャンネルが切れている**（Table 7-2, p18）。この状態で
   下流をスキャンしても何も見つからない。
2. `0x70` に 1 バイト書いて、使いたいチャンネルのビットを立てる。STOP を出す。
3. **下流のデバイスを、そのデバイス本来のアドレスで普通に読み書きする。** マルチプレクサは
   透過なので、ホスト側のドライバは何も変える必要がない。
4. 別のチャンネルに切り替えるときは、また `0x70` に書く。前のチャンネルを閉じるかどうかは
   任意だが、同じアドレスのデバイスが両方にいるなら**必ず閉じる。**
5. 終わったら `0x00` を書いて全部閉じておくと、下流の事故が上流に伝わらない。
6. 下流のバスが固まったら RESET ピンを Low にする。全チャンネルが切れて状態機械が
   初期化される（§7.4.1, p14）。

Unit PaHub (U040) は `0x70` 固定（A2/A1/A0 が GND）で、Grove コネクタ 6 本を持つ。
チャンネル 6 と 7 は基板上に出ていない可能性があるが、**これは datasheet ではなく製品側の
話であり、本ガイドでは未確認。**

## 利用上の注意

- **チャンネルが閉じている間、その先のデバイスはバスから見えない。** これが最も多い
  つまずき。I2C スキャンをしても `0x70` しか出てこないのは正常である。「センサが死んだ」と
  判断する前に、チャンネルを開いたか確認する。
- **電源投入直後は全部閉じている。** 明示的に開けるまで、下流には誰も居ないのと同じ。
- **同じアドレスのデバイスを複数チャンネルで同時に開くと衝突する。** 複数チャンネルを
  同時に開けるのは便利な機能だが、それはアドレスが衝突しない場合に限る。「全部開いて
  スキャン」は、まさに TCA9548A を使う理由になっている状況で壊れる。
- **マルチプレクサ自身のアドレスと下流のアドレスが衝突しうる。** `0x70`〜`0x77` は
  この catalog では PCA9548A（同じ範囲）、QMP6988（`0x70`）、PAJ7620U2（`0x73`）、
  **BME688 と BMP280（`0x76`/`0x77`）**が使う。BME680/BMP280 系は極めてよく使われるので、
  マルチプレクサを `0x76` や `0x77` に置くと、そのチャンネルを開いた瞬間に上流から見て
  同じアドレスが 2 個存在することになる。**マルチプレクサのアドレスは下流に居ない値に
  すること。** 既定の `0x70` はこの点では比較的安全だが、QMP6988 とはぶつかる。
- **チャンネルの切り替えには STOP が要る。** 制御バイトを書いた後、STOP を出す前に
  repeated START で下流にアクセスしても切り替わっていない（§7.5.4, p17）。
  多くの Arduino ライブラリは `endTransmission()` を呼ぶので自然に STOP が出るが、
  低レベルで組む場合は要注意。
- **バス容量は合算される。** 開いているチャンネルの配線容量が上流に足し込まれる。
  Grove ケーブルを何本も繋いだ状態で 400kHz を使うと、波形が鈍って通信が不安定になる。
  規定上限は 400pF（Table 5.6, p7-8）。**必要なチャンネルだけを開けるのは、衝突回避だけで
  なく波形のためでもある。**
- **オン抵抗があることを忘れない。** 低い VCC ほど大きく、1.8V では最悪 70Ω（Table 5.5, p7）。
  プルアップを強くしすぎると、下流デバイスの Low レベルが上流で規定値まで下がらない。
- **RESET ピンはプルアップが必須。** datasheet が明記している（§7.4.1, p14）。開放のままに
  してはいけない。
- **設定は揮発性。** 電源が瞬断すれば `0x00` に戻る。ホスト側は「今どのチャンネルを
  開けたつもりか」を状態として持たず、アクセスのたびに書き直すほうが安全。
- **書き込みバイト数に制限は無いが、意味があるのは最後の 1 バイト。** 誤って 2 バイト送ると
  最後の値が採用される（§7.5.4, p17）。「レジスタ番号 + 値」のつもりで 2 バイト書くと、
  **値のほうがチャンネル選択として解釈される。**

### PCA9548A との違い

この catalog には NXP の PCA9548A（`chips/pca9548a.yaml`、datasheet Rev 5.1 / 2015-10）も
入っている。**ホストから見た振る舞いは同じ**である。

| | TCA9548A (TI) | PCA9548A (NXP) |
|---|---|---|
| アドレス | `0x70`-`0x77`（A2/A1/A0） | `0x70`-`0x77`（A2/A1/A0） |
| 制御バイト | 1 ビット / チャンネル、複数同時可 | 同じ |
| リセット値 | `0x00` | `0x00` |
| RESET ピン | アクティブ Low | アクティブ Low |
| I2C 速度 | 0-400kHz | 0-400kHz |
| **電源電圧** | **1.65–5.5V** | **2.3–5.5V** |

つまり**レジスタ・トランザクション・アドレスのどれも違わない。** 同じドライバがそのまま
動く。実務上の差は電源電圧の下限（1.8V 系で使えるのは TCA9548A のほう）と、スイッチ抵抗や
タイミングの細部だけである。**どちらが載っているかを I2C から判別する方法は無い**
（どちらも ID レジスタを持たない）。

## 出典と確度

- 参照した文書: **TCA9548A datasheet SCPS207H（Rev H、2012-05 初版 / 2024-09 改訂）**。
  TI の公式配布 URL（`ti.com/lit/ds/symlink/tca9548a.pdf`）。一次資料としての確度は高い。
- 比較に使った第二ソース: **PCA9548A datasheet Rev 5.1（2015-10）**、NXP 公式配布。
- アドレス、制御バイトの意味、複数チャンネル同時接続、STOP 後に有効化されること、
  リセット値 `0x00`、RESET / POR の振る舞い、100kHz / 400kHz 対応、電源電圧、オン抵抗:
  **すべて datasheet に明記がある。**
- **datasheet に一箇所、抽出テキストが崩れている場所がある。** §7.5.2 の Figure 7-3
  （アドレスバイトの図、p15）はテキスト抽出時にビットの並びが `1 1 1 0 A1 A2 A0` と
  入れ替わって見える。正しい対応は同じページの Table 7-1（A2/A1/A0 → `0x70`-`0x77`）の
  ほうで、本ガイドはそちらを採った。
- **未確認（実測なし）**: `0x70` が実際に ACK するか、書いた制御バイトがそのまま読み返せるか、
  400kHz で動くか、複数チャンネルを同時に開いたときの実際の波形。
  `observations/tca9548a/` はまだ無い。
- **未調査**: 下流にデバイスをぶら下げた状態での振る舞い（`scenarios/tca9548a/p0.yaml` でも
  `downstream-addressing` と `channel-sweep` は deferred）、RESET ピンの実機挙動、
  Unit PaHub が 8 チャンネルのうち何本を外に出しているか。
- **製品側の未確認事項**: Unit PaHub のチャンネル番号と Grove コネクタの対応は
  M5Stack のドキュメント側の情報であり、本ガイドでは確かめていない。
