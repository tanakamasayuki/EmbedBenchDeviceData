# SSD1315 — 128x64 モノクロ OLED ドライバ / コントローラ

> OLED パネルを直接駆動する表示コントローラ。I2C にはレジスタが無く、スレーブアドレスの
> 後に置く**コントロールバイト**でコマンド列（`0x00`）と表示データ列（`0x40`）を切り替える。
> **I2C 経由では書き込み専用**で、今表示している絵を読み返す手段は無い。
>
> **確度**: Solomon Systech の SSD1315 datasheet Rev 1.1 (2017-04) に基づく。ただし
> Solomon Systech は自社サイトで PDF を配布しておらず、参照したのは再配布ミラー
> （`cursedhardware.github.io`）。**実測は未着手**で、`profiles/ssd1315.yaml` の evidence は
> `datasheet` / `tentative`、`observations/ssd1315/` はまだ存在しない。

## これは何か

128 セグメント × 64 コモンの単色 OLED / PLED パネルを、ホストから見て 1 個の I2C デバイス
として扱えるようにする駆動 IC + コントローラ。128×64 **ビット**の表示 RAM（GDDRAM）を内蔵し、
そこに書いた内容をパネルへ出し続ける。ホストは絵を送り込むだけでよく、リフレッシュや
走査は IC が勝手にやる。

ホストインタフェースはピンで選ぶ方式で、8080/6800 パラレル、4 線 SPI、3 線 SPI、I2C の
4 通りある（§6.1, p11-17）。M5Stack Unit Mini OLED (U166) は I2C 構成で、`0x3c` に居る。

**できること**:

- 128×64 の白黒ビットマップ表示。1 画素 = 1 ビット。
- コントラスト 256 段（コマンド `0x81`）、全画面の白黒反転（`0xA6`/`0xA7`）、全点灯（`0xA5`）。
- ハードウェアによる水平・垂直スクロール（Scrolling Command Table, p41-44）。
- チャージポンプ内蔵。パネル駆動用の高電圧を IC が自分で作れる（`0x8D`）。

**できないこと・持っていないもの**:

- **I2C では読めない。** datasheet は「シリアルモードではデータ読み出しを提供しない」
  （§1.1, p46）「シリアルモードではステータス読み出しを提供しない」（§1.2.22, p56）と
  明記している。GDDRAM の読み返しもステータスレジスタ読みも、8080/6800 パラレルモード
  専用の機能である。**したがってフレームバッファ 1024 バイトをホスト側に持つのが前提**に
  なる。「画面の一部だけ読んで、変更して、書き戻す」はできない。
- 階調が無い。GDDRAM は 128×64 **ビット**なので、画素は点くか点かないかの 2 値。コントラストは
  画面全体に効く 1 個の設定であって、画素ごとの明るさではない。
- ID レジスタが無い。**チップに「お前は誰だ」と聞く方法が無い。**
- 文字フォントも図形描画も持たない。ビットマップはホストが作る。
- 割り込み線が無い（そもそも通知することが無い）。
- パネルの温度・電流・寿命に関する情報を返さない。

**電気的な現実**:

- 電源が 3 系統ある。VDD 1.65–3.5V（ロジック）、VBAT 3.0–4.5V（チャージポンプ用）、
  VCC 7.5–16.5V（パネル駆動用）（§2 Features, p6）。VCC は内部チャージポンプで作るか
  外部から与えるかを選ぶ。Unit のようなモジュールでは基板上で完結している。
- I2C の SDA は `SDAIN`（D1）と `SDAOUT`（D2）に分かれていて、外部で結んで 1 本の SDA に
  する。**`SDAOUT` を繋がない実装では ACK が返らない**（§6.1.5 b, p15）。さらに ITO 配線の
  抵抗とプルアップが分圧を作るため、ACK が有効な Low レベルに届かないことがある、とも
  書かれている。つまり「書き込みは効いているのに NACK が返る」構成が正規にあり得る。
- SCL の最小サイクル時間は 2.5us（Table 9-6, p33）。**上限 400kHz** であって、それ以上の
  根拠は datasheet に無い。

## レジスタ・コマンド

### 転送の形

レジスタポインタは存在しない。1 トランザクションは

```
S | スレーブアドレス+W | [コントロールバイト | データバイト ...] | P
```

コントロールバイトのビット割り当ては `Co(b7) D/C#(b6) 0 0 0 0 0 0`（§6.1.5.2, p16）。

| Co | D/C# | 値 | 意味 |
|---|---|---|---|
| 0 | 0 | `0x00` | **以降のバイトはすべてコマンド。**コントロールバイトはもう出さない |
| 0 | 1 | `0x40` | **以降のバイトはすべて GDDRAM データ。**列ポインタが 1 バイトごとに +1 |
| 1 | 0 | `0x80` | 次の 1 バイトだけコマンド。その次はまたコントロールバイト |
| 1 | 1 | `0xC0` | 次の 1 バイトだけデータ |

つまり `0x40` を 1 個送ってから 1024 バイトを流し込めば全画面が書ける。ライブラリによって
`0x00`/`0x40`（Co=0）を使うものと `0x80`/`0xC0`（Co=1）を使うものがあり、どちらも正しい。

### 主なコマンド

Appendix IV「Command Table and Command Descriptions」（p37-59）より。**この付録だけ本体と
別の版・別のページ番号を持つ**（付録の表紙相当に Rev 1.0 / Dec 2016 / P 5/34 とある）。
以下のページ番号は抽出 PDF の通しページ。

| Hex | 追加バイト | 意味 |
|---|---|---|
| `00`-`0F` | — | ページアドレッシング時の列アドレス**下位**ニブル |
| `10`-`17` | — | ページアドレッシング時の列アドレス**上位**ニブル |
| `20` | A | メモリアドレッシングモード。A=`00` 水平 / `01` 垂直 / `10` **ページ（リセット既定）** |
| `21` | A, B | 列の開始・終了アドレス（0-127、既定 0/127）。水平・垂直モード専用 |
| `22` | A, B | ページの開始・終了アドレス（0-7、既定 0/7）。水平・垂直モード専用 |
| `40`-`7F` | — | 表示開始行（0-63） |
| `81` | A | コントラスト。有効範囲 `01`-`FF`、リセット値 `7F` |
| `A0` / `A1` | — | セグメントリマップ（左右反転）。`A0` がリセット既定 |
| `A4` / `A5` | — | RAM の内容を表示 / RAM を無視して全点灯 |
| `A6` / `A7` | — | 正転 / 反転表示 |
| `A8` | A | マルチプレクス比 = A+1（16-64、リセット既定 63 = 64MUX） |
| `AD` | A | IREF を内部にするか外部にするか、内部時の ISEG |
| `AE` / `AF` | — | 表示 OFF / ON |
| `B0`-`B7` | — | ページアドレッシング時のページ指定（0-7） |
| `D5` | A | 表示クロック分周比と発振周波数 |
| `8D` | A | チャージポンプ設定。`14`/`94`/`95` で有効、`10` で無効（p40, §1.2.23 p56） |
| `E3` | — | NOP |

**コマンド表に無いビットパターンを送ってはいけない。** datasheet は「予期しない結果が
起こり得る」と明記している（Table 1-2 の注記, p46）。

### アドレッシングモード（§1.2.3, p47-48）

- **ページアドレッシング（リセット既定）**: 8 ページ × 128 列。書くたびに**列ポインタだけ**が
  +1 される。次のページに行くにはページと列を指定し直す必要がある。書き始める前に
  3 つ送るのが決まり: ページ（`B0`+n）→ 列下位（`00`+lo）→ 列上位（`10`+hi）。
- **水平アドレッシング**: 列末に達すると列が開始値に戻り、ページが +1 される。全画面を
  1 回の連続書き込みで埋められる。
- **垂直アドレッシング**: ページが先に進み、ページ末で列が +1 される。

1 データバイトはその列の 8 行分をまとめて塗る。**D0 がいちばん上の行、D7 がいちばん下**
（Figure 6-14, p21）。

## 典型的な使い方

1. RES# を 3us 以上 Low にしてから High に戻す（§6.9.1, p23）。リセット直後の状態は
   §6.5（p19）に列挙されていて、表示 OFF、コントラスト `7F`、開始行 0、列カウンタ 0、
   正転表示、セグメント / コモンともリマップ無し。
2. `0x00` に続けて初期化コマンド列を送る。パネル固有の値（`A8` のマルチプレクス比、
   `D5` のクロック、`DA` の COM 配線、`DB` の VCOMH など）は**パネルのメーカーが決めるもので
   datasheet には無い**。M5Stack のライブラリが持っている初期化列に従うのが安全。
3. 内部チャージポンプ構成なら `8D` `14` を送ってから `AF`（表示 ON）を送る（§6.9.2, p24 /
   §1.2.23, p56）。順序が逆だと点かない。
4. `AF` の後、SEG/COM が実際に出るまで **100ms**（tAF, §6.9.1 p23）。
5. 全画面更新: `20` `00`（水平モード）→ `21` `00` `7F` → `22` `00` `07` でポインタを左上に
   置き、コントロールバイト `0x40` を 1 個送ってから 1024 バイトを連続で流す。
6. 部分更新: `20` `02`（ページモード）にして `B0`+page / `00`+lo / `10`+hi でポインタを置き、
   必要な列数だけ書く。**元の絵は読めないので、ホスト側のバッファから合成する。**
7. 消すときは `AE`（表示 OFF）→ VCC を切る（§6.9.1, p23）。

## 利用上の注意

- **I2C では一切読み出せない。** これがこのチップを使う上で最大の制約である。`0x3c` を
  read で叩いても意味のあるものは返らない。デバイス検出は「write が ACK されるか」で
  やるしかなく、しかも後述のとおり ACK が返らない構成もあり得る。
- **`0x3c` は sh1107・ssd1309 と同じアドレスで、3 つとも ID レジスタを持たない。**
  バスに聞いて区別することはできない。実務上の見分け方:

  | | 解像度 | ページ数 | チャージポンプ | この catalog での製品 |
  |---|---|---|---|---|
  | SSD1315 | 128 × 64 | 8（`B0`-`B7`） | **内蔵**（`8D`） | Unit Mini OLED (U166) |
  | SSD1309 | 128 × 64 | 8（`B0`-`B7`） | **無し**。VCC 7.0–16.0V を外部から | Unit Glass2 |
  | SH1107 | **128 × 128** | **16**（`B0`-`BF`） | 内蔵 DC-DC（`AD` + `8A`/`8B`） | Unit OLED |

  つまり **縦が 64 か 128 か**でまず SH1107 が分かれ、残り 2 つは `8D` コマンドの有無、
  すなわち基板に高電圧を作る外部回路があるかどうかで分かれる。初期化列を取り違えると、
  I2C は正常に見えるのに画面が真っ暗、という壊れ方をする。
  なお `0x3d` 側には Unit Glass のコントローラ（`m5stack-mcu-u158`）も居る。
- **コントロールバイトを忘れるとデータがコマンドとして解釈される。** ビットマップの
  バイト列がそのままコマンド列として実行され、表示が消えたり反転したりスクロールを
  始めたりする。しかも読み返せないので原因が見えない。
- **リセット直後はページアドレッシングモード**（`20` の RESET 値が `10b`, p37）。
  水平モードのつもりで 1024 バイトを流すと、1 ページ分（128 バイト）を超えたところで
  列ポインタが 127 を超える。**この場合の挙動は §1.2.3 に書かれていない。** いずれにせよ
  意図した絵にはならない。全画面書き込みの前に `20` `00` を送る。
- **チャージポンプを有効にせずに `AF` を送っても点かない。** 「I2C は通っているのに
  真っ暗」の最も多い原因。`8D` `14` → `AF` の順を守る。
- **表示 ON の直後 100ms は何も見えない**（tAF, p23）。初期化直後の目視で判断しない。
- **ACK が返らない構成が正規に存在する。** `SDAOUT` を繋がなければ ACK は無視される、と
  datasheet が言っている（§6.1.5 b, p15）。I2C スキャナに出てこないのに書き込みは通る、
  という状態があり得る。Unit Mini OLED の基板が実際どちらの結線かは**未確認**。
- **400kHz を超えない。** tcycle の最小値が 2.5us（Table 9-6, p33）。100kHz / 400kHz の
  どちらでも動くはずだが、実測はまだ無い。
- **`0x21` / `0x22` はページアドレッシングモードでは効かない。** 逆に `00`-`0F` / `10`-`17` /
  `B0`-`B7` は水平・垂直モードでは効かない。モードとコマンドの組み合わせを間違えると
  黙って無視される。

## 出典と確度

- 参照した文書: **SSD1315 datasheet Rev 1.1 (2017-04)**。ただし付録 IV（コマンド表）だけは
  Rev 1.0 (2016-12) のままで、本体と版が揃っていない。これは PDF 側の状態であって
  転記ミスではない。
- **一次資料の入手経路が公式ではない。** Solomon Systech は自社サイトでの PDF 配布を
  営業窓口経由に限定しており、公開 URL が無い。参照したのは広く流通しているミラー
  （`cursedhardware.github.io/epd-driver-ic/SSD1315.pdf`）。改訂日・版数はその PDF の
  記載をそのまま使っており、より新しい版の有無は確認できていない。
- コントロールバイト（`0x00` / `0x40`）、アドレッシングモード、コマンド表、リセット既定値、
  I2C タイミング: **datasheet に明記がある。**
- **未確認（実測なし）**: `0x3c` が実際に ACK するか、Unit Mini OLED の SDAOUT が結線されて
  いるか、400kHz で動くか、パネルに合う初期化列が何か、ページモードで列 127 を超えたときに
  何が起きるか。`observations/ssd1315/` はまだ無い。
- **未調査**: スクロールコマンド（p41-44）、FR 同期（§6.4, p19）、内部 IREF の設定（`AD`）は
  読んでいない。M5Stack のライブラリが実際に送っている初期化列も突き合わせていない。
- **確認できないこと**: このチップは ID レジスタを持たないので、**実機に載っているのが
  本当に SSD1315 かどうかを I2C から確かめる手段が無い。** 製品表記を信じるしかない。
