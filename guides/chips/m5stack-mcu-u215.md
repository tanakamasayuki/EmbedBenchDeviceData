# Unit CardKB2 (U215) — カードサイズ QWERTY キーボード

> 押されたキーの ASCII コードを 1 バイトで返すだけのキーボード。**レジスタマップは
> ほぼ存在しない**（キー入力にレジスタを使わず、レジスタと呼べるのはファームウェア
> バージョンの `0xF1` 一本だけ）。これは記述漏れではなく、このユニットの設計である。
>
> **確度**: M5Stack が `Unit_CardKB2_User_Manual_EN` を公開しており、I2C の読み方と
> キーコード表はそこに書かれている。本ガイドはそれと `M5Unit-KEYBOARD` ライブラリ
> v0.1.0 のソースを突き合わせて書いた。ただし `profiles/m5stack-mcu-u215.yaml` の
> evidence は `inferred` / `tentative` のままで、**実測では未確認**。バスで動かした
> 記録はまだ無い。

## これは何か

42 キーの QWERTY 配列を持つ、カードサイズのキーボード。中身は ESP32-C61HF4 で、
Wi-Fi 6 と BLE を持っている。M5Stack のユニットとしては珍しく、**ホストとの繋ぎ方を
キーボード側で 4 通りから選ぶ**構成になっている。

| キー操作 | モード | LED |
|---|---|---|
| Fn + Sym + 1 | **I2C**（工場出荷時の既定） | 白 LED が 1 回点滅 |
| Fn + Sym + 2 | UART（115200-8N1） | 白 LED が 2 回点滅 |
| Fn + Sym + 3 | ESP-NOW ブロードキャスト | 白 LED が 3 回点滅 |
| Fn + Sym + 4 | BLE HID | 白 LED が 4 回点滅 |

選んだモードは保存され、電源を入れ直しても残る。**モードの切り替えはキーボード上でしか
できない。バス経由では変えられない。** I2C のデータが存在するのは I2C モードのときだけで、
別のモードに入っているユニットは、バスから見ると単に「いない」のと同じである。

### なぜレジスタが 1 本しか無いのか

**キー入力の読み出しにレジスタポインタを使わないためである。** ホストは
アドレス `0x5F` に対して**ポインタバイトを書かずに、いきなり 1 バイト読む**。返るのは
そのとき押されたキーの ASCII コードで、何も押されていなければ `0x00` が返る。
それだけである。

これは M5Stack のユーザマニュアルにもそのまま書かれている（"Keypad data register:
Reads 1 byte of data directly via I2C and returns the ASCII code value corresponding to
the pressed key"）。「レジスタ」という語が使われてはいるが、実体はポインタを持たない
生の read であって、アドレスは存在しない。

もう一方の「Firmware version register」だけが本物のレジスタで、`0xF1` を指定して
1 バイト読む。ライブラリが `begin()` で 1 回読むだけの値である。

**したがって、`profiles/m5stack-mcu-u215.yaml` に載っているレジスタが `0xF1` 一本
だけなのは、調査が途中だからではない。** それが全部である。キーの FIFO も、スキャン
ビットのレジスタも、モード切り替えのレジスタも無い。ライブラリ上でも、CardKB2 のクラスは
`UnitKeyboardBitwise` ではなく `UnitKeyboard` を継承していて、CardKB や FacesQWERTY が
使う `0x10`（スキャン）・`0x20`（モード）・`0xFE`（バージョン）のいずれにも触れない。
それらのレジスタがこのユニットに存在するという根拠は、ソースにもマニュアルにも無い。

できること:

- 押されたキーの ASCII コードを 1 バイトずつ受け取れる。
- Aa（Caps Lock）、Sym（記号モード）の状態に応じて、同じキーから違う ASCII が出る。
  切り替えはキーボード側が処理するので、ホストは何もしなくてよい。
- キーリピートもキーボード側がやる（後述）。
- ファームウェアバージョンを読める（`0xF1`）。

できないこと・持っていないもの:

- **押されているキーの一覧は取れない。** 取れるのは「直前に押された 1 キー」だけ。
  同時押しの検出も、キーが離されたことの検出も I2C モードには無い。
- **キーバッファ（FIFO）が無い。** ポーリングの間に 2 つ押されたら、片方は消える。
- **ホストからは何も設定できない。** 明るさも LED も、モードも、リピート時間も、
  I2C アドレスも変更するレジスタが無い。ライブラリの `readMode()` / `writeMode()` は
  このユニットでは常に失敗すると明記されている。
- **矢印キーは I2C では使えない。** Fn + D / X / Z / C はカーソル移動に割り当てられて
  いるが、ライブラリはその値（ソース上は 180〜183）を有効なキーとして受け取らない。
  ヘッダにも「Fn+D/Z/X/C arrow keys are not available in I2C/UART mode」と書かれている。
- 割り込み線は無い。**ポーリングするしかない。**
- バッテリは載っていない。USB Type-C か Grove の 5V から給電する。

## 早見表

| 項目 | 値 |
|---|---|
| I2C アドレス | `0x5F`（ユーザマニュアルとライブラリの既定値が一致）。**変更する手段は無い** |
| キー読み出し | **ポインタバイト無しの 1 バイト read**。押鍵時は ASCII、無押鍵時は `0x00` |
| レジスタ | `0xF1`（ファームウェアバージョン）1 本のみ |
| I2C 速度 | 100kHz（マニュアルが明記、ライブラリも 100kHz を使う） |
| ポーリング周期 | ライブラリの既定は 10ms |
| 中身 | ESP32-C61HF4（RISC-V 32bit 120MHz、Flash 4MB、Wi-Fi 6 / BLE） |
| キー数 | 42 キー + Reset ボタン + Boot ボタン |
| ホストとの接続 | I2C / UART / ESP-NOW / BLE HID をキーボード上で選択（既定は I2C） |
| インタフェース | Grove HY2.0-4P × 1（I2C / UART 用）、USB Type-C（給電・書き込み・シリアル出力） |
| 電源 | USB Type-C または Grove の DC 5V。待機 19.31mA。バッテリ非搭載 |
| キーリピート | **キーボード側が行う。** 300ms 長押しで開始、以後 50ms 間隔 |
| 重量 | 22.4 g |

## レジスタ / コマンド

**キーデータ（レジスタではない）**

| 操作 | 長さ | 意味 |
|---|---|---|
| `0x5F` からポインタ無しで read | 1 | 押されたキーの ASCII コード。何も押されていなければ `0x00` |

**レジスタ**

| アドレス | 長さ | R/W | 意味 |
|---|---|---|---|
| `0xF1` | 1 | R | ファームウェアバージョン。ライブラリは `begin()` で 1 回読み、ログに出すだけで、**値の符号化については何も決めていない**（転送が失敗したときだけエラー扱いにする） |

**バイト順**: 複数バイトの値が存在しないので、バイト順を気にする箇所は無い。

**キーコード**: マニュアルに 3 枚の対応表（通常 / Caps Lock / 記号モード）がある。
代表的な値は Delete = `0x08`、Enter = `0x0A`、Space = `0x20`、数字と英字は素直な ASCII。
Fn + 1 は Esc（`0x1B`）。表で空欄になっているキーは値を出さない。

**ライブラリが受け付けるバイトの範囲**: `M5Unit-KEYBOARD` の `UnitCardKB2::update()` は、
読んだバイトが次のいずれかでなければ**黙って捨てる**。

- `0x08`〜`0x0D`
- `0x1B`
- `0x20`〜`0x7E`

## 典型的な使い方

1. ユニットが I2C モードに入っていることを確かめる。工場出荷時は I2C だが、誰かが
   Fn + Sym + 2〜4 を押していれば別のモードのままである。**戻すには Fn + Sym + 1 を
   押し、続けて RST ボタンを押す。**
2. `0x5F` に ACK が返るか確認する。ライブラリの `begin()` は、ポインタ無しの 1 バイト
   read を最大 3 回試して疎通を見る。
3. `0xF1` を 1 バイト読んでファームウェアバージョンを取る（ライブラリはここまでを
   `begin()` でやる）。
4. あとは 10ms 程度の周期で、`0x5F` からポインタ無しの 1 バイト read を繰り返す。
   `0x00` なら何も押されていない。`0x00` 以外なら、それが押されたキーの ASCII である。
5. 同じバイトが連続して返ってくることがある。それはキーボードのオートリピート
   （300ms 長押し後、50ms 間隔）であって、ホスト側で押し直しが起きたわけではない。

## 利用上の注意

- **応答が無いときは、まずモードを疑う。** バスに出てこないユニットは壊れているのでは
  なく、UART / ESP-NOW / BLE HID モードに入っているだけのことが多い。ライブラリ自身、
  `begin()` が失敗したときの診断メッセージとして「device may not be in I2C mode」を
  出し、Fn + Sym + 1 を押してから RST を押すよう案内している。モードは電源を切っても
  保存されるので、一度触ってしまうと次の電源投入でも直らない。
- **ポインタ無しの read であることを忘れない。** 一般的な I2C デバイスのつもりで
  「レジスタ `0x00` を読む」と書いてしまうと、その `0x00` はポインタとして解釈されずに
  ただの write として出るか、あるいは意図しない結果になる。読むときはアドレスバイトの
  直後にそのまま 1 バイト受け取る。
- **`begin()` の疎通確認自体がキーを 1 つ食う可能性がある。** 基底クラスの
  `UnitKeyboard::begin()` は 1 バイト読んで捨てる。初期化の直前に押されていたキーは
  そこで消える。
- **バッファが無いので、ポーリングが遅いと打鍵を落とす。** 10ms 周期は「速すぎる」
  のではなく、これが前提の設計である。表示の更新などで周期が伸びると入力が抜ける。
- **ノイズのようなバイトが実際に観測されている。** ライブラリのフィルタは形式的な
  ものではなく、ソースのコメントが `0x01` を「AtomS3 上で実際に観測された偽の値」
  として名指ししている。自前で実装するなら、同じように受け入れる値を制限したほうが
  よい。範囲外を素直に文字として扱うと、画面に化けた文字が出る。
- **矢印キーは飛んでこない。** Fn + D / X / Z / C はマニュアル上カーソル移動だが、
  I2C モードではライブラリが受け取らない。矢印が要るなら UART モード
  （`UnitCardKB2UART` が扱うフレーム形式）を使うことになる。
- **`0x0D`（CR）は受け入れられるが、マニュアルのキーコード表には出てこない。**
  ライブラリのフィルタは `0x08`〜`0x0D` を通すのに、マニュアルの表で制御文字として
  挙がっているのは `0x08`（Delete）と `0x0A`（Enter）だけである。**`0x0D` が実際に
  出るキーがあるかは未確認。**
- **Sym は押しっぱなしの修飾キーではなくトグルである。** 1 回押すと記号モードに入り、
  青 LED が点く。もう一度押すまで戻らない。Caps Lock（Aa）は緑 LED。Fn を押している
  間は赤 LED。ホスト側で「Shift を押しながら」の発想で組むと合わない。
- **モードを切り替えた直後は RST を押す。** ヘッダに警告がある（修飾キーの状態を
  リセットするため。将来のファームウェアで直る予定と書かれている）。
- **USB シリアルには常に出ている。** どのモードでも、USB Type-C 側には
  `KEY [KEY_ID] [KEY_STATE]` の形式で 115200 bps で出力される。デバッグにはこちらが
  使える（KEY_ID は 行番号 × 11 + 列番号）。
- **本リポジトリの probe は read-only。** `scenarios/m5stack-mcu-u215/p0.yaml` は
  `0xF1` を読むだけである。書けるレジスタがそもそも無いので、他のユニットと違って
  「書き込みを保留している」わけではない。

## 出典と確度

- I2C アドレス `0x5F`、通信速度 100kHz、ポインタ無しの 1 バイト read、無押鍵時に `0x00`、
  `0xF1` がファームウェアバージョンであること、キーコード対応表、モード切り替えの
  キー操作、キーリピート 300ms / 50ms: **ユーザマニュアルに記載がある。**
- 受け入れるバイトの範囲、`0x01` が AtomS3 上で実際に観測された偽値であること、
  `begin()` が 1 バイト読んで捨てること、CardKB と違って「離した」ではなく「押した」を
  返すこと、`readMode()` / `writeMode()` が常に失敗すること: `M5Unit-KEYBOARD` v0.1.0 の
  ソース（`src/unit/unit_CardKB2.cpp` / `.hpp`、`src/unit/unit_Keyboard.cpp`）から
  起こした**推定**。`profiles/` の evidence は `inferred` / `tentative`。
- **`profiles/` に載っているレジスタが `0xF1` 1 本だけなのは coverage の不足ではない。**
  ライブラリがレジスタとして触るのはそこだけであり、それ以外のアドレス空間については
  ソースもマニュアルも何も述べていない。**未知**である。
- **未確認**: 実機のキャプチャがまだ無い。`0x5F` が本当に ACK するか、ポインタ無し
  read が期待どおり動くか、`0xF1` の値の意味（メジャー / マイナーの割り当てなど）、
  `0x0D` を出すキーが存在するか、`0xF1` 以外のアドレスがどう振る舞うかは、いずれも
  確かめられていない。
- **参考**: `chips/m5stack-mcu-u215.yaml` の注記は「ユーザマニュアルは I2C アドレスを
  書いていない」としているが、マニュアルの III 章「1 Keypad data register」に
  `Communication address: 0x5F` の記載がある。
