# INA226 — 電流・電圧・電力モニタ

> シャント抵抗の両端電圧とバス電圧を 16bit で測り、内蔵の乗算器で電流と電力まで
> 計算して返す IC。**ただし電流レジスタと電力レジスタは、キャリブレーション
> レジスタに値を書くまで 0 のままである。** そのキャリブレーション値が電流の
> 1 LSB を決めており、これを理解しないと INA226 は「電圧計」でしかない。
>
> **確度**: Texas Instruments のメーカー datasheet **SBOS547C**（2011 年 6 月初版、
> 2026 年 8 月改訂、全 41 ページ）に基づく。レジスタ・ビット定義・単位・
> 計算式・タイミングはすべてこの文書由来。**未確認**: 実機のキャプチャはまだ無く、
> `observations/ina226/` は存在しない。

## これは何か

電源ラインに入れたシャント抵抗の電圧降下（= 電流）と、その先のバス電圧を測る IC。
ハイサイドにもローサイドにも入れられる。I²C / SMBus 互換のインタフェースを持ち、
測定値をレジスタから読む。

**このチップ自身は電流を測っていない。**測っているのは 2 つの電圧、
すなわち IN+ / IN− 間の差動電圧と、VBUS ピンの電圧だけである。電流と電力は、
ユーザがキャリブレーションレジスタに書いた値を使って内部で計算した結果である
（datasheet §6.5 の冒頭, p.15）。

できること:

- シャント電圧を ±81.92 mV の範囲、2.5 µV/LSB で測れる。
- バス電圧を 0〜36 V の範囲、1.25 mV/LSB で測れる。**電源電圧とは独立**なので、
  チップは 3.3 V で動かしたまま 36 V のバスを監視できる。
- 電流と電力を、レジスタから直接アンペア / ワットに換算できる形で読める
  （キャリブレーション済みの場合）。
- 変換時間を 140 µs〜8.244 ms の 8 段階から、シャントとバスで**独立に**選べる。
- 平均化回数を 1 / 4 / 16 / 64 / 128 / 256 / 512 / 1024 から選べる。
- 連続変換モードと単発（triggered）モード、そして power-down モードを持つ。
- Alert ピンで、シャント電圧の上下限・バス電圧の上下限・電力上限・変換完了の
  いずれかを通知できる。SMBus Alert Response にも応答する。
- I²C アドレスを 16 通り（`0x40`〜`0x4F`）選べる。
- 精度が高い。ゲイン誤差 max 0.1 %、シャント側オフセット max 10 µV、CMRR typ 140 dB。

できないこと・持っていないもの:

- **シャント抵抗を内蔵していない。** 外付けであり、その抵抗値は
  キャリブレーション計算の入力になる。
- **キャリブレーションレジスタを書かない限り、電流レジスタも電力レジスタも 0 のまま**
  （Table 7-1 の脚注 2, p.22 / §6.5.3, p.16）。エラーは出ない。ただ 0 が返る。
- **電力の LSB を自由に選べない。** 電流 LSB の 25 倍に内部固定されている。
- **レジスタは全部揮発性。** 電源を入れ直すと既定値に戻る。EEPROM は無い
  （§6.5.4, p.17）。
- **同時に有効にできる Alert 機能は 1 つだけ。** 複数立てると上位ビットのものが勝つ。
- 温度は測らない。
- 負のバス電圧は測れない（バス電圧レジスタの D15 は常に 0）。

電気的な条件:

- 電源 VS 2.7〜5.5 V（推奨 3.3 V）、typ 330 µA。動作温度 -40〜125 °C。
- SDA / SCL はオープンドレイン。外部プルアップが必要。
- 入力の絶対最大定格は 差動 ±40 V、コモンモード -0.3〜40 V、VBUS -0.3〜40 V。
  ただし **実際に印加してよいのは 36 V まで**（§6.3.1 の Note, p.10）。
- 入力バイアス電流 0.1 nA、VBUS の入力インピーダンス 830 kΩ。
- I²C は fast mode（最大 400 kHz）と high-speed mode（最大 2.94 MHz）。
- バスをロックしないよう 28 ms（typ）の SMBus タイムアウトを持つ。
- Alert ピンはオープンドレイン。使わないならフローティングで構わない。

## レジスタ

`profiles/ina226.yaml` の内容に、datasheet 由来の単位・ビット定義・POR 値を足したもの。
**すべて 16bit で、MSB のバイトが先に出る**（§6.5.5.3 の Note, p.19）。

| ポインタ | 名前 | R/W | POR | 意味 |
|---|---|---|---|---|
| `0x00` | Configuration | R/W | `0x4127` | リセット、平均回数、変換時間、動作モード |
| `0x01` | Shunt Voltage | R | `0x0000` | シャント電圧。**2 の補数、2.5 µV/LSB** |
| `0x02` | Bus Voltage | R | `0x0000` | バス電圧。**符号なし、1.25 mV/LSB**、D15 は常に 0 |
| `0x03` | Power | R | `0x0000` | 電力。**LSB = 電流 LSB × 25** |
| `0x04` | Current | R | `0x0000` | 電流。**LSB = ユーザが決めた Current_LSB**、符号付き |
| `0x05` | Calibration | R/W | `0x0000` | **15bit（D15 は未使用）。ここが電流 LSB を決める** |
| `0x06` | Mask/Enable | R/W | `0x0000` | Alert の機能選択とフラグ |
| `0x07` | Alert Limit | R/W | `0x0000` | Alert のしきい値 |
| `0xFE` | Manufacturer ID | R | `0x5449` | 固定値 |
| `0xFF` | Die ID | R | `0x2260` / `0x2261` | Device ID(15:4) と Revision ID(3:0) |

**Configuration レジスタ（`0x00`）のビット**（Table 7-2, p.22）

| ビット | 名前 | 意味 |
|---|---|---|
| D15 | `RST` | `1` を書くと POR 相当のリセット。**自己クリアする** |
| D11–D9 | `AVG[2:0]` | 平均回数。`000`=1（既定）、`001`=4、`010`=16、`011`=64、`100`=128、`101`=256、`110`=512、`111`=1024 |
| D8–D6 | `VBUSCT[2:0]` | バス電圧の変換時間。`000`=140 µs 〜 `111`=8.244 ms（既定 `100`=1.1 ms） |
| D5–D3 | `VSHCT[2:0]` | シャント電圧の変換時間。同上（既定 `100`=1.1 ms） |
| D2–D0 | `MODE[2:0]` | `000`/`100`=power-down、`001`=シャント単発、`010`=バス単発、`011`=両方単発、`101`=シャント連続、`110`=バス連続、**`111`=両方連続（既定）** |

D14–D12 は定義されていないが、POR 値 `0x4127` は D14 が 1 である
（`0x4127` = `0100 0001 0010 0111`）。既定値をそのまま読み戻すと D14 が立って見える。

**Mask/Enable レジスタ（`0x06`）のビット**（Table 7-12, p.26）

| ビット | 名前 | 意味 |
|---|---|---|
| D15 | `SOL` | シャント電圧の上限超過で Alert |
| D14 | `SUL` | シャント電圧の下限割れで Alert |
| D13 | `BOL` | バス電圧の上限超過で Alert |
| D12 | `BUL` | バス電圧の下限割れで Alert |
| D11 | `POL` | 電力の上限超過で Alert |
| D10 | `CNVR` | 変換完了で Alert |
| D4 | `AFF` | Alert 発生フラグ（読み出し） |
| D3 | `CVRF` | 変換完了フラグ（読み出し） |
| D2 | `OVF` | **演算オーバーフロー。立っていたら電流・電力は無効** |
| D1 | `APOL` | Alert の極性。`0`=アクティブ Low（既定）、`1`=アクティブ High |
| D0 | `LEN` | `1`=ラッチ、`0`=トランスペアレント（既定） |

**転送の形**（§6.5.5.3, p.18–20）

- 書き込み: `[アドレス+W] [ポインタ] [MSB] [LSB]`。**書き込みには必ずポインタが要る。**
- 読み出し: いったん `[アドレス+W] [ポインタ]` を送って STOP または repeated START、
  続けて `[アドレス+R]` で 2 バイト読む。
- **ポインタは書き込むまで保持される。** 同じレジスタを繰り返し読むならポインタの
  再送は不要。

## 典型的な使い方

1. `0xFE` を読んで `0x5449` が返ることを確認する（通信確認）。`0xFF` の Die ID は
   `0x2260` か `0x2261`。
2. **シャント抵抗の値 R_SHUNT と、想定する最大電流を決める。**
3. 電流の 1 LSB を決める:

   ```
   Current_LSB ≥ 最大想定電流 / 2^15
   ```

   最小値をそのまま使えば分解能が最大になるが、換算を楽にするために
   キリのよい値（1 mA/bit など）へ切り上げるのが普通である。
4. キャリブレーション値を計算する:

   ```
   CAL = 0.00512 / (Current_LSB × R_SHUNT)
   ```

   `0.00512` はスケーリングのための内部固定値である。
5. `0x05` に CAL を書く。**ここを書かないと 6 以降が意味を持たない。**
6. `0x00`（Configuration）に平均回数・変換時間・モードを書く。既定のままでも
   シャントとバスの連続変換は動く。
7. 変換完了を待つ。単発モードなら `0x06` の `CVRF` を見る。
8. 読む:
   - `0x01`（シャント電圧）× 2.5 µV
   - `0x02`（バス電圧）× 1.25 mV
   - `0x04`（電流）× Current_LSB
   - `0x03`（電力）× Current_LSB × 25
9. 単発モードで次の測定が要るなら、`0x00` を**もう一度書く**（値が同じでも書く）。

## 利用上の注意

- **キャリブレーションレジスタ（`0x05`）が電流の LSB を決めている。書かないと
  `0x03`（電力）と `0x04`（電流）は 0 のままである。** これは故障ではなく仕様で、
  Table 7-1 の脚注 2（p.22）と §6.5.3（p.16）が明記している。
  「INA226 を繋いだのに電流が 0 A から動かない」の原因はほぼこれである。
  この状態でも `0x01`（シャント電圧）と `0x02`（バス電圧）は正しく測れているので、
  **どうしても計算をチップに任せたくないなら、この 2 本だけ読んでホスト側で
  I = Vshunt / Rshunt を計算しても構わない**（datasheet も §6.5.3 でそれを認めている）。
- **CAL は「校正値」ではなく「スケール定義」である。** シャント抵抗の値と、
  ユーザが選んだ電流 1 LSB の両方が入った量で、
  `CAL = 0.00512 / (Current_LSB × R_SHUNT)` である。
  電流レジスタは内部で `Current = ShuntVoltage × CAL / 2048` として作られ（式 3, p.15）、
  電力レジスタは `Power = Current × BusVoltage / 20000` として作られる（式 4, p.16）。
  **したがって CAL を変えると、電流と電力の「読み値の意味」がまるごと変わる。**
  誰かが CAL を書き換えたまま忘れると、レジスタ値は動いているのに単位が違う、
  という気づきにくい壊れ方をする。
- **電力の LSB は電流 LSB の 25 倍に内部固定されている。** 別々に選ぶことはできない。
  Current_LSB を 1 mA/bit にすれば Power_LSB は 25 mW/bit になる。
- **CAL は 15bit である**（Table 7-11, p.26 で D15 が未使用）。Current_LSB を欲張って
  小さくしすぎると、計算した CAL が 32767 に収まらなくなる。
- **CAL はシステム全体の誤差校正にも使える。** 外部の電流計と読み合わせて、
  `Corrected_CAL = trunc(CAL × 実測電流 / INA226 の読み値)` に置き換える手が
  §6.5.2.1（p.16）にある。ただしこれをやると CAL は「理論値」ではなくなる。
- **全レジスタが揮発性である。電源投入のたびに CAL と Configuration を書き直す**
  （§6.5.4, p.17）。バッテリ監視のように電源が入り切りする用途では、
  復帰処理に必ず組み込む。
- **`OVF`（Mask/Enable の D2）が立っていたら電流・電力は無効。** 読めてしまうので
  気づきにくい。
- **`CVRF` は Mask/Enable レジスタを読むとクリアされる。** また Configuration への
  書き込み（power-down 設定を除く）でもクリアされる（§6.3.1, p.11）。
  ポーリングのために `0x06` を読むと、その読み出し自体がフラグを消す。
  Alert と変換完了を両方使っている場合、`0x06` を読むタイミングの設計に注意する。
- **Alert 機能は同時に 1 つしか監視できない。** 複数のビットを立てると、
  D15 に近いほうが優先されて Alert Limit と比較される（§6.3.1.2, p.12）。
  変換完了（`CNVR`）だけは他の 1 機能と併用でき、その場合はどちらが原因かを
  `AFF` と `CVRF` で見分ける。
- **シャント電圧は符号付き（2 の補数）、バス電圧は符号なし。** 電流レジスタも
  符号付きである。同じ 16bit だからと同じ処理に通すと、逆流時に値が跳ねる。
- **アドレスピンは GND / VS だけでなく SDA / SCL のレベルも取る**（Table 6-2, p.18）。
  I²C のバス線をアドレスピンに直結するという、他のチップではあまり見ない配線が
  正規の使い方である。これで 2 ピンから 16 アドレスを作っている。
  **チップは毎回のバス通信で A0 / A1 の状態をサンプルする**ので、
  通信開始前にピンのレベルを確定させておく必要がある。
- **バス電圧レジスタのフルスケールは 40.96 V だが、入力に 36 V を超える電圧を
  かけてはいけない**（§6.3.1 の Note, p.10）。レジスタが 40.96 V まで表現できることと、
  ピンに 40 V かけてよいことは別である。
- **Configuration への書き込みは、進行中の変換を止めて新しい設定でやり直す**
  （§7.1.1, p.22）。設定を変えた直後の 1 回は、変換時間ぶん待つ必要がある。
- **平均化と変換時間の組み合わせで更新周期が決まる。** シャントとバスの両方を
  連続変換するなら `(VSHCT + VBUSCT) × AVG` が 1 サンプルの周期になる。
  例: 588 µs × 2 × 4 回平均 ≈ 4.7 ms（§6.4.1, p.13 の例）。
- **datasheet に内部矛盾が 1 つある。** Table 7-1（p.22）は Die ID の POR 値を
  `0x2260` / `0x2261` としているが、Table 7-15（p.28）のビット表は POR 値を全部 0 と
  書いている。実機では前者が正しいはずだが、**本リポジトリでは測って確かめていない**。
  `scenarios/ina226/p0.yaml` が `die-id` を出力に挙げているのは、ここを実測で
  埋めるためでもある。
- **M5Stack の Unit INA226-10A / INA226-1A に載っているシャント抵抗の値を、
  本リポジトリは記録していない。** 製品名から測定レンジは推測できるが、
  R_SHUNT が分からなければ CAL は計算できない。ユニットを使うなら、まず
  シャント値を M5Stack のドキュメントか回路図で確認すること。
- 入力にノイズが乗る用途では、10 Ω 以下の直列抵抗と 0.1〜1 µF のセラミック
  コンデンサによる入力フィルタが推奨されている（§6.4.2, p.14）。
  ΔΣ ADC のサンプリングは typ 500 kHz（±30 %）なので、その高調波（1 MHz 以上）の
  過渡が問題になる場合に限られる。
