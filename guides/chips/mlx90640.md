# MLX90640 — 32×24 赤外線サーマルアレイ

> 768 画素のサーモパイルアレイ。1 枚のフレームは RAM 832 ワードの一括読み出しで、
> そこから温度を得るには EEPROM 832 ワードの校正係数を当てはめる計算が要る。
> **レジスタアドレスが 16bit** で、普通の 8bit レジスタデバイスとは転送の形が違う。
>
> **確度**: Melexis の datasheet（REVISION 12, 2019-12-03, 60 ページ）に基づく。
> **実測では未確認**。probe はレジスタと EEPROM / RAM の一部を読むだけで、フル
> フレームの読み出しはしていない。

## これは何か

32×24 = 768 個のサーモパイル画素を並べたサーマルカメラ用センサ。MLX90614 が
「1 点の温度を数値で返す」のに対して、こちらは **生の ADC 値を 768 個返すだけ**で、
温度に直すのはホストの仕事である。この差が実装量のほとんどを決める。

内部は「ROM（プログラム）+ RAM（測定結果）+ EEPROM（工場校正係数）+ 制御レジスタ」で、
測定は電源投入後に連続で回り続ける。ホストは好きなタイミングで RAM を読む。

できること:

- 768 画素の赤外線データを 0.5 / 1 / 2 / 4 / 8 / 16 / 32 / 64 Hz で更新し続ける。
- 画素の配置パターンを chess（工場既定・校正済み）と interleaved（TV 走査）から選ぶ。
- ADC 分解能を 16 / 17 / 18（既定）/ 19bit から選ぶ。
- I2C アドレス、リフレッシュレート、読み出しパターンを EEPROM に焼いて起動時の既定値にする。
- SDA / SCL は 5V トレラントなので、5V の I2C バスに直結できる（電源は 3.3V のまま）。

できないこと・持っていないもの:

- **画像を出さない。温度も出さない。** 返るのは補償前の生データで、温度にするには
  EEPROM の校正係数を復元して 1 画素ずつ計算する必要がある（datasheet 11 章、22〜46 ページ）。
  Melexis が公開している C の API を使うのが現実的な選択肢である。
- **1 回の測定で全画素は更新されない。** フレームは 2 つのサブページに分かれており、
  リフレッシュレートで更新されるのは片方だけ。**全画素を揃えるには 2 回読む**必要があり、
  実効的な画像レートは設定値の半分になる。
- **周囲温度 Ta の計算には両方のサブページが要る。** 片方だけ読み続けても Ta は求まらない。
- **不良画素がある。** 最大 4 画素まで、出力が無い / 規格外になることが許容されており、
  どの画素かは EEPROM に記録されている。周囲の画素から補間して埋めるのはホストの仕事。
- **割り込み線・データレディピンは無い。** 新データの有無は Status Register (`0x8000`) の
  bit3 を読むしかない。しかも**このビットは自動でクリアされない**。
- **EEPROM はほとんど書き換えられない。** 消去/書き込みサイクルは 10 回（Table 5）。
  設定を EEPROM に焼くのは実質「数回だけ許されている操作」である。

電気的な現実:

- 電源 3.0 〜 3.6V。**3.3V ± 0.05V に保つことが推奨**されている（NOTE 1）。消費電流 15〜25mA。
- I2C クロックは typ 400kHz、max 1MHz（FM+ 対応、既定で有効）。
- **SDA のシンク電流は 10mA に制限されている**。I2C 規格の 20mA を満たさない唯一の項目で、
  熱設計上の都合とされる（NOTE 4）。プルアップを強くしすぎると VOL が上がる。
- EEPROM 操作は 400kHz までで行うこと（NOTE 5）。書き込みセル時間は 5ms 以上。
- POR 後、最初の有効データは 40ms + リフレッシュレートで決まる時間の後。
- **規定確度に達するには熱的な安定に最大 4 分かかる**（12.2.2）。電源投入直後の値は温い/冷たい。
- I2C アドレスは `0x01`〜`0xFF` の範囲で変更可能。**`0x00` は避けること**。既定は `0x33`
  （8bit 表記なら write = `0x66`、read = `0x67`）。

M5Stack Unit Thermal (U016) / Thermal2 (U149) はこれを `0x33` で使う。

## レジスタ / メモリマップ

| アドレス | 中身 |
|---|---|
| `0x0000`〜`0x03FF` | ROM（Melexis のプログラム。触らない） |
| `0x0400`〜`0x06FF` | **測定 RAM: 768 画素** |
| `0x0700`〜`0x073F` | 補助データ。`0x0700` Ta_Vbe、`0x0708` CP(SP0)、`0x070A` GAIN、`0x0720` Ta_PTAT、`0x0728` CP(SP1)、`0x072A` VDDpix |
| `0x2400`〜`0x273F` | **EEPROM: 工場校正係数と設定**。`0x240C`〜`0x240F` が起動時にレジスタへ転送される |
| `0x8000` | Status register |
| `0x800D` | Control register 1 |
| `0x800F` | I2C configuration register |
| `0x8010` | I2C アドレス（EEPROM `0x240F` から起動時にロード） |

Status register `0x8000`:

| ビット | 意味 |
|---|---|
| [2:0] | 最後に測定したサブページ（`000` = 0、`001` = 1） |
| [3] | **新データが RAM にある。1 になったら読み、読んだらホストが 0 に戻す** |
| [4] | RAM 上書き許可（enable overwrite） |
| [5] | ステップモードでの測定開始（10.5 の測定フロー中で言及される） |

Control register 1 `0x800D`（EEPROM `0x240C` の既定値は `0x1901`）:

| ビット | 意味 |
|---|---|
| [0] | サブページモード有効（既定 1） |
| [2] | データホールド（1 にすると上書き許可時のみ RAM に転送） |
| [3] | サブページ繰り返し |
| [4] | 測定するサブページの選択（[3] と組み合わせて意味が決まる。Table 6 参照） |
| [9:7] | リフレッシュレート（`010` = 2Hz が既定） |
| [11:10] | ADC 分解能（`10` = 18bit が既定） |
| [12] | 読み出しパターン（0 = interleaved、**1 = chess が既定**） |

**転送の形（16bit アドレス）**:

```
書き込み
  S  [SA<<1|W]  A  [addr MSB]  A  [addr LSB]  A  [data MSB]  A  [data LSB]  A  P

読み出し
  S  [SA<<1|W]  A  [addr MSB]  A  [addr LSB]  A
  Sr [SA<<1|R]  A  [data MSB]  A  [data LSB]  A  ...（アドレスは自動インクリメント）... NA  P
```

アドレスもデータも **MSB first の 16bit** である。8bit レジスタデバイスのつもりで
アドレスを 1 バイトしか送らないと、当然まったく違う番地を読む。

**フレーム読み出しは一括転送である。** RAM の `0x0400`〜`0x073F` を 1 回のトランザクションで
832 ワード = 1664 バイト読む。Melexis 公式 API はこれに Control Register 1 と
Status Register のサブページ番号を足して **834 ワードのフレームバッファ**として扱う。
校正用の EEPROM も同じく 832 ワード（`0x2400`〜`0x273F`）で、こちらは**起動後に 1 回だけ**
読めばよい。

## 典型的な使い方

1. POR 後、40ms + リフレッシュレート分の時間を待つ。
2. **EEPROM `0x2400`〜`0x273F` の 832 ワードを 1 回だけ読み**、校正係数を復元して
   ホスト側のメモリに置く（datasheet 11.1、22〜29 ページ。17 個の小節に分かれている）。
3. 必要ならリフレッシュレートと読み出しパターンを Control register 1 (`0x800D`) に書く。
   これは揮発なので毎回書く。EEPROM (`0x240C`) に焼くのは 10 回しかできない。
4. Status register (`0x8000`) の bit3 を読み、1 になるのを待つ。
5. RAM `0x0400`〜`0x073F` の 832 ワードを一括で読む。
6. **Status register の bit3 を 0 に書き戻す。**
7. サブページ番号（`0x8000` の [2:0]）を見て、どちらのフレームだったかを記録する。
8. 4〜7 をもう一度回して、逆のサブページを取る。
9. 両方のサブページが揃ったら、VDD → Ta → ゲイン補正 → オフセット補正 → 感度正規化 →
   放射率・反射温度補正、の順で 768 画素分の温度を計算する（11.2、30〜46 ページ）。
10. 温度が要らず画像だけでよいなら、計算を途中で打ち切る短縮フローが用意されている
    （13.3 Using the device in "image mode"、p54）。

## 利用上の注意

- **生データだけでは何も分からない。** RAM の値は補償前の ADC 出力で、そのまま可視化しても
  固定パターンノイズだらけの模様が出るだけである。**EEPROM の係数を当てはめて初めて
  画像になる**。ここを飛ばした実装が「変な模様しか出ない」原因のほとんど。
- **new-data フラグは read-to-clear ではない。** `0x8000` の bit3 は「ホストがクリアすること」と
  データシートが明記している（10.4）。クリアを忘れると常に「新データあり」に見え、
  同じフレームを読み続けることになる。
- **サブページを追わないとフレームが混ざる。** 更新されるのは毎回片方だけなので、
  サブページ番号を見ずに 832 ワードを 2 回読むと、同じサブページを 2 回取ったり、
  読んでいる最中に上書きされて 2 つの時刻が混ざったフレームになる。
  混在が困る場面のために `en_overwrite` と data hold のビットがある。
- **高いリフレッシュレートには I2C の帯域が要る。** 832 ワード = 1664 バイトを 400kHz で
  読むと、ACK 込みで約 37ms かかる（1664 × 9 ÷ 400000）。サブページ 1 枚ぶんの時間は
  16Hz で 62.5ms、32Hz で 31ms なので、**32Hz 以上は 400kHz では読み切れない**。
  FM+（1MHz）が要る。この計算は本ガイドで行ったもので、datasheet に表としては無い。
- **EEPROM の書き換えは 10 回しかできない。** リフレッシュレートやアドレスを EEPROM に
  焼く操作は、設計中に何度も試せる類のものではない。運用時の設定は毎回レジスタに
  書くのが正しい。EEPROM を書く場合は「`0x0000` を書いて消去 → 5ms 以上待つ →
  新しい値を書く → 5ms 以上待つ」で、かつ 400kHz 以下で行う（Table 5 の NOTE 2 / NOTE 5）。
- **アドレス変更は EEPROM `0x240F`。`0x00` にしてはいけない。** 既定値は `0xBE33`（下位バイトが
  アドレス）。変えた個体は次の電源投入から新アドレスになる。10 回制限があるので、
  同一バスに複数個載せる設計は事前に決めておく。
- **chess パターンから離れると校正が効きにくくなる。** 工場校正は chess パターンで行われて
  おり、interleaved にすると固定パターンノイズが増える。Melexis 自身が chess を推奨している
  （10.6 の NOTE1）。
- **電源投入直後の値は信用できない。** 電気的には動いていても、熱的に安定するまで最大 4 分。
  短時間で校正・比較する用途では、この過渡を待つ必要がある。
- **リフレッシュレートを実行中に変えても、測定中のサブページが終わるまで反映されない**（12.2.1 NOTE）。
- **SDA のシンク電流上限が 10mA しかない。** プルアップを 1kΩ 以下にすると VOL 規格
  （0.4V @ 3mA）を満たさなくなる。長いバスで速度を上げたいときはプルアップを強くしがちだが、
  このデバイスでは逆効果になりうる。データシートはむしろ電流源プルアップやバスアクセラレータ、
  あるいは**クロックを落とすこと**を勧めている（14. Application Comments）。
- **不良画素は必ずある前提で組む。** 最大 4 画素。EEPROM に記録されているので、読み出して
  補間するか、少なくとも「異常値の画素がある」ことを許容する。
- **電源を別にできる。** MLX90640Bxx は完全な I2C 互換なので、MCU 側が 2.6〜5V、センサ側が
  3.3V という構成が可能（13.2）。

## 出典と確度

- メモリマップ、レジスタのビット定義、転送の形、リフレッシュレート、EEPROM の耐久と
  書き込み手順、電気仕様: すべて Melexis datasheet REVISION 12（2019-12）由来。
- 「Melexis 公式 API はフレームを 834 ワードとして扱う」は API 実装側の事実であり、
  datasheet には 832 ワードの RAM 範囲としてしか書かれていない。
- 「400kHz では 32Hz 以上のリフレッシュレートを読み切れない」は本ガイドで行った算術で、
  datasheet に記載があるわけではない。**実測では未確認**。
- **未確認**: 実機のキャプチャが無い。`0x33` で応答するか、レジスタの既定値が表のとおりか、
  400kHz / FM+ で通るかは確かめられていない。
- **未調査**: probe はレジスタと EEPROM / RAM の一部を読むだけで、フルフレーム読み出し・
  EEPROM 全読み出し・リフレッシュレートの掃引・サブページ追跡・FM+ 設定はすべて deferred。
- M5Stack Unit Thermal / Thermal2 の FOV（55° 版か 110° 版か）は**未確認**。
