# BMI270 — 6 軸 IMU（加速度＋角速度）

> 16bit の 3 軸加速度センサと 3 軸ジャイロを 1 パッケージに収めた IMU。**電源投入の
> たびに 8 KB の設定ファイルをチップへ書き込まないと、動作可能状態にすら入らない。**
> これがこのチップを扱ううえで最大の前提である。
>
> **確度**: Bosch Sensortec のメーカー datasheet
> BST-BMI270-DS000-08 **文書リビジョン 1.6**（2026 年 3 月、全 150 ページ）に基づく。
> レジスタ・ビット定義・初期化手順・単位はすべてこの文書由来。**未確認**: 実機の
> キャプチャはまだ無く、`observations/bmi270/` は存在しない。8 KB の設定ファイルの
> 中身は Bosch も公開しておらず、GitHub の API ソースにバイナリ配列として置かれている
> だけである。

## これは何か

加速度と角速度を測るセンサ。加速度計は「センサに加わっている力の向きと大きさ」を
返す（自由落下でゼロ）、ジャイロは「回転の速さ」を返す（静止でゼロ）。両者は
ハードウェアで同期して測られる。

ただしこのチップは単なるセンサではなく、**内部に feature engine と呼ばれる処理エンジンを
持っている**。歩数カウント、手首を返す動作の検出、動き/静止の検出といった機能が
チップ側で動く。その処理エンジンのプログラムが、後述する 8 KB の設定ファイルである。

できること:

- 加速度を ±2 / ±4 / ±8 / ±16 g、16bit で読める。ODR は 0.78 Hz〜1.6 kHz。
- 角速度を ±125 / ±250 / ±500 / ±1000 / ±2000 dps、16bit で読める。ODR は 25 Hz〜3.2 kHz。
- 温度を読める（1/512 K/LSB、`0x0000` が 23 °C）。ただし後述の制約がある。
- 2 KB の FIFO に加速度・角速度・タイムスタンプ・AUX センサのデータを溜められる。
- 2 本の割り込みピン（INT1 / INT2）に、データレディ・FIFO 水位・FIFO フル・エラー・
  各種フィーチャー出力を自由に割り付けられる。
- **副 I²C マスタ（AUX I/F）を持っていて、磁力計などをぶら下げて 9 軸にできる。**
  Bosch は BMM150 を例に挙げている。AUX に繋いだセンサのデータは IMU と同期する。
- OIS 用の副 SPI インタフェースを持つ（手ぶれ補正向け、10 MHz）。
- Sensortime タイムスタンプでホストとの時刻同期ができる。
- オフセット補正（加速度・ジャイロ）と、ジャイロの感度誤差補正（CRT）ができ、
  結果を NVM に焼ける。

できないこと・持っていないもの:

- **設定ファイルを上げるまで動かない。** POR / ソフトリセットの直後は suspend mode で、
  8 KB を転送して `INTERNAL_STATUS` が `init_ok` になるまで動作可能状態にならない
  （§4.4, p.25）。設定ファイルは datasheet には載っておらず、Bosch の
  BMI270-Sensor-API（`bmi270.c` 内の `bmi270_config_file`）にバイナリ配列として
  入っている。中身の仕様は非公開である。
- **磁力計を内蔵していない。** 単体では 6 軸であって、方位は出せない。
- 気圧計も持たない。
- **PWR_CTRL の既定値は `0x00`、つまり加速度計もジャイロも温度計も全部 off。**
  初期化を済ませても、ここを書かないとデータは更新されない。
- 姿勢（クォータニオンやオイラー角）は返さない。センサフュージョンはホスト側の仕事。

電気的な条件:

- VDD 1.71〜3.6 V、インタフェース側の VDDIO 1.2〜3.6 V。独立に電源を切ってよいが、
  **VDDIO を切るときはインタフェースピンを GNDIO 付近に保つこと**（§4.3, p.24）。
- SDX / SCX は外部プルアップが必要。
- SDO でアドレスを選ぶ（GND → `0x68`、VDDIO → `0x69`）。
- I²C は standard(100k) / fast(400k) / fast mode plus(1 MHz) に対応。
- POR 後、全レジスタにアクセスできるまで 450 µs。
- ジャイロの起動時間は suspend → normal で typ 45 ms（fast start mode なら 2 ms）。
  加速度計は 2 ms。
- **advanced power save が有効なあいだ（既定は有効）、レジスタ書き込みの間隔を
  450 µs 以上空ける必要がある**（Table 20, p.128 の tIDLE_wacc_sum）。

**`INTERNAL_STATUS`(0x21) の読み方**（§5.2.33, p.85）

| ビット | 意味 |
|---|---|
| 3:0 `message` | `0x00` not_init / **`0x01` init_ok** / `0x02` init_err / `0x03` drv_err / `0x04` sns_stop / `0x05` nvm_error / `0x06` start_up_error / `0x07` compat_error |
| 5 `axes_remap_error` | 軸のリマップが不正（同じ軸に複数割り当てた） |
| 6 `odr_50hz_error` | 50 Hz を要求するフィーチャーに対して帯域が足りない |

**測定値の単位への直し方**

- 加速度 [g] = 生値 ÷（`ACC_RANGE` に対応する LSB/g）。既定の ±8g なら 4096 LSB/g。
- 角速度 [dps] = 生値 ÷（`GYR_RANGE` に対応する LSB/dps）。既定の ±2000dps なら
  16.4 LSB/dps（Table 3 では 16.384、レジスタ説明では 16.4 と丸めている）。
- 温度 [°C] = 23 + 生値 / 512。`0x8000` は無効値。

## 典型的な使い方

datasheet §3 Quick Start Guide（p.17–22）と §4.4（p.25）の手順そのままである。

1. `0x00` を読んで `0x24` が返ることを確認する。
2. `PWR_CONF`(0x7C) に `0x00` を書き、advanced power save を切る。
3. **450 µs 以上待つ。**
4. `INIT_CTRL`(0x59) に `0x00` を書き、設定転送を準備する。
5. **8 KB の設定ファイルを `INIT_DATA`(0x5E) へバースト書き込みする。**
   先頭バイトから順に送る。ホストが 8 KB を一度に送れないなら分割してよいが、
   その場合は各回のあとに `INIT_ADDR_0` / `INIT_ADDR_1` を「書いたバイト数 ÷ 2」だけ
   進める。
6. `INIT_CTRL`(0x59) に `0x01` を書いて転送を確定する。**この書き込みは POR /
   ソフトリセット後に 1 回だけ**行ってよい。
7. 20 ms 以内に `INTERNAL_STATUS`(0x21) の `message` が `0x01`（init_ok）になる。
   ここまでで初期化完了、チップは configuration mode に入る。
8. `PWR_CTRL`(0x7D) で必要なセンサを有効にする（例: 加速度＋ジャイロ＋温度で `0x0E`）。
9. `ACC_CONF`(0x40) / `GYR_CONF`(0x42) で ODR・帯域・フィルタ性能を設定し、
   `ACC_RANGE`(0x41) / `GYR_RANGE`(0x43) でレンジを決める。
10. `PWR_CONF`(0x7C) で power save の扱いを決める（normal 運転なら `0x02`）。
11. `0x0C` から 12 バイトをバースト読み出しすると、加速度 3 軸と角速度 3 軸が
    まとめて取れる。加速度だけなら `0x0C` から 6 バイト。

## 利用上の注意

- **8 KB の設定ファイルを上げないと、このチップは使えない。** POR でも
  ソフトリセット（`CMD` に `0xB6`）でも設定は消えるので、そのたびに上げ直す。
  「たまに動かない」のではなく、初期化していない BMI270 は
  `INTERNAL_STATUS` が `0x00`（not_init）のまま、datasheet が保証する動作をしない。
  設定ファイルは datasheet に載っておらず、
  [BMI270-Sensor-API の `bmi270.c`](https://github.com/BoschSensortec/BMI270-Sensor-API/blob/master/bmi270.c)
  にある `bmi270_config_file` 配列を持ってくる以外に入手方法が無い（§4.4 脚注 4, p.25）。
  **中身の仕様は公開されていない。** 自作ドライバでも、この配列だけは Bosch から
  そのまま持ってくることになる。
- **設定転送には時間がかかる。** datasheet は SPI 10 MHz で約 6.6 ms と書いている
  （§4.4, p.25）。I²C 400 kHz なら 8192 バイト × 9 ビットで、単純計算で 200 ms 前後に
  なる（この見積りは datasheet の記述ではなく本ガイドでの計算）。起動シーケンスの
  タイムアウト設計をするときに効いてくる。
- **`INIT_CTRL` に `0x01` を書くのは 1 回だけ。** datasheet が明示的に
  「must not be performed more than once after POR or soft reset」と書いている
  （§4.4, p.25）。初期化をやり直したければ、先にソフトリセットを打つ。
- **`PWR_CTRL` の既定値は `0x00` で、全センサが無効。** 初期化に成功しても、
  ここを書かなければデータレジスタは `0x00` のまま更新されない。「初期化は通ったのに
  値が動かない」の典型的な原因である。
- **advanced power save が有効なままだと、レジスタ書き込みの間隔を 450 µs 空けなければ
  ならない。** `PWR_CONF.adv_power_save` の既定値は 1 なので、初期化シーケンスの
  最初にこれを落とすのは形式ではなく必須である（Table 20 の tIDLE_wacc_sum, p.128）。
  連続書き込みで詰まると、書いたつもりのレジスタが入っていない。
- **BMP280 / BMM150 とは補償の事情が違う。** BMP280 や BMM150 は補償係数をホストが
  読んで計算しなければならないが、BMI270 の工場トリムは NVM から内部で自動適用され、
  出力はそのまま LSB/g・LSB/dps で読める。**係数を読む必要は無い。**
  ただし個体差そのものが消えるわけではなく、
  - 加速度のゼロ g オフセットは typ ±20 mg（Table 2, p.12）
  - ジャイロの感度誤差は typ ±2 %、CRT 実施後で typ ±0.4 %（Table 3, p.14）

  であって、精度が要るならユーザ側で FOC（オフセット補正、§4.13, p.65–66）や
  CRT（感度再トリム、§4.14.2, p.68）を行い、結果を NVM に焼く必要がある。
  **この作業は個体ごとにやることになる。**
- **`0x0C` から読む。`0x04` からではない。** `DATA_0`–`DATA_7`（`0x04`–`0x0B`）は
  AUX センサ用の領域で、AUX を使っていなければ意味のない値が入る。オフセットを
  6 バイト間違えると、加速度のつもりで磁力計の枠を読むことになる。
- **`FEATURES`(0x30–0x3F) はページ切り替え式である。** `FEAT_PAGE`(0x2F) で 0〜7 の
  ページを選ぶと、同じ 16 バイトの意味がまるごと変わる（§5.2 の FEATURES Pages 表,
  p.74）。歩数計の設定もジャイロのゲイン更新も、このページの向こう側にある。
  ページを戻し忘れたまま別の設定を書くと、無関係なフィーチャーを壊す。
- **温度はジャイロが normal mode のときだけ有効。** 全センサが suspend だと温度計は
  止まる。ジャイロが normal なら 10 ms 周期、standby / fast power up なら 1.28 s 周期で
  更新される（§5.2.34, p.86）。`0x8000` は「無効」を意味する値であって、
  -32768 という測定値ではない。
- **`CMD`(0x7E) は読み戻せない。** 常に `0x00` を返す。
- **不正な `ACC_CONF` / `GYR_CONF` を書くと、エラーが `EVENT` レジスタに出て、
  データレジスタの内容は未定義になる**（§4.16, p.69）。ODR とフィルタ設定の組み合わせは
  レジスタ説明の表で確認する。
- **NVM 操作中はレジスタが応答しない。** NVM の読み書きが進行しているあいだ、
  書き込みは捨てられ、読み出しはアドレスにかかわらず `STATUS` レジスタを返す
  （§4.15, p.69）。ソフトリセット直後の boot 期間も同様にインタフェースが使えない。
- **本リポジトリの probe は設定ファイルを上げていない。**
  `scenarios/bmi270/p0.yaml` は `config-file-upload` `soft-reset`
  `power-mode-configuration` `feature-engine` を `deferred` にしている。したがって
  probe が出力する `axis-bytes` は初期化前のレジスタ内容であって、実際の加速度・
  角速度ではない。`internal-status` を出力に含めているのは、まさにこの「初期化
  していない状態」を記録するためである。
- Unit Mini IMU-Pro（U171）では、BMM150 は BMI270 の AUX I/F 経由ではなく
  Grove バス上に `0x10` で直接載っている（`products/m5stack-u171.yaml`）。
  BMI270 の AUX 機能を使って 9 軸同期を組むかどうかはホスト側の選択になる。

## 出典と確度

- レジスタ、ビット定義、単位、初期化手順、電気的条件、タイミング:
  Bosch Sensortec **BST-BMI270-DS000-08 文書リビジョン 1.6**（2026 年 3 月）。
  本ガイドの記述はすべてこの文書に対応するページを持つ。
- 8 KB 設定ファイルの転送時間の I²C 換算（約 200 ms）は、datasheet の記述ではなく
  本ガイドでの単純計算である。
- **実測で確認していないこと**: 実機のキャプチャがまだ無い。`observations/bmi270/` は
  存在しない。チップ ID が `0x24` を返すか、初期化前のレジスタが表のリセット値を
  返すか、400 kHz / 1 MHz で動くかは、いずれも文書上の記述であってこのリポジトリでは
  測っていない。
- **未調査**: `scenarios/bmi270/p0.yaml` は設定ファイルの転送、ソフトリセット、
  電源モードの設定、feature engine をすべて `deferred` にしている。**このリポジトリは
  まだ一度も BMI270 を「動く状態」にしていない。** 実データ、ODR の精度、FIFO の挙動、
  割り込みは何も測られていない。
- 設定ファイルの中身は Bosch が仕様を公開していない。本ガイドも中身については何も
  述べていない。
- 搭載製品の実装（プルアップ値、SDO の配線、INT ピンの引き出し）は M5Stack の回路図を
  確認していない。**未確認**。
