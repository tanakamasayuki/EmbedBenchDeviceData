# BMM150 — 3 軸地磁気センサ

> 地磁気の 3 軸成分を測るセンサ。**電源投入直後は suspend mode に入っていて、
> `0x4B` に電源制御ビットを書くまで、チップ ID すら読めない。** また出力は生の
> ADC 値で、**個体ごとの trim データによる温度補償を通さないと µT にならない。
> しかもその trim レジスタのアドレスは datasheet に載っていない。**
>
> **確度**: Bosch Sensortec のメーカー datasheet
> BST-BMM150-DS001-05 **Revision 1.4**（2020 年 4 月、全 56 ページ）に基づく。
> レジスタ・ビット定義・単位・タイミングはこの文書由来。ただし補償係数のレジスタ
> アドレスと補償式だけは**この文書に存在せず**、Bosch の BMM150 API のソースにしか
> 無い（本ガイドもアドレスの具体値は書いていない）。**未確認**: 実機のキャプチャは
> まだ無く、`observations/bmm150/` は存在しない。

## これは何か

ホール素子を使った 3 軸の地磁気センサ。X / Y / Z 各軸の磁束密度を測る。
用途は電子コンパス（方位）と、IMU と組み合わせた 9 軸の姿勢推定である。

できること:

- 磁束密度を X / Y 軸で ±1300 µT、Z 軸で ±2500 µT の範囲で測れる。分解能は 0.3 µT。
- 出力データレート（ODR）を 2 / 6 / 8 / 10 / 15 / 20 / 25 / 30 Hz から選べる。
- X/Y 軸と Z 軸それぞれについて、内部での繰り返し測定回数（repetition）を独立に
  指定できる。回数を増やすとノイズが減り、消費電流と測定時間が増える。
- forced mode で 1 回だけ測ることも、normal mode で自動的に回し続けることもできる。
- 割り込みを 4 種類持つ（低しきい値・高しきい値・オーバーフロー・データレディ）。
  INT ピンと DRDY ピンに出せる。
- セルフテスト（通常・アドバンスト）がある。
- I²C と SPI（3 線 / 4 線）に対応。

できないこと・持っていないもの:

- **suspend mode ではほとんど何も答えない。** 電源投入後の既定がこの状態で、
  アクセスできるのは電源制御ビットと SPI3 有効ビットだけ。**チップ ID(`0x40`) を
  読むと I²C では `0x00` が返る**（§4.2.2, p.11）。
- **µT を返さない。** 出力は 13bit / 15bit の生 ADC 値で、温度補償と感度補償は
  ホスト側の仕事。しかもその係数は個体ごとに違う。
- **方位（heading）を返さない。** 方位を出すにはハードアイアン / ソフトアイアンの
  校正と、傾き補正のための加速度センサが要る。datasheet の
  「heading accuracy ±2.5 deg」は**完全に校正済みで理想的な傾き補正がされている
  前提の値**である（§1.1 脚注 2, p.6）。
- FIFO が無い。
- アドレスは 4 択のみ（`0x10`–`0x13`）。

電気的な条件:

- VDD 1.62〜3.6 V（typ 2.4 V）、インタフェース側の VDDIO 1.2〜3.6 V。
- SDA / SCL は VDDIO へ外部プルアップが必要。
- **VDDIO が切れているときにインタフェースを High にしてはいけない。恒久的に壊れる**
  （§4.1, p.11 が「absolutely prohibited」と書いている）。
- I²C を使うなら PS ピンを VDDIO に直結することが推奨されている（§4.1, p.11）。
- アドレスは CSB と SDO の 2 本で選ぶ（Table 30, p.36）。
- 消費電流は active mode 10 Hz で、低電力プリセット 170 µA、レギュラー 0.5 mA、
  エンハンスト 0.8 mA。

## レジスタ

`profiles/bmm150.yaml` の内容に、datasheet 由来のビット定義と単位を足したもの。
レジスタは `0x40`〜`0x71` の 50 番地に割り当てられており、**`0x40`〜`0x4A` は read-only**
（書いても無視される）。

| アドレス | 長さ | R/W | 意味 |
|---|---|---|---|
| `0x40` | 1 | R | チップ ID = `0x32`。電源制御ビットが 1 のときのみ読める |
| `0x42`–`0x49` | 8 | R | 磁界データ + RHALL。下記参照 |
| `0x4A` | 1 | R | 割り込みステータス。`Low Int X/Y/Z`(2:0), `High Int X/Y/Z`(5:3), `Overflow`(6), `Data overrun`(7) |
| `0x4B` | 1 | R/W | 既定 `0x00`。`Power Control`(0), `Soft Reset`(1), `SPI3en`(2), `Soft Reset`(7)。**suspend でもアクセスできる唯一のレジスタ** |
| `0x4C` | 1 | R/W | 既定 `0x06`。`Self Test`(0), `Opmode`(2:1), `Data rate`(5:3), `Adv. ST`(7:6) |
| `0x4D` | 1 | R/W | 既定 `0x3F`。軸ごとの割り込み有効ビット、`Overflow Int En`(6), `Data Overrun En`(7) |
| `0x4E` | 1 | R/W | 既定 `0x07`。`Interrupt Polarity`(0), `Interrupt Latch`(1), `DR Polarity`(2), `Channel X/Y/Z`(5:3), `Interrupt Pin En`(6), `Data Ready Pin En`(7) |
| `0x4F` | 1 | R/W | Low Threshold |
| `0x50` | 1 | R/W | High Threshold |
| `0x51` | 1 | R/W | `REPXY`。X/Y の繰り返し回数。**nXY = 1 + 2 × REPXY** |
| `0x52` | 1 | R/W | `REPZ`。Z の繰り返し回数。**nZ = 1 + REPZ** |
| `0x53`–`0x71` | — | — | datasheet 上は reserved。**このなかに trim レジスタがある**（§5.6, p.26） |

**データレジスタのビット配置**（§4.3.1, p.14 / §5.4, p.23–25）

ここが単純な「LSB / MSB の 2 バイト」になっていない点が要注意である。

| アドレス | bit7 … bit0 |
|---|---|
| `0x42` | `DATAX[4:0]`（bit7-3）／固定 0（bit2-1）／`SelfTestX`（bit0） |
| `0x43` | `DATAX[12:5]` |
| `0x44` | `DATAY[4:0]`（bit7-3）／固定 0（bit2-1）／`SelfTestY`（bit0） |
| `0x45` | `DATAY[12:5]` |
| `0x46` | `DATAZ[6:0]`（bit7-1）／`SelfTestZ`（bit0） |
| `0x47` | `DATAZ[14:7]` |
| `0x48` | `RHALL[5:0]`（bit7-2）／固定 0（bit1）／**`Data Ready Status`（bit0）** |
| `0x49` | `RHALL[13:6]` |

X / Y は 13bit の 2 の補数、Z は 15bit の 2 の補数、RHALL は 14bit の符号なし。
**RHALL は「ホール素子板の抵抗値」であって、温度補償の入力そのものである。
捨ててはいけない。**

**`0x4C` の設定値**

- `Opmode[1:0]`（bit2-1）: `00` normal / `01` forced / `10` 予約（使用禁止）/ `11` sleep。
- `Data rate[2:0]`（bit5-3）: `000` = 10 Hz（既定）、`001` = 2、`010` = 6、`011` = 8、
  `100` = 15、`101` = 20、`110` = 25、`111` = 30 Hz。
- `Adv. ST[1:0]`（bit7-6）: アドバンストセルフテスト用の内部磁界生成。

**`0x4B` の設定値**

- `Power Control`(bit0): `1` で suspend → sleep、`0` で suspend へ戻る。
- ソフトリセットは **bit7 と bit1 の両方に 1 を書く**。全レジスタがリセットされるが、
  `0x54` より上の trim レジスタと `0x4B` 自身は残る。実行後は必ず sleep mode になる。
  **suspend 中はソフトリセットが無視される。**

## 典型的な使い方

1. `0x4B` に `0x01` を書いて **suspend から sleep へ上げる**。これをやるまで先に進めない。
2. `0x40` を読んで `0x32` が返ることを確認する。ここで初めてチップ ID が読める。
3. **trim（補償係数）を読み出す。** Bosch の BMM150 API はこれを初期化時に行う
   （§4.5, p.17）。アドレスと式は datasheet に無いので、API のソースを見る以外に方法が
   無い。
4. `0x51` / `0x52` に繰り返し回数を書く（ノイズと消費電流のトレードオフ）。
5. `0x4C` に ODR と opmode を書く。連続測定なら `Opmode = 00`（normal）、
   ホスト側で 1 回ずつ叩くなら `Opmode = 01`（forced）。
6. 測定完了を待つ。`0x48` の bit0（Data Ready）を見るか、DRDY ピンを使う。
7. **`0x42` から 8 バイト（ステータスも要るなら `0x4A` まで）を 1 回のバースト読み出しで
   取る。**
8. 各軸のビットを組み立て、RHALL と trim を使って温度・感度補償を掛け、µT に直す。
9. 使い終わったら `0x4B` の bit0 を `0` に戻して suspend に落とすと消費電流が下がる。

## 利用上の注意

- **電源投入直後は suspend mode。ほぼ何も答えない。** これが BMM150 で最初に必ず
  引っかかる点である。suspend でアクセスできるのは `0x4B`（電源制御と SPI3 有効）だけ。
  **チップ ID を読むと I²C では `0x00` が返る**（§4.2.2, p.11 / §5.3, p.23）。
  I²C アドレスへの ACK は返るのに ID が `0x00` なので、「デバイスは居るのに壊れている」
  と誤診しやすい。実際には `0x4B` に `0x01` を書くだけで正常になる。
  本リポジトリの probe（`scenarios/bmm150/p0.yaml`）が safety を `reversible-write` に
  して `suspend-state-read` → `power-control-write` → `identity-read` → `restore-suspend`
  という順序を組んでいるのは、まさにこの挙動を記録するためである。
- **温度補償を掛けないと出力は µT にならない。しかも係数は個体ごとである。**
  trim データは Bosch の製造ラインで NVM に書き込まれ、変更できない（§4.5, p.17）。
  API はこれを初期化時に読み出して補償に使う。**補償前の生値は、隣の個体と直接
  比較することすらできない。**
- **その trim レジスタのアドレスは datasheet に書かれていない。** レジスタマップ
  （§5.2, p.22）では `0x53`〜`0x71` が単に reserved / N/A になっており、
  §5.6（p.26）がソフトリセットの説明のなかで「`0x54` より上の trim レジスタ」と
  一度だけ触れるだけである。**具体的なアドレス、ビット幅、符号、補償式は
  Bosch の BMM150 API のソースにしか存在しない。** datasheet だけを読んで
  自前ドライバを書き切ることはできない、という珍しいチップである。
  `scenarios/bmm150/p0.yaml` が `trim-register-read` を `deferred` にしているのも、
  読むべきアドレスが一次資料から確定できないためである。
- **RHALL を読み飛ばさない。** `0x48`/`0x49` の 14bit 符号なし値は温度補償の入力である。
  「磁界 3 軸だけ欲しい」と 6 バイトで止めると、補償が計算できない。
  読むなら `0x42` から 8 バイトである。
- **LSB レジスタの下位ビットはデータではない。** `0x42`/`0x44` の bit0 はセルフテスト
  結果、`0x48` の bit0 はデータレディフラグである。マスクせずにシフトすると、
  磁界値に 1 LSB のゴミが乗り、しかもセルフテストの状態によって値が変わる。
- **X/Y は 13bit、Z は 15bit で幅が違う。** 3 軸を同じルーチンで処理すると Z が壊れる。
  符号拡張のビット位置も軸ごとに違う。
- **バースト読み出しを使う。** データレジスタは 1 パッケージ単位で同時更新され、
  読み出し中の更新はシャドウレジスタに退避される。ただしこの保護が効くのは
  「1 回の読み出しシーケンスの中」だけで、I²C では STOP コンディションで区切られる
  （§4.3.1, p.14）。個別に読むと軸が混ざる。
- **`0x40`〜`0x4A` は read-only。** 書いても黙って無視される。
- **ソフトリセットは suspend では効かない。** sleep か active に上げてから打つ。
  また、ソフトリセットは POR とは違い trim と `0x4B` を残す。完全な POR 相当に
  したければ、いったん suspend に落としてから sleep に戻す（§5.6, p.26）。
- **forced mode で繰り返し回数より速くトリガすると、データが書かれない。**
  測定サイクルが完了しなかった場合、結果はデータレジスタに反映されない。
  最短周期は概ね `1 / (145 × nXY + 500 × nZ + 980) [µs]` である（§4.2.4, p.13）。
- **INT / DRDY ピンは既定で high-Z。** `0x4E` の bit6 / bit7 を立てるまで、
  割り込みは配線されていても出てこない。
- **磁気センサなので、基板上の電流や磁性体の影響を受ける。** 近くを流れる電流が
  変わるだけで読み値が動く。校正は「その基板に載った状態」で行う必要がある。
- BMI270 は AUX I²C マスタに BMM150 を繋ぐ構成を想定している（BMI270 datasheet
  §4.10 / §7.3）。ただし Unit Mini IMU-Pro（U171）では BMM150 は Grove バス上に
  `0x10` で直接載っており、ホストから直に見える（`products/m5stack-u171.yaml`）。
