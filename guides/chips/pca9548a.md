# PCA9548A — 8 チャンネル I2C バスマルチプレクサ

> 上流の SDA/SCL を 8 組の下流バスに分配するスイッチ。制御バイト 1 本で、どのチャンネルを
> 繋ぐかを決める。同じアドレスのデバイスを何台も同じホストにぶら下げるための部品。
>
> **名前の似た PCA9554 とは別物**である。PCA9554 は IO エキスパンダ（汎用の入出力を 8 本
> 増やす）で、こちらはバスそのものを切り替えるスイッチ。型番だけで選ぶと確実に間違える。
>
> **確度**: NXP の datasheet Rev. 5.1（2015-10-01）に基づく。`profiles/pca9548a.yaml` の
> evidence は `datasheet` / `tentative` で、**実機のキャプチャはまだ無い**。制御バイトの
> 読み戻し、複数チャンネル同時イネーブル、RESET ピンの挙動、400kHz での動作はいずれも未実測。

## これは何か

I2C のバススイッチ（マルチプレクサ）。上流 1 組の SCL/SDA が、下流の SC0/SD0 〜 SC7/SD7 の
8 組に分岐する。どの組を繋ぐかは、デバイス内部にある**たった 1 バイトの制御レジスタ**で決まる。
ビット 0 がチャンネル 0、ビット 7 がチャンネル 7 に対応し、立っているビットのチャンネルが
上流に導通する。

**チャンネルを有効にするとは、下流のバスが上流のバスに物理的に繋がるということ**である。
繋がっている間、そのチャンネルにいるデバイスは上流から見て普通の I2C デバイスに見える。
デバイス自身のアドレスがそのまま使われ、mux はアドレスを書き換えたりしない。

**複数のチャンネルを同時に有効にできる。** 制御バイトに複数のビットを立てれば、それらが
まとめて上流に繋がる。同じ内容を複数の下流に一斉に書き込むときには使えるが、読み出すと
複数のデバイスが同時に応答して値が壊れる。

### 何のためにあるか

I2C はアドレスが 7 bit しかなく、多くのセンサは変更できる範囲が 2〜8 通りしかない。
**同じ型番のセンサを 3 個以上並べたい、という時点で行き詰まる。** mux はこの問題だけを
解くための部品で、「同じ 0x44 の SHT30 を 8 個」のような構成を、チャンネルを切り替えながら
1 個ずつ相手にすることで成立させる。

### できないこと・持っていないもの

- **レジスタマップが無い。** 制御バイト 1 本だけで、レジスタポインタもオートインクリメントも
  無い。書けば制御レジスタに入り、読めば制御レジスタが返る。それ以外の機能は無い。
- **バッファ・リピータではない。** 中身は双方向のパスゲート（アナログスイッチ）で、
  導通中の Ron は typ 11Ω / max 30Ω（VDD 3.0〜3.6V）。**下流の配線容量とプルアップは
  上流から見えたまま**になり、有効にしたチャンネルの分だけ上流のバス容量が積み上がる。
  波形を整え直したり、クロックストレッチを吸収したりはしない。
- **下流のバスが Low に張り付いたら、上流も張り付く。** ソフトウェアからは復旧できない。
  RESET ピンを Low にするか、電源を切り直すしかない。
- **自分と下流のアドレス衝突は解決できない。** mux 自身も 0x70〜0x77 のどれかを占める
  デバイスなので、有効にしたチャンネルの先に同じアドレスのデバイスがいると、両方が ACK を返す。
- **割り込みの集約機能は無い。** 同じ PCA954x ファミリでも PCA9545 などは下流の INT を
  まとめる端子を持つが、PCA9548A には無い。
- **電源投入直後は全チャンネル切断**（制御レジスタ 0x00）。使う前に必ず 1 バイト書く必要がある。

### 電気的な現実

- 電源 2.3〜5.5V。全 I/O は 6V トレラント。
- **レベル変換はパスゲートのクランプで行う。** 能動的な変換回路ではなく、VDD が「通せる
  最大電圧」を決める。上流 5V・下流 3.3V のような構成では、mux の VDD を低い側に合わせ、
  各チャンネルにそれぞれのプルアップを付ける。
- 各バスラインの容量上限は 400pF。チャンネルを複数開けるとここに近づく。
- POR は VDD が VPOR（typ 1.6〜1.7V）に達した時点で解除される。**一度立ち上がったら、
  VDD を 0.2V 未満まで落とさない限りリセットはかからない。** 電源のダラ下がりやホットスワップ
  では制御レジスタが残る。

### TCA9548A との関係

本カタログには [`chips/tca9548a.yaml`](../../chips/tca9548a.yaml) として TI の TCA9548A も
入っている。**セカンドソース相当で、ソフトウェアから見た挙動は同一**である。アドレス
（0x70〜0x77）、制御バイトのビット割り当て、RESET の意味、24 ピンのピン配置まで同じで、
ドライバはそのまま通る。違うのは電気仕様。

| | PCA9548A（NXP Rev. 5.1） | TCA9548A（TI Rev. H） |
|---|---|---|
| 電源電圧 | 2.3〜5.5V | **1.65〜5.5V** |
| I/O 耐圧 | **6V** | 5V |
| Ron（VDD 3.0〜3.6V） | 5 / 11 / 30 Ω | 5 / 12 / 30 Ω |
| POR 電圧 | VPOR max 2.1V の 1 点規定 | 立ち上がり VPORR / 立ち下がり VPORF を別々に規定 |
| パッケージ | SO24 / TSSOP24 / HVQFN24 | TSSOP24 / VQFN24 / VSSOP24 |
| 本カタログでの搭載 | Unit PaHub v2.0 / v2.1 | Unit PaHub（初代 U040） |

つまり **M5Stack の PaHub は初代と v2.0 で中身の IC が入れ替わっている**が、I2C 上の見え方は
変わらない。

## レジスタ / コマンド

レジスタは 1 本だけで、アドレス指定という概念が無い。

| | 長さ | R/W | 意味 |
|---|---|---|---|
| 制御バイト | 1 | R/W | ビット n が 1 でチャンネル n が導通。書けば設定、読めば現在の状態 |

| ビット | 意味 |
|---|---|
| B0 | チャンネル 0（SC0/SD0）。1 = 有効 |
| B1 | チャンネル 1 |
| B2 | チャンネル 2 |
| B3 | チャンネル 3 |
| B4 | チャンネル 4 |
| B5 | チャンネル 5 |
| B6 | チャンネル 6 |
| B7 | チャンネル 7 |

**転送の形**:

- 書き込み: `S` → スレーブアドレス + W → 制御バイト 1 バイト → `P`。複数バイト送った場合は
  **最後の 1 バイトだけが残る**。
- 読み出し: `S` → スレーブアドレス + R → 制御バイト 1 バイト → マスタが NACK → `P`。
  レジスタポインタを書く手順は不要。

**チャンネルが実際に導通するのは STOP 条件の後**である。datasheet はこれを、切り替えの瞬間に
全ての SCx/SDx が High であることを保証して偽のパルスを出さないため、と説明している。

## 典型的な使い方

1. 制御バイトを 1 バイト読む。電源投入直後なら `0x00` が返る。デバイスの存在確認も兼ねる。
2. 目的の下流デバイスがいるチャンネルのビットを立てて 1 バイト書き、**STOP を出す**。
3. STOP の後、下流デバイスに対して普通に I2C トランザクションを行う。アドレスは下流デバイス
   自身のもの。mux は透過している。
4. 別のチャンネルに移るときは、次の制御バイトを書く。いったん `0x00` を経由する必要は無いが、
   衝突を避けたいなら経由した方が安全。
5. 使い終わったら `0x00` を書いて全チャンネルを切る。上流から下流の容量が外れる。

## 利用上の注意

- **PCA9554 と混同しない。** PCA9554 は IO エキスパンダで、こちらはバススイッチ。
  アドレス帯（0x20 台 / 0x70 台）も役割も違う。
- **mux 自身のアドレスと下流のアドレスがぶつかる。** 本カタログでは `0x70` を
  `pca9548a` / `tca9548a` / **`qmp6988`**（Unit ENV-III の気圧センサ）の 3 件が使う。
  ENV-III を PaHub の**下流**に付けるのは正しいが、チャンネルを開けたまま `0x70` を叩くと
  mux と QMP6988 の両方が ACK を返し、SDA を同時に引く。さらに `0x76` / `0x77` は
  `bmp280` / `bme688` と、`0x73` は `paj7620u2` と重なる。**mux は 0x70〜0x77 の外に
  逃げられない**ので、衝突したら下流デバイス側のアドレスを動かすか、A2/A1/A0 で mux を
  空いている番地へずらす。
- **チャンネルは STOP の後で切り替わる。** 制御バイトを書いたトランザクションの中で
  repeated START を打って下流に行こうとしても、まだ繋がっていない。**必ず STOP を出す。**
  多くの I2C ライブラリでは `endTransmission()` を `true`（既定）で呼ぶことに相当する。
- **複数チャンネルを同時に開けたときの読み出しは壊れる。** 書き込みのブロードキャストには
  使えるが、読み出しは 1 チャンネルずつ。また開けた分だけ上流のバス容量が加算され、
  400pF を超えると立ち上がりが鈍って通信が成立しなくなる。
- **バッファではないので、下流の問題はそのまま上流に出る。** 下流のデバイスがクロックを
  ストレッチすれば上流も止まるし、下流の SDA が Low に張り付けば上流も張り付く。
  「mux を挟んだから独立している」という理解は誤り。切れているチャンネルだけが独立している。
- **張り付いたら RESET ピンしかない。** これが PCA9548A に RESET がある理由そのもの。
  ただし **Grove（HY2.0-4P）は 5V / GND / SDA / SCL の 4 極**なので、M5Stack の PaHub では
  RESET 線が外に出ていない。ユニットとして使う限り、復旧手段は電源の抜き差しになる。
- **電源を軽く落としただけではリセットされない。** VDD を 0.2V 未満まで下げないと POR が
  かからず、制御レジスタが前の値のまま残る。「電源を入れ直したのに前のチャンネルが
  開いている」はこれで起きる。
- **アドレスピンを開放にしない。** A0〜A2 に内部プルアップは無い。浮かせるとアドレスが不定になる。
- **レベル変換に使うなら VDD の選び方が全て。** VDD がパスゲートの通す最大電圧（Vo(sw)）を
  決める。最も低いバス電圧以下になるよう VDD を選び、各チャンネルにそれぞれの電圧の
  プルアップを付ける。datasheet 6.5 と Fig 7 に電圧の対応がある。
- **400kHz は datasheet の値であって、実効値ではない。** mux 自体は周波数に対して透過なので、
  実際の上限は「上流 + 開いているチャンネルの配線容量」で決まる。本カタログでは未実測。

## 出典と確度

- 制御バイトの定義、アドレス、電気特性、タイミング: NXP **PCA9548A Product data sheet
  Rev. 5.1（2015-10-01）**。
- TCA9548A との比較: TI **TCA9548A データシート Rev. H（2024-09）** の Features / 5.3
  Recommended Operating Conditions / 5.5 Electrical Characteristics。
- `profiles/pca9548a.yaml` は datasheet から起こしたもので、`confidence: tentative`。
- **未確認**: 実機のキャプチャがまだ無い。制御バイトの書き戻しが一致するか、複数チャンネルを
  同時に開けたときの挙動、下流アドレッシング、RESET ピンの効き方、400kHz で動くかは
  いずれも実測していない（`scenarios/pca9548a/p0.yaml` の `deferred` がそのまま残っている）。
- **未確認**: M5Stack Unit PaHub v2.0 / v2.1 の基板上で A2/A1/A0 が実際にどう結線されているか。
  製品としてのアドレスが `0x70` であることは製品情報による。
- **未調査**: Grove コネクタに RESET が出ていないことは、HY2.0-4P が 4 極であることからの
  推定であって、基板を確認した結果ではない。
