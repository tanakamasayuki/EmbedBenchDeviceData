# MPU6886 — 6 軸 IMU（3 軸ジャイロ + 3 軸加速度）

> 3 軸ジャイロと 3 軸加速度計を 1 パッケージに入れた MotionTracking デバイス。
> 同じ `0x68` に居て配線互換の MPU-6050 とは **WHO_AM_I が `0x19` か `0x68` か**で見分ける。
> リセット直後は**スリープしている**（PWR_MGMT_1 のリセット値は `0x41`）。
>
> **確度**: InvenSense の datasheet（DS-000193, rev 1.1, 2017-03-29, 59 ページ）に基づく。
> TDK InvenSense はこの部品のページを既に落としており、M5Stack がホストしているコピーが
> 現時点で最良の一次資料である。**実測では未確認**。

## これは何か

MEMS のジャイロ（角速度）と加速度計を 16bit の ADC で読み、デジタルフィルタと 1kB の FIFO を
挟んでホストに渡すセンサ。姿勢推定・振動計測・歩数計・落下検出などの土台になる。

3mm × 3mm × 0.75mm の 24 ピン LGA で、耐衝撃は 20,000g。工場で感度が校正済みなので、
量産時の個別校正は（少なくとも感度については）不要とされている。

できること:

- ジャイロを ±250 / ±500 / ±1000 / ±2000 dps のいずれかのレンジで読む（131 / 65.5 / 32.8 / 16.4 LSB/dps）。
- 加速度を ±2 / ±4 / ±8 / ±16 g のいずれかで読む（16384 / 8192 / 4096 / 2048 LSB/g）。
- ダイ温度を読む（326.8 LSB/°C、25°C オフセット）。
- 1kB の FIFO に貯めて、ホストがまとめて吸い出す（バスのトラフィックとホストの起床回数を減らす）。
- Wake-on-Motion 割り込み（加速度がしきい値を超えたら INT を上げる）。
- 軸ごとにスタンバイさせる、加速度計だけ低消費電力でデューティ動作させる、など 8 種類の電力モード。
- 自己診断（self-test）。

できないこと・持っていないもの:

- **磁気センサ（コンパス）が無い。** 6 軸であって 9 軸ではない。方位は出ない。
- **姿勢を出さない。** DMP（Digital Motion Processor）に相当する姿勢演算機能は
  この datasheet には記載が無い。クォータニオンやオイラー角が欲しければホストで積分・
  フュージョンする。
- **気圧・高度は測らない。**
- **5V トレラントではない。** VDD / VDDIO とも 1.71〜3.45V。
- **I2C は 400kHz まで。** それ以上は SPI（10MHz）に行くしかない。
- **リセット直後は測定していない。** スリープ状態で起動する（後述）。

電気的な現実:

- VDD 1.71〜3.45V、VDDIO 1.71〜3.45V（別電源にできる）。
- 消費電流: 6 軸ローノイズで 2.79mA typ、加速度計のみで 321µA、スリープで 6µA。
- **I2C の最大バス速度は 400kHz。** SDA / SCL は open-drain でプルアップは外付け。
- アドレスは `b110100X`。**LSB は AD0 / SA0 ピンの論理レベル**で決まり、Low で `0x68`、
  High で `0x69`。同一バスに 2 個まで。
- 割り込みは INT / DRDY ピン。極性、push-pull / open-drain、パルス幅（50µs）または
  ラッチ、クリア方法をレジスタで選べる。
- **ジャイロの立ち上がりに 35ms typ / 100ms max かかる**（enable してからドライブが安定するまで）。
- ジャイロを止めるとマスタークロックが内部発振器へ切り替わり、その遷移に約 20µs かかる。

M5Stack Unit Mini IMU (U095) はこれを `0x68` で使う。

## レジスタ

主要なものだけ。全体は datasheet の Table 15（p29-31）。

| アドレス | 名前 | 長さ | 意味 |
|---|---|---|---|
| `0x0D`〜`0x0F` | SELF_TEST_*_ACCEL | 各 1 | 加速度計の自己診断値（工場でプログラム済み。`0x00` ではない） |
| `0x19` | SMPLRT_DIV | 1 | サンプルレート分周 |
| `0x1A` | CONFIG | 1 | DLPF 設定と FIFO_MODE。**リセット値 `0x80`** |
| `0x1B` | GYRO_CONFIG | 1 | ジャイロのフルスケール（bit4:3） |
| `0x1C` | ACCEL_CONFIG | 1 | 加速度計のフルスケール（bit4:3） |
| `0x1D` | ACCEL_CONFIG2 | 1 | 加速度計の DLPF / 平均回数 |
| `0x37` | INT_PIN_CFG | 1 | INT ピンの極性・駆動形式・**bit4 INT_RD_CLEAR** |
| `0x38` | INT_ENABLE | 1 | 割り込み許可（WoM、FIFO オーバーフロー、DATA_RDY） |
| `0x39` | FIFO_WM_INT_STATUS | 1 | FIFO ウォーターマーク割り込み。**read-to-clear** |
| `0x3A` | INT_STATUS | 1 | 割り込みステータス。**read-to-clear** |
| `0x3B` | ACCEL_XOUT_H | 6 | 加速度 X / Y / Z（各 16bit、H が先、2 の補数） |
| `0x41` | TEMP_OUT_H | 2 | 温度（16bit、H が先） |
| `0x43` | GYRO_XOUT_H | 6 | ジャイロ X / Y / Z（各 16bit、H が先、2 の補数） |
| `0x68` | SIGNAL_PATH_RESET | 1 | 信号経路のリセット |
| `0x6A` | USER_CTRL | 1 | FIFO 有効化など |
| `0x6B` | PWR_MGMT_1 | 1 | **リセット値 `0x41`**。bit7 DEVICE_RESET、bit6 SLEEP、bit5 CYCLE、bit3 TEMP_DIS、bit2:0 CLKSEL |
| `0x6C` | PWR_MGMT_2 | 1 | 軸ごとのスタンバイ（STBY_XA〜STBY_ZG） |
| `0x70` | I2C_IF | 1 | bit6 I2C_IF_DIS。**1 を書くと I2C が死んで SPI 専用になる** |
| `0x72`,`0x73` | FIFO_COUNTH/L | 各 1 | FIFO のバイト数 |
| `0x74` | FIFO_R_W | 1 | FIFO の読み書き。空のとき `0xFF` が返る |
| `0x75` | WHO_AM_I | 1 | **`0x19`** |

**`0x3B`〜`0x48` の 14 バイトは連続**しており、加速度 6 + 温度 2 + ジャイロ 6 を
1 回のバースト読み出しで取れる。これが最も普通の使い方である。

**転送の形**: 書き込みは「スレーブアドレス + レジスタアドレス + データ…」。
複数バイト続けるとレジスタアドレスは自動でインクリメントする。読み出しは
「スレーブアドレス + W + レジスタアドレス」→ repeated START →「スレーブアドレス + R」→
データ n バイト（アドレスは自動インクリメント）。MFRC522 のような「同じレジスタが
繰り返される」タイプではない。

## 典型的な使い方

1. **WHO_AM_I (`0x75`) を読む。** `0x19` なら MPU-6886。`0x68` が返ったらそれは MPU-6050 で、
   レジスタマップは似ているが別物である。
2. PWR_MGMT_1 (`0x6B`) の bit7 に 1 を書いてデバイスリセット。このビットは完了すると
   自動で 0 に戻るので、0 になるまで待つ。リセット後は再びスリープ状態になる。
3. **PWR_MGMT_1 に `0x01` を書く**（SLEEP を落とし、CLKSEL = 001 の自動選択にする）。
   `0x00` を書くと SLEEP は落ちるが CLKSEL が 000（内蔵 20MHz）になり、
   datasheet が「フル性能には 001 が必須」としている条件を満たさない。
4. ジャイロが立ち上がるまで待つ（35ms typ / 100ms max）。
5. GYRO_CONFIG (`0x1B`) / ACCEL_CONFIG (`0x1C`) でフルスケールを、CONFIG (`0x1A`) と
   ACCEL_CONFIG2 (`0x1D`) で DLPF を、SMPLRT_DIV (`0x19`) でサンプルレートを設定する。
6. `0x3B` から 14 バイトをバーストで読む。各軸は 2 バイトを `(H << 8) | L` として符号付き
   16bit に組み、フルスケールに対応する LSB 感度で割る。
7. 割り込みで駆動するなら INT_ENABLE (`0x38`) の DATA_RDY_INT_EN を立て、INT ピンの立ち上がりで
   INT_STATUS (`0x3A`) を読む。読んだ時点でフラグはクリアされる。

## 利用上の注意

- **リセット直後はスリープしている。** datasheet の Table 15 の直後の注記（p31）に
  「リセット値は下記以外すべて `0x00`」とあり、その例外として **Register 107 (PWR_MGMT_1) = `0x41`** が
  挙がっている。`0x41` は bit6 SLEEP = 1、CLKSEL = 001 である。**つまり起動時は寝ており、
  SLEEP を落とさない限りデータは更新されない。** ドライバによってここの扱いが割れているが、
  datasheet の記述はこの 1 か所であり、明確に「寝ている」である。
  `0x3B` を読んで常に同じ値（あるいは 0）が返るなら、まずここを疑う。
- **datasheet の 9.9 SLEEP MODE には誤記がある。** 「SLEEP bit in PWR_MGMT_2」と書かれているが、
  SLEEP ビットがあるのは PWR_MGMT_1 (`0x6B`) である。PWR_MGMT_2 (`0x6C`) は軸ごとの
  スタンバイ制御しか持たない。
- **8.30 の温度レジスタの説明も H / L が入れ替わっている。** TEMP_OUT_H (`0x41`) が
  「Low byte」、TEMP_OUT_L (`0x42`) が「High byte」と書かれているが、他のセンサデータ
  レジスタと同じく H が上位である。
- **スリープ中に未定義レジスタを読んではいけない。** 9.7 UNLISTED REGISTER LOCATIONS に
  「スリープ中に未掲載のレジスタを読むとデバイスがハングし、電源を入れ直すまで復旧しない」と
  ある。**レジスタ空間を `0x00`〜`0xFF` まで舐めるダンプは、このデバイスでは危険**である。
  本カタログの probe が identity と既知のレジスタしか読まない理由でもある。
- **WHO_AM_I は MPU-6050 との唯一の見分け方である。** アドレス（`0x68`/`0x69`）も、
  加速度・温度・ジャイロが `0x3B`〜`0x48` に並ぶことも、PWR_MGMT_1 が `0x6B` にあることも
  同じなので、**MPU-6050 用のコードは MPU-6886 でも「それらしく動いてしまう」**。
  違いは感度スケール（MPU-6050 の温度式は 340 LSB/°C + 36.53 オフセット）、
  レジスタの細部、そして WHO_AM_I の値。`0x19` の確認を省くと、温度が数十度ずれた
  まま出荷される種類のバグになる。
- **`0x70` (I2C_IF) の bit6 に 1 を書くと I2C が使えなくなる。** SPI 専用モードに入り、
  以降 I2C では応答しない。復旧はハードリセットか電源再投入。誤って書くレジスタとしては
  最悪の部類なので、`0x70` 近辺への書き込みには注意する。
- **INT_STATUS (`0x3A`) と FIFO_WM_INT_STATUS (`0x39`) は read-to-clear。** 読んだ瞬間に消える。
  2 か所から読むと片方が取りこぼす。さらに INT_PIN_CFG (`0x37`) の bit4 INT_RD_CLEAR を 1 に
  すると**どのレジスタを読んでもクリアされる**ようになり、`0x3B` を読んだだけで
  DATA_RDY フラグが消える。既定（0）は INT_STATUS を読んだときだけクリア。
- **FIFO_COUNT はラッチ方式。** FIFO_COUNTH (`0x72`) を読んだ時点で H / L 両方がラッチされる。
  逆に、新しい値を取り込むには FIFO_COUNTL (`0x73`) を読む必要がある、と datasheet は
  書いている。2 バイトを別々のトランザクションで読むと値が食い違う。
- **FIFO が空のときは `0xFF` が返る。** これは意図された「空」の印で、正常なセンサデータが
  `0xFF` になることはないとされている。
- **ジャイロは有効化してすぐ使えない。** 35ms typ / 100ms max。電源投入から数 ms で読み始めて
  「ジャイロの値がおかしい」と言うのは、ほぼこれ。
- **低消費電力モードから低ノイズモードへ切り替えた直後の数サンプルは整定していない**（9.3）。
  ジャイロで GYRO_CYCLE を先に立ててから電源を入れると、最初の 1 サンプルは
  低ノイズモードの未整定値になるので捨てるべき、とも書かれている（9.5）。
- **ゼロ点は個体ごとにずれている。** ジャイロの初期 ZRO 誤差は ±10 dps、加速度計の
  ゼロ g 出力は基板実装後で ±100 mg。**感度は工場校正済みだがオフセットは違う。**
  静止状態でのオフセット取得はアプリケーション側の責任である。温度でも動く
  （ジャイロで ±0.05 dps/°C）。
- **`0x68` / `0x69` は混み合っているアドレスである。** 本カタログだけでも
  [BMI270](../../chips/bmi270.yaml) が同じ `0x68` / `0x69` を使う。ほかにも DS3231 / DS1307 などの
  RTC が `0x68` を使うのが定番で、バススキャンで `0x68` が見えても中身が何かは分からない。
  **WHO_AM_I を読むまで種類を決めつけない。**
- **5V を掛けない。** VDD / VDDIO とも最大 3.45V。5V の Grove バスに直結する構成では
  ユニット側にレギュレータとレベル変換があることを前提にしている。
- **400kHz は仕様上の上限そのもの。** それ以上に上げる余地は無い。本カタログでは
  100kHz / 400kHz とも未実測。

## 出典と確度

- レジスタアドレス、リセット値、ビット定義、感度、電源条件、I2C の手順:
  すべて InvenSense DS-000193 rev 1.1 由来。
- **この datasheet はメーカーが公開していない。** TDK InvenSense は MPU-6886 の製品ページと
  datasheet を既に取り下げており、`invensense.tdk.com` の URL はすべて 404 になる。
  参照している PDF は M5Stack がホストしているコピーで、表紙に
  "InvenSense Confidential - Advanced Information for GHIC Only" と入っている。
  内容の正しさは他の出所と突き合わせて確認していない。
- **未確認**: 実機のキャプチャが無い。`0x68` で応答するか、WHO_AM_I が本当に `0x19` を返すか、
  PWR_MGMT_1 が実測でも `0x41` で立ち上がるかは確かめられていない。
  **本ガイドが「リセット直後はスリープ」と書いているのは datasheet の記述に基づく推論**であり、
  実測で裏を取っていない。
- **未調査**: probe は read-only なので、スリープ解除・レンジ切り替え・DLPF 切り替え・
  FIFO・割り込み設定はすべて deferred。400kHz での動作も未実測。
- MPU-6050 / MPU-9250 の WHO_AM_I 値（`0x68` / `0x71`）は比較のために挙げたもので、
  本カタログの一次資料には含まれていない。
