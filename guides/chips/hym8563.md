# HYM8563 — I2C リアルタイムクロック / カレンダ

> 32.768kHz 水晶で秒〜年を刻む RTC。値はすべて **BCD**、アドレスは `0x51` 固定。
> レジスタ構成は NXP PCF8563 と互換。**読むのは無害だが、書くとユーザーの時計が壊れる。**
>
> **確度**: メーカー（杭州捷茂微電子）の datasheet **V2.2（中国語、17 ページ）** に基づく。
> `chips/hym8563.yaml` が記録している URL は alldatasheet.com の HTML ページで PDF ではなく、
> `tools/datasheet_text.py` では扱えない。**M5Stack がミラーしている PDF** を 2026-08-15 に
> 取得して読んだ。実機のキャプチャは無い。

## これは何か

秒・分・時・日・曜日・月・年をカウントし続けるだけの専用 IC。ホストの電源が落ちても、
バックアップ電池が繋がっていれば時刻を保つ。M5Stack Unit RTC (U126) はボタン電池を
載せているので、母艦を外しても時計は進み続ける。

できること:

- 秒（`0x02`）から年（`0x08`）までの 7 バイトを連続で読み書きできる。
  内部のアドレスポインタは読み書きのたびに自動で進む。
- 世紀ビット（`0x07` の bit7）を持つ。`C=0` で 20XX、`C=1` で 19XX。年が 99 → 00 に
  繰り上がると自動で反転する（p10, 表12）。
- **閏年を自分で処理する。** 年カウンタが閏年のとき、2 月を 29 日にする（p9, 表9）。
- アラームを 4 種類（分・時・日・曜日）持ち、一致で `AF` フラグと `INT` を立てる。
- 8bit のカウントダウンタイマ（`0x0F`）を持つ。クロック源は 4096 / 64 / 1 / (1/60) Hz から選ぶ。
- CLKOUT ピンに 32.768kHz / 1024Hz / 32Hz / 1Hz の方形波を出せる（既定は 32.768kHz、出力有効）。
- 電源低下検出器を持ち、電源が落ちたことを `VL` ビットで記録する。

**できないこと・持っていないもの**:

- **温度補償が無い。** 水晶の温度特性はそのまま誤差になる。TCXO 内蔵の RTC ではない。
  実際の日差は水晶と負荷容量に依存し、datasheet は精度（ppm）の数値を示していない。
- **ミリ秒が読めない。** 分解能は 1 秒。`0x02` を読んだ瞬間が秒のどこかは分からない。
- **タイムゾーンも夏時間も知らない。** カレンダの数字を持っているだけである。
- **年は 2 桁（00〜99）。** 世紀ビットと合わせても表せるのは 1900〜2099 の 200 年。
- **アドレスは変更できない。** `0x51` 固定で、ピンもレジスタも無い。
- **時刻が正しいかを自分では判断しない。** 正しさの手掛かりは `VL` ビットだけ（後述）。
- **温度・電池電圧を読めない。** 電池が減っていることは、電源が落ちて `VL` が立つまで分からない。

**電気的な現実**:

- 動作電圧 1.5〜5.5 V（I2C 停止時、25 ℃）、**I2C を 400 kHz で動かすなら 1.8〜5.5 V**（p3）。
- **時計データの信頼性が保証されるのは VDD ≥ Vlow のときだけ**（p3 の DC 特性表）。
  これが後述の `VL` ビットの意味に直結する。
- 休眠電流は VDD=3.0 V, 25 ℃, CLKOUT 禁止で typ 250 nA（p3）。
  **CLKOUT を 32.768kHz で出したままだと typ 650 nA**、SCL が動いていれば
  400 kHz で最大 800 µA まで上がる。電池寿命を気にするなら CLKOUT は切る。
- `INT`、`CLKOUT`、`SDA` はいずれも**オープンドレイン**（p2）。プルアップが要る。
- SCL / SDA の絶対最大定格は -0.5〜+6.5 V なので、5 V の I2C バスにそのまま置ける。

## レジスタ

全 16 本。datasheet p7 の表1・表2 が一覧。

| アドレス | 名前 | 中身 |
|---|---|---|
| `0x00` | 制御/状態 1 | bit7 `TEST`、bit5 `STOP`、bit3 `TESTC`。それ以外は 0 |
| `0x01` | 制御/状態 2 | bit4 `TI/TP`、bit3 `AF`、bit2 `TF`、bit1 `AIE`、bit0 `TIE` |
| `0x02` | 秒 | **bit7 = `VL`（電源低下フラグ）**、bit6-0 = 秒 BCD（00〜59） |
| `0x03` | 分 | bit6-0 = 分 BCD（00〜59）。bit7 は無効 |
| `0x04` | 時 | bit5-0 = 時 BCD（00〜23）。bit7,6 は無効 |
| `0x05` | 日 | bit5-0 = 日 BCD（01〜31）。bit7,6 は無効 |
| `0x06` | 曜日 | bit2-0 = 0〜6（日曜が 0）。**BCD ではない** |
| `0x07` | 月 / 世紀 | **bit7 = `C`（0 → 20XX、1 → 19XX）**、bit4-0 = 月 BCD（01〜12） |
| `0x08` | 年 | bit7-0 = 年 BCD（00〜99） |
| `0x09` | 分アラーム | bit7 = `AE`（**0 で有効**）、bit6-0 = 分 BCD |
| `0x0A` | 時アラーム | bit7 = `AE`、bit5-0 = 時 BCD |
| `0x0B` | 日アラーム | bit7 = `AE`、bit5-0 = 日 BCD |
| `0x0C` | 曜日アラーム | bit7 = `AE`、bit2-0 = 曜日 |
| `0x0D` | CLKOUT 周波数 | bit7 = `FE`（1 で出力有効、既定）、bit1-0 = `FD1:FD0` |
| `0x0E` | タイマ制御 | bit7 = `TE`（1 で有効）、bit1-0 = `TD1:TD0` |
| `0x0F` | タイマ値 | 8bit のカウントダウン値 `n`。周期 = n ÷ クロック周波数 |

`0x0D` の `FD1:FD0`: `00` = 32.768kHz、`01` = 1024Hz、`10` = 32Hz、`11` = 1Hz（p11, 表20）。

`0x0E` の `TD1:TD0`: `00` = 4096Hz、`01` = 64Hz、`10` = 1Hz、`11` = 1/60Hz（p12, 表22）。
**使わないときは `11` にしておく**と消費電力が下がる、と datasheet が推奨している（p11, 表21）。

**転送の形**: ポインタ 1 バイトを書いて repeated START を打ち、必要な長さを読む。
アドレスは 1 バイトごとに自動で進むので、`0x02` を指定して 7 バイト読めば
秒〜年が一度に取れる。レジスタは全部で 16 本（p6）だが、**`0x0F` の次にポインタが
`0x00` へ巻き戻るかどうかは datasheet に明記が無い（未確認）**。

## 典型的な使い方

**読むだけ**（安全）:

1. `0x02` を指定して 7 バイトをまとめて読む。1 バイトずつ読むと、読んでいる途中で
   秒が繰り上がって「23:59:59 の次に 23:00:00」のような値ができる。
2. **最初に読んだバイトの bit7（`VL`）を見る。** 1 なら、この 7 バイトは信用してはいけない（後述）。
3. 各バイトの有効ビットだけを取り出してから BCD → 10 進に直す。
   - 秒 = `buf[0] & 0x7F`、分 = `buf[1] & 0x7F`、時 = `buf[2] & 0x3F`
   - 日 = `buf[3] & 0x3F`、曜日 = `buf[4] & 0x07`（BCD 変換不要）
   - 月 = `buf[5] & 0x1F`、世紀 = `buf[5] & 0x80`
   - 年 = `buf[6]`（BCD）+ 世紀に応じて 1900 か 2000 を足す
4. BCD → 10 進は `(v >> 4) * 10 + (v & 0x0F)`。

**書く**（ユーザーの時計を上書きする）:

1. `0x02` を指定して秒〜年の 7 バイトを一度に書く。各値は 10 進 → BCD に直しておく
   （`(v / 10) << 4 | (v % 10)`）。
2. 秒を書くとき `VL`（bit7）に 0 を入れる。これで「電源低下は起きていない」の意味になる。
3. 月（`0x07`）を書くときに世紀ビットを入れる。1900 年代なら bit7 を立てる。
4. 曜日（`0x06`）は BCD ではないので、そのまま 0〜6 を書く。

## 利用上の注意

- **読むのは無害、書くのは破壊的。** この IC はユーザーの時計そのものである。
  `0x02`〜`0x08` に書けば、それまで刻んでいた時刻は失われる。デバッグ目的で
  「とりあえず適当な値を入れて確認する」のは、他人の腕時計を勝手に合わせ直すのと同じ。
  本リポジトリの `scenarios/hym8563/p0.yaml` が read-only で、`time-write` を `deferred` に
  していただけの理由がここにある。

- **`0x02` の bit7 は秒ではない。** `VL`（電源低下フラグ）である。マスクせずに BCD 変換すると、
  `VL=1` のときに秒が 60 以上のあり得ない値になる。M5Unified の PCF8563 ドライバも
  `readRegister8(0x02) & 0x80` で `VL` を見てから `& 0x7f` で秒を取り出している
  （`M5Unified/src/utility/rtc/PCF8563_Class.cpp`）。

- **`VL=1` は「秒だけおかしい」ではなく「時刻全体が信用できない」の意味。**
  datasheet の DC 特性表（p3）は、時計/カレンダのデータが保証されるのは VDD が
  `Vlow` 以上のときだけだと書いている。`VL=1` は、その `Vlow` を一度でも下回った
  という記録である。つまり **`VL=1` のときは年月日時分秒のすべてが疑わしい**。
  値が「もっともらしく見える」ことは何の保証にもならない。
  `VL=1` を見たら、時刻を表示に使ってはいけない。NTP などの外部ソースから
  取り直して書き込むのが正しい対処である。

  なお **`VL` は自動では消えない**。`0x02` に `VL=0` を含む値を書いて初めて落ちる。
  つまり「電池を交換したのに `VL` が立ったまま」は正常な振る舞いで、
  時刻を設定し直すまで立ち続ける。

- **発振が止まるとリセットが掛かり、`VL` は 1 になる。** 内蔵のリセット回路は
  発振器が停止したときに動き、`TF`・`VL`・`TD1`・`TD0`・`TESTC`・`AE` を **1 に**、
  それ以外のすべてのレジスタ（アドレスポインタを含む）を 0 にする（p6）。
  したがって出荷直後・電池切れ直後の `0x02` は `0x80`（VL=1、秒=00）になる。

- **BCD である。** `0x59` は 89 ではなく 59 秒。逆に 10 進の 59 をそのまま書くと
  `0x3B` = BCD では「3B」という不正な値になる。読み・書きの両方で変換を忘れない。

- **曜日と曜日アラームだけ BCD ではない**（p6 に明記）。`0x06` は 0〜6 の生の値。
  一括で BCD 変換を掛けるコードはここで間違える。0〜6 の範囲では BCD と 2 進が一致するので
  **バグがあっても症状が出ない**のがたちが悪い。

- **`AE` は反転論理。** アラームレジスタの bit7 は `AE`（Alarm Enable）だが、
  **0 で有効、1 で無効**である（p10, 表15）。リセット後は 1（無効）になる。

- **`AF` と `TF` はソフトでしか消えない。** アラーム一致で `AF`、タイマ満了で `TF` が立ち、
  ハードでは落ちない。しかも `0x01` に書き戻すときの規則が特殊で、
  **書き込み時に 0 を書くとクリア、1 を書くと保持**である（p8, 表4）。
  片方だけ消したいときは、読んだ値に対して論理積を取って書き戻す
  （datasheet も「重ね書きで別のフラグを消さないよう論理積を実行する必要がある」と書いている）。
  素直にリード・モディファイ・ライトすると、その間に立った方のフラグを消してしまう。

- **`0x51` は本カタログ内で 3 つのデバイスと衝突する。**
  `eeprom`（M5Stack Unit AMeter の校正 EEPROM）と `m5stack-mcu-u026`（Unit 16-Key
  Capacitive Touch）が同じ `0x51`。HYM8563 のアドレスは変えられないので、
  Unit RTC と Unit AMeter を同じ Port.A に繋ぐことはできない。
  I2C マルチプレクサ（`pca9548a` / `tca9548a`）で分けるしかない。

- **`0x00` の `STOP` ビットを立てると時計が止まる。** RTC の分周器が非同期に 0 にされ、
  時刻が進まなくなる（CLKOUT の 32.768kHz は出続けるので、外からは動いているように見える）。
  `TEST` / `TESTC` も含め、`0x00` に不用意に書かない。

- **CLKOUT は既定で有効。** `0x0D` のリセット値は `FE=1` で 32.768kHz が出っぱなしになる。
  電池駆動で使うなら `0x0D` に `0x00` を書いて止める（休眠電流 typ 650 nA → 250 nA）。

- **タイマ値を正確に読み戻すには、SCL がタイマクロックの 2 倍以上必要**（p11）。
  1/60Hz のタイマなら問題にならないが、4096Hz を選んだうえで遅い I2C で読むと値がずれる。

- **datasheet の誤植に注意。** 時アラーム（p10, 表16）と曜日アラーム（p11, 表18）の
  値の範囲がどちらも「00〜59」と書かれているが、ビット幅（それぞれ bit5-0 と bit2-0）から
  実際は 00〜23 と 0〜6 である。中国語版 V2.2 で確認した誤りで、PCF8563 の記述が正しい。
