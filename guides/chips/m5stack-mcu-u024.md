# Unit Joystick (U024) — アナログジョイスティック入力ユニット（初代）

> 2 軸スティックと押し込みスイッチを I2C で読むだけのユニット。**レジスタは存在しない。**
> ポインタバイトを書かずに 3 バイト読むと X, Y, ボタンが返る。それがプロトコルのすべてである。
>
> **確度**: datasheet も I2C プロトコル文書も専用 Arduino ライブラリも無い。本リポジトリに
> `profiles/m5stack-mcu-u024.yaml` は存在せず、レジスタマップも実測も持っていない。
> 本ガイドの根拠は M5Stack 製品ページの仕様表と、ベンダーが公開している**ホスト側**
> サンプルコード 2 本だけである。**バス上で確認された挙動は一つも無い。**

## これは何か

アナログ 2 軸ジョイスティック（可変抵抗式）と押し込みスイッチを、基板上の ATmega328P が
AD 変換して I2C で返すユニット。ホストから見える相手は ATmega であってスティックではない。
**つまり I2C の相手は固定機能 IC ではなくファームウェアであり、通信仕様はこの製品固有のもの**である。

LEGO 互換の取り付け穴が 2 つあり、製品ページはゲームコントローラやロボット操縦の入力を
用途として挙げている。

できること:

- X / Y を 0〜255 の 8bit 値として読める。
- 押し込みスイッチの状態を読める。

できないこと・持っていないもの:

- **レジスタが無い。** ファームウェアのバージョンも、ハードウェアの種別も読めない。
  したがって **I2C から「これは Joystick だ」と同定する手段が無い。**
- **アドレスを変更できない。** 同じバスに 2 台並べられない。
- **割り込み線が無い。** 変化を知るにはポーリングするしかない。
- **キャリブレーション・デッドゾーン・中心補正が一切無い。** 中心値の個体差はホスト側で吸収する。
- **LED もブザーも無い。** 光らせるものが載っていない。
- **分解能を上げられない。** 返るのは 8bit だけで、生の ADC を 12/16bit で取り出す口は無い。
  （後継の Unit Joystick2 にはある。下の「兄弟機」を参照）

## 早見表

| 項目 | 値 |
|---|---|
| I2C アドレス | `0x52`（固定。変更手段なし） |
| 電源 | 5V（Grove の赤） |
| インタフェース | Grove HY2.0-4P |
| I2C 速度 | ベンダーのサンプルは `Wire.begin(21, 22, 400000UL)` で **400kHz** 初期化。上限は**未実測** |
| 中身 | ATmega328P + アナログジョイスティック + 押し込みスイッチ |
| 割り込み | 無し（ポーリング） |
| 転送の形 | **ポインタバイト無し**の 3 バイト読み出し |
| X / Y 出力 | 0〜255（サンプルコードのコメントは実効レンジを **10〜250** と書く） |
| ボタン出力 | `0` = 離、`1` = 押（サンプルコードのコメント由来。**未確認**） |
| 寸法 / 重量 | 48.0 × 24.0 × 32.0mm / 11.0g |
| その他 | LEGO 互換穴 ×2 |

## レジスタ / コマンド

**既知のレジスタマップは無い。そもそもレジスタが無い可能性が高い。**

製品ページには「Protocol」として次の 1 行だけの表が載っている。

| REG | len | description | return values |
|---|---|---|---|
| `0x52` | 3 | Read joystick status | `[0]` X VALUE `[1]` Y VALUE `[2]` BTN STATUS |

**この `REG` 欄の `0x52` はレジスタ番号ではなく I2C アドレスである。** M5Stack の製品ページは
レジスタを持たないユニットでもこの表形式を使い回すので、アドレスが REG 欄に入る。実際、
ベンダーのサンプルコードはどちらも `Wire.requestFrom(0x52, 3)` を呼ぶだけで、
**読み出しの前にポインタバイトを一切書いていない**。書き込みトランザクション自体が
サンプルには現れない。

したがって現時点で言えるのは「アドレス `0x52` に 3 バイト要求すると X, Y, ボタンが返るらしい」
までであり、ポインタバイトを書いたときに何が起きるか（無視されるのか、別の応答になるのか、
そもそも ACK するのか）は分かっていない。

**何があればこれが確定するか**（有用な順）:

1. **実機のキャプチャ。** ポインタバイトを 1 バイト書いてから読む／いきなり読む、要求長を
   1〜8 バイトに振る、といった probe を当てれば、レジスタの有無はほぼ即座に決着する。
   本ユニットは read-only の探索で危険が無い（書き込み先が無いので副作用の心配が薄い）。
2. **UIFlow が実機を叩くところのキャプチャ。** UIFlow はサンプルコードとは別実装なので、
   もし別の読み方をしていればレジスタの存在が分かる。
3. **スレーブ側 firmware のソース。** 兄弟製品の CardKB と Makey は
   `M5-ProductExampleCodes` に `firmware_328p/` として公開されているが、
   **Joystick のディレクトリには `Arduino/` と `UIFlow/` しか無く firmware が無い。**
   これが公開されれば一次資料になる。
4. **ATmega328P の flash 吸い出し。** lock bit 次第。分解が要る。

**レジスタを捏造しないこと。** 後継の Unit Joystick2（`0x63`）は `0x00` / `0x20` / `0x30` …
という整ったレジスタマップを持つが、**それは別 MCU（STM32G030）の別ファームウェアであり、
本機に当てはめる根拠は何も無い。**

## 典型的な使い方

1. Wire を開く（ベンダーのサンプルは 400kHz）。
2. `0x52` に 3 バイト要求する。**ポインタバイトは書かない。**
3. 1 バイト目が X、2 バイト目が Y、3 バイト目がボタン。
4. 起動直後にスティックを触らずに数回読み、その値を中心として記録する。個体ごとに
   中心はずれているので、これをやらないと常にどちらかに倒れているように見える。
5. あとは一定周期（サンプルは 200ms）で読む。

## 利用上の注意

- **I2C から機種を同定できない。** バージョンレジスタも ID レジスタも無いので、
  `0x52` が ACK したという事実以上のことは分からない。同じアドレスに別のものが
  ぶら下がっていても、3 バイト読めてしまえば区別がつかない。**接続確認はスキャンではなく
  「スティックを動かしたら値が動くか」で行うしかない。**
- **本カタログ内の `0x52` 衝突**: [`chips/m5stack-mcu-u024-c.yaml`](../../chips/m5stack-mcu-u024-c.yaml)
  （Unit Joystick v1.1）が**同じ `0x52`** である。どちらもアドレスを変更できないので、
  **初代と v1.1 を同じバスに並べることはできない。** 後継の Unit Joystick2 は `0x63` なので
  共存できる。
- **VL53L0X との取り違えに注意。** [`chips/vl53l0x.yaml`](../../chips/vl53l0x.yaml) の notes が
  書くとおり、VL53L0X の 7bit アドレスは `0x29` で、**その 8bit 表記の write アドレスが `0x52`**
  である。7bit の `0x52` とは別物なので実際のバス上では衝突しないが、ST のデータシートや
  ログを突き合わせるときに「`0x52` が 2 つある」ように見えて混乱する。
- **ボタンの極性が M5Stack の他ユニットと逆に見える。** Unit Scroll や Unit Joystick2 は
  押下が `0` のアクティブ Low だが、本機のサンプルコードは `// Z(0: released 1: pressed)` と
  コメントしている。**どちらが実機の挙動かは未確認。** 真偽値へ変換する前に実機で必ず確かめること。
- **X / Y を 0 や 255 で判定しない。** 製品ページは「0-255」と書くが、ベンダーのサンプルは
  `// X(range: 10~250)` とコメントしている。端まで倒しても `0` / `255` に届かない個体が
  あり得るので、しきい値は余裕を持たせる。
- **3 バイト未満／4 バイト以上を要求したときの挙動は未確認。** AVR の Wire スレーブは
  要求長が送信バッファを超えると `0xFF` を返すのが普通だが、本機で確かめられていない。
- **割り込みが無いのでポーリング周期が応答性の上限になる。** 素早いスティック操作の
  中間位置は取りこぼす。ただし「読むと消える」たぐいのレジスタは（レジスタ自体が無いので）
  存在せず、取りこぼしても値が失われるわけではない。
- **本ガイドに書かれたことは、寸法と重量を除いてどれも実測で確認されていない。**

## 出典と確度

- **datasheet: 無い。** M5Stack はこの世代の Joystick について I2C プロトコル文書
  （他ユニットにはある Protocol PDF や画像）を一切公開していない。参照先は製品ページのみ。
- **ベンダー Arduino ライブラリ: 無い。** `M5Unit-Joystick` に相当するリポジトリは存在せず、
  [`collection/vendor_libraries.toml`](https://github.com/tanakamasayuki/I2CDeviceDB/blob/38f1d82/collection/vendor_libraries.toml) にも
  `collection/vendor/` にもエントリが無い。あるのは `M5Unit-Joystick2`（後継機用、別アドレス・別 MCU）だけで、
  **本機には使えない。**
- **`profiles/`: 無い。** レジスタマップを起こす元となるソースが存在しないため。
- **キャプチャ: 無い。** `observations/` にも `scenarios/` にもこのチップのディレクトリは無い。
- アドレス `0x52`、3 バイト読み、バイトの並び（X, Y, BTN）: **製品ページの Protocol 表と
  ベンダーのホスト側サンプルコードの両方に基づく**（この 2 つは互いに一致している）。
- 400kHz、X/Y の実効レンジ 10〜250、ボタンの `0: released 1: pressed`:
  **サンプルコードの引数とコメント由来**。ソースコードのコメントであって仕様書ではない。
- 搭載 MCU が ATmega328P であること: [`chips/m5stack-mcu-u024.yaml`](../../chips/m5stack-mcu-u024.yaml) の
  記載による。**製品ページは MCU 型番を書いていない**（v1.1 の製品ページは MEGA8A と書いている）。
- **次にやるべき最も有用な一手**: `0x52` に対する read-only の probe を書いて実機に当てること。
  ポインタバイトを書いた場合と書かない場合、要求長 1〜8 バイトの応答を並べて記録すれば、
  「レジスタが無い」という本ガイドの中心的な主張が確定するか反証される。書き込み先が
  存在しないと考えられるため、探索の副作用リスクが低い部類のユニットである。
